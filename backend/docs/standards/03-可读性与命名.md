# 03 可读性与命名

## R1 长度与复杂度上限（必须）

| 对象 | 上限 | linter |
|------|------|--------|
| 函数 | 80 行 / 50 条语句（不计注释） | `funlen` |
| 函数认知复杂度 | 20 | `gocognit` |
| 单个文件 | 500 行代码（不计注释和空行） | `revive: file-length-limit` |

测试文件不受这三条限制，因为表驱动测试天然就长。

超出上限时，按下面的方式拆：

- **文件按职责拆**，文件名用 `<模块>_<职责>.go`。正例是 AI 配置模块拆成了 [ai_config.go](../../internal/service/ai_config.go)、`ai_config_import.go`、`ai_config_registry.go`、`ai_config_run.go`、`ai_config_secret.go`、`ai_config_seed.go`。
- **函数按步骤拆**：带编号的步骤注释（见 R6）就是天然的拆分边界。把一个步骤抽成私有方法，原来的位置只留一行调用和原来那条步骤注释。
- 不要为了压行数而把逻辑挤成一行，也不要拆出只被调用一次、名字又说不清用途的函数。

**原因**：超过一屏的函数，读的人得来回滚动才能记住状态，复杂度高的函数，测试也很难覆盖全所有分支。

## R2 包命名（必须）

- 小写、单数、名词，名字说明用途，比如 `pagination`、`errcode`、`storage`。
- **禁止**新建 `utils`、`common`、`helper`、`base`、`misc` 这类包（原因见 [U3](04-复用与抽象.md#u3-禁止大杂烩包必须)）。
- 包名不要和它导出的名字重复：写 `storage.New`，不要写 `storage.NewStorage`。
- **检查**：review。

## R3 文件命名（必须）

- 用 snake_case，和文件里的主类型对应，**用单数**：`canvas_project.go` 对应 `CanvasProject`。
- 同一个模块在不同层的文件同名，例如 `model/generation_task.go`、`repository/generation_task.go`、`service/generation_task.go`、`handler/generation_task.go`。这样按文件名搜索，就能一次看到这个模块的所有层。
- 只给测试用的导出放在 `export_testing.go` 里（见 [T3](05-测试.md)）。
- **存量**：`model/canvas_projects.go` 用了复数，与其他层不一致（X6）。
- **检查**：review。

## R4 标识符命名（必须）

- 缩写全大写：`UserID`、`URL`、`JSON`、`HTTPStatus`。存量问题：`utils.MyClaims.UserId`（X6）。
- 不要遮蔽内置函数：变量名不要用 `max`、`min`、`len`、`new`、`real`，改用 `maxBytes`、`limit`。存量 9 处（X6）。
- 接收者名用 1～2 个字母，同一个类型的所有方法保持一致，例如 `s *XxxService`、`r *XxxRepository`、`h *XxxHandler`。
- 布尔变量和字段用 `isXxx`、`hasXxx`、`canXxx`，或者直接用形容词，例如 `enabled`。
- 请求结构体的命名规则：
  - 统一叫 `CreateXxxReq`、`UpdateXxxReq`、`ListXxxReq`；
  - 列表项叫 `XxxItem`，对外视图叫 `XxxView`。
- 时长一律用 `time.Duration`，不要用表示秒数的 `int`。常量名或注释里写清单位，例如 `defaultTaskDeadline = 30 * time.Minute`。
- 禁止魔法数：有业务含义的数值都提成带注释的常量。正例：[generation_task.go 开头的常量块](../../internal/service/generation_task.go)。
- **检查**：`revive: var-naming / receiver-naming / redefines-builtin-id / time-naming`；其余靠 review。

## R5 函数签名（必须）

- 第一个参数是 `ctx`（见 A8），最后一个返回值是 `error`。
- 参数超过 4 个，或者有多个同类型参数容易传错位置时，改用输入结构体。正例：`repository.SaveDraftInput`。
- 部分更新的字段用指针，比如 `Title *string`，用来区分“没传”和“传了空值”。
- 不要用 `(bool, error)` 同时表达两种失败。如果 `false` 本身就是一种业务结果（比如 `ExtendLease` 的 `false` 表示任务已进入终态），在 doc 注释里写明它的含义。
- **检查**：review。

## R6 注释（必须）

1. **导出的符号必须有注释，并且以符号名开头**：

   ```go
   // Create 提交生成任务：Idempotency-Key 保证重复提交只创建一个任务，返回 202 + 任务快照。
   func (h *GenerationTaskHandler) Create(c *gin.Context) {
   ```

   目前全仓库有 112 处导出符号缺注释，或者注释没有以名字开头（X4）。其中 handler 的 40 个方法里有 17 个是后一种情况。改到哪里就顺手补上。

2. **service 层还要按步骤写逻辑注释**：`// 1. ...`、`// 2. ...`，续行用 `//    ` 缩进对齐。完整要求见 [AGENTS.md 规则 2](../../AGENTS.md)。

3. **注释写“为什么”**，不要复述代码。下面几种情况必须写出原因：
   - 安全相关的设计；
   - 故意忽略的错误；
   - 默认值、边界修正、降级策略；
   - 错误转换（repository 错误 → errcode → HTTP 状态码）。

4. 禁止提交被注释掉的代码。需要保留的历史，在 git 里找。

5. TODO 写成 `// TODO: 说明（关联的设计文档或 issue）`。没有上下文的 TODO 等于没写。

6. 改了逻辑，必须同步改注释。与代码不符的注释比没有注释更糟。

- **检查**：`revive: exported` 检查第 1 条；其余靠 review。

## R7 控制流（必须）

- 错误先处理、尽早返回，正常路径不要缩进在 `else` 里。
- 超过 3 个分支的 `if-else if` 链，改成 `switch`。
- **检查**：`revive: indent-error-flow / early-return / superfluous-else`、`staticcheck QF1003`。

## R8 文案语言（必须）

注释、错误提示、日志 message 统一用中文。代码标识符、日志字段名、JSON 字段名用英文。

## R9 格式（必须）

- 统一用 `make fmt` 格式化（gofmt + goimports）。
- import 分三组，组与组之间空一行：标准库 / 第三方 / `video-canvas/...`。
- **检查**：`make lint` 中的 `gofmt`、`goimports`。
