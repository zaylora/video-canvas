# 06 工程化与协作

## G1 提交前检查（必须）

| 目标 | 等价命令（没装 make 时直接运行） | 作用 |
|------|----------------------------------|------|
| `make fmt` | `golangci-lint fmt ./...` | gofmt + goimports 自动整理 |
| `make lint` | `golangci-lint run --new-from-merge-base=master ./...` | 只查增量，**输出 `0 issues.` 才算通过** |
| `make test` | `go test ./...` | 单元测试 |
| `make test-race` | `go test -race ./...` | 涉及并发的改动必须跑 |
| `make lint-all` | `golangci-lint run ./...` | 全量检查，跟踪存量问题 |
| `make tools` | `go install github.com/golangci/golangci-lint/v2/cmd/golangci-lint@v2.14.0` | 安装与 CI 同版本的 linter |

- `make lint` 只检查增量，所以存量问题不会挡住当前的提交；但你改动过的代码行必须是干净的。
- golangci-lint 的版本号固定在 [Makefile](../../Makefile) 的 `LINT_VERSION` 里。升级时，本地、CI 和这张表一起改。

## G2 换行统一为 LF，编码统一为 UTF-8（必须）

- [backend/.gitattributes](../../.gitattributes) 设置了 `* text=auto eol=lf`。
- **原因**：gofmt 只认 LF。Windows 上默认 `core.autocrlf=true`，检出的文件是 CRLF，结果 `gofmt -l .` 会把这些文件全部报成“未格式化”。本规范生效前，就有 35 个文件因此在本地过不了 lint，而 CI 在 Linux 上检出的是 LF，所以一直没暴露。
- 编辑器建议设置：VS Code 里 `"files.eol": "\n"`。

## G3 lint 配置与 nolint（必须）

- 修改 [.golangci.yml](../../.golangci.yml) 时，同步修改对应的规范条目（见 [README](README.md#怎么改规范)）。
- 局部豁免只能写成下面这样：**指明具体 linter，并写出原因**，否则 `nolintlint` 会报错：

  ```go
  f, err := os.Open(full) //nolint:gosec // full 已由 l.path 校验，不会越出存储根目录
  ```

- 豁免多于 3 处的，不要逐行写 nolint，在 `.golangci.yml` 的 `exclusions` 里按路径登记，并在[存量问题清单](存量问题清单.md)里写明原因。

## G4 提交信息用 Conventional Commits（必须）

```
<type>(<scope>): <中文描述>

<可选正文：为什么改、影响范围>
```

- `type` 从下表选。[cliff.toml](../../../cliff.toml) 按 type 生成 CHANGELOG 的分组：

  | type | CHANGELOG 分组 |
  |------|----------------|
  | `feat` | Added |
  | `fix` | Fixed |
  | `refactor`、`perf` | Changed |
  | `docs` | Documentation |
  | `build`、`ci`、`chore` | Changed |
  | `test`、`style` | Other |
  | `revert` | Reverted |

- `scope` 可以省略，常用的有 `backend`、`web`、`ci`，或者模块名，例如 `task`、`canvas`。
- **type 后面用半角冒号 + 空格。**
  - 反例：历史提交 `feat：新增画布项目管理功能` 用了全角冒号。git-cliff 没把它识别成规范提交，结果 CHANGELOG 里显示成 `Feat：新增...`，前缀原样保留。
- 一个提交只做一件事。反例：`feat: 添加 GitHub Actions 工作流… feat: 添加 CHANGELOG.md…` 把两件事塞进了一条提交。
- 不兼容的改动（比如改错误码数值、改响应结构），在正文里写 `BREAKING CHANGE: 说明`。
- **检查**：review；以后可以在 CI 里加 commitlint。

## G5 分支与 PR（建议）

- 从 `master` 拉功能分支：`feat/<简述>`、`fix/<简述>`。
- PR 描述写三件事：**改了什么、为什么改、怎么验证的**（跑了哪些测试、手动点了哪些接口）。
- 一个 PR 只解决一个问题，diff 尽量控制在 400 行以内（不含测试和生成的文件）。
- 接口有变更的 PR，必须同时更新 [README.md](../../README.md) 的接口表。

## G6 CI（建议，待落地）

现状：[release-docker.yml](../../../.github/workflows/release-docker.yml) 只在打 tag 时运行 `gofmt` + `go vet` + `go test`，**PR 和 master 上的推送都没有检查**。

建议新增 `.github/workflows/ci.yml`，在 PR 和推送到 master 时运行。后端部分：

```yaml
backend:
  runs-on: ubuntu-latest
  services:
    postgres:
      image: postgres:17
      env: { POSTGRES_PASSWORD: postgres, POSTGRES_DB: video_canvas_test }
      ports: ["5432:5432"]
      options: >-
        --health-cmd pg_isready --health-interval 5s --health-retries 10
  env:
    TEST_DATABASE_DSN: host=localhost user=postgres password=postgres dbname=video_canvas_test sslmode=disable
  steps:
    - uses: actions/checkout@v4
      with: { fetch-depth: 0 } # --new-from-merge-base 需要完整历史
    - uses: actions/setup-go@v6
      with:
        go-version-file: backend/go.mod
        cache-dependency-path: backend/go.sum
    - uses: golangci/golangci-lint-action@v8
      with:
        version: v2.14.0
        install-mode: goinstall # 用当前 Go 版本编译，避免预编译二进制不支持 Go 1.27
        working-directory: backend
        only-new-issues: true
    - working-directory: backend
      run: go test -race ./...
```

上线后，发布工作流里的 quality 任务可以改成复用这个工作流。

## G7 依赖管理（必须）

- 引入新的直接依赖之前，先和维护者确认有没有必要。标准库或现有依赖能做的，不要再加新库。
- 改完依赖后执行 `go mod tidy`，`go.mod` 和 `go.sum` 在同一个提交里提交。
- 版本号固定写在 go.mod 里，不要用 `@latest` 写进脚本。工具的版本也一样固定（见 G1）。

## G8 数据库变更（必须 + 待决策）

- 新增表时，在 `model.All()` 中注册；`database.auto_migrate=true` 时，启动会自动迁移。
- **只做增量变更**：加表、加列、加索引。改列名、改列类型、删列之前，必须在 PR 里写明数据迁移方案和回滚方案。
  - **原因**：`AutoMigrate` 不会删列，也不会改名。改个名字的实际效果是“新增一列，旧列里的数据留在原地”。
- 需要额外 DDL 的（比如部分索引），写在 [initialize/db.go](../../internal/initialize/db.go) 里，并且写成幂等的（`IF NOT EXISTS`）。
- **待决策**：生产环境继续依赖 `auto_migrate`，还是切换到版本化迁移工具（goose / atlas）？这件事在首次正式上线前需要维护者拍板，定下来之后更新本条。

## G9 配置与密钥（必须）

- 本地私有配置放在 `configs/config.local.yaml`（已 gitignore），启动时用 `-c` 指定。
- 密钥只通过环境变量注入：`APP_JWT_SECRET`、`APP_DATABASE_DSN`、`APP_AI_SECRET_KEY`……**绝不提交**到仓库。
- 新增配置项的步骤见 [A10](01-架构与分层.md)。
