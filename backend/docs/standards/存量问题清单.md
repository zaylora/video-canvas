# 存量问题清单

规范生效时（2026-09-30）已经存在的违例。数据来自 `make lint-all`，golangci-lint v2.14.0。

- **基线**：全量 192 个问题，增量 0 个。
- **处理原则**：
  1. `make lint` 只检查增量。新代码和改动过的代码行必须是干净的。
  2. 存量问题**不要求一次性清完**。改到哪个函数，就顺手修掉那个函数里的问题。
  3. 下表的“处理方式”写的是**长期例外**的，登记后保留，不用去修。
  4. 本清单每个月，或者每次大重构之后，用 `make lint-all` 刷新一次数字。

## X1 handler/health.go 直接访问 DB 和 Redis，并直接写 JSON

- **规则**：A1、A6
- **现状**：健康检查持有 `*gorm.DB` 和 `*redis.Client` 做探活；降级时用 `c.JSON` 返回 503。
- **处理方式**：**长期例外**。探活本来就需要直接碰基础设施，而且要按探活约定返回状态码。`.golangci.yml` 已经按路径豁免了这个文件。

## X2 service 与 provider 契约依赖 provider/dsl

- **规则**：A3
- **现状**：
  - `service` 下有 6 个文件 import 了 `provider/dsl`：`ai_config*.go`、`generation_task.go`、`export_testing.go`；
  - `provider/types.go` 本身也依赖 `dsl`，也就是契约依赖了实现；
  - `engine`、`worker`、`aiconfigfake` 同样依赖 `dsl`。
- **处理方式**：随 [协议插件设计](../../../docs/design/协议插件设计.md) 的重构一并消除。重构期间：
  - 新代码不要增加对 `dsl` 的依赖；
  - `dsl` 包内部的 lint 问题不去修：8 个 gocognit、3 个 errorlint、1 个 govet、1 个 early-return，它们会随包删除一起消失。
  - 重构完成后，把 `provider/dsl`（或它的替代包）加进 depguard 的 service 规则里。

## X3 错误码 4xxxx 同时容纳了多个模块

- **规则**：A9
- **现状**：任务、积分、素材、AI 配置、WS 五个模块的错误码共用 `4xxxx` 号段。
- **处理方式**：**长期例外**。已发布的错误码数值不能改；这几个模块的新错误码继续追加在 `4xxxx`，新模块从 `5xxxx` 开始。

## X4 导出符号缺注释，或注释没有以名字开头（112 处）

- **规则**：R6
- **分布**：
  - handler 共 28 处：`generation_task` 7、`canvas_project` 7、`user` 6、`asset` 4 等。其中 17 个是方法注释写成了 `// 查询单个任务` 这种形式，另外 11 处是构造函数或类型缺注释。
  - `repository/user.go` 8
  - `config/config.go` 7
  - `pkg/logger` 6
  - `model/user.go`、`model/canvas_projects.go` 各 5
  - 其余散落在 30 个文件里，每个文件 1～4 处。
- **处理方式**：改到哪个文件就把那个文件补齐。可以按包分批，做成独立的 `docs:` 或 `refactor:` 提交，**不要和功能改动混在一起**。
