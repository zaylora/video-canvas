# 04 复用与抽象

## U1 同样的逻辑出现第三次再抽（建议）

- 第一次直接写，第二次允许复制，第三次再抽成公共代码。
- 抽之前先判断：这几段代码重复的是**同一条知识**（一处改了，其他几处也必须跟着改），还是只是**碰巧长得像**？
  - 前一种应该抽；
  - 后一种强行合并，将来会被迫加 `if` 参数去区分调用方，最后比复制还难维护。
- **检查**：review。

## U2 抽出来的代码放哪（必须）

| 使用范围                                           | 放在哪里                                                             | 正例                                                                                 |
| -------------------------------------------------- | -------------------------------------------------------------------- | ------------------------------------------------------------------------------------ |
| 只在一个包内用                                     | 包内私有函数，放在使用它的文件里；多个文件都用时，放进包内的公共文件 | [repository/repository.go](../../internal/repository/repository.go) 的 `translate()` |
| 同一层的多个文件用                                 | 该层的公共文件                                                       | [handler/bind.go](../../internal/handler/bind.go)                                    |
| 多个内部包用                                       | `internal/pkg/<用途>/`                                               | `internal/pkg/response`、`internal/pkg/errcode`                                      |
| 可以被外部模块引用，**并且不依赖任何 internal 包** | 仓库根下的 `pkg/<用途>/`                                             | [pkg/pagination](../../pkg/pagination/pagination.go)                                 |

- 不确定放哪时，选范围更小的位置。以后要往外挪很容易，往回收很难。
- **检查**：`depguard` 保证 `pkg/` 不依赖 internal；放的位置对不对靠 review。

## U3 禁止大杂烩包（必须）

不要新建 `utils`、`common`、`helper` 这类包。

- **原因**：这种包名不说明用途，什么都能往里放。时间一长，它会依赖一切，也被一切依赖，最容易成为循环依赖的源头。
- **存量**：`internal/pkg/utils` 里现在放着 JWT 和 RequestID（X6）。以后按用途拆成 `internal/pkg/jwtutil` 和 `internal/pkg/requestid`；在拆之前，不要再往里加东西。
- **检查**：review。

## U4 接口要小，由使用方定义（必须）

- 接口只列使用方真正调用的方法，见 [A2](01-架构与分层.md)。
- 只有在以下两种情况才定义接口：
  1. 需要在测试里替换实现；
  2. 确实存在多个实现，比如 `storage` 有 local 和 s3 两套。

  不要为了“以后可能换”而预先抽接口。

- 一个接口超过 10 个方法时，考虑按使用场景拆开。正例：`repository.GenerationTaskTx` 把事务内可用的原语单独拆成了一个接口。
- **检查**：review。

## U5 泛型只用于真正与类型无关的代码（建议）

- 适合用泛型的场景：容器、集合运算、通用算法，比如去重、分批。
- 不要为了省几行代码，把业务逻辑写成泛型。泛型的类型约束一复杂，读的人就得先解一遍类型才能看懂业务。
- **检查**：review。

## U6 先用已有的公共设施（必须）

动手写之前先查下表，**已有的能力不要重新实现一遍**：

| 需求                           | 用这个                                                   | 位置                                                                                                                  |
| ------------------------------ | -------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------- |
| 绑定并校验请求参数（中文提示） | `bindJSON` / `bindQuery` / `bindURI` / `pathID`          | [handler/bind.go](../../internal/handler/bind.go)                                                                     |
| 取当前登录用户                 | `currentUserID(c)`                                       | [handler/canvas_project.go](../../internal/handler/canvas_project.go)（位置不合理，应该挪到 `bind.go`，X6）           |
| 统一响应                       | `response.OK` / `OKPage` / `Accepted` / `Fail`           | [internal/pkg/response](../../internal/pkg/response/response.go)                                                      |
| 业务错误                       | `errcode.ErrXxx`、`.WithMsg()`                           | [internal/pkg/errcode](../../internal/pkg/errcode/errcode.go)                                                         |
| 分页参数修正                   | `pagination.Query`（`Normalize` / `Offset` / `Limit`）   | [pkg/pagination](../../pkg/pagination/pagination.go)                                                                  |
| gorm 错误翻译                  | `translate(err)` → `ErrNotFound`                         | [repository/repository.go](../../internal/repository/repository.go)                                                   |
| 模糊搜索转义                   | `escapeLike`                                             | [repository/canvas_project.go](../../internal/repository/canvas_project.go)（第二个模块要用时，挪到 `repository.go`） |
| 事务                           | `WithTx(ctx, fn)`                                        | 见 [A5](01-架构与分层.md)                                                                                             |
| 日志                           | `logger.Info` / `Warn` / `Error`，`logger.L().With(...)` | [internal/pkg/logger](../../internal/pkg/logger/logger.go)                                                            |
| RequestID                      | `utils.GetRequestID(c)`                                  | [internal/pkg/utils](../../internal/pkg/utils/request_id.go)                                                          |
| JWT 签发和解析                 | `utils.GenerateToken` / `ParseToken`                     | [internal/pkg/utils](../../internal/pkg/utils/jwt.go)                                                                 |
| 对象存储                       | `storage.Storage`、`storage.ValidateKey`                 | [internal/storage](../../internal/storage/types.go)                                                                   |
| 推送给用户                     | `ws.Broadcaster`（nil 时换成 `ws.NopBroadcaster{}`）     | [internal/pkg/ws](../../internal/pkg/ws/types.go)                                                                     |
| 可降级缓存                     | `cache.*`（`rdb == nil` 时所有方法都是空操作）           | [internal/cache](../../internal/cache/user.go)                                                                        |

新增一项公共设施时，同步更新这张表。

## U7 测试 fake 的复用（必须）

| 使用范围                          | 放在哪里                                                                                                                                              |
| --------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------- |
| 只有一个测试文件用                | 写在这个测试文件里                                                                                                                                    |
| 同一个测试包的多个文件用          | 放进这个测试包的 `helpers_test.go`                                                                                                                    |
| service 测试和 handler 测试都要用 | `internal/service/<模块>fake/` 独立包，**不能依赖 service 包**，否则会产生循环依赖。正例：[aiconfigfake](../../internal/service/aiconfigfake/fake.go) |

- 共享的 fake 要和真实实现保持相同的语义，比如状态机、哨兵错误。真实实现改了，fake 必须跟着改。
- **检查**：review。
