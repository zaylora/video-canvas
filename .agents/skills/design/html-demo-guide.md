# 演示 HTML 写法指南

设计收敛后要交付两份文档。这份指南只管其中给用户读的那份：**可交互的 HTML 演示文档**。给 AI 记录的 Markdown 文档见 `skill.md` 第 6 步。

写之前先复制同目录的 [`html-demo-template.html`](html-demo-template.html) 作为起点，按本指南替换内容。模板里已经有全部通用样式和脚本，只需要写内容。

## 0. 定位

- 它不是 Markdown 的网页版，也不是只给人看的效果图。**它和 Markdown 一样是可落地的设计文档**：原型的交互行为、数据模型、接口、状态、错误和边界，都要写到开发者能直接照着实现的粒度。
- 分工上，Markdown 侧重依据和完整细节（证据、取舍、来源），HTML 侧重运转方式和界面行为（看得见、点得动、能做决定）。
- 读者是用户和需求方，不一定懂实现。读完前两个标签页，应该能说出：要做什么、一条请求怎么走、什么情况会回退、哪些已确认哪些还没定。
- 能点的地方尽量让人点：对比用表，流程用图，配置类功能用可点击原型，而不是大段文字。

## 1. 技术形态

- **单文件 `.html`，双击即开**。内联 CSS 和原生 JS，不用构建、框架或后端。
- 外部资源只允许两个 CDN：Google Fonts（Geist、Geist Mono）和 lucide 图标（`unpkg.com/lucide@固定版本/dist/umd/lucide.min.js`）。离线时字体回退系统字体、图标缺失，都不能影响阅读。
- **状态全放内存，刷新复原**，并在页面里写明。不真实调用任何外部服务，不依赖 localStorage 保存必要状态。
- **颜色全走 CSS 变量**：shadcn 风格的 HSL 令牌（`--background`、`--foreground`、`--muted`、`--border`、`--primary` 等）加语义色 `--ok`、`--bad`、`--warn`、`--info`、`--violet`（RGB 三元组，方便 `rgb(var(--ok) / .1)` 取透明度）。明暗主题只换变量，用 `html.dark` 切换，顶栏放切换按钮。
- 仓库里已有演示 HTML 或前端令牌时，优先沿用同一套令牌，让原型看起来像真实产品。
- 动态插值一律过 `esc()` 转义再进 `innerHTML`。
- 输入框、下拉的编辑只改状态、不整体重绘，否则输入时会失焦；需要刷新其他区域时延迟局部重绘。
- 表格放进 `.cmp-wrap`，窄屏横向滚动；页面在手机宽度下不出现整页横向滚动。

## 2. 页面骨架

1. **吸顶顶栏**：左侧 logo + 文档标题，中间标签页，右侧“设计标注”开关和明暗切换。
2. **标签页按读者的问题分，不按文档章节分**，一般 3–5 个，顺序固定为：
   - 总览：这是什么、一条请求怎么走、有哪些形态、对比、场景推演
   - 交互演示（概念可操作时）：选一个选项，改几个参数，看结果
   - 可点击原型（涉及界面时）：在假浏览器框里走完整流程
   - 数据与接口（提案）：关系、数据模型、接口、核心代码、已确认的决定
3. **每个标签页**：`h1` + `lead`（2–4 句人话：解决什么问题、做什么，用粗体点出最关键的边界），然后是若干 `.sec` 块。
4. **每个 `.sec`**：`h2` + 一句 `.sub`（说明这一块回答什么问题）+ 内容。

## 3. 总览页的固定顺序

1. **阅读说明**（info 提示框）：数据来自哪里；示意和真实的界线；设计稿是否已实现。紧跟**核实度图例**：已核对官方页面 / 调研检索未逐条复核 / 未验证需实测。
2. **主线流程图**：4–6 个节点用箭头串联，关键节点高亮；图下用一句“设计：”解释为什么这样分层；再接一个 warn 提示框写**回退 / 兜底**——缺失、停用、失败时系统怎样仍可用。
3. **形态 / 方案分类**：2–4 张等宽卡片。每张含图标和名称、一个限制或默认标签、一句话说明（加粗关键对象）。
4. **对比表**：列是候选，行是维度，**最后一行固定是“核实度”**。单元格用 `.y` 标支持、`.m` 标有限制或风险并把限制写进格子里；不确定的写“未验证：具体缺什么信息”，不留空白。
5. **场景推演**，标题形如“客户要做 X 时，会发生什么”：左边有序步骤（每步一句加粗动作，加一行 `small` 补充），右边 warn 提示框写**边界和后果**，末尾一行灰字说明交付时要提前告知什么。

## 4. 交互演示页

- 左侧选项列表，右侧面板随选择变化。
- 提供少量可改参数，实时展示结果（例如拼出的 URL、计算出的数值），让用户感到“真的会这样”。
- 前置条件做成可勾选清单。
- 页面上写明哪些部分是示意（例如“签名部分由 SDK 生成，这里只示意”）。

## 5. 可点击原型

- 放进假浏览器框：顶部三个圆点 + 假地址栏，路径用面包屑形式（如 `admin.example.com / 系统设置 / 模块名`）。
- 在内存里实现**一条完整流程**，不是只画静态界面。配置类功能默认走：草稿 → 校验 → 试跑 → 发布 / 回滚 / 停用。多步操作用抽屉或向导，顶部有 stepper。
- **预置一个有意义的起点**（例如一个草稿），并在 `lead` 里写明**怎么触发失败**（例如“域名里写 `bad`”），让用户能看到错误长什么样。
- 必须覆盖：空、加载中、成功、失败（说明原因和下一步）、不可用。**不可选的选项禁用并写原因，不要隐藏。**
- 异步用 `setTimeout` 模拟，并标注“模拟，非真实调用”；耗时、体积等数字标“示意”。

## 6. 设计标注层

- 原型和关键区块用 `.note` 包裹（紫色虚线框），框下配 `.note-txt`（紫色小字）。
- 标注写**为什么这样设计、取代了什么、放弃了什么**，不要复述界面上已有的文字。
- 顶栏“设计标注”开关控制显隐，默认开启，关闭后原型看起来就是干净的产品界面。

## 7. 数据与接口页

- 整页标题带“（提案）”，`lead` 说明尚未实现，以及它和 Markdown 设计文档哪一节对应。
- 顺序：**关系表**（谁绑谁、为什么）→ **数据模型表**（字段 + 一句话含义，标注唯一、索引、乐观锁、是否含密钥）→ **接口表**（方法路径 + 业务含义 + 业务错误）→ **核心接口 / 解析流程的伪代码块**（标“提案”）。
- **写到可实现**：字段要有类型或取值范围、唯一和索引约束；接口要有请求参数、返回和业务错误；状态要有迁移规则（什么条件下从哪到哪）。不能只写“支持 xx”。
- 说明对现有项目的复用点（例如沿用哪个迁移机制、哪个版本流程），不要让人以为所有东西都要新建。
- 页尾 **“已确认的决定”有序列表**：每条加粗结论 + 原因，只写用户在访谈中明确回答过的内容；已搁置的决定也要写出来。

## 8. 文字风格

- 面向不懂实现的读者：先说人话，再给术语；代码符号用 `<code>`；句子短；关键对象、边界、结论加粗。
- **每个断言带状态**：已核对 / 调研未复核 / 未验证 / 提案 / 示意。绝不把未验证的内容写成事实，也不把提案写成现状。
- 取舍和边界直说：“本期不做”“不覆盖”“需要提前告知客户”。
- 数字有来源或标“示意”；价格、版本、限制类信息注明访问日期来源在 Markdown 的来源章节。

## 9. 和 Markdown 文档的关系

- **Markdown 是准绳**。HTML 里的每个事实、决定、数字都能在 Markdown 里找到。
- 做 HTML 时发现新的设计决定，**先回写 Markdown**，再在 HTML 里体现，并在已确认的决定里注明“主文档已回写”。
- Markdown 头部链接到 HTML；HTML 的 `lead` 或阅读说明里写明对应 Markdown 的章节。
- 完整来源清单留在 Markdown，HTML 只放必要的简短出处。

## 10. 交付前自检

- 双击能打开；所有标签页都能切换；没有控制台报错。
- 明暗主题下文字、边框、提示框都清晰；窄屏下表格可横向滚动。
- 原型走过一遍成功路径和失败路径；输入框不失焦。
- 所有“提案 / 示意 / 未验证”都有标记；对比表末行有核实度。
- 与 Markdown 的数字、决定、边界一致；开发者只读 HTML 也能实现，没有“这里怎么做”的空白。
- 按项目约定不使用 Playwright 等浏览器自动化；靠通读代码核对逻辑，并让用户自己打开页面确认视觉。
