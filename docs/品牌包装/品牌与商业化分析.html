01现状诊断

README 第一句是「开源的 AI 视频创作无限画布」。这句话和即梦 Octo、LibTV、Higgsfield Canvas、Topview、Wireflow 的自我介绍几乎一样，访客看完分不出差别，也看不到你真正领先的地方。

你真正有、闭源 SaaS 没有的东西

能力仓库里的依据为什么值钱
开源、可私有化部署MIT 许可；scripts/deploy.sh 一行命令部署；GHCR 镜像数据和素材不出门，工作室和企业敢用
任意模型都能接JS 协议插件跑在隔离的 plugin-runner 里，内置 NewAPI 插件不被任何一家模型厂商锁死，新模型出来当天就能接
开箱即用的运营后台积分冻结与退款、用户注册、渠道、模型「草稿 → 校验 → 试跑 → 发布 / 回滚」拿到手就能当成 SaaS 对外运营
画布 Agent + 影视技能库v0.2.0 的画布 Agent、审批卡片；v0.2.1 的技能导入与版本管理用对话就能搭分镜，方法论还能沉淀和复用
素材存在自己的存储里本地磁盘、OSS、COS、S3、R2，可以建多套符合合规要求，存储成本可控
保存可靠本地优先草稿、revision 乐观锁、多标签页互斥编辑永不丢稿，这是专业用户最在意的底线
README 有几处已经过时，会损害可信度：警告框还写着 v0.1.0，实际已经是 v0.2.1；路线图里「画布 Agent 与 skills 管理」没打勾，其实 v0.2.0 和 v0.2.1 已经发布。

02竞品格局

2026 年，「节点画布 + 多模型 + Agent」已经是 AI 视频工具的标准形态，单靠画布形态做不出差异。

产品形态和我们的关系
即梦 Octo字节旗下的画布产品，节点里可以对话，分镜一键生成视频，底层是 Seedance 2.0C 端流量和模型都是它的优势，不正面竞争

03定位

一句话定位：开源的 AI 影视创作画布，自带 AI 副导演，能接任何模型，部署在你自己的服务器上。

目标客户（按商业价值排序）

客户他们要什么我们卖什么
API 中转站和代理商手里有模型渠道，缺一个能直接面对终端用户的产品部署好就能上线一个自有品牌的 AI 视频站，积分、注册、模型上下架都现成。付费意愿最强
漫剧、广告、MCN 工作室素材保密、能接自家模型、团队一起用私有化部署、画布 Agent、技能库沉淀方法论
开发者和技术团队可以二次开发、自己写模型插件开源代码、插件契约、清晰的分层架构

不做什么

  • 不拼 C 端流量，不自研大模型。
  • 不把未上线的能力写进宣传，比如导演台、分镜表、资产管理、版本控制。

04产品命名

命名原则

  • 中文名两个字、好念、有影视语感；英文名短，能注册域名和 GitHub 组织。
  • 名字背后要有能讲的故事，并且和核心交互（节点连线）对得上。
  • 避开 AI 视频领域已经在用的名字。

08视觉识别与 Logo

现在 Logo 用的是 lucide 的 Film 通用图标，配色是 shadcn 默认的灰阶加紫蓝渐变。和大量 AI 产品撞色，看起来像模板。

色彩

放弃紫色 AI 渐变，改用深黑底配放映机琥珀光，带电影院的质感，在同类产品里一眼能认出来。琥珀色只用在品牌位置和关键操作上，界面其余部分继续用中性灰。

放映黑oklch(0.13 0 0)
放映机琥珀oklch(0.78 0.15 70)
深琥珀oklch(0.62 0.16 55)
胶片白oklch(0.97 0.01 85)

五个 Logo 方向

都从同一个品牌理念出发：镜头与镜头的连接。每个方向都放在深底、浅底、琥珀底上看一遍，再看 64 到 16 像素的小尺寸表现，以及和文字组合后的样子。这些都是几何概念稿，选定方向后要交给设计师精修线宽、圆角和视觉重心。

打开后检查：去掉琥珀色，只剩一种颜色时还认不认得出来（印章、烫金、传真这类场景只能用单色）。

场景预览

在上面任意一张卡片里点「在场景中预览」，就能切换这里展示的 Logo。

推荐：01 镜间光

  • 理由：它是 Slogan「意义，在镜头之间」的直接图形化。品牌故事、产品交互（节点连线）、Logo 三者讲的是同一件事，这是最难被模仿的地方。
  • 延展性：中间那道光可以单独拿出来用，比如加载指示、页面分隔线、生成成功时的一道闪光、视频转场。品牌在界面里会有记忆点，而不只是左上角的一个图标。
  • 备选：如果更看重「一眼看懂是做什么的」，选 02 双帧连线；如果确定英文名就叫 Kule、要做字母标识，选 03。
  • 不依赖名字：除了 03 绑定字母 K，其余四个方向就算最后不叫「连镜」也能用。

使用规范（以 01 镜间光为例）

安全区四周至少留出图形宽度的 1/4，虚线框内不放其他元素。
最小尺寸24px 及以下换用小尺寸版：括号加粗，光束改成实心短条，不做渐隐。
首选用法放映黑底 + 胶片白括号 + 琥珀光束。浅底时光束换成深琥珀，保证对比度。

不要这样用

拉伸变形
旋转倾斜
把光束换成紫色等其他颜色
放在杂乱的画面上不加底

交付清单（给设计师）

  • 矢量源文件；SVG 标准版、小尺寸版、单色版、反白版。
  • 横排、竖排两种中英文组合，以及只有图形的版本。
  • 站点图标：favicon.svg、favicon.ico（16/32/48）、apple-touch-icon 180px、Android 512px。
  • GitHub Social Preview（1280 × 640）、README 横幅、社交平台头像。
  • 替换代码里的 web/public/favicon.svg，以及登录页、侧栏里的 Film 图标。

字体：英文继续用 Geist；中文大标题可以试试思源宋体，带一点电影海报的味道。落地方式：品牌色补进 web/src/index.css 的 :root 和 .dark，组件只引用 token，不写死颜色。

11README 改造

README 是开源项目的门面。现在的写法偏工程，开篇就讲技术实现，商业价值要读到很后面才看得到。新结构：

  1. 居中横幅：Logo、名称、Slogan、一句话定位、徽章，以及官网、Demo、文档、English 的链接。
  2. Hero GIF。
  3. 为什么选连镜：三大支柱，每条一到两行。
  4. 功能亮点：每个支柱配一张截图。
  5. 对比表：和闭源画布 SaaS、ComfyUI 比较开源、私有化、任意模型、Agent、计费后台。只写能核实的事实。
  6. 适用场景：工作室、运营者、开发者。
  7. 一行命令部署，加首次配置。
  8. 架构、目录结构、本地开发：折叠进 <details>，或者移到 docs/。
  9. 路线图（修正勾选状态）、贡献指南、Star History、社区群、License。

另外出一份 README.en.md。GitHub 上的流量大部分来自英文用户。

12商业化

许可证：要在项目火起来之前决定

MIT 意味着任何人都可以拿代码换个皮直接卖，你很难再收回来。如果想保留商业空间，许可证要尽早定。

方案好处代价
继续用 MIT传播最快，社区和企业没有顾虑护城河只剩品牌和服务，别人可以直接换皮商用
AGPL-3.0别人改了代码拿去提供服务，必须开源部分企业会因为合规顾虑不敢用
Open-core（推荐）社区版开源，换取传播；商业功能单独授权要长期维护两条产品线的边界
源码可见 + 商业授权（如 BSL）保护最强不再算严格意义上的开源，社区口碑会受影响

已经以 MIT 发布的版本无法收回，新许可证只对之后的版本生效。改许可证前建议先咨询律师。

版本划分（提案）

能力社区版专业版企业版
画布、Agent、技能库、插件接模型✓✓✓
积分、注册、模型发布流程✓✓✓
白标（站点名、Logo、主色、自定义域名）—✓✓
自助充值、套餐、支付对接、兑换码—✓✓
团队空间、协作、成员权限——✓

定价需要先调研中转站和工作室的付费意愿，这里不给具体数字。

变现闭环的缺口

现在积分只有两个来源：注册赠送，以及管理员在后台手动调整（POST /admin/users/:id/credits、/admin/users/batch/credits）。积分不够时接口返回 402「积分不足」，但用户没有地方自己充值。

对运营者来说，这一环是最缺的。建议按以下顺序补齐：

  1. 兑换码：后台生成，线下卖给用户。不涉及支付牌照，最快能做。
  2. 积分套餐 + 订单记录：为接入支付打好数据基础。
  3. 支付插件：沿用现在 JS 插件的思路，支付宝、微信、Stripe 各写一个插件，运营者自己填商户号。

收入来源

  • 商业授权：专业版、企业版按年订阅。
  • 托管服务：替不想自己运维的客户部署和维护。
  • 技术支持与定制：工作室定制工作流、技能库、私有模型接入。
  • 插件与技能市场（长期）：第三方模型插件、付费技能包，平台抽成。
