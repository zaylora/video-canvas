## 1. 问题和目标

用户评审已实现的两个页面后的原话：**太专业，没有那么好的审美，对用户而言不易理解、不易上手。** 参照「模型渠道」页重做。

读代码核对出的"太专业"的具体来源（事实，见 `pages/admin/usage/*`、`pages/admin/logs/*`）：

| 现状 | 为什么难懂 |
| --- | --- |
| 列表是 7 列的表格：任务编号（前 8 位十六进制）、类型 / 模型（`kling-v2`）、状态、积分「8 → 6」、耗时「4.2s」、创建时间 | 每一列都要自己拼出"这是怎么回事"；十六进制编号和模型 key 对运营没有意义 |
| 筛选条一次摆出 7 个控件（搜索、状态、类型、模型、时间、含试跑、用户标签） | 不知道先点哪个 |
| 摘要条是一行小字：「总数 120 成功 100 失败 3 已取消 …」 | 看不出重点，没有"哪个要处理" |
| 抽屉从头到尾是技术字段平铺：状态时间线的事件名、`error_code`、上游错误原文、`asset #206`、渠道 / 插件、`input_json` 的键值 | 想知道"他为什么没拿到视频"要自己读完 |
| 审计列表列出 `user.credit_adjust`、`channel.auto_off` 这类动作的中文名，对象是 `kling` / `7`，摘要是键值拼接 | 是"日志语言"，不是"谁做了什么"的人话 |

目标：**不懂技术的运营，打开页面 5 秒内知道"有什么、哪里有问题"，点一条能读懂"发生了什么、要不要处理"；懂技术的人想看原文时，一次点击能拿到。**

| 技术字段怎么办 | ~~抽屉顶部加「简单 / 详细」切换~~ → **已取消，抽屉一律完整显示**（见 §0） | ~~同一份数据两种深度~~ |

## 3. 设计原则（从上面推出）

1. **先说结论，再说细节。** 每条记录第一眼是一句人话："张三生成了 1 个视频 · 失败了，积分已退回"。
2. **用状态色而不是文字区分轻重。** 正常保持中性，只有需要处理的才用色（沿用后台"不到处刷绿"的约定）。
3. **技术字段不删，收起来。** 详细模式里一个不少，只是默认不占位置。
4. **和「模型渠道」页一个语气。** 同样的卡片（`bg-card rounded-lg border`，选中 `border-primary/60 bg-primary/5`）、同样的 `Tag` / `StatusLabel`、同样的按钮尺寸，不引入新的视觉元素。
5. **一个页面只有一个主任务。** 使用记录是"找人 → 看结果"；操作审计是"看最近谁动了什么"。

### 4.2 概览卡（替换原来的一行小字摘要）

- 复用 `components/admin-ui/stat-card.tsx`（总览页同款），4 张：**全部、成功、需要关注、进行中**。
- 数据仍是 `GET /admin/usage/summary`（不改接口）：`成功 = succeeded`；`需要关注 = failed + expired + canceled`（副标题拆开写"失败 8 · 超时 2 · 取消 1"）；`进行中 = active`。
- 点卡片 = 把状态筛选切到对应值：成功 → 成功，进行中 → 进行中，全部 → 全部。"需要关注"点击落到**「失败」**：后端 `status` 只支持单值，不能一次查失败 + 超时 + 取消；超时和取消数量小，副标题里的"超时 2""取消 1"各自可点，分别筛选。这是默认值，见 §11。
- 当前筛选下有 0 条时卡片置灰；加载中显示 `Skeleton`；失败不显示（沿用现有行为）。
- 数字用 `tabular-nums`；"需要关注"大于 0 时副标题用 `text-status-warning`，其余中性。

### 4.3 筛选条

| 控件 | 旧 | 新 | 理由 |
| --- | --- | --- | --- |
| 搜索 | 一个输入框，占位"用户名 / 邮箱 / 任务编号" | 不变，占位改成"找人：输入用户名或邮箱，也可以粘贴任务编号" | 一句话说明能输入什么 |
| 状态 | 下拉：全部 / 成功 / 失败 / 已取消 / 已超时 / 进行中 | **分段控件** `Segmented`：全部 · 成功 · 失败 · 进行中 · 更多▾（取消、超时） | 最常用的 4 个直接可点；与渠道页的"全部 / 已启用 / 已停用"同款 |
| 时间 | 下拉：今天 / 24 小时 / 近 7 天 / 近 30 天 | 不变 | — |
| 类型、模型、含试跑 | 平铺在条上 | **收进「更多筛选」弹出层**（Popover）；有已选项时按钮上显示数字角标 | 这三个是少数人才用的 |
| 已选用户 | 一个标签 | 不变（带 ✕） | — |

### 4.4 任务卡片（替换表格行）

沿用渠道页 `ChannelItem` 的卡片样式：`bg-card rounded-lg border px-3 py-2.5`，hover `bg-muted/60`，被点开的那条 `border-primary/60 bg-primary/5`，右侧 `ChevronRight`。

```
● 张三 生成了一个视频                              3 分钟前
  可灵 v2 · 用了 8 积分 · 用时 42 秒
```

- 第一行：**状态点** + `用户名` + **一句话**（由前端按"类型 + 状态"拼，见下表）+ 右对齐相对时间（悬停显示绝对时间）。
- 第二行（`text-muted-foreground text-xs`）：模型展示名 · 积分一句话 · 用时 / 失败原因 / 当前进度。
- 点用户名 = 加入用户筛选（保留）；整张卡点开抽屉；键盘 Enter / Space 同样。
- 窄屏（<640px）第二行换行，时间移到第一行下面。

一句话与第二行的文案规则（纯函数，放进 `utils/admin/log-rules.ts`，带单测）：

| 状态 | 第一行动作 | 第二行尾部 | 状态点 |
| --- | --- | --- | --- |
| succeeded | 生成了一个{视频/图片/音频/文本} | `用了 {实扣} 积分 · 用时 {人话时长}` | 绿（`status-success`） |
| failed | 生成{类型}失败了 | `{用户文案} · 积分已退回` | 红（`destructive`） |
| expired | 生成{类型}超时了 | `等太久没出结果 · 积分已退回` | 琥珀（`status-warning`） |
| canceled | 取消了{类型}生成 | `积分已退回` | 灰 |
| pending / queued | 正在排队生成{类型} | `排队中 · 已等 {时长}` | 蓝，脉动 |
| running / finalizing | 正在生成{类型} | `生成中 · 已 {时长}` | 蓝，脉动 |
| 试跑任务 | 前缀「试跑」小标签 | 不扣积分 | 同上 |

- 时长人话：`<60s` 写"42 秒"，`<3600s` 写"3 分 20 秒"，更长写"1 小时 5 分"。**替换** 现有 `4.2s` / `2m10s`。
- 积分人话：成功"用了 8 积分"；失败 / 取消 / 超时"积分已退回"；进行中"已冻结 8 积分"；试跑"不扣积分"。
- 进行中的"已 N 秒"每秒刷新（沿用现有 `useNow`）。

### 4.5 空 / 加载 / 失败

| 状态 | 表现 |
| --- | --- |
| 首次加载 | 概览 4 张 `Skeleton` 卡 + 6 条卡片骨架（`h-14`，同渠道页） |
| 翻页 / 改筛选 | 保留旧卡片并半透明（已实现的 `refreshing`），不闪 |
| 没有记录（无筛选） | `EmptyState`：「这个时间范围内还没有人生成过内容」+「放宽到近 30 天」 |
| 筛选后没有 | `EmptyState`：「没有符合条件的记录」+「清除筛选」 |
| 请求失败 | 沿用 `LoadFailed`（重试） |

## 5. 任务详情抽屉

### 5.1 结构：头部 → 结论 → 内容 → 技术详情

```
┌ 张三 · 生成视频                  [简单 | 详细]  ✕ ┐   ← 头部固定
│ 3 分钟前 · 可灵 v2                                │
├───────────────────────────────────────────────────┤
│ ┌ 结论卡 ───────────────────────────────────────┐ │
│ │ ● 生成成功                                    │ │   ← 简单、详细都有
│ │ 用时 42 秒 · 用了 8 积分                      │ │
│ └───────────────────────────────────────────────┘ │
│ 提示词    一只猫在草地上奔跑                       │   ← 简单：只有提示词
│ 产物      [ 视频播放器 ]                          │   ← 渲染（已实现，沿用）
│ 积分      冻结 8 → 实扣 8（没有退款）              │   ← 人话一句
│ ───────────── 详细模式才有 ─────────────          │
│ 经过      状态时间线（带每一步的时间）             │
│ 参数      resolution 1K · seed 1386169686 …       │
│ 失败原因  错误码 + 上游错误原文（折叠代码块）       │
│ 任务信息  任务编号（完整，可复制）· 渠道 · 插件     │
└───────────────────────────────────────────────────┘
```

### 5.2 「简单 / 详细」切换（已取消，见 §0，本节留作历史）

- 位置：抽屉头部右侧，`Segmented`（与渠道页状态筛选同款），两项"简单 / 详细"。
- **默认简单**；选择记在 `localStorage`（键 `admin.usage.drawerMode`），下次打开沿用。**这是纯界面偏好，不是业务状态**，所以允许用本地存储。
- 只影响抽屉（已确认）；切换时抽屉内容原地替换，不关闭、不重新请求（数据本来就一份）。
- 切换动效：详细模式独有的区块用 `AnimatePresence` + 高度展开（`layout`）淡入，`DURATION.base`；减少动态效果时直接显示 / 隐藏。

### 5.3 两种模式各显示什么

| 区块 | 简单 | 详细 | 说明 |
| --- | :-: | :-: | --- |
| 头部：用户 · 类型、相对时间、模型展示名 | ✓ | ✓ | 用户名可点（加入筛选） |
| **结论卡**（状态点 + 一句结论 + 用时 / 积分） | ✓ | ✓ | 失败时多一行"原因"，用用户文案；有"怎么办"提示，见 §5.4 |
| 提示词 | ✓ | ✓ | 长文本折叠，最多 4 行，点"展开" |
| 产物（图 / 视频 / 音频 / 文本渲染） | ✓ | ✓ | 沿用已实现的渲染 |
| 积分 | 一句话 | 一句话 + 流水明细 | 简单："冻结 8，最后扣了 8"；详细再列 freeze / settle / refund |
| 经过（状态时间线） | ✗ | ✓ | 事件名改人话（见 §5.5），保留时间 |
| 参数（input 除提示词外的键值） | ✗ | ✓ | |
| 失败原因详情（错误码 + 上游原文折叠） | ✗ | ✓ | |
| 任务信息（完整任务编号 + 复制、渠道、插件、画布、节点） | ✗ | ✓ | |
| 试跑追踪 | ✗ | ✓（仅试跑） | 沿用现有组件 |

### 5.4 失败时的"怎么办"提示（简单模式也显示）

结论卡下方一行 `text-xs text-muted-foreground`，按错误码给运营能直接用的话（**由前端映射，纯函数带单测，未知错误码给通用文案**）：

| 情形 | 提示 |
| --- | --- |
| `moderation` | 内容没通过审核，不是系统问题；用户改改提示词再试即可。 |
| `invalid_param` | 用户填的参数不合适，不是系统问题。 |
| `provider_balance` | 上游账户余额不足，**需要运维去充值**。 |
| `submit_unknown` | 提交结果不确定，上游可能已经扣费，建议让运维核对。 |
| `timeout` / expired | 生成等太久，积分已自动退回；可以让用户重试。 |
| `canceled` | 用户或管理员取消了，积分已退回。 |
| `provider_error` 及其他 | 平台暂时出问题，积分已退回；反复出现请找运维（切到「详细」看原因）。 |

### 5.5 时间线事件改人话（详细模式）

| 事件 | 旧 | 新 |
| --- | --- | --- |
| created | 已创建 | 提交了任务 |
| submitted | 上游已受理 | 平台开始处理 |
| finalizing | 转存产物 | 生成完成，正在保存结果 |
| succeeded | 成功 | 完成 |
| failed | 失败 | 失败了 |
| canceled | 已取消 | 被取消 |
| expired | 已超时 | 等太久，已超时 |

每一步显示绝对时间（时:分:秒）+ 和上一步的间隔（"+4 秒"），一眼看出卡在哪。

### 5.6 窄屏与键盘

- 抽屉宽度沿用 `admin-ui/sheet.tsx` 的 560px，<640px 全宽。
- 切换控件、复制按钮、用户名链接都有 `focus-visible` 描边；Esc 关闭（已实现）。
- 产物视频 / 音频控件原生可键盘操作。

### 6.2 记录卡片（已改为表格，见 §0，本节留作历史）

- 同样用渠道页的卡片样式。第一行是**一句话**："{操作人} {做了什么}{对象}"，第二行是**变化摘要**（沿用现有 `auditNote`，已经是人话片段）。

### 6.3 一句话的拼法

- 由 `AUDIT_ACTION_LABEL` 的**现有中文名**（"调整了积分""封禁了账号"）直接接在操作人后面，对象在后："运营小王 **调整了积分** · 张三"。
- 不新增动作→句子的庞大映射：沿用已有标签，对象放在句末，保证和后端动作常量的覆盖测试（已有）一致。
