画布加载卡顿 P0：合并节点的连接点重测

打开一张 200 个节点的画布，加载页会卡住约 11 秒。原因是每个节点挂载时各自通知 xyflow 重新测量连接点，一共引发了 196 轮全画布同步重渲染。把这些通知合并成一次，并跳过挂载时的那次，可以把这 11 秒压到 0.1 秒左右。

根因

每个节点单独排一个 rAF，每个 rAF 都重渲染整张画布

200 个节点挂载，各自的 useEffect 调用 updateNodeInternals(id)。

web/src/pages/canvas/video-node.tsx:286 · text-node.tsx:39

xyflow 12.12 的 useUpdateNodeInternals 每调用一次就 requestAnimationFrame 一次，并带 force: true。同一帧排进了约 200 个回调。

@xyflow/react/dist/esm/index.js:3928

每个回调都会走一遍：store 测量节点，发出 dimensions 变化，触发 onNodesChange，Flow 执行 setNodes 并整体重渲染，StoreUpdater 再把 nodes 写回 store，200 个 NodeWrapper 全部重渲染。

store 变化经 useSyncExternalStore 进入 React，走同步优先级，所以不会让出主线程

浏览器在每个 rAF 回调之后都会刷新微任务，所以 React 每轮都要同步跑完一次渲染和提交。约 200 轮 × 53 ms 都挤在同一个任务里，页面这段时间完全卡住。

复杂度 O(节点数²)：节点数翻倍，卡顿时间约变成 4 倍

方案

两处改动

  • 合并：同一次提交里各节点发起的重测请求先放进一个集合，等到微任务时用一次 updateNodeInternals([...ids]) 发出。xyflow 只会排一个 rAF，也只引发一轮重渲染。
  • 跳过挂载：节点挂载时 xyflow 本来就会测量一遍连接点，挂载时那次调用是多余的。只在 handleSignature 真正变化时才排队。

两处都要做。只跳过挂载的话，模型清单晚到时所有节点的签名会同时变化，又会排出 200 个 rAF。只做合并的话，挂载时仍然会多出一轮无用的全画布重渲染。

验收

  • 关掉 React DevTools 插件，用同一张 200 节点画布重新录制加载过程。
  • 加载阶段不再出现超过 200 ms 的长任务；同一帧内的 FireAnimationFrame 降到个位数。
  • 功能回归：切换模型让输入口增减后，连到新口上的线能正常显示；从模型清单还没返回的冷启动打开画布，连线也正常。

风险

  • 跳过挂载 如果某类节点的连接点是在挂载后异步渲染出来的（签名没变但 DOM 变了），挂载那次测量会量不到。目前两类节点的 handles 都在首次渲染时给出，回归测试里要专门检查这一点。
  • xyflow 升级 方案依赖 updateNodeInternals 支持传入 id 数组（12.x 已支持）。升级 xyflow 时要回看这个 hook。
  • 范围 P0 只解决加载时的 196 轮。单轮 53 ms 的成本（内联回调导致 NodeWrapper 的 memo 失效、没开可视区裁剪、每个节点一套 motion 弹簧）留给 P1，它同时也是拖动卡顿的主因。
