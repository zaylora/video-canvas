# 总览页（后台 · AI 配置）

> 2026-10-10 · 原型：[总览页原型.html](总览页原型.html)（浏览器直接打开，右下角有状态切换）
> 关联：[后台交互优化设计.md](../后台管理设计/后台交互优化设计.md)

## 1. 问题和目标

现状（`web/src/pages/admin/ai/overview/index.tsx`）：三张「上线进度」大卡 + 一张「待处理」清单。

- 系统跑起来之后三步全绿，三张大卡占掉最显眼的位置，信息量却只有「3 个可用 / 4 个可用 / 10 个在线」。
- 全页都是**配置现状**，没有任何**运行情况**：今天跑了多少任务、成功率多少、哪个模型在被用、哪个渠道在排队，运营看不到。
- 待处理为空时，首屏几乎是一片空白。

目标：

1. 总览回答三个问题：**系统现在健康吗**（关键指标）、**最近用得怎么样**（趋势与占比）、**哪里要处理**（渠道负载、待处理）。
2. 用图表表达趋势和占比：堆叠柱形图（任务量）、环形图（调用占比）、负载条（渠道实时压力）。
3. 上线引导只在没走完时占大位置，走完收成一行。
4. 运营一眼能分出「正常」和「异常」：异常用语气色，正常保持中性，不到处刷绿。

已确定的决定（来自 grill 访谈）：

| 决定 | 结论 |
| --- | --- |
| 数据范围 | 配置清单 + 渠道实时负载 + **新增后端统计接口** |
| 页面主次 | 运行优先；引导条全绿后折叠；有待处理时在顶部标出 |
| 图表实现 | shadcn chart（recharts），**已同意安装** |

## 3. 逐个控件

### 3.1 页头操作区

| 控件 | 说明 |
| --- | --- |
| 待处理 chip | 仅 `todos.length > 0` 时出现，`warning` 语气，文案「N 项待处理」；点击平滑滚到「待处理」卡并让它的描边闪一下（1.2s，伪元素 opacity）。0 项时整个消失。 |
| 范围分段 | `Segmented` 两项：近 7 天 / 近 30 天，默认 7；滑块用 `layoutId` + `SPRING`。影响：趋势图、占比、成功率 KPI；不影响今日任务、在线模型、可用渠道。状态只存在本页，不入 URL。 |
| 刷新按钮 | `Button size="icon"` + `RefreshCw`，`aria-label="刷新"`；刷新中图标旋转，按钮禁用；同时刷新统计与渠道负载（清单也 `reload`）。 |

### 3.2 引导条（`onboarding-steps.tsx`）

- 判定：三步 `ok` 全为真 → 细条常驻、大卡默认收起（用户可展开，状态只在本页内存里，刷新恢复收起）；任一未完成 → 直接显示大卡，不可收起。
- 细条：`Card` 一行，三段「✓ 名称 + 次要色小字」之间用 `›` 连接，右侧 `Button variant="ghost" size="sm"`「展开引导 / 收起引导」，带 `aria-expanded`。
- 大卡：沿用现有三张卡的内容与按钮（`canWrite` 为假时不显示上传 / 新建渠道按钮的逻辑不变）。
- **变更：原为「细条与大卡互换」**，现改为手风琴式往下拉：
  - 三步都完成时，细条常驻，右侧「展开引导 / 收起引导」按钮带向下箭头（展开时翻转 180°）；大卡默认收起，点开后从细条下方往下拉出来，再点往上收回去。
  - 细条左侧：收起时是打勾的步骤摘要；展开时换成「上线进度 · 三步都已完成」标题，避免和下面的大卡重复（`DURATION.fast` 淡入淡出切换）。
  - 有一步没完成时，直接显示三张大卡，不提供收起（还没配好时引导就该摆在眼前）。
  - 下面的内容区不再套 `layout` 动画，由被拉开的高度自然推下去，免得两套动画互相拉扯。

### 3.3 KPI 卡（`stat-card.tsx`，新的 admin-ui 部件）

| 卡 | 数值 | 副文案 | 迷你图 | 点击 |
| --- | --- | --- | --- | --- |
| 今日任务 | 今天已创建的任务数 | 「昨日 N」（今天没过完，不做同比百分比，避免误导） | 近 7 天任务量迷你柱，今天一根不透明、其余 45% | 无 |
| 成功率 · 近 N 天 | `成功 ÷ (成功 + 失败)`，一位小数 | 「失败 N 次」；没有已结束任务时「还没有已结束的任务」 | 近 7 天成功率折线（`status-success`） | 无 |
| 在线模型 | `在线 / 全部` | 有不可用 → `destructive` 色「N 个不可用」；否则「N 个未上线」；全在线「全部在线」 | 无 | 跳模型页 |
| 可用渠道 | `可用 / 全部` | 有未设 Key → `warning` 色「N 个未设 Key」；否则「N 个不可用」；全可用「全部可用」 | 无 | 跳渠道页 |

- 数值用 `AnimatedNumber`（number-flow），带 `tabular-nums`；大字号 `text-3xl font-semibold`，单位 / 分母用 `text-base text-muted-foreground`。
- 可点击的两张整卡是 `<button>`：hover 底色加深 3%，按下 `whileTap` 0.985（卡片太大，用 `TAP` 的 0.96 会晃眼，单独取小值，写进 `lib/motion.ts` 为 `TAP_CARD`），右上角 hover 时出现 `ArrowUpRight`。
- 状态色只出现在副文案上，数字本身永远是前景色。

### 3.4 任务量（堆叠柱形图，`task-trend-chart.tsx`）

- 数据：`daily[]`，每天三段堆叠：成功（`--status-success`）在下、其他（`--chart-other`）居中、失败（`--destructive`）在上。失败在最上面最显眼。
- 每根柱只有最上面那一段带圆角（7 天半径 4，30 天 2.5）；段之间用 1px `--card` 色描边分开。
- Y 轴：4 条横向网格线（虚线 `--border`），刻度取 1 / 2 / 5 × 10ⁿ 的整数；不画轴线。X 轴：7 天每天一个标签（`10/4`），30 天每 5 天一个；最后一天写「今天」并用前景色。
- 悬停：整根柱的列高亮（`--muted` 55%），Tooltip 在柱右侧 14px，靠右翻到左边；内容「10 月 4 日 · 周日 / 成功 / 失败 / 其他 / 合计」。键盘：图表容器可聚焦，左右键切换当前日期（recharts `accessibilityLayer`）。
- 标题下副标题：「近 7 天共 892 次 · 日均 127」；右上图例（成功 / 失败 / 其他）。
- 无障碍：`role="img"` + `aria-label` 概述；颜色之外靠 Tooltip 文案区分三类。

### 3.5 调用占比（环形图，`share-donut.tsx`）

- 卡头右侧小号分段：**模型 | 类型**。模型取前 5 名 + 「其他」（`--chart-other`），类型取 视频 / 图片 / 音频 / 文本（只列有数据的）。
- 环：直径 148px、环宽 18px、片间 2.5px 缝隙；中心显示总次数 + 「次调用」。
- 悬停（环或图例行）：该片保持，其余降到 30% 透明度（图例其余行 45%），中心换成「该项次数 + 名称 · 占比」。键盘聚焦图例行等价于悬停。
- 图例每行：色块 · 名称（超长省略）· 次数 · 占比（一位小数，右对齐，`tabular-nums`）。
- 色：前 5 名按 `--chart-1…5` 顺序；类型也按此顺序。

### 3.6 渠道负载（`channel-load.tsx` + `admin-ui/load-bar.tsx`）

- 数据：`listChannelLoads()`（已有）+ 渠道清单里的 `rate_limit.max_running`。每 15 秒轮询，页面不可见（`document.hidden`）时暂停，回到前台立即刷新一次。
- 每行：渠道名（下面一行小字 key）· 负载条 · 状态文字。
  - 条：底层「生成中 + 排队」浅色，上层「生成中」实色；分母是 `max(max_running, 生成中 + 排队)`；`max_running = 0`（不限）时分母取所有渠道里的最大值，文字写「2 / 不限」。
  - 满载（生成中 ≥ 上限且上限 > 0）：条换 `status-warning`，文字多一个「满载」Tag；有排队时再加蓝色「排队 N」Tag。
  - 渠道不可用：不画负载，行变淡，右侧 Tag「未设 Key」/「已停用」/「不可用」。
  - 空闲：文字「空闲」，条为空。
- 排序：不可用的排最后，其余按「生成中 + 排队」降序；最多显示 6 行，底部「全部 N 个渠道 →」链接到渠道页。
- 条用 `scaleX`（`origin-left`）+ `SPRING` 过渡，不对 `width` 做动画。
- 「每 15 秒刷新」是静态文字加一个静态绿点，不做脉冲动画。

### 3.7 待处理（沿用现有逻辑，只改版式）

- 数据和修复动作完全沿用 `adminTodos()` 与 `runTodo`，不改 `utils/admin/health.ts`。
- 版式：图标块（语气色）· 说明文字（可换行，不再用 `flex-1 text-sm` 单行）· 右侧 `outline sm` 按钮；行间 1px 分隔线。因为卡变窄了（1/3 宽），文字允许两行。
- 修复成功后该行 `opacity 1→0 + translateX(0→8px)`（`DURATION.exit`），其余行用 `layout` 补位；清单清空后显示「一切正常，没有要处理的事」。

## 4. 动效表

所有时长 / 曲线取自 `lib/motion.ts`；只动 `transform` 与 `opacity`。

| 触发 | 对象 | 属性 | 时长 / 曲线 | 方向与说明 |
| --- | --- | --- | --- | --- |
| 页面首次进入 | 引导条、KPI、各图表卡 | opacity 0→1，translateY 8px→0 | `DURATION.base` + `EASE_OUT`，按 `STAGGER`（0.03s）依次错开，最多错开 `STAGGER_MAX` 张 | 自下往上浮起；只在挂载时播放，定时刷新数据不重播 |
| 柱形图出现 / 切换范围 | 整组柱子 | scaleY 0→1 | `DURATION.slow` + `EASE_OUT` | 原点在绘图区底边，所有柱子一起长起来；关掉 recharts 自带动画（它改 SVG 属性，不是 transform） |
| 环形图出现 / 切换维度 | 整个环 | rotate -50°→0，scale .94→1，opacity 0→1 | `DURATION.slow` + `EASE_OUT` | 以环心为原点 |
| 悬停环片 / 图例行 | 其余环片、其余图例行 | opacity →30% / 45% | `DURATION.fast` | 离开恢复 |
| 悬停柱形图 | Tooltip | opacity 0→1，translateY 4px→0 | `DURATION.fast` + `EASE_OUT` | 随鼠标换列时直接换内容，不重播 |
| 范围分段 / 维度分段 | 滑块 | translateX | `SPRING`（`layoutId`） | — |
| KPI 数值变化 | 数字 | 滚动 | number-flow 默认 | 向上滚 / 向下滚由数值大小决定 |
| 负载数值变化 | 负载条 | scaleX | `SPRING` | origin-left；条宽不动画 |
| 展开 / 收起引导 | 大卡容器；箭头 | 高度 0→auto + opacity 0→1（透明度晚 0.04s）；箭头 rotate 0→180° | 展开 `DURATION.slow` + `EASE_OUT`，收起 `DURATION.slowExit`；箭头 `DURATION.base` | 往下拉 / 往上收；开了减少动态效果时只淡入淡出 |
| 修复待处理 | 被修复那一行；其余行 | opacity + translateX；`layout` | `DURATION.exit`；`SPRING` | 向右淡出，其余补位 |
| 点「N 项待处理」 | 待处理卡描边 | 伪元素 opacity 0→1→0 | 1.2s | 滚动到卡片后闪一下，一次性 |
| 点击按钮 / 可点 KPI 卡 | 自身 | scale | `TAP`（按钮）/ `TAP_CARD` 0.985（整卡） | `whileTap` |
| 减少动态效果 | 以上全部 | 降级为只做 opacity 淡入 | — | 无位移、无旋转、无缩放，滑块直接切换 |

不做常驻循环动画（骨架屏的轻微呼吸沿用现有 `Skeleton`，属于加载占位）。

## 5. 状态表

| 状态 | 页面表现 |
| --- | --- |
| 加载中（清单或统计未就绪） | 各卡片内容换 `Skeleton`，卡片外框和标题保留；引导条一条骨架；清单与统计**各自独立**加载，先到先显示，不互相等。 |
| 正常 | 如 §2。 |
| 引导没走完（新装） | 三张大卡 + 当前步骤高亮；KPI 照常显示（模型 / 渠道副文案「还没有模型 / 渠道」）；图表区走「还没有任务」；负载卡显示「还没有渠道」+ 新建按钮。 |
| 还没有任务 | 趋势图保留坐标轴与网格，中间居中文字「这段时间还没有任务」+ 次要说明；环形图画虚线空环，中心 0，图例位置写「这段时间还没有任务」；成功率 KPI 为「—」，副文案「还没有已结束的任务」；今日任务 0。 |
| 统计接口失败 | 趋势图卡、占比卡内容换成「任务统计加载失败 + 重试」；今日任务、成功率两张 KPI 显示「—」+「统计加载失败」；**配置类 KPI、渠道负载、待处理不受影响**。失败 toast 由 `request.ts` 全局弹，页面不重复弹（见 `coding-standards.md` §3）。 |
| 负载接口失败 | 负载卡保留上一次成功的数据，右上角「每 15 秒刷新」换成 `warning` 色「刷新失败，显示的是旧数据」；从没成功过则显示失败 + 重试。 |
| 渠道 / 插件 / 模型清单失败 | 沿用现在的行为（对应 KPI 与待处理停在骨架）。 |
| 无写权限（`admin` 非 `super_admin`） | 引导大卡不显示「上传插件 / 新建渠道」；待处理的按钮文案按现有 `todoLabel` 降级；图表与负载全部可读。 |
| 窄屏（<1100 / <900 / <640） | §2 的断点规则；趋势图随容器宽度重算（`ResponsiveContainer`），30 天时 X 标签自动稀疏。 |
| 深 / 浅主题 | 全部走 token；图表色用 §6 新增的 `--chart-*`，两套主题各一组。 |

## 6. 颜色 token

只引用 token，不写死 hex / 十六进制。

- **成功 / 失败 / 运行中**：`--status-success`、`--destructive`、`--status-running`、`--status-warning`（已有）。
- **类别色**（占比图的前 5 名）：用现有 `--chart-1…5`，但它们目前是**灰阶**，放在图里分不出片。因此在 `index.css` 里**覆盖后台主题的 `--chart-1…5`**（`.admin-theme` 与 `.dark.admin-theme` 各一组），前台与画布不受影响（目前没有任何代码引用 `--chart-*`）：

  | token | 浅色 | 深色 | 色相 |
  | --- | --- | --- | --- |
  | `--chart-1` | `oklch(0.58 0.15 250)` | `oklch(0.72 0.14 250)` | 蓝 |
  | `--chart-2` | `oklch(0.55 0.2 295)` | `oklch(0.7 0.16 295)` | 紫 |
  | `--chart-3` | `oklch(0.62 0.12 205)` | `oklch(0.8 0.12 205)` | 青 |
  | `--chart-4` | `oklch(0.7 0.16 70)` | `oklch(0.8 0.15 75)` | 琥珀 |
  | `--chart-5` | `oklch(0.6 0.2 345)` | `oklch(0.74 0.17 345)` | 粉 |

- **新增 `--chart-other`**（「其他」「取消」这类中性项）：`:root` 取 `oklch(0.708 0 0 / 0.45)`，`.dark` 取 `oklch(1 0 0 / 0.22)`。
- 柱形图 / 环形图通过 shadcn `ChartConfig` 把这些 token 绑给各系列（`color: "var(--status-success)"`），组件内不出现色值。

## 7. 统计口径与后端接口

前端没有任何历史数据，需要新增接口。**口径统一，页面上所有数字都能对上**：

- 范围：`generation_tasks.created_at` 落在统计区间内，且 `is_test = false`（运营试跑不算）。
- 三个桶：
  - `succeeded`：状态 `succeeded`；
  - `failed`：状态 `failed` + `expired`；
  - `other`：`canceled` + 所有进行中（`pending / queued / running / finalizing`）。
- 成功率 = `succeeded ÷ (succeeded + failed)`，`other` 不进分母（结果还没定 / 用户主动取消，不算系统问题）。
- 今日任务 = 今天三个桶之和；柱形图每天高度 = 三个桶之和；环形图总数 = 区间内三个桶之和。三处同一口径。

### 7.1 `GET /admin/ai/stats?days=7|30`

权限：`admin` 与 `super_admin`。`days` 只接受 7 或 30，其他值 400（10001）。

```json
{
  "days": 7,
  "daily": [
    { "date": "2026-10-04", "succeeded": 80, "failed": 4, "other": 3 }
  ],
  "by_model": [ { "model": "kling-v2", "label": "可灵 v2", "count": 250 } ],
  "by_kind":  [ { "kind": "video", "count": 540 } ]
}
```

- `daily` 长度恒为 `days`，没有任务的日子补 0，按日期升序，**最后一项是今天**；日期按 `Asia/Shanghai` 的自然日分桶（与个人中心热力图的默认时区一致），格式 `YYYY-MM-DD`。「昨日」取倒数第二项，不单独加字段。
- `by_model` 按 `count` 降序给全量，前端取前 5 名并合并「其他」；`label` 取模型当前展示名，模型已被删除时回退 `model` key。
- `by_kind` 的 `kind` 取 `video / image / audio / text`。
- 性能：现有索引是 `(user_id, created_at)`，全站按时间范围聚合需要补 `created_at` 单列索引（迁移里补建）；30 天范围的聚合建议只扫 `created_at >= 起点` 并 `GROUP BY` 日期 / 状态桶 / `model_id` / `kind`。是否加短缓存（如 30 秒）后端自行决定，前端每 60 秒轮询一次。
- 契约写入 `backend/docs/admin-ai-api.md`，前端路径进 `api/admin/ai/endpoints.ts`，类型进 `type.d.ts`（沿用 snake_case，见 `coding-standards.md` §4 的管理端例外）。

## 10. 原型说明

- 原型用手写 SVG 还原 recharts 的外观（网格、圆角柱、堆叠缝、环形图），实现时由 shadcn chart 渲染；入场用 CSS 关键帧模拟，实现时同样关掉 recharts 自带动画、改用 CSS。
- 右下角「原型演示控制」可切换：正常 / 有待处理 / 新装未完成 / 还没有任务 / 加载中 / 统计失败，以及深浅主题；拖窄浏览器窗口看窄屏。
- 数据为模拟数据，渠道负载在原型里每 3 秒变一次（实际 15 秒）。

## 11. 需要你在浏览器里重点看的点

1. 柱形图堆叠顺序（成功在下、失败在上）和 7 / 30 天切换时柱子的生长观感；30 天时柱宽、X 轴稀疏是否舒服。
2. 环形图悬停时中心文字替换、其余片变淡是否足够清楚。
3. 负载条的「满载 / 排队」表达，三层信息（生成中 / 排队 / 上限）是否一眼能读懂。
4. 引导条收起 ↔ 展开时下方内容滑动的节奏。
5. 深色主题下三种语气色（成功绿 / 失败红 / 其他灰）在 `--card` 底上的对比度。
6. 「有待处理」状态下，页头 chip 和待处理卡的联动。
