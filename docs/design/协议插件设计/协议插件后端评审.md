> 评审对象：[协议插件设计](./协议插件设计.md)，后端提交 `cef0dc8`（“后端完成插件协议设计”）

## 1. 结论

**后端没有完成。完成度约 55%，不满足阶段 1 验收：13 条里完整满足 3 条，部分满足 7 条，不满足或无法闭环 3 条。**

| 层 | 状态 | 说明 |
|---|---|---|
| 插件运行时（runner、goja 沙箱、Runtime 池、超时中断、崩溃与不可用分类） | 基本完成 | 顶层代码死循环没有超时保护，见 P0-5 |
| 插件宿主（请求描述校验、鉴权注入、文件引用、准备阶段、binary、结果校验、脱敏、追踪、SSRF） | 基本完成 | 渠道限流没有生效，Transport 每次新建 |

`backend/docs/admin-ai-api.md` 大半是在描述尚不存在的接口，前端的 `web/src/api/admin-ai/endpoints.ts` 已经按它写完，这些请求现在会整片 404。

### 文档与代码不一致

`backend/docs/admin-ai-api.md` 需要同步：

1. 声称已删除 `/secrets*`，实际仍注册，且没有 super_admin 限制。
2. `/me`、`/plugins*`、`/channels*`、`/test-runs/:id/trace` 都没实现，文档按已存在的口吻写。
3. `msg` 写 `"ok"`，实际是 `"success"`；`data: null` 实际是整个 `data` 字段省略。
4. 声称 `GET /models?kind=` 新增 `text`，实际被拒。
5. `dry-run` 声称展示“注入后的最终请求”，实际返回的是宿主校验后的请求描述，不含注入后的鉴权头。
6. 声称读权限是 `admin` 或 `super_admin`，实际 `super_admin` 被 403。
7. 声称 `/schema/model` 可用，实际恒 400。

## 5. 补齐阶段 1 的建议顺序

1. **先补管理层**（P0-1、P0-2）：`RequireSuperAdmin`、`RequireAdmin` 放行两种角色；插件服务（预检、版本查重、登记、启停、删除、内置插件启动登记）；渠道服务（校验、增改、凭证、check、import）；审计写入；handler 与路由；`/me`；`/test-runs/:id/trace`；`/secrets*` 迁走或限制为 super_admin。这一步做完，**前端才有东西可接**。
2. **修阻断缺陷**：healthcheck（P0-3）、runner 顶层执行加超时（P0-5）、`/models` 接受 `text`（P1-6）、`/schema/model` 路由（P1-7）。
3. **清残留**（P0-4）：删 `provider/dsl`、`provider/engine`、`legacy` 旧测试，`go mod tidy`。
4. **补测试**（P1-10）：把停放的测试迁到新签名，补第 4 节列出的缺项。
5. 再处理 P1-8、P1-9、P1-11 与 P2。

## 6. 对前端的直接影响

前端设计见 [协议插件前端设计](./协议插件前端设计.md)。这份评审对它有五个约束：

1. **前端不能等后端补完再开始**，但必须以 `admin-ai-api.md` 为契约、用 mock 开发，并在每个接口上标注“后端未实现”，直到 P0-1、P0-2 完成。
2. **列表接口缺字段**：`GET /models` 的列表项只有 `key / kind / enabled / sort / 版本号`，没有展示名和渠道，前端模型列表无法显示“用了哪个渠道”，建议后端补 `label` 与 `channel`。
3. **`channelSettings` 键序**（P2-12）修复前，渠道表单字段会按字母序出现。
4. **`dry-run` 不含注入后的鉴权头**，前端不要把它标成“最终请求”。
5. **`/secrets*` 会被删或限权**，前端的旧凭证面板应直接删除，Key 统一走 `PUT /channels/:key/secret`。
