主题

设计要点

1 · 看得见的才是能做的

  • admin 看不到上传、设 Key、两个危险开关
  • 只读页仍显示信息，写操作不渲染
  • 403 只做兜底页，不靠点了再报错来教育用户

2 · Key 永远只写

  • 输入框永远为空，成功后只显示“已设置”
  • 不进 URL、不进 store、不回显
  • 已设置时覆盖前要确认

3 · 上传即反馈

  • 预检问题精确到字段路径，与文件同屏
  • 预检不通过是 HTTP 200，对话框不关闭
  • 版本不可变：sha256、渠道引用数是一等信息

角色与权限

操作 super_admin admin admin 看到什么
查看插件、版本、meta ✓ ✓ 正常显示
上传、启停插件，删除版本 ✓ — 不渲染按钮，页头写“只读”
查看渠道（不含 Key） ✓ ✓ Key 只显示“已设置”
新建 / 修改渠道、设 Key、检查、两个危险开关 ✓ — 抽屉以只读打开，操作区不渲染
从渠道导入模型 ✓ ✓ 可用（导入只是草稿）
模型编辑、校验、试跑、发布、回滚、上下架 ✓ ✓ 可用

关键流程

A · 运维接入新协议
运维上传插件→预检（失败看字段路径）→新建渠道→设 Key→连通性检查→去上架模型
B · 运维升级插件
运维上传新版本→渠道出现“可升级”→切换版本→对相关模型试跑→旧任务按旧版本跑完
C · 运营上架（主任务）
运营新建模型→渠道下拉（只列可用）→上游模型 / input_schema→保存草稿→试跑→看追踪→发布
D · 运营批量起草
运营渠道行“导入模型”→选草稿→带入编辑器（不上架）→逐个保存→走流程 C 后半段

场景 错误码 页面行为
无权限 403 / 10004 布局显示 403 页；提示“角色刚变更可稍后重试”
runner 不可用 503 / 50021 在上传、检查、dry-run、导入旁就地提示，保留输入；不设常驻横幅

删除版本被引用 409 / 50005、50006 对话框内显示具体原因

追踪为空 — 中性提示“任务尚未产生追踪”，不是错误

分阶段

阶段 0 · 地基（前端独立可做）

删旧凭证面板；角色 store 与 getAdminMe 接线；布局与三个子路由；补 utils/admin 单测；添加 shadcn 组件；mock 适配层；拆分 index.tsx

阶段 1 · 插件页与渠道页

上传与预检内联反馈；渠道抽屉与危险开关；Key 只写；连通性检查；导入对话框；按角色显隐

阶段 2 · 模型页改造与追踪

渠道与上游模型表单；表单与 JSON 双向；发布确认框；试跑后追踪时间线

阶段 3 · 打磨

审计日志页（依赖后端接口）、无障碍与暗色走查、筛选搜索、评估代码编辑器

依赖后端

后端的插件、渠道、/me、trace 接口目前都没有实现（见后端评审 P0-2）。前端按 admin-ai-api.md 契约用 mock 开发，联调需要等后端补齐。另外希望后端在模型列表项里补 label 与 channel，并让 channelSettings 保持键序。

原型只用于走查设计，不是最终实现；控件用 shadcn neutral 令牌近似，真实实现按 components/ui 与规范来。管理端按桌面宽度（≥1024px）设计。
