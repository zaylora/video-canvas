# 故事板（宫格分镜图）设计

> - 范围：每个片段生成一张宫格分镜图，作为片场里脚本和视频之间的一步；片场生视频时自动把它作为参考图带上，让模型按这张图的构图和镜头顺序来拍。
> - 日期和状态：2026-11-19，已实现（分支 `feat/drama-storyboard-board`）。实现时的出入见 §13，§6–§8 已按实现改过。
> - 证据约定：**事实**附文件路径或来源链接；**推断**是基于事实的判断；**提案**是尚未实现的设计。
> - 方案演进：
>   - 最初列了四种理解（逐镜关键帧、项目视觉设定集、宫格分镜图、两层都要），用户选了「宫格分镜图」，另外几种的取舍见 §9。
>   - 第一版实现把版本存在片段上，后端配了专门接口。试用后用户要求「完全复用资产管理、放进画布」，于是**改成短剧画布上的图片节点**，原来的后端接口和迁移都删掉了，见 §13。
>   - 第二次调整（同日）：故事板要用到分镜脚本（片段），而片段在片场里才生成，单独的「故事板」工序排在片场前面不顺。于是**去掉顶部「故事板」工序，并进片场**，由后端代写画布节点，见 §14。原型：[片场故事板-原型.html](片场故事板-原型.html)。
> - 配套演示：[故事板-演示.html](故事板-演示.html)

## 1. 设计摘要

- **问题**：现在的分镜只有文字。片场生视频时，模型拿到的是片段提示词，加上提示词里 `@` 引用的角色、场景、道具图。没有一张图告诉模型这一段每个镜头的构图、站位和景别，所以生成结果常常和导演意图对不上，同一段重抽几次画面差异也很大。
- **目标**：生视频之前，先把每个片段的镜头画成一张宫格图，用户能先看图、再定稿。生视频时把这张图作为参考图带上，让模型按格子顺序拍。
- **结论**：
  - 在「资产管理」和「片场」之间加一个顶部标签「故事板」，按集展示每个片段的宫格图。
  - 格数按片段【时间轴】里的镜头数自动定，一镜一格。
  - 每个片段保留多版宫格图，选一版「采用」，也可以上传自己的图替换。
  - 片场生视频时自动带上采用的宫格图。宫格图缺失或过期时只提醒，不拦截生成。

### 设计约束

- 生成任务、扣费、并发、WebSocket 推送都必须复用现有的生成任务服务，不另起一套。
- 片段已经有 `revision` 乐观锁。「采用哪一版宫格图」写在片段上，要沿用同一把锁。
- 只有部分视频模型支持参考图（`caps.refs.image`）。`i2v` 会把第一张图当成首帧，宫格图不能当首帧用。

### 当前缺口

- 片段级没有图片产物，也没有对应的生成任务类型。
- 片场的参考素材条只认 `@` 资产，没有「系统自动附带的参考图」这个概念。

## 3. 用户与场景

- **用户**：用短剧工作台批量做多集 AI 短剧的创作者。他们熟悉「剧本 → 资产 → 分镜 → 片场 → 成片」这条流程，最在意的是视频的可控性和返工成本。
- **触发场景**：一集的分镜已经生成，资产图也基本齐了，准备进片场出视频之前。
- **主任务**：打开「故事板」→ 选集 → 一键生成本集所有片段的宫格图 → 逐张看，不满意的重抽或上传 → 进片场生视频，宫格图自动带上。
- **成功指标（提案）**：
  - 带宫格图生成的片段，「采用」前的平均重抽次数比不带时下降。
  - 进片场前已有宫格图的片段占比。

**观察（调研检索，未逐条复核）**：

1. 主流产品都是「资产自动关联 + 镜级画面」两层，镜级画面可以单独重抽。
2. 参考图都有数量上限（3 / 4 / 7 张），需要按优先级裁剪。
3. 6 家都没有明确的「设定改了，旧结果已过期」提示，这是可以做出差异的地方。
4. 「宫格分镜图喂给视频模型当参考」是 Seedance 一类全能参考模型的社区常见玩法。官方是否专门优化过，**未验证**。

### 依赖框架调研

- 宫格图由图片模型直接生成整张图，前端只负责展示和上传，不需要额外的画布或编辑库。
- 「按镜头数切格子」是一个几行正则就能完成的纯函数，不值得引库。
- 结论：**未发现需要引入的依赖**，全部复用现有的生成任务、素材、take 轮播组件。

## 5. 设计原则

1. **故事板是片段的附属产物，不是新的数据源头**。宫格图从片段原稿推导出来，原稿一改宫格图就过期；不反过来用宫格图改原稿。
2. **一镜一格，格子和时间轴对齐**。格子顺序就是镜头顺序，模型和用户都能对上号（用户回答）。
3. **提醒，不拦截**。宫格图缺失或过期时照样能生视频，老项目和只支持文生视频的模型不受影响（用户回答）。
4. **和片场视频的 take 用同一套心智**：多版、采用一版、可上传替换（用户回答）。
5. **参考图名额先给宫格图**。宫格图同时编码了构图、站位和镜头顺序，信息密度最高；但角色主图仍然优先于角色补充图。

## 6. 推荐方案

### 6.1 信息架构

> §14 起，故事板并进片场，下面「故事板页」的部分已由 §14 取代，留作记录。

- 顶部标签变成：**总览 / 剧本 / 资产管理 / 故事板 / 片场 / 成片**。地址栏 `?area=board`，快捷键改成 1–6。
- **故事板就是短剧画布上的图片节点**，每个片段一个。它和资产在同一块画布上，但不是资产：
  - `data.drama` 没有 `type`，不进资产列表，也不能被片段 `@` 引用；
  - 标记写在 `data.drama.board = {segmentId, sourceHash, layout, shotCount}`。
- 故事板页**完全复用资产管理那一块**（用户 2026-11-19 要求）：
  - 同一个短剧画布编辑器，顶部「列表 ⇄ 画布」切换。
  - 列表视图盖在画布上，一行三张 16:9 卡片。卡片外观和入场动画同资产卡：封面按状态显示，出过图的底部渐变写名字，原稿改过的左上角标「原稿已改」。
  - 卡片悬停浮出半透明胶囊：空卡「生成 · 上传」，出过图的只有「重新生成」。
  - 点卡片切到画布视图并飞到那个节点。在画布里可以看大图、重新生成、切换历史版本（节点自带）。
  - 顶栏右侧是就绪数、「生成本集故事板 · n」。图片模型不在这里选，在项目设置里。
- 片场：
  - 参考素材条最前面多一个固定的「故事板」芯片（缩略图 + 状态）。
  - 生成按钮旁边按需显示提醒：「未引用故事板」或「故事板已过期」。

### 6.2 核心流程

1. **批量生成本集**：点「生成本集故事板」，确认框里显示要生成的片段和预计积分。确认后依次在画布上建节点（或更新已有节点），再一起提交生成。
2. **逐张审看**：卡片状态有 待生成 / 生成中 / 已出图 / 失败 / 原稿已改 五种，都读自画布节点的实时数据。
3. **调整**：
   - 卡片上点「重新生成」：用现在的原稿重写节点的提示词和 `sourceHash`（提示词按项目设置里选的故事板模板重拼），保留用户在节点上换过的模型和参数。
   - 换版本、看大图都在画布里做，用节点自带的历史。
   - 空卡可以上传图片（同资产空卡，不提供从素材库选）。
4. **生视频**：片场里选中片段，参考素材条已经带着故事板芯片，点生成即可。
5. **原稿改了**：片段原稿的哈希和节点上的 `sourceHash` 对不上，卡片和片场芯片都标「已过期」。旧图仍然可以用，由用户决定要不要重新生成。

### 6.3 宫格图怎么生成（默认值）

- **格数**：解析原稿【时间轴】里形如 `0-3秒：` 的行，得到镜头数 n，再按下表选布局：

  | 镜头数 | 布局 |
  | --- | --- |
  | 1–4 | 2×2 |
  | 5–6 | 3×2（3 列 2 行） |
  | 7–9 | 3×3 |
  | ≥10 | 3×3，第 9 格合并剩余镜头，并提示「镜头过多，建议拆段」 |
  | 0（解析不出） | 2×2，并提示「没识别到时间轴，按 4 格生成」 |

  故事板固定是 **16:9 横版**（用户 2026-11-19 确认，不跟短剧画幅），所以 5–6 镜一律 3 列 2 行。没用到的格子留白。

- **图片提示词**：把原稿填进「故事板提示词」模板拼出，不额外调用文本模型。模板在项目设置的「提示词」里选，和其他环节一样可以用内置的，也可以用「我的提示词」（没有「技能」来源）：
  - 内置模板在 `backend/internal/drama/prompts/board.md`：宫格说明（「n 格分镜图，从左到右、从上到下依次对应以下镜头，每格右上角标号，格间细白线」）、`{{画面}}`、固定结尾（无字幕、人物与参考图一致）。
  - 占位符：`{{格数}}` `{{列数}}` `{{行数}}` `{{比例}}`，以及 `{{画面}}`。`{{画面}}` 是原稿的【画幅风格】【场景与光】【参考与人物】【站位】四栏，加上【时间轴】每镜一行（去掉台词和声音）。台词按「说话人（语气）：『原文』」整句去掉，引号里有句号也不拆开，台词后面的终点画面保留。
  - 自定义模板必须保留 `{{画面}}`，只能用上面这五个占位符，花括号要成对；写了不认识的（如 `{{颜色}}`）、花括号没配成对、缺了 `{{画面}}` 都不能保存。前端保存前先查并报错，后端同样校验（67017，带原因）；前端拼接时万一缺了，画面接在最后。
  - 编辑器（`PlaceholderEditor`）：上方一排按钮往光标处插占位符；占位符在编辑器里是整体的一块（像 `@` 引用的 chip），光标进不去、字改不了，退格一下整块删掉；存回文本时写成 `{{名字}}`。手打的不认识的 `{{xx}}` 就是普通文字，由保存前的检查拦下。
  - 模板正文随项目视图的 `prompt_settings.board.bodies.board` 返回（只有这个环节返回正文）；选「我的」时是保存时的快照，改回内置时是当前内置模板。只影响之后生成 / 重新生成的节点，已有节点的提示词不变。
- **参考图**：原稿里 `@` 引用的资产节点连线进故事板节点（只连画布上还在的，按出现顺序，不超过图片模型的参考图上限）。生成时由节点按现有规则带入参考图，提示词里的 `@` 展开成图片编号。
- **图片模型**：在「项目设置」的「故事板」一行选，存在项目的 `image_models.board`（空串 = 跟随场景图片模型）；没选就用 `Drama.imageModels.scene`，再没有就用第一个可用的图片模型。只影响之后新建的节点，已有节点保留用户在节点上选的模型，也不会像资产卡那样跟着换。
- **节点位置**：放在所有非故事板节点的右边，每集一行、每段一列（`boardNodePosition`）。
- **整图比例**：固定 16:9（模型有比例参数时传 16:9）。

### 6.4 生视频时怎么引用

- 只在模型支持参考图且走 `omni` 时带入宫格图。它占 `input.images` 的**第 1 张**。其余参考仍按现有规则（`resolveBindings`）排列：主图和声音优先，补充图按剩余名额添加，只是可用名额少了 1 张。超出上限的照旧截断，参考素材条显示「部分未带入」。
- 带入宫格图时，提示词最前面加一行固定说明：「参考图1是本段的分镜宫格图，按格子编号顺序对应时间轴镜头，只参考构图、站位与景别，成片画面中不出现宫格线和编号。」这一行不写进片段原稿，只在组装 `input` 时临时加上，片场里能预览。
- 模型只支持 `i2v` 时（第一张图会被当成首帧），**不带宫格图**，芯片显示「当前模型不支持，未带入」。
- 只支持 `t2v` 的模型同上，芯片显示「当前模型不收参考图」。
- 片场的参考素材条可以手动把故事板芯片关掉。这只是本次的偏好，存在 `drama-studio` 的 prefs 里，不落库。

## 7. 状态与异常

| 状态 | 宫格墙卡片 | 片场芯片 | 生视频 |
| --- | --- | --- | --- |
| 分镜未生成 | 整页空状态：「这一集还没有分镜」+ 去片场 | — | — |
| 待生成（没有节点或节点没图） | 虚线框「待生成」，悬停「生成 · 上传」 | 「未引用故事板」 | 可以生成，不带 |
| 生成中 | 虚线框 + 转圈 | 有上一版就沿用上一版 | 沿用上一版（没有就不带） |
| 已出图 | 封面 + 名字 | 缩略图 | 带入，第一张 |
| 失败 | 红色虚线框 + 失败原因，悬停「生成」 | 有上一版就沿用 | 同左 |
| 原稿已改 | 封面 + 左上角「原稿已改」 | 「已过期」 | 照样带入，提示「故事板已过期」 |
| 模型不支持 | — | 「未带入」 | 不带入 |

其他情况：

- **积分不足 / 并发满**：节点提交时沿用生成任务的错误，故事板页汇总成一条提示。
- **重新生成分镜**：旧片段的故事板节点留在画布上，`segmentId` 对不上，不再显示、不计数，用户可以在画布里删掉。
- **故事板节点被删**：卡片回到「待生成」，片场不带。

## 8. 数据与工程影响（已实现）

### 8.1 数据

- **前端（画布节点，存在短剧画布的 payload 里）**：故事板节点是 `kind: "image"` 的普通节点。
  - 标记写在 `data.drama = { episodes: [集号], board: { segmentId, sourceHash, layout, shotCount } }`，`sourceHash` 是出图时片段原稿的 SHA-256。
  - 提示词、模型、参数、生成历史都是节点自带的。
- **后端**：**没有新表、新列、新接口、新错误码**。只给集摘要加了 `done_board_count`：

## 14. 并进片场（2026-11-19 第二次调整）

**为什么**：故事板按片段的【时间轴】出图，片段是在片场里生成分镜脚本时才有的。单独的「故事板」工序排在片场前面，用户得先去片场生成分镜、再回来做故事板、再去片场生视频，顺序拧巴。用户决定：去掉顶部「故事板」，故事板就是片场里每个片段的中间一步（原型：[片场故事板-原型.html](片场故事板-原型.html)）。

**界面**：

- 顶部工序：**总览 / 剧本 / 资产管理 / 片场 / 成片**，快捷键 1–5；旧链接 `?area=board` 落到片场。「有分镜但故事板没出齐」的提醒点挪到片场标签。
- 片场中间预览顶部「故事板 | 视频」切换，两面各带状态点（故事板过期 / 失败写字）。没手动切过时，选中片段有视频看视频、没有看故事板；点生成视频后切到视频。连播时固定看视频。
- 故事板一面：16:9 宫格图；还没有时虚线框 +「生成故事板 · 积分」；生成中显示和画布图片节点同一套的实时状态（排队 / 生成中、进度百分比、已耗时），按节点上绑的任务（`taskId`）订阅，刚提交、画布还没读到任务时才暂时显示「正在同步任务状态」；失败写原因、可重新生成；原稿改过左上角「原稿已改 · 重新生成」。
  - **大图先铺缩略图，原图加载完再淡入盖上去**，不做点击放大。
  - **多版**：大图下方一排小缩略图（也只加载缩略图），当前版本描边；点哪版就把哪版设为当前版本（滑到哪版采用哪版，和视频一致），生视频带的就是它。多版时左右拖动、横向滚轮、← → 也能换到相邻版本。
  - **框里只放状态，按钮都在框下面的按钮行里**：虚线框里只有图标、标题（和失败原因），「生成故事板」（没出过图）/「重新生成」（有图或失败）在框下面那一行，生成中框里已经有进度所以不放。大图框、版本条（固定 52px）、按钮行（固定 40px）的位置始终占着，所有状态下大图框一样高。
  - 下面是「n 镜 · 宫格 · 16:9」「重新生成」「进入画布查看」（点了就在片场里切到画布视图并飞到这个故事板节点，不跳工序）。**没出图（包括生成失败）也有「进入画布查看」**：节点在生成分镜时就建好了。
- 底部片段条右上角：「批量生成故事板 · n」，在「批量生成分镜视频」（原「批量生成」）左边、样式一样（ghost + sm，都不带图标；缺的、失败的、过期的，先确认再一起提交；n 是还要补的张数，悬停写已可用张数 / 片段数）。顶部条左边「片场 | 画布」切换的「片场」用场记板图标（`Clapperboard`）。时长、分辨率、比例挪到「重新生成分镜脚本」和视频模型之间；「已保存」不再常驻，只在保存出错时显示。
- 底部片段条：每格底部两段小条（左故事板、右视频；绿好了、琥珀过期 / 生成中、红失败），没视频时缩略图显示故事板。
- 右侧参考素材条的故事板芯片、「本次不带」照旧。

**工程**：片场没有挂画布编辑器，故事板生成改成后端代写画布（用户选定的方案）：

- `POST /drama-segments/:sid/board`：前端按模板拼好节点内容和任务输入（`planBoardInput`），后端建图片任务、一次 CAS 写节点 / 连资产 / 绑任务、推 `canvas.patch`（`DramaSegmentService.GenerateBoard`，图层操作在 `canvasgraph.UpsertBoard`）。
- 任务结束：片段服务作为生成任务观察者，把结果按前端 `planBackfill` 的同一形状写回故事板节点（`canvasgraph.BackfillBoard`），再推 `canvas.patch`。
- 片场读画布的 `useDramaAssets` 订阅这张画布的 `canvas.patch`，收到就重读。
- 删掉旧故事板页（`board-area.tsx` / `board-overlay.tsx` / `board-ui.ts`）和只给它用的前端建节点代码（`ensureBoardNode`、`boardNodePosition`）；新节点的位置规则搬到后端。

**分镜时就建节点**：分镜脚本成功落库后，后端在画布上把本集每个片段的故事板节点建好（空节点：没图、没任务，带 `drama.board` 标记，位置按集 / 段排好），重新生成分镜时片段换了新的，旧片段的节点连同连线清掉（`canvasgraph.SyncBoards`，`DramaCanvasService.SyncBoards`）。片段和画布是两次写入，这一步失败只记日志，不影响分镜成功；点「生成故事板」时沿用已有节点（没有就新建，老片段也能补上）。已有节点原样保留，不改它的图、历史和出图时的原稿哈希。

**切换版本**：`PUT /drama-segments/:sid/board/output`，请求体 `{output_id}`，后端把节点的 `activeOutputId` 和 `src / mediaType / assetId` 镜像切到那一版并推 `canvas.patch`（`canvasgraph.SelectBoardOutput`）；没有这一版返回 10001，已经是当前版本时不写。

**这一版没做**（原型里有）：片场里上传替换故事板。需要再加后端接口；可以在片场的画布视图里上传。

**片场的「片场 | 画布」切换**（和资产管理同款，放在顶部条左边；资产管理里第一项叫「列表」，片场里叫「片场」）：「片场」是原来的片场（资产库 / 预览 / 编辑 / 片段条），「画布」是整块换成当前这张短剧画布（和资产管理里是同一张），画布视图下顶部条只留这个切换、其余按钮藏起来，也不留片段条。画布只在选了「画布」时才挂载（编辑器要拿编辑锁、开销大），切回「列表」就卸载。**两面都不卸载，像资产管理那样**：片场的内容区是列表和画布叠在一起（`Face`），切换只改看哪一面——看不见的那面透明、不可点、对读屏隐藏（`inert`），两面交叉淡入淡出（只动 opacity，约 200ms）。列表不卸载，所以切回来时滚动位置、选中的片段、编辑中的提示词都还在，也没有整屏卸载 / 重新挂载的闪烁和卡顿。画布编辑器很重（要拿编辑锁、每个节点约 28 个 DOM），所以在片场各区域都挂完之后的**空闲时间后台挂上**（`requestIdleCallback`，Safari 退回短定时器），不和第一屏抢；用户点「画布」时它已经在了，不用等。「进入画布查看」＝切到画布面并带上目标节点，画布显示后视口**过渡着飞到**那个节点（`useApplyCanvasFocus` 调 `focusNode`，和资产管理里点卡片一样，能看到从当前位置到节点的过程），只在画布看得见的时候才飞。画布加载失败（读取出错、被别的标签页占着编辑锁）就卸载画布、回列表，再点会重新挂。状态在 `canvasEntryReducer`（view / mounted / target）。

## 15. 进入片场分节奏挂载（2026-11-19）

进入片场有点卡：资产库每个资产一张缩略图（上百个资产就是上千个 DOM 节点）、片段条每格带拖动排序、右侧还有 Tiptap 提示词编辑器，以前在同一帧里全部挂完。jsdom 里量过各区域的相对挂载量：资产库最重（120 个资产约 1700 个节点），片段条次之，预览最轻。

**做法**（不做虚拟列表：资产库要拖进提示词、片段条要拖动排序，虚拟列表会和这些交互打架，风险比收益大）：

- **分三拍挂载**（`usePhasedMount`，每拍一帧）：0 骨架（顶部条 + 分栏面板，面板一直在，分栏库靠它记尺寸）→ 1 预览和右侧编辑区（用户马上要看的）→ 2 资产库和片段条（最重的两块）。每块挂上时淡入并轻轻上移到位（只动 opacity / transform）。
- **长列表分批追加**（`useStaggeredCount`）：资产库先画 14 项、之后每帧追加 10 项（跨分组合计，分组标题上的数量仍写全量）；片段条先画 8 格、之后每帧追加 6 格。已画出的不收回，列表后来变长时接着往上追加，变短时不超过新的总数。新追加的每一项带很短的淡入。片段条追加完之前不响应拖动排序，免得顺序和画出来的对不上。
- 都尊重「减少动态效果」。

**没有做的**：最终稳态的 DOM 量不变（资产很多时仍然多），只是进入时不再一帧卡死；真实浏览器里的帧耗时没量过（只在 jsdom 里比了相对大小），不够的话可以调每批大小。

## 16. 内置提示词与「按选的标签生成」（2026-11-20）

- **内置故事板提示词改成手绘分镜稿**（`backend/internal/drama/prompts/board.md`）：铅笔单线条线稿、不追求光影和色彩、突出动作与镜头节奏；每个镜头标注镜头类型、表演提示、音效说明，并在格子右上角标编号；镜头要完整串联；宫格的列数 / 行数 / 格数仍用占位符（`{{列数}}` `{{行数}}` `{{格数}}`），不写死 4×3 或 12 格——每个片段按自己的镜头数排。结尾只保留人物与参考图一致那几句，**不写**字幕、贴图、旁白、背景音乐（这是出图，不是出视频）。已保存的老项目仍用保存时的内置文本（快照）。
- **还没做：音效说明的来源**。拼装时仍只带画面（台词和声音行去掉），图片模型只能自己根据画面编音效说明；要不要把逐镜的声音信息一并带进 `{{画面}}`，待定。
- **按选的标签生成视频**：视频模型要求「通用」等需要转写的格式时，以前「立即生成」要先转写才能点。现在**提示词面板上选哪个标签就用哪份文字**：选「原稿」按原稿生成（不转写也行），选「转写」按转写稿生成，选了转写但还没有转写稿才拦（「先把原稿转写为 X」）。没手动选过时的默认同面板：有转写稿看转写，没有看原稿；换片段回到默认。批量生成同样按当时选的标签，选原稿就整批用原稿，不再逐个问「转写后生成 / 原稿生成」。视频模型本身吃 Seedance 原稿时只有原稿，没有标签。

## 17. 视频提示词里怎么写故事板（2026-11-20）

调研（火山引擎 Seedance 2.0 提示词指南、社区分镜宫格用法）的结论和落地：

- **怎么引用**：官方案例写法是「参考图片中的分镜图，……各个分镜构图要按照顺序出现」；图片按顺序上传、提示词里用「图片1、图片2」指代；越要紧的素材说明越靠前；空间关系尽量靠参考图表达，少写文字。落地：故事板固定是图片1，生视频时 `BOARD_LINE` 加在提示词最前面（已有），这次改成：手绘分镜宫格图、各格按编号顺序对应镜头、只参考构图 / 站位 / 景别 / 镜头衔接。
- **不让宫格画进成片**：社区做法是明说「不出现分镜格线、边框、编号、批注」；参考图里的字和笔触会被模型原样带进成片，所以说明行里点名「宫格线、边框、编号、线稿笔触、图上的批注文字」都不要，并要求「按下面写的画风生成」（防止成片也变成铅笔稿）。
- **字幕和 BGM**：官方写法是「保持无字幕」「避免生成任何文字或字幕」「不要生成 Logo / 水印」，并说明无法保证 100% 不出字幕（横屏比竖屏出字幕概率低）；BGM 没有官方否定写法，社区用「无背景音乐，仅保留环境音」。落地：内置视频提示词（`storyboard_draft.md`）每段末尾固定一栏【限制】：「无字幕，无背景音乐，画面不出现文字、水印和标志；声音只保留环境声、动作音效和台词。」它是“不写否定句”规则的唯一例外；转写成通用 / H3 时保留（H3 对应 `No subtitles, …` 和 `No non-diegetic music.`）。只改内置提示词；用户自己写的「我的提示词」不加，已生成的分镜脚本不自动变。
- **没改的**：官方指南说模型对精确到秒（0–3 秒）的支持不稳定、建议用「镜头1 / 镜头2」。我们的时间轴按起止秒写，是之前定的设计，这次不动；如果实测发现时间轴不稳，再改成镜头序号。

## 18. 故事板说明行改成按段生成、片场可见（2026-11-21）

问题：说明行只在提交时临时加，片场看不到（§6.4 说的「片场里能预览」没做）；而且写死「手绘分镜」，老项目快照和「我的」模板出的是写实宫格，说法对不上；宫格固定 16:9，竖屏短剧没交代怎么处理；3 镜排 2x2 时多出的第 4 格模型也会演。

再次调研（火山引擎 Seedance 2.0 提示词指南、社区宫格用法）补充的几条：官方示例「参考图片中的分镜图……各个分镜构图要按照顺序出现」；构图来源和人物形象分别指向不同图片（「参考图片3中的分镜构图……女孩形象参考图片1」）；社区写法「按从左到右、从上到下的顺序演绎」；只写「参考某张图」不说参考什么，模型会全盘照抄或随机取用。

落地：

- `BOARD_LINE` 常量换成 `boardLine(镜头数, 短剧比例)`（`web/src/utils/drama/board.ts`），故事板节点上的 `shotCount` 随 `BoardRef` 传进来：
  - 按从左到右、从上到下对应镜头，能数清时写「第1到第N格依次对应下面的第1到第N个镜头」，格子有富余时写「第N+1格不用」；没识别到镜头或超过 9 镜（最后一格合并）只写「各格依次对应下面的各个镜头」。
  - 只借每格的构图、人物站位、景别和镜头衔接；人物形象、服装和场景细节以其他参考图和文字为准。
  - 短剧画幅不是 16:9 时加「成片按 X 画幅重新构图」。
  - 不再写「手绘」，改成不出现宫格线、边框、格子编号和批注文字，也不沿用宫格图本身的笔触和色调，画风按下面写的。
- `SegmentPlan.boardLine` 是这次实际加在最前面的说明（没带入为空串）；片场提示词框顶部的 `BoardLinePreview`（`prompt-pane.tsx`）原样显示：灰色、不可编辑，默认一行、点开看全文。仍不写进原稿。
- 语言跟提交的正文走（`promptLang`）：去掉对白 `<d>…</d>`、资产引用和引号里的原文后，拉丁字母比汉字多三倍以上算英文，配英文说明（「Image 1 is the storyboard grid for this segment. …」，意思和中文版一一对应）；否则中文。实际只有 H3 转写稿是英文，原稿和通用转写稿都是中文。按正文判断而不是按标签判断，手写的英文提示词也对得上；片场预览跟着当前标签的文字一起变。
