# 视频节点「截取帧」设计

> **范围**：视频节点功能区的「截取帧」下拉（首帧、尾帧、自定义）。首帧、尾帧一键截取；自定义在节点下方打开选帧面板，暂存若干帧后确认，一次建出多个图片节点。
> **日期与状态**：2026-10-14，已实现，未提交（见 §10）。
> **证据约定**：**事实**附文件路径或提交号；**推断**是基于事实的判断；**提案**是尚未实现的设计；**未验证**需要实现时实测。
> **方案演进**：`feature/video-frame-capture` 分支（提交 `dd2cc3c`，2026-10-10）已经做过一版，用隐藏 `<video>` 加 canvas 取帧，未合并。当前分支后来引入了 Mediabunny（视频修剪）。本设计把那一版的交互和测试摘到当前分支（来源线不带，连线照视频修剪用普通连线），**取帧引擎换成 Mediabunny**。
> **参考图**：4 张——功能区下拉（首帧、尾帧、自定义）、选帧面板空态、暂存 3 帧后的面板、悬浮小块时的大图预览（标「00:04 截取帧」）。

## 1. 设计摘要

- **问题**：功能区「截取帧」三项目前没有处理函数，点了只提示「敬请期待」。用户想把视频里的某一帧单独拿出来，当图生图、图生视频的参考。
- **目标**：选中视频节点 → 截取帧 → 首帧、尾帧点一下就在右侧长出图片节点；自定义可以拖到任意时刻、反复截取、确认后一起落到画布。全程不扣积分，后端不装 ffmpeg。
- **已确认的决定**：
  1. **取帧引擎用 Mediabunny**（`CanvasSink` 按时间戳解码），不再用隐藏 `<video>` 加 canvas；**不做回退**，浏览器不支持 WebCodecs 就提示（与视频修剪一致）。
  2. **帧图和源视频之间连普通连线，照视频修剪的做法**：帧图是上传型节点（`uploaded: true`），不出生成面板，这根线不会被它自己拿去生成，所以不需要单独的「来源线」。分支里的来源线（含后端 `canvasgraph` 改动）**不带过来**。
  3. **自定义面板只在预览里用 `<video>`**，导出一律走 Mediabunny，预览和导出各用各的。
  4. **接入方式是摘取，不是合并分支**：分支落后 67 个提交，还混着扩图的提交。
- **第一版刻意不做**：循环预览、快捷键说明面板、批量连续抽帧（每隔 N 秒一张）、截出的帧自动作为下游节点的输入、来源线。

### 推断

- 取帧是**纯前端能力**：后端不改。
- **帧图连普通连线是安全的**：`uploaded: true` 的节点不出生成面板（`node-overlays.tsx:206`），视频→帧图这根线不会被帧图自己当参考素材；视频修剪的剪辑节点也是同样的上传型节点加普通连线（`trim.ts` 的 `buildTrimNode`），已经在用。
- 首帧、尾帧、自定义最终都归结为「给一个时间戳，得到一张图」，所以引擎只需要一个 `frameAt` 能力。
- 分支的 `<video>` 取帧方式在尾帧上有硬伤：它自己的注释写着"正好等于时长时多数浏览器取不到画面"，只能往前取 0.03 秒绕过去。

## 3. 用户与场景

- **用户**：在画布上编排 AI 生成素材的创作者。
- **场景**：① 拿 AI 生成视频的尾帧，作为下一段视频的首帧继续往下接；② 从长视频里挑几个关键时刻做参考图；③ 从视频里取一帧再做局部重绘、扩图。
- **主任务**：首帧、尾帧——点一次，几秒内右侧出现图片节点。自定义——拖到想要的画面，点相机，重复几次，点确认。

## 4. 方案

### 4.1 取帧引擎（Mediabunny）

`TrimEngine` 里新增一个能力，**不新建第二个引擎模块**：

```ts
frameAt: (src: string, spec: FrameSpec, options: { maxEdge: number; type: "image/png" | "image/jpeg" }, signal: AbortSignal) => Promise<Blob>;
// FrameSpec = "first" | "last" | number（秒）
```

- **首帧**：读 `track.getFirstTimestamp()`，用它取帧。第一帧的时间戳不一定是 0，直接按 0 取有概率拿到黑帧。
- **尾帧**：用 `computeDuration()` 和最后一帧时间戳取最后一帧。具体用哪个值最稳，**需要在实现时拿真实视频实测**（见 §7）。
- **自定义**：按传入时间戳取，钳在首帧时间戳到尾帧之间。
- **导出**：整帧最长边封顶 4096（沿用分支的 `FULL_FRAME_MAX_EDGE`），默认 PNG（保真，后面还要当首帧用）。
- **错误**：沿用 `TrimError` 的几类（不支持、没有画面、解不了码、跨域）。分支里的 `FrameCaptureError` 文案并入同一套，不并存两个错误类。
- **并发**：同一个视频同一时刻只做一次取帧；自定义面板内的连续点击排队，不丢。

### 4.2 模式与状态

- 新增 `useFramePickStore`，照 `useTrimStore` 的结构：`nodeId`、`current`（预览时刻）、`seek`（带 nonce 的定位请求）、`staged`（暂存帧）、`enter / leave / reset`。只活在内存，不存档，不进撤销栈。
- 退出时机：Esc、取消选中、多选、确认后。与视频修剪**互斥**：同一时刻只有一个模式，进入一个会先退出另一个。
- `NodeOverlays` 里在 `trimming` 判断旁边加 `framePicking` 判断，面板取代功能区和生成面板。

### 4.3 首帧、尾帧（一键）

1. 点下去立刻在源视频右侧建出一个上传型图片节点，进度显示在节点里。
2. 同时挂一根普通连线（视频 → 图片），和视频修剪一样。
3. 后台读视频、`frameAt`、交给 `uploadRunner`。
4. 失败：撤掉刚建的节点和连线，toast 说原因（多半是存储没开跨域读取）。
5. 建出节点后、文件截好前，用 `uploadRunner.hold(id)` 占位，免得被误判成上传中断后标红「上传失败」。
6. 同一个视频正在取帧时再点，提示「正在截取，请稍候」。

### 4.4 自定义面板

布局按参考图 2 和 3，样式复用修剪面板（`ChromePill`、胶片条、播放头）：

- **上排**：胶片条（缩略图复用 `useTrimSource` 的读取）加白色播放头。点击或拖动胶片条定位，方向键走一帧（按 30fps 取 1/30 秒），Shift 走一秒。
- **下排左**：播放键加 `00:04 / 00:08`。
- **下排中**：已暂存的帧 `#1 #2 #3` 小块加相机按钮。没有暂存时只有一个带文字的「截取帧」按钮（参考图 2），有暂存后收成纯相机图标（参考图 3）。
- **下排右**：「确认」。暂存为空时置灰。
- **小块**：悬浮弹出大图，标「00:04 截取帧」（参考图 4）；右上角 × 丢弃。
- **暂存上限**：沿用分支 `MAX_STAGED_FRAMES = 9`；同一时刻（一帧内，约 0.015 秒）重复截取不收。到上限或重复时 toast 说明原因。
- **截取只是暂存**：点相机后调用 `frameAt` 取一张 PNG，存在内存里（`File` 加 object URL 用作小块图）。点「确认」才一次性建出多个图片节点；Esc 或选中别的节点就丢弃，离开时释放所有 object URL。

### 4.5 节点里的预览

- 画面显示在**节点自己的画幅里**，复用 `trim-stage` 的做法：独立 `<video>`，由仓库的 `seek` 请求定位，不占 `videoSlots`。
- 控件只保留参考图里有的：喇叭（预览自己的静音）和全屏；不画进度条。
- 播放键在面板里，播放时播放头跟着走。
- 预览用 `<video>` 而不是 Mediabunny：只是为了看，不要求精确；导出才要求精确，走 §4.1。

### 4.6 连线与新节点

- 帧图节点和连线**照视频修剪的 `buildTrimNode`**：上传型图片节点（`uploaded: true`、`status: "running"`、`uploadProgress: 0`），一根 `ANIMATED_EDGE_OPTIONS` 普通连线（视频 → 帧图），标题用 `newNodeLabel` 去重。
- **摆放**：单个节点（首帧、尾帧）用 `placeBeside`；自定义一次出多个时，沿用分支 `frame-nodes.ts` 的排法（同一列从上往下，排满换列，避开已有节点）。
- **上传占位**：新增 `uploadRunner.hold(id)`。一键截帧要先建节点再截图，没有占位会被误判成上传中断而标红「上传失败」。
- **不带过来的**：分支的 `source-edge.ts`、存档 `relation` 字段、`canvas-persistence` / `graph-changes` / `link-rule` 的来源线改动、后端 `canvasgraph` 三处。**后端不改，`canvas-persistence.ts` 只需带过来"保存时端点是未存下来的上传中节点的连线不存"这一条**（避免悬空线），先对照当前文件确认是否已有同样保护再决定。

## 5. 状态与异常

| 场景 | 行为 |
| --- | --- |
| 浏览器不支持 WebCodecs | 点首帧、尾帧、自定义都只 toast，不进模式、不建节点（沿用 `UNSUPPORTED_TRIM_MESSAGE` 同款文案） |
| 视频格式解不了码 | 首帧、尾帧：撤掉节点并提示；自定义：面板内提示，相机禁用 |
| 存储没开 CORS | 同上，文案提示联系管理员配置存储桶 |
| 视频没有素材或正在生成中 | 功能区按钮本来就整体禁用（`node-toolbar-state.ts`） |
| 节点正在被修剪编码 | 进入截取帧提示「另一段视频正在编码」，不进入 |
| 一键截帧中源节点被删 | 取消取帧，撤掉待填图的节点 |
| 暂存到上限 | toast「最多暂存 9 帧」 |
| 暂存帧重复 | toast「这一帧已经截过了」 |
| 确认时源节点已不存在 | 丢弃暂存，toast 说明 |
| 帧图上传失败 | 沿用现有的节点上重试，toast「帧图上传失败，可以在节点上重试」 |
| 撤销 | 首帧、尾帧、自定义确认各算一步：新节点和连线一起撤掉 |
