画布 Agent 调优

修好 Agent 的排版，再给它装一个「行车记录仪」

这份设计做三件事。A：Agent 搭分镜时节点和组互相压住、组框框不住节点，根因已经找到，给出修法。B：做一套调优 Harness：线上每一轮 Agent 都记下完整轨迹，再用一个命令行工具跑预先写好的用例，自动检查画布结构，把报告写给 AI 编码助手看，让调提示词有凭据可依。C：顺带排查出 15 条你还没遇到的隐患。本轮只出设计，代码还没改。

阅读说明。事实来自 2026-10-20 perf/agent 分支的代码，完整证据和行号在 Agent调优Harness.md。原型和演示里的运行、耗时、token 都是模拟示意。不知道从哪看起，先看「排版问题」页，把参数调成 9:16，问题一眼可见。

主线：一次调优是怎么走的

编码助手改了提示词以后，怎样知道改得是好是坏。

用例 JSON初始画布、用户原话、预写的应答剧本、断言、预算
harness run用测试账号调用真实后端，按剧本回答 Agent 的提问和审批
后端记轨迹每次模型请求、每次工具调用都记原文和耗时；索引存 PG，原文存素材存储
轨迹包 + 断言后端生成 report.md 和 trace.jsonl，CLI 补上断言：不重叠、成员在组内、该有的连线
编码助手读报告定位到出错的那一步，改提示词或工具，再跑一遍
设计：埋点全部放在 Go 侧（模型代理和工具执行这两个入口），Node 运行时不用改。Go 已经能拿到模型请求的原文和工具调用的参数、返回，在这里记录最省事，而且 Node 进程里没有存储凭据，本来也不该让它写。
轨迹没记上时（兜底）：上传失败只记一条 warn，并给这一轮打上 trace_complete=false，用户的运行不受任何影响。Harness 拿不到管理员凭据时照样跑用例和断言，报告里标「无轨迹」。

线上用户反馈「Agent 把画布搭乱了」时，会发生什么

这是 Harness 的第二种用法，也是「线上也记轨迹」这个决定的来由。

  1. 管理员打开生产后台「日志管理 → Agent 运行」按用户邮箱和时间筛选，找到那一轮；报错数一列很显眼
  2. 点「下载轨迹包」得到 agent-trace-9137.zip，同时写一条审计 agent.trace.export
  3. 把 zip 拷到开发机，解压到 .harness/imports/9137/开发环境连不到生产环境，这一步靠人搬运
  4. 交给编码助手它读 report.md，看到比如「第 14 步 canvas_arrange 报错 3 次」，再去 trace.jsonl 里查原文
  5. 修复后，把这一轮转成回归用例二期 to-case；一期先手写用例
边界：轨迹里有用户的剧本和提示词原文。
  • 只有管理员能导出，每次导出都留审计；普通用户连自己的原文轨迹也看不到
  • 14 天后自动删除，过期的行下载按钮置灰
  • 下载下来的 zip 离开系统后就不受审计管控了，解压目录 .harness/ 已加进 .gitignore，不会进仓库
  • 图片只记素材 id，请求头一律不记，渠道 Key 不会进轨迹

对外发布时，要在隐私说明里写明：「Agent 对话过程会保留 14 天，用于排查问题」。

为什么节点会重叠、组会压组

模拟 Agent 一次批量操作：先建一个镜头组，往里放节点，再建下一个组……下面并排画出现在的后端算法和修复后的算法算出来的结果，节点按前端实际尺寸画。把画幅调成 9:16，或者组数调到 2 个以上，就能看到问题。红色表示有重叠或越出组框。两边的算法都用 JS 照着后端逻辑重写，结果是示意。

每组的节点按顺序为 文本 → 关键帧图片 → 视频 → 图片。画布上原有一个剧本节点，放在左上角。

修法（已确认方向：后端照搬尺寸规则 + 前端兜底）

共六项，按 TDD 实现：先写失败的测试，再改代码。

F1 后端算真实尺寸

规则与前端逐条一致：音频 1:1 → mediaAspect → 参数里的 aspect_ratio/ratio → 模型默认比例（由 service 注入）→ 16:9。前后端共用一份测试向量 node-size-cases.json。

F2 组框立刻贴合

每加一个成员就贴合一次，不再等这一批结束。组内一行最多 4 个，超过就换行。

F3 本批新建的东西主动避让

新的组放到已有内容的左下方，如果还和别的东西重叠就继续往下挪。用户原有的节点一律不动。

F4 canvas_arrange 能排组

组当作一个整体参与排列。提示词改成「搭好后把镜头组按 column 排列」，版本升到 10。

F5 前端兜底

成片的实际画幅和参数不一致时（比如选了 Auto），组框只往大撑，并把右边、下边的邻居推开，最多级联 3 层。这次调整不进撤销栈。

F6 parentId 和 position 一起改

合并和撤销时把这两个字段当成一组：要么一起写，要么一起保留。与隐患 C1、C2 一起修。

待实测：文本节点的高度按 324 推断，没在浏览器里量过。宽度 576 已核对（node-card.tsx:263 的 w-xl）。实现 F1 前要先量一次。

Harness 命令行：跑一个用例

左边是终端，右边是生成的输出目录。数据都在内存里，运行是模拟的，不会真的调用接口。预置用例是「三镜头 9:16 分镜」，点「运行」就能走完一遍。想看失败的样子，可以：① 勾选「删掉画幅那条应答」（Agent 提了没预写的问题，用例判失败）；② 代码版本切到「修复前」（结构断言失败）；③ 把预算上限改得比用例预算小（拒绝开跑）。

断言判定
run_status终态在列表里
no_overlap顶层对象之间、同组成员之间两两不相交；尺寸用 F1 的规则

count某种节点或组的数量在范围内
every_group_has每个组都包含所列种类

asked / not_asked是否出现过某类提问

（不做）LLM 裁判你已确认不要，主观质量由人看报告判断

// agent/harness/runner.mjs（提案）
for (const c of cases) total += c.budget * repeat
if (total > maxCredits) exit("预算闸门：" + total + " > " + maxCredits)

jwt = login(HARNESS_EMAIL, HARNESS_PASSWORD)
canvas = POST /canvas { title: "[harness] " + c.id, graph: fixture }
sess   = POST /canvas/:id/agent/sessions { mode }
run    = POST /agent/sessions/:sid/runs { message, selection, budget_credits }  // 头 X-Agent-Harness
loop every 1s until terminal(run) or timeout:
  for ev in GET /events?after=seq:
    if ev.type == "approval.created":
      a = firstMatch(c.answers, ev)
      if !a: POST /runs/:rid/cancel; fail("未预写的提问：" + ev.question); break
      POST /approvals/:aid/decision a.answer
if c.wait_tasks: poll canvas every 5s until bound tasks done|error
after  = GET /canvas/:id
pack   = admin ? GET /admin/agent/runs/:rid/trace?format=json : null  // 同一环境的后端；没有管理员凭据时报告标「无轨迹」
writeFiles(dir, pack.files)                                       // report.md、trace.jsonl … 由后端生成
result = assertions(c.expect, before, after, trace, events)
write assertions.json; prepend 断言结论 to report.md
if !keep: DELETE /canvas/:id
