画布导入导出演示

把一张画布存成 JSON，在另一个账号里原样还原

在画布里点「导出」得到一个 .canvas.json 文件；在另一个账号的画布列表点「导入画布」选这个文件，得到一张新画布，内容和原画布一样。 两张画布完全隔离：素材文件也各存一份，之后任何一边改动、删节点、删画布，都不影响另一边。

阅读说明。项目现状来自读代码（文件路径见 Markdown 文档 §2.1）；同类产品来自官方文档和检索，LibTV、即梦没有查到公开的画布 JSON 导入导出，不作依据。 本文都是设计提案，尚未实现；原型里的数字和耗时是示意，数据在内存里，刷新复原。对应 Markdown：画布导入导出.md。

主线流程：一张画布怎么从 A 账号到 B 账号

关键在中间：JSON 里不放素材地址，只放内容哈希，B 导入时后端按哈希找到文件并复制一份给 B。

A 账号 · 导出
点「导出画布」先保存，只导出已保存内容
后端换掉素材引用素材 ID / 地址 → 内容哈希；去掉任务状态
下载文件标题.canvas.json
B 账号 · 导入
列表页「导入画布」选文件，前端先做轻量检查
按哈希找文件并复制在存储里复制一份，建 B 名下的新素材
建角色卡 + 新画布一个事务写入，返回导入报告
设计：改写 JSON、查哈希、复制文件都在后端做——哈希查找和文件复制只有后端能做，改写规则放一处才好测试；前端只负责选文件和下载。
素材找不到时（回退，画布仍可用）：节点、提示词、连线都照常导入，只是那个节点的素材位置为空，导入后弹出报告列出是哪些节点。不会因为一个素材让整张画布导入失败。

三类内容各怎么处理

导出文件里什么带、什么不带，按这三类区分。

素材（图 / 视频 / 音频）
哈希引用导入时复制文件

只写 SHA-256 和元信息，不写地址和 ID。每个节点只带当前选中的那一版结果，历史版本不带。

角色卡
内容内嵌不进素材库

名称、设定、主图、补充图、声音都写进文件。导入时给 B 新建一张卡，重名自动改成「名字 (2)」。

运行状态
不带

revision、taskId、pendingTaskIds、errorTaskRef 全不带；「生成中」的节点导入后是「待生成」。

同事 B 导入我的画布时，会发生什么

一次导入分几步，以及一个需要提前说清的边界。

  1. 校验文件格式名、版本号、大小、数量上限、哈希格式、引用是否悬空。
  2. 找素材并复制按哈希去重；找到就在存储里复制，建 B 名下的素材；找不到记入报告。
  3. 建角色卡同名自动改名；主图找不到就不建卡，节点显示「已失效」。
  4. 改写并写入把哈希换成新素材 ID，重建地址；素材、角色卡、画布在一个事务里写入。
  5. 给出报告全部成功直接打开新画布；有缺失或改名先弹结果。
边界：拿到这个文件的人，就能在本系统里导入出同样的素材。
  • 哈希猜不出来，所以「拿到文件」等于「原主交出来的」。
  • 只在同一个部署内有效；换一套部署，文件里的哈希找不到对应文件。
  • 导入的素材占 B 自己的一份存储。

导出时要提前告知用户：这份文件包含提示词和素材的内容标识，分享前请确认对象。

数据与接口（提案）

下面都是设计提案，尚未实现。对应 Markdown 设计文档 §7（格式）、§8（工程影响）。开发者只读这一页也能实现。

关系

文件里的对象和数据库里的对象怎么对应。

对象允许的关系为什么
文件里一条素材（哈希）导入时对应 assets 里 0~N 条同哈希记录，取一条；复制后生成 1 条新记录同一内容可能被多人上传；导入者要有自己的独立记录和文件
新素材记录user_id = 导入者；storage_key 新生成；task_id 为空storage_key 全局唯一，不能和原记录共用
文件里一张角色卡导入时新建 1 张 character_cards，归导入者角色卡用户私有，名称在同用户下不区分大小写唯一
导入出的画布新的 canvas_projects，revision = 1与原画布无任何关联，互不影响

数据模型

只改一张表，沿用现有 SQL 迁移机制（backend/migrations/），新增 0012（加列）和 0013（.notx.sql 并发建索引，大表规则）；不新建表。

assets 表（新增一列）
sha256varchar(64) NOT NULL DEFAULT ''。文件内容的 SHA-256，小写十六进制；空串表示还没算。普通索引 idx_assets_sha256，不唯一；不含密钥。
写入时机新上传 / 生成转存：落盘时顺手算；浏览器直传和历史素材：导出时才补算并写回；写回幂等（WHERE sha256 = ''），并发补算各算一次也无害
查找规则WHERE sha256 = ? AND byte_size = ?，取 id 最小且文件可读的一条；跨用户

导出 / 导入的核心流程（伪代码）

// 导出（提案）
export(userID, canvasID):
  p = canvasRepo.GetByID(userID, canvasID)            // 带 user_id，别人的画布 = 不存在
  payload = decode(p.PayloadJSON)
  refs = collectAssetRefs(payload)                     // 集中清单：assetId / params.images|videos|audios / outputs / scene.thumb / 角色卡
  for each distinct assetID in refs:
      a = assetRepo.Get(userID, assetID)
      if a.sha256 == "": a.sha256 = hashFile(a)        // 算完幂等写回；读不到则跳过并计数
  doc = rewrite(payload, assetID→hash, 只保留 activeOutput, 去掉 status=running/taskId/…)
  doc.characters = embed(角色卡内容, 主图/补充图/声音 → hash)
  assert noLeak(doc)                                   // 不得出现 /files/、素材数字 ID、user_id、revision
  return { document: doc, report: { skipped_assets } }

// 导入（提案）
import(userID, doc):
  validate(doc)                                        // format / version / 大小 / 上限 / 哈希格式 / 引用不悬空
  copied = {}                                          // hash → 新素材
  for each hash in doc.assets:
      src = assetRepo.FindBySha256(hash, doc.assets[hash].byteSize)   // 跨用户
      if src == nil: report.missing += …; continue
      key = newStorageKey()
      storage.Put(key, storage.Open(src))              // 复制文件；失败进入 missing
      copied[hash] = Asset{ userID, key, kind/mime/size/宽高/时长 取自 src, source: "upload", fileName: src.FileName }
  tx:
      insert copied assets
      for each card in doc.characters: create 角色卡（主图缺失则跳过；重名改名「名 (2)」）
      canvas = rewrite(doc.canvas, hash→新素材ID, 重建 src / paramAssets.url / outputs / activeOutputId / characterId)
      insert canvas { userID, title+"（导入）", revision: 1 }
  on tx failure: delete copied 的对象文件
  return { canvas, report }

已确认的决定

  1. 导出整张画布为 JSON；导入生成一张全新画布，与原画布完全隔离：用户原话「相互隔离，不能说参考了这个修改了，另外就不修改了」。
  2. 同一部署、同一存储内搬画布；素材用内容哈希在后端定位，JSON 不写真实地址：用户给出的思路，已核对可行（需新增哈希列）。
  3. 素材文件在存储里复制一份：用户选择推荐项；原因是 storage_key 全局唯一，且要完全隔离。
  4. 拿到 JSON 就能认领素材：用户选择推荐项；不做签名。
  5. 入口：列表页导入 + 画布内导出：用户选择推荐项。
  6. 只带当前选中的那一版生成结果：用户选择。
  7. 角色卡内嵌、导入时新建，不进素材库；不带 revision、taskId、pendingTaskIds、running 状态：用户在访谈中明确。
  8. 不导出视口 viewport：用户原话「这个不需要」；导入的新画布按默认视口 {0,0,1} 打开，节点是否在视野内待实测（Markdown §11.4）。
  9. 已搁置：跨部署搬画布、导出文件签名、导入到已有画布、列表卡片导出、异步导入。
  10. 主文档已回写：以上决定见 Markdown §11.1、§11.2；默认值见 §11.3，待你扫一眼的两项见 §11.4。
