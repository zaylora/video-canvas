# 画布导入 / 导出设计：把一张画布存成 JSON，在另一个账号里原样还原

> - **范围**：给画布新增「导出为 JSON 文件」和「从 JSON 文件导入为新画布」。包含：(1) 导出文件的格式和字段；(2) 素材用内容哈希（SHA-256）在后端定位并复制；(3) 角色卡内嵌导出、导入时新建；(4) 导出 / 导入的入口、流程、异常和接口。不含：跨部署（存储不共用）搬画布、导入到已有画布、选区导出、批量导出、画布 Agent 对话记录、导出文件加密或签名。
> - **日期 / 状态**：2026-10-24 · 已实现，待用户手动验证（2026-10-25）。
> - **证据约定**：**事实**附文件路径或来源链接；**推断**是基于事实的判断；**提案**是尚未实现的设计；**默认值**是用户没被问到、由本文暂定的做法，实现前可推翻。
> - **方案演进**：无转向。用户最初问的是「能不能导出 / 导入 JSON」，访谈中明确了场景是「同一部署内不同账号之间搬画布」，据此排除了「JSON 内嵌素材文件」的方案（§9）。
> - **配套演示**：[画布导入导出-演示.html](画布导入导出-演示.html)（建议先读，里面有 JSON 字段浏览器和可点击原型）。

## 1. 设计摘要

- **问题**：画布数据只存在创建者账号里。要把一张画布给同事、或换一个账号继续做，现在只能重新搭。画布里的图片、视频只存了地址和素材 ID，这两样都只在原账号有效（§2.1），直接复制画布内容过去，素材节点会是空的。
- **目标**：
  - 在画布里点一下「导出」，得到一个 `.canvas.json` 文件。
  - 在另一个账号的画布列表点「导入画布」选这个文件，得到一张**新画布**，内容和原画布一模一样（节点、连线、分组、提示词、参数、素材、当前选中的那一版结果、角色卡）。
  - 两张画布**完全隔离**：导入后任何一边的修改、删节点、删画布，都不影响另一边。
- **推荐结论**：
  - JSON 里**不写素材地址和 `assetId`**，每个素材只写内容哈希（SHA-256）和少量元信息；导入时后端按哈希在存储里找到文件，**在存储里复制一份**，给导入者建独立的素材记录。
  - 角色卡内容直接写进 JSON，导入时给导入者新建角色卡；重名自动改名；不进资产库文件夹。
  - 不带任务相关的运行状态：`revision`、`taskId`、`pendingTaskIds`、`errorTaskRef`，`running` 状态一律还原为 `idle`。
  - 节点只带**当前选中的那一版**生成结果，历史版本不带。
  - 节点、连线、分组的 ID 原样保留（提示词里 `@` 引用靠节点 ID，§6.3）。
  - 入口：画布列表页「导入画布」，画布内 Logo 菜单「导出画布」。

### 2.2 设计约束

1. 素材 `storage_key` 全局唯一，两个账号的素材记录**不能**指向同一个文件（§2.1），所以导入必须复制文件（用户已确认，§11.1）。
2. 素材只有「文件」没有「内容标识」，要新增哈希字段（§8.1）。
3. 节点 / 连线 / 分组 ID 在提示词 `@` 引用、`parentId`、`outpaintFrom` 里互相引用，改 ID 就要重写这些引用（§6.3）。
4. 保存靠 `revision` 乐观锁，导出必须读到**已保存**的内容：未保存的本地修改不在后端（§7）。
5. 本项目约定：后端测试在 `backend/internal/tests/`，前端测试在 `web/src/tests/`，先写失败测试；前端格式化用 oxfmt。

### 2.3 当前缺口

- 无导出 / 导入接口、无文件格式；`assets` 无内容哈希；存储无复制能力；列表页和画布菜单无入口。

已在 §11 收敛。仍有 2 项低风险默认值待你扫一眼（§11.3）。

## 3. 用户与场景

- **用户**：用 AI 做短剧 / 分镜 / 广告片的创作者和团队成员；同一部署内有多个账号。
- **触发场景**：
  1. 把一张做好的画布交给同事，同事用自己的账号继续做，不影响原画布。
  2. 自己换账号（比如个人号 → 团队号）搬画布。
  3. 把一张画布当「模板」留一份，之后多次导入。
- **主任务**：「导出一个文件 → 在另一个账号导入 → 得到一张一模一样、互不相干的新画布」。
- **成功指标（提案）**：
  - 导入后的画布，节点 / 连线 / 分组 / 提示词 / 参数 / 当前版本素材 / 角色卡与原画布一致（单元测试可验证）。
  - 导入后删除原画布或原素材节点，新画布不受影响。
  - 导出文件里找不到任何 `/files/` 地址、素材数字 ID、用户 ID、任务 ID（单元测试扫描）。

- 采用「信封（格式名 + 版本号）+ 素材表与节点分开 + 节点只引用」的结构（Excalidraw / tldraw 的共同点）。

### 4.3 依赖框架调研

- **结论：未发现需要新引用的依赖。** 哈希用 Go 标准库 `crypto/sha256`，JSON 处理用 `encoding/json`，前端下载用浏览器 `Blob` + `<a download>`，选文件用 `<input type="file">`。画布和下拉菜单、对话框已有组件。
- 因此无需向用户征求引用决定（skill §3.1）。

## 5. 设计原则

1. **隔离优先**：导入的是副本，素材文件也复制，两张画布之后互不相干。
2. **JSON 是业务数据，不是内部快照**：只放用户能理解的内容；ID、地址、任务状态这类只在原环境有意义的东西不放。
3. **宽进严出**：导出时保留未知字段（以后加字段不会被丢）；导入时严格校验大小、类型、哈希格式，一切以后端查到的素材为准，不信 JSON 里的元信息。
4. **不阻断可用部分**：个别素材找不到、角色卡重名，只记入报告，不让整次导入失败。
5. **版本可演进**：文件带 `format` 和 `version`，导入器按版本迁移，高于当前版本明确拒绝。

## 6. 推荐方案

### 6.1 信息架构与入口

- **导出**：画布内左上角 Logo 下拉菜单（`top-left-bar.tsx`）新增「导出画布」，放在「新建画布」下方。
- **导入**：画布列表页（`pages/home/canvas-list`）顶部新增「导入画布」按钮，选择 `.json` 文件。
- 列表卡片菜单上的导出、批量导出、拖文件到页面导入：本期不做（§10）。

### 6.2 导出流程

1. 点击「导出画布」→ 先保存（沿用画布现有 `onSaveNow`）。保存失败或处于冲突状态则**不导出**，toast 说明原因。
2. 调用 `GET /canvas/:id/export`。后端读已保存的 `payload_json`，找出所有素材引用，没有哈希的素材现场读文件算哈希并写回（§8.1），再按 §7 的规则改写，返回导出文档和报告。
3. 前端把 `document` 序列化成 JSON 下载，文件名 `<画布标题>.canvas.json`（标题里的非法文件名字符替换为 `_`）。报告里有被跳过的素材时 toast 提示数量。
4. 导出前的确认文案（**默认值**）：「导出文件包含提示词、参数和素材的内容标识。拿到文件的人可以在本系统里导入出同样的素材。」

### 6.3 导入流程

1. 列表页点「导入画布」→ 选文件。前端先做轻量检查：大小不超过上限、能 `JSON.parse`、`format` 正确，否则直接提示，不发请求。
2. `POST /canvas/import`，请求体 `{ document }`。后端按顺序：
   1. 校验文档：格式、版本、大小、数量上限、哈希格式、引用是否都能在 `assets` / `characters` 里找到。
   2. 逐个素材（按哈希去重）：在 `assets` 里按 `sha256` 找一条文件可读且大小一致的记录 → 从它所在存储读出 → 写入导入者当前存储的新 key → 记下新旧对应。找不到的记入报告，不中断。
   3. 创建角色卡（需要主图素材）。主图找不到则不建卡，该节点按「已失效」处理；补充图 / 声音找不到则跳过该项。同名（不区分大小写）自动改名。
   4. 改写节点：把哈希换成新素材 ID，重建 `src`、`paramAssets.url`、`outputs`、`activeOutputId`、`scene.thumb`、`characterId`。
   5. 一个数据库事务内写入：素材记录 + 角色卡 + 新画布（`revision = 1`，归属导入者，`viewport` 写默认值 `{ x: 0, y: 0, zoom: 1 }`，因为文件不带视口）。事务失败则删除已复制的文件。
3. 前端收到报告：全部成功 → toast 并直接打开新画布；有缺失或改名 → 弹出结果对话框列出详情，再由用户点「打开画布」。
4. 导入的画布标题：沿用原标题，末尾加「（导入）」，超过 60 字截断前部（**默认值**）。

### 6.4 节点 / 连线 ID 为什么原样保留

提示词里的 `@[名字](节点id)`、节点的 `parentId`、`outpaintFrom` 都靠节点 ID 互相引用。ID 只在**单张画布内**唯一（不是全库唯一），导入出的是新画布，原样保留不会冲突；重新生成则必须同步改写所有提示词里的 token，容易漏。（**推断**，依据 `prompt-tokens.ts:11-21`。）预设 `#[名称](种类/id)` 是全局常量，原样保留。

## 7. 导出文档格式（提案）

### 7.1 总体结构

```json
{
  "format": "video-canvas/canvas",
  "version": 1,
  "exportedAt": "2026-10-24T08:00:00Z",
  "appVersion": "0.4.16",
  "canvas": { "title": "…", "nodes": [ … ], "edges": [ … ] },
  "assets": { "<sha256>": { "kind": "image", "mimeType": "image/png", "byteSize": 482113, "width": 1024, "height": 1024, "durationMs": 0, "fileName": "角色.png" } },
  "characters": { "c1": { "name": "林夏", "description": "…", "avatar": "<sha256>", "extras": ["<sha256>"], "voice": "<sha256>" } }
}
```

### 7.2 顶层字段

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `format` | string，固定 `"video-canvas/canvas"` | 识别这是本系统的画布文件，导入时第一项校验 |
| `version` | integer，当前 `1` | 文件格式版本。导入器比当前支持的版本高就拒绝；低就按版本迁移 |
| `exportedAt` | string，RFC 3339 UTC | 导出时间，只展示，不参与逻辑 |
| `appVersion` | string | 导出时的应用版本（取仓库 `VERSION`），只展示，用于排查 |
| `canvas` | object | 画布本体，见 §7.3 |
| `assets` | object，键为小写 64 位十六进制 SHA-256 | 本画布用到的所有素材，**按内容哈希去重**（同一文件被多个节点用，只写一条） |
| `characters` | object，键为文件内局部编号（`c1`、`c2`…） | 本画布节点引用的角色卡内容；没有角色卡节点时为 `{}` |

### 7.3 `canvas`

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `title` | string，1–255 | 画布标题 |
| `nodes` | array | 节点列表（含组节点），顺序**必须保持**：组排在成员之前（`xyflow` 的要求，导入端仍会再规整一次，`group.ts` 的 `normalizeFlowNodes`） |
| `edges` | array | 连线列表 |

### 7.4 节点（`type: "canvas"`）

保留的字段名与现在 `payload_json` 里一致，减少转换；**改写**和**删除**的字段列在下面两张表。

| 字段 | 处理 | 说明 |
| --- | --- | --- |
| `id` | 原样 | 节点 ID，画布内唯一，提示词 `@` 引用靠它 |
| `type` | 原样 | 固定 `"canvas"` |
| `position`、`origin`、`parentId` | 原样 | 位置；`origin` 是旧存档才有；`parentId` 指向所属组节点 |
| `data.kind` / `label` | 原样 | 节点种类（`script`/`image`/`video`/`audio`/`director`/`character`）和标题 |
| `data.prompt` / `model` | 原样 | 提示词和所选模型 key |
| `data.params` | **改写** | 其中 `images` / `videos` / `audios`（素材 ID 数组）里的每一项，从素材 ID 换成素材哈希；其余参数原样 |
| `data.paramAssets` | **改写** | **键**从素材 ID 换成素材哈希；值去掉 `url`，保留 `fileName`、`mediaType`；导入时键换成新素材 ID、按新素材重建 `url` |
| `data.status` | **改写** | `running` → `idle`；`idle` / `done` / `error` 原样 |
| `data.assetId` | **改写为** `data.assetHash` | 素材哈希 |
| `data.src` | **删除** | 导入时按新素材重建 |
| `data.outputs` | **改写** | 只保留当前选中那一版（§11.4）：`{ assetHash, mediaType, model?, createdAt }`；去掉 `id`、`src`、`assetId`、`taskId` |
| `data.activeOutputId` | **删除** | 导入时设为唯一一版的新素材 ID |
| `data.scene` | **改写** | 导演台场景整体保留；其中 `thumb: { assetId, url }` 改为 `thumbHash` |
| `data.characterId` | **改写为** `data.characterRef` | 指向文件内 `characters` 的局部编号 |
| 其余字段 | 原样 | `mediaType`、`mediaAspect`、`uploaded`、`fileName`、`text`、`error`、`outpaintFrom`、以及将来新增的未知字段，都原样保留 |
| `data.taskId`、`pendingTaskIds`、`errorTaskRef` | **删除** | 任务只在原环境有意义（用户要求） |
| `data.labelCache` | **删除** | 只是占位缓存，导入后由角色卡实时取 |
| `data.uploadProgress` | 不会出现 | 前端本来就不持久化 |

### 7.5 组节点、连线、素材、角色卡

| 对象 | 字段 | 说明 |
| --- | --- | --- |
| 组节点 `type: "group"` | `id`、`position`、`width`、`height`、`data.{label,color?,labelColor?}` | 原样 |
| 连线 | `id`、`source`、`target`、`sourceHandle?`、`targetHandle?` | 原样；`source` / `target` 必须指向存在的节点，否则导入时丢弃该连线并记入报告 |
| `assets[hash]` | `kind`（image/video/audio）、`mimeType`、`byteSize`、`width`、`height`、`durationMs`、`fileName` | 只用于展示和**交叉校验**：导入时以后端查到的素材记录为准；`byteSize` 与查到的文件不一致视为找不到 |
| `characters[ref]` | `name`（1–64）、`description`（≤500）、`avatar`（哈希，必填）、`extras`（哈希数组，≤4）、`voice`（哈希或 `null`） | 角色卡内容；素材都在 `assets` 里 |

### 7.6 导出后一定没有的东西（验收用）

`src` 的 `/files/` 地址、素材数字 ID、`user_id`、画布 ID、`revision`、任务 ID、角色卡十六进制 ID、`viewport`（用户决定不带，§11.1；视口本来就是「这台设备此刻看哪里」的视图状态，存在本机 localStorage，不属于画布内容，`web/src/utils/canvas/viewport-store.ts:1-3`）。导出实现必须对结果做一次扫描断言，防止将来新增的素材字段漏改写（风险见 §8.4）。

## 8. 数据与工程影响

### 8.1 素材内容哈希（提案）

- `assets` 新增列 `sha256 varchar(64) NOT NULL DEFAULT ''`，加普通索引 `idx_assets_sha256`（**不**唯一：同一内容可以有多条素材记录）。沿用现有迁移机制，拆成两个文件：`0012_asset_sha256.sql`（加列）和 `0013_asset_sha256_index.notx.sql`（`CREATE INDEX CONCURRENTLY IF NOT EXISTS`，`assets` 可能是大表，见 `backend/AGENTS.md` 迁移规则 19）。
- **新素材**：`ingest` 已经把内容落到临时文件，在落盘同时算 SHA-256 写入。
- **直传素材**（`asset_direct.go`，浏览器直传、服务端没有读过全文）和**历史素材**：哈希为空，**导出时才补算**——读文件、算哈希、写回；写回是幂等的（`UPDATE … WHERE sha256 = ''`），同一素材并发补算时各算一次也无害，所以不引入 `singleflight`（`golang.org/x/sync` 目前只是间接依赖，仓库里没人用）。不做全库回填任务。
- 导入时按哈希找：`WHERE sha256 = ? AND byte_size = ?`，取 `id` 最小且文件可读的一条（跨用户，§11.2）。
- 代价：首次导出带大量历史大视频的画布会变慢（**未验证，需实测**）；补算过一次后之后都快。

### 8.2 素材复制

- 沿用 `Storage.Open` + `Storage.Put`，不新增存储接口：从源素材所在存储（`assets.storage_id`）读出，写入导入者当前启用的存储，生成新 `storage_key`，新素材 `user_id = 导入者`、`source = upload`（**默认值**，避免把别人的生成产物混进导入者的「生成历史」）、`task_id = NULL`、`file_name` 取原值。
- 本地磁盘存储下是文件复制；S3 兼容存储下经服务端中转一次，没有用对象存储的服务端 `CopyObject`。大文件较慢，若成为瓶颈再加可选的 `Copier` 接口（**待实测**）。
- 失败清理：沿用 `service/asset.go` 的 `cleanup`，事务失败时删除本次已复制的对象。

### 8.3 接口（提案）

| 方法与路径 | 说明 | 业务错误 |
| --- | --- | --- |
| `GET /canvas/:id/export` | 返回 `{ document, report }`。`document` 即 §7 的导出文档；`report = { skipped_assets: number }`（无法读取、被跳过的素材数） | `30001` 画布不存在（含别人的画布）；`30008` 画布超过导入上限，无法导出（节点、素材数、素材总大小或文件大小，具体原因写进提示） |
| `POST /canvas/import` | 请求体 `{ document }`；成功返回 `{ canvas: { id, title, revision }, report }`（HTTP 200：仓库规则 A6 要求响应只走 `response.OK` 等统一出口，没有 201） | `30005` 文件格式不对（缺 `format` / 字段非法 / 引用悬空）；`30006` 文件版本高于当前支持；`30007` 文件或素材数量超限 |

`report`（导入）的结构：

```json
{
  "assets": { "total": 12, "copied": 11, "missing": [{ "node_id": "n7", "file_name": "雨夜.mp4" }] },
  "characters": { "created": 2, "renamed": [{ "from": "林夏", "to": "林夏 (2)" }], "invalid": [{ "node_id": "n9", "name": "老王" }] },
  "edges_dropped": 0
}
```

错误码编号沿用 `errcode` 现有 3000x 段，实现时按该包命名习惯定稿。

### 8.4 导出 / 导入的改写实现（提案）

- 后端用 `map[string]any` 遍历 `payload_json`，只改 §7.4 列出的字段，其余原样透传，这样将来新增的字段不会被丢。
- 风险：新增的、引用素材的字段（例如以后给节点加「封面素材」）如果没加进改写规则，会把原环境的素材 ID 泄进导出文件，并在导入端指向别人的素材。**缓解**：§7.6 的导出扫描断言；实现时把「素材引用字段清单」集中在一个文件里，每新增引用素材的字段都要来这里登记。
- 导入端不信任文档：哈希必须是 64 位小写十六进制；素材元信息以后端为准；`assets` / `characters` 里没被引用的条目忽略（不复制、不建卡）。

### 8.5 前端改动面

- 画布内：Logo 菜单新增「导出画布」；调用 `onSaveNow`，成功后请求导出、下载文件。
- 列表页：新增「导入画布」按钮、隐藏 `<input type="file" accept=".json,application/json">`、导入结果对话框。
- 不改画布保存、`revision`、`serializeGraph` 的逻辑；导入出的画布走现有 `getCanvas` 打开。
- API 层新增 `exportCanvas(id)`、`importCanvas(document)`（`web/src/api/canvas/`）。

### 8.6 与现有机制的关系

- 乐观锁：导入创建的是新画布，`revision = 1`，不涉及冲突。
- 积分 / 任务：导入不产生生成任务，不扣积分。
- 画布 Agent 对话：按画布存在 `/canvas/:id/agent/sessions`，不属于 `payload_json`，**不导出**。
- 软删除：删除导入出的画布或原画布互不影响（素材已是独立副本）。

## 9. 方案取舍

| 决策 | 选择 | 放弃 | 原因 |
| --- | --- | --- | --- |
| 素材怎么表示 | 哈希引用 | 内嵌 base64 / 带地址 | 地址和 ID 只在原账号有效；内嵌体积过大；同部署哈希够用 |
| 素材怎么落地 | 复制文件 | 多记录共享一个文件 | `storage_key` 全局唯一；共享要加引用计数并改删除逻辑；用户要求完全隔离 |
| 谁能按哈希认领 | 拿到 JSON 就能 | 签名 / 只认自己的 | 哈希无法猜出，「有 JSON」等于「原主交出来的」；签名要管密钥且 JSON 不能再手工编辑；只认自己的会让跨账号搬画布失败 |
| 导入落点 | 新建画布 | 替换 / 合并进当前画布 | 隔离要求；ComfyUI 的替换会丢工作 |
| 历史版本 | 只带当前版本 | 全带 / 导出时勾选 | 每版都是一个素材，全带要复制大量文件 |
| 节点 ID | 原样保留 | 重新生成 | 提示词 `@` 引用靠它，重新生成要改写 token |
| 谁来改写 JSON | 后端 | 前端 | 哈希查找、文件复制必须在后端；改写规则集中一处可测 |

**对导入者的意义**：你拿到的是一份独立副本，不会因为对方改动而变化；代价是占用你自己的一份存储（用户已接受，§11.1）。

## 10. MVP 与后续

**一期（本文范围）**

- 导出（保存 → 后端导出 → 下载）、导入（选文件 → 后端复制 / 改写 / 建画布 → 报告）。
- 验收：
  1. 导出文件里无 `/files/` 地址、素材数字 ID、`user_id`、画布 ID、`revision`、任务 ID（扫描断言通过）。
  2. 账号 A 导出、账号 B 导入，节点 / 连线 / 分组 / 提示词 / `@` 引用 / 参数 / 当前版本素材 / 角色卡一致。
  3. 导入后素材是 B 名下的新记录，文件是新 key；A 的画布和素材不变。
  4. 个别素材缺失时画布仍可打开，缺失节点素材位置为空，报告列出节点。
  5. 角色卡重名自动改名；主图缺失时节点显示「已失效」。
  6. 版本高于当前的文件被拒绝；`format` 不对的文件被拒绝；超限文件被拒绝。
  7. 导出前保存失败则不导出。

**后续（已搁置，将来要做时可复用本文）**

- 跨部署搬画布（文件带素材内容，或 zip 包）。
- 导入到已有画布 / 选区导出。
- 列表卡片菜单导出、批量导出、拖文件导入。
- 导入异步化（走任务队列），应对超大素材。
- 导出文件加签名。

## 11. 待确认问题与已确认事项

### 11.1 已确认（用户的回答）

1. 导出整张画布为 JSON；导入生成一张全新、与原画布完全隔离的画布（用户原话：两个画布「相互隔离，不能说参考了这个修改了，另外就不修改了」）。
2. 场景是同一部署、同一存储内不同账号之间搬画布；素材用内容哈希在后端定位，JSON 不写真实地址。
3. 角色卡：JSON 内嵌内容，导入时给当前用户新建，不进素材库；`revision` 不管。
4. 素材文件：**在存储里复制一份**（推荐项，用户选择）。
5. 认领规则：**拿到 JSON 就能认领**（推荐项，用户选择）。
6. 入口：**列表页导入 + 画布内导出**（推荐项，用户选择）。
7. 历史版本：**只带当前选中的那一版**（用户选择）。
8. 视口 `viewport`：**不导出**（用户原话「这个不需要」）。导入出的新画布按默认视口打开。

### 11.2 已搁置的决定

- 跨部署（存储不共用）：哈希在目标环境找不到文件，本期不支持，见 §10 后续。
- 签名防伪造：本期不做。

### 11.3 默认值（不需要用户决定，可推翻）

- 素材缺失：节点保留、素材位置置空、导入后汇总提示（用户追问后确认「删节点没问题」，未选具体项，按推荐项处理）。
- 导入的素材 `source = upload`；导入画布标题加「（导入）」；角色卡重名改名为「名字 (2)」「名字 (3)」…
- 节点 / 连线 / 分组 ID 原样保留（§6.4）。
- 上限（**示意数字，实现前按实际配置定**）：文件 ≤ 10 MB；节点 ≤ 2000；素材 ≤ 200 个；素材总字节 ≤ 1 GB。
- 文件名后缀 `.canvas.json`。
- 模型 key 在导入端找不到（例如模型已下线）：本期不处理，沿用画布打开时现有的处理（**未验证**，需实测当前行为）。

### 11.4 仍待确认

- 不带视口后，新画布按默认视口 `{0,0,1}` 打开，节点可能不在视野中央。我没有查到打开画布时是否会自动「适应视图」（`pages/canvas/flow.tsx` 里没有看到 `fitView`），**未验证，需实测**；若不好用，导入时可由后端按节点包围盒算一个初始视口写入新画布（仍不进文件）。
- 视频素材很大时，同步导入可能超过请求超时。若实测超时，需要改成异步任务（§10 后续提前）。（**未验证**）
- 导入的素材 `source` 用 `upload` 是否符合资产页「生成历史 / 个人资产库」的预期，需要对照资产页筛选逻辑再核一遍（**未验证**）。

### 13.3 与设计的出入

以下是实现中的裁决（`Ruling:`）和值得记下的偏差，均已在实现时选定，用户尚未逐条确认。

**裁决**

- 在分支 `feat/canvas-import-export` 上直接开发，不开 worktree（用户记忆「不开 worktree」；也不直接提交到 master）。
- `canvas_transfer.go` 里先声明服务层接口 `TransferRepo`（`WithTx`）和 `TransferTx`，只有声明；计划原文说由 Task 7 定义，但 Task 6 的依赖结构需要它才能编译。
- 接受 Task 4 的偏差：`CollectRefs` 只收集「被保留的那一版输出」的素材 ID，不收集每个 `outputs[].assetId`。这与「只导出选中的那一版」（§11.1-7）一致，且与 `Build` 共用 `keptOutput`，两处不会走偏。代价：导出时算哈希的素材比计划字面少。
- Task 10：去掉 `runCanvasExport` 失败时额外弹的 `notify.error('导出失败，请稍后重试')`，依赖请求层的全局提示（`coding-standards` 第 3 节）。计划要求弹，设计没有要求。
- Task 11：`runCanvasImport` 的 `error` 结果不带文案，界面不再额外弹提示，理由同上。计划写的是 `toast.error(message)`。

**其他偏差**

- `CollectRefs` 只收集被保留输出的素材（见上）。
- 在设计之外增加 `CheckDocumentClean`：扫描传入文档里的原环境字段（`assetId`、`taskId` 等，`url` 除外），夹带则按 `30005` 拒绝。
- `service` 里的 `TransferTx` 是 `repository.CanvasTransferTx` 的别名，没有单独定义一套类型。
- 请求体是 `{"document":null}` 时返回 `30005`（400），不是通用的参数错误 `10001`，有测试锁定。
- 导出 / 导入请求失败时前端不再额外弹错误提示（见上两条裁决）。
- 文件里存在、但没有任何节点引用的角色卡，导入时仍会创建（只可能出现在手改的文件里）。
- 角色卡的主图 / 补充图 / 声音如果指向的素材类型不对（例如主图不是图片），按「素材缺失」处理。
- 成功响应是 HTTP 200，不是 201（规则 A6）。设计和 HTML 已同步。
- `paramAssets` 的键是素材 ID 而不是字段名，这一点已在写计划时更正进设计，实现按更正后的规则。
- 此外：`Build` 额外有一道字段名守卫（出现 `assetId` / `src` / `url` / `taskId` / `characterId` 就报错），设计里没有；见 13.4 的风险项。

### 13.4 遗留事项 / 已知问题

标 ⚠️ 的是评审台账里写明「最终评审要处理」或「确有缺口」的项，建议优先看。

**后端**

- 素材：`FindBySha256` 的空哈希保护没有单独的测试。
- 素材：5 条上限的测试只检查条数，没检查返回的是不是 id 最小的 5 条。
- 素材：`SetSha256IfEmpty` 的注释里 `sha256 = ''` 用了弯引号。

- 素材：`DiscardCopies` 遇到 nil 元素会 panic；没有测试覆盖关闭 Body 和非 NotFound 错误透传。
- canvasdoc：非字符串的引用被 `hashRefs` / `Validate` 静默忽略。
- canvasdoc：没有节点 id 缺失 / 重复检查。
- canvasdoc：`Parse` 对非对象节点之外的解码错误给出的提示「节点和连线必须是对象」有误导。

- ⚠️ `Build` 的额外泄露扫描会拒绝任意深度、名为 `url` / `src` / `assetId` / `taskId` / `characterId` 的键，包括自由结构的 `data.params` / `scene`。模型参数里若恰好有叫 `url` / `src` 的字段，导出会失败；同时它对「别的键名下出现 `/files/`」这类值泄露无能为力。建议改成按值扫描 `/files/`，并把键名禁用收窄到已知路径。
- `CollectRefs` 会把非十进制的 `paramAssets` 键当作素材 ID 返回，应过滤 `^\d+$`。

- `Restore`：手改文档里的原环境字段只在节点 `data` 第一层被清掉，嵌套字段、组节点、`paramAssets` 的值、`scene` 的额外字段会原样通过（前端没有可利用路径；`Import` 已用 `CheckDocumentClean` 做了兜底）。

- canvasdoc：`Validate` 不校验标题长度、角色卡名称长度和补充图数量。这三项已由 `Import` 在服务层强制：标题 ≤ 60 字（`TestImport_TitleTruncation`）、卡名 ≤ 64 字（`TestImport_CharacterRename` 的子用例「64 字的名字改名后仍不超过 64 字」和「超长名字和设定截断」）、补充图 ≤ 4 张（`service/character_card.go` 的 `maxCharacterExtraAssets`，**目前没有测试覆盖超过 4 张的情况**）。

- `Import`：角色卡数量上限只在事务开头计一次，并发导入可能超出（与现有创建接口一致）；测试没有断言传给 `CopyBySha256` 的 `byteSize`、改名重试耗尽。

### 13.5 未验证，需要手动实测

以下几项**没有验证过**，不要当成已通过。本次没有用浏览器，所有前端结论都来自读代码和单元测试。

- **大视频同步导入会不会超时**：导入是同步请求，里面要在存储里复制素材；视频很大时可能超过请求超时。若实测超时，需要改成异步任务（§10 后续提前）。
- **`source=upload` 与资产页筛选的关系**：导入的素材记为 `upload`，是否符合资产页「生成历史 / 个人资产库」的预期，没有对照资产页的筛选逻辑核对。
- **去掉视口后，新画布默认位置下节点是否在视野内**：新画布按默认视口 `{0,0,1}` 打开，没有确认打开时是否会适应视图；若节点不在视野里，可改成后端按节点包围盒算初始视口（仍不进文件）。
- **导出含不可导入规模（超过 200 个素材或 2000 个节点）画布时的行为**：目前能导出、但导入会被拒（见 13.4）。
- **浏览器里的真实视觉与交互**：导出按钮位置和提示、导入按钮、结果弹窗的颜色和排版、导入后跳转，都没有在浏览器里看过。

**手动端到端检查清单**（不用 Playwright）：

1. 用账号 A 做一张画布：有图片 / 视频节点（含多版本结果）、导演台、角色卡节点、带 `@` 引用的提示词、分组和连线。

4. 换账号 B，在画布列表点「导入画布」选这个文件。
5. 检查新画布：标题带「（导入）」；节点、连线、分组、参数和 A 的一致；每个素材节点显示的是当前选中那一版；素材可以正常预览 / 播放。

9. 缺素材：先在 A 删掉某个素材（或在测试环境让存储里少一个文件）再导出 / 导入，确认画布能打开、对应节点素材位置为空、结果弹窗列出这些节点。
10. 打开新画布，确认节点是否在视野内（见上）。
11. 异常文件：改坏 `format`、把 `version` 改成 2、选一个超过 10 MB 的文件，确认都被拒绝并有清楚的提示。
12. 导出前断网或让保存失败，确认不会下载文件。
