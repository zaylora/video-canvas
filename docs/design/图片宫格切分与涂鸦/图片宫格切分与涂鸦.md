# 图片节点「宫格切分」「图片编辑（涂鸦）」与文本节点功能区精简

> **范围**：节点选中后上方的功能区。图片节点精简并新增「宫格切分」、把「图片编辑」做成涂鸦；文本节点精简并让「放大预览」真正可用。
> **日期与状态**：2026-10-21，设计稿，未实现。
> **决定来源约定**：**【用户】** 是用户明确说过或在参考图里标过的；**【我的决定】** 是设计时替用户拿的主意，用户没有确认过，审阅时重点看这些。
> **配套演示**：[图片宫格切分与涂鸦-演示.html](图片宫格切分与涂鸦-演示.html)（含可点击原型，建议先看它）。
> **参考图**：功能区红框标注（图片、文本各一张）；宫格切分下拉；「自定义」展开的 5×5 格子选择器；切分线编辑态（带「重置均分」）；涂鸦标注顶栏（标注 / 画笔 / 框选 / 文字 / 颜色 / 粗细 / 撤销 / 重做 / 保存）。

## 1. 要解决什么

功能区现在有一批只弹「敬请期待」的占位按钮，既不能用又占地方。用户要：

1. 把占位按钮删掉，只留真正要做的。
2. 图片能按宫格切开，切线位置可以手动调。
3. 图片能涂鸦标注。
4. 文本节点的放大查看能用。

四件事都不依赖后端和模型，全部在浏览器里完成，不扣积分。后来又追加了两件生成面板上的事（参考图悬停放大、编辑提示词弹窗里显示参考图），见 §10。

## 2. 目标、非目标

**目标**

- 图片功能区变成：**图片编辑、扩图、宫格切分（下拉）**，右侧放大、下载、加入资产库不动。【用户】
- 文本功能区变成：只剩右侧**复制、放大预览**。【用户】
- 宫格切分和涂鸦的结果都变成**新的图片节点，并从源节点连一条线**，和扩图一样；源节点不改。【用户】

**非目标**

- 局部重绘、智能超清、抠图、去水印**不做**，这次只是把入口删掉。视频节点的功能区不动（视频自己的「智能超清」「工具」保留）。【用户】
- 涂鸦不做橡皮、不做已落笔内容的选中、移动、改字；撤销重做是唯一的修改手段。【我的决定】
- 切分结果不打 zip 下载，不做批量下载。【我的决定】
- 不改后端，不加模型、不扣积分。

**反目标（做到了也算失败）**

- 切分或涂鸦的图比原图糊、有缝、少一圈像素。
- 进入编辑态后，取消选中或点到别处，留下半截状态（覆盖层不退出、节点被半建出来）。
- 大图（长边超过 4096）把标签页卡死或内存爆掉。

## 3. 图片功能区

【用户】删除「局部重绘」「智能超清」「工具」（含抠图、去水印）。

最终从左到右：`图片编辑`、`扩图`、`宫格切分 ▾`，分隔线，放大、下载、加入资产库。

- 改动入口是 `web/src/constants/node-toolbar.ts` 的 `NODE_TOOLBAR.image`，并清理不再使用的图标导入。`node-toolbar.test.ts` 里若有按钮数量或 id 的断言要同步改。
- 「图片编辑」目前带积分星（`paid: true`）。涂鸦是纯前端，**【我的决定】去掉星**；「扩图」仍收费不变；「宫格切分」同样不带星。

## 4. 宫格切分

### 4.1 入口与下拉

【用户】「宫格切分」是带 ▾ 的下拉按钮，菜单：

- 4 宫格 (2×2)、9 宫格 (3×3)、16 宫格 (4×4)、25 宫格 (5×5)
- 分隔线
- 自定义 ›：鼠标移到上面，**右侧弹出**标题为「自定义宫格」的 5×5 灰色小格选择器。鼠标划过哪个格，从左上到该格的矩形高亮，并显示 `行×列`，点击确认。

现有下拉（`ToolbarMenuGroup` / `MenuAction`）只支持扁平菜单项，**要扩展出「带子面板的菜单项」**，不要为这个按钮另起一套下拉。

【我的决定】自定义的行数、列数范围各 1 到 5，但 1×1 不可选（至少 2 格）。1×N、N×1 可选，用来切横幅或竖条。

### 4.2 编辑态

点选任意预设或自定义后，进入切分编辑态：

- 【用户】图片上显示切分线，**每条线可拖动**，切分位置不必均分；左上角有「重置均分」按钮。
- 线之间不能交叉、不能拖出图片；相邻两线最小间隔 **【我的决定】取图片对应边长的 2%**。
- 横线、竖线各自独立拖动，结果始终是「行线 × 列线」的矩形网格，不做每行切法不同的不规则网格。
- 需要有「确认」和「取消」。确认前不建节点；取消、取消选中、多选都退出且不留痕迹。
- 退出方式、覆盖层取代功能区和生成面板的做法，照扩图（`store/outpaint.ts`、`OutpaintOverlay`、`NodeOverlays` 里的分支、`video-node.tsx` 里的 leave effect）。

### 4.3 结果

【用户】点确认后，**切出来的每一格都建成一个新图片节点**，都从源节点连线。【我的决定】细节：

- 命名：`<源节点标题> 行-列`，如源标题「图片」得到「图片 1-1」「图片 1-2」，列在同一行里递增；源标题本身带数字（如「图片 2」）就是「图片 2 1-1」，不做特殊处理。每个标题照常过 `newNodeLabel` 去重，所以对同一张图再切一次，新标题会自动带后缀，不会重名。
- 尺寸：每个新节点用 `nodeFrameSize(该格宽高比)` 定大小，和其它图片节点一致，不按源节点缩小。
- 摆放：在源节点右侧，**按行列排成网格**，同一行的节点顶对齐、行高取该行最高的节点，行列间距沿用 `placeBeside` 的 80px 口径；这是「顺序和相邻关系和原图一致」，不要求像素级对应。整组不压到已有节点（`placeBeside` 只摆单个，需要一个摆一组的版本）。
- 源图用节点当前展示的版本（`data.src`），多版本时不另外让用户选。
- 每格是上传型节点（`uploaded: true`），做法同 `buildFrameNodes` + `useFrameNodes`（先建节点，`uploadRunner` 带进度上传，失败时可重试或撤掉该节点）。
- 一次切分产生一条撤销记录（`history.record()` 一次）。
- 25 个上传不要同时全部发出，并发上限交给实现者定。
- 上传限制不是问题：后端单文件上限默认 200MB（`service/asset.go` 的 `defaultMaxUpload`，可配置），PNG 在允许的类型里；25 格的总体积约等于原图，不会超限。

### 4.4 切分算法

- 用**累积整数边界**切（先算好每条线的像素坐标并取整，每格宽 = 相邻边界之差），保证格与格严格相接、没有缝也不重叠、总宽总高等于原图。
- 切出来的格按**原图分辨率**输出，PNG，**不缩放**；单格长边超 4096 的极端情况才按 `COMPOSE_MAX_EDGE` 限制（和扩图一致）。
- 读原图复用 `utils/canvas/outpaint-compose.ts` 的 `loadSourceImage`（fetch 成 blob 再 `createImageBitmap`，避免跨域污染）；canvas 可注入，便于测试。

### 4.5 库的选择

【用户】让调研轻量库。结论：没有值得引入的现成库，核心只是「一组 x/y 边界 + `drawImage`」，拖拽交互项目里扩图的 `outpaint-frame-layer.tsx` 已有先例。宫格切分**不加新依赖**（涂鸦用 Fabric.js，见 5.3）。

## 5. 图片编辑（涂鸦）

### 5.1 入口与界面

点「图片编辑」进入涂鸦模式。【用户】顶部是一条标注工具栏，从左到右：关闭（× 标注）、**画笔、框选、文字**、颜色、粗细、撤销、重做、保存。

- 【用户】画笔：自由手绘；框选：画矩形；文字：在图上放文字。三个工具互斥。
- 【我的决定】框选画的是**空心矩形框**（描边，颜色和粗细同画笔），不是遮罩、不是选区。
- 【我的决定】文字工具：点图上一处，出现输入框，输入后回车或失焦落字；字号随粗细档位变化，颜色同当前色；落字后不能再改、不能拖，只能撤销。
- 【我的决定】颜色是一个色块按钮，点开是 8 色左右的预设色盘，默认红（参考图里是红）。粗细是滑块。
- 撤销、重做按操作粒度：一笔、一个框、一段文字各算一步；没有可撤销时按钮置灰。
- 关闭（×）放弃涂鸦，退出规则见 5.4。

### 5.2 保存与结果

【用户】保存后在源节点右侧新建一个图片节点，从源节点连线，源节点不改。

- 导出是**原图分辨率**：Fabric 画布的**逻辑尺寸等于原图像素**（长边超 4096 时按比例缩到 4096），屏幕上只用 CSS 缩小显示，所以标注坐标、笔画粗细、字号天然是原图像素；保存时把 `canvas.toCanvasElement()` 叠在原图上导出 PNG。
- 新节点是上传型（同 `buildFrameNodes` 的做法），标题 **【我的决定】** `<源节点标题> 标注`，沿用 `newNodeLabel` 去重。
- 没有任何标注就点保存：**【我的决定】** 不建节点，提示「还没有标注内容」。

### 5.3 库的选择

调研结果：[react-sketch-canvas](https://www.npmjs.com/package/react-sketch-canvas)（SVG、零依赖，但只有画笔）；Konva（约 55KB gzip）、Fabric（约 92KB gzip）功能全但对「画笔 + 矩形 + 文字」偏重。文字这一项两者不同：**Fabric 自带画布内文字编辑**（`IText` / `Textbox`），**Konva 没有**，官方文档要求自己叠 textarea（[Konva 文档](https://konvajs.org/docs/sandbox/Editable_Text.html)）。Konva 官方有自由画笔和带撤销重做的示例，撤销重做仍是自己维护一个列表。以上为检索结论，未实测。Fabric 因此是三种工具里省事最多的选项。

**【用户】涂鸦选用 Fabric.js。** 用户先看了 [试验页](fabric-涂鸦试验.html)，再从 Fabric、Konva、react-sketch-canvas 和自写里选定 Fabric（此前一度选过自写，后改为 Fabric）。落地要点：

- **版本与体积**：7.4.0（2026-05-18 发布，MIT）。完整 UMD 包 299KB、gzip 约 92KB，**已实测**。改用 ESM 具名导入（`Canvas`、`PencilBrush`、`Rect`、`IText`）后 tree-shaking 能小多少，**未测**。
- **动态加载、单独分包**：只在进入涂鸦时才加载，不进主包。先例是截取帧设计里 Mediabunny 的做法（`docs/design/截取帧/截取帧.md`）。【我的决定】
- **三种工具**：画笔用 `PencilBrush`；框选用 `Rect`（透明填充、描边、`strokeUniform: true`）；文字用 `IText`（画布内直接编辑，结束编辑时空文字直接移除）。
- **落笔后不能再改**：每个生成的对象一律 `selectable: false, evented: false`，对应非目标“不做已落笔内容的选中、移动、改字”。
- **撤销重做 Fabric 不自带**：自己维护一个对象栈（撤销 = 从画布移除最后一个对象并压入重做栈，重做反之；新增对象时清空重做栈）。试验页里约 20 行。
- **嵌在 xyflow 节点里**：编辑区要加 `nodrag`、`nowheel`、`nopan` 之类的类名，不让画布手势穿透；退出编辑态时必须 `dispose()` 释放 Fabric 画布。
- **试验页只写了、没人验证过的三点，实现时先验证**：画布被 CSS 缩小显示时笔迹是否有偏移；中文输入法的候选框和光标是否正常；导出的粗细比例是否和屏幕一致。
- **Fabric 7 的坑（实现时已验证）**：对象默认以**中心点**定位（`originX` / `originY` 默认 `center`，旧版是 left/top），创建 `Rect`、`IText` 时必须显式写 `originX: "left"`、`originY: "top"`，否则框和文字会整体偏移半个尺寸；框选用 `fill: null` 而不是 `"transparent"`；画布 `enableRetinaScaling` 要关掉，否则 4096 的图在视网膜屏上会开出 8192² 的画布。
- **不用 React 封装库**，直接用原生 Fabric API，放在一个 `useEffect` 里创建和销毁。【我的决定】

### 5.4 编辑态的共同规则（切分与涂鸦）

参考图里两个编辑态都是**直接盖在画布上的节点里**（切分线画在图上，涂鸦顶栏浮在节点上方），不是全屏弹层，所以照扩图的覆盖层做。以下由我定，用户没有确认过：

- **原地编辑，靠画布缩放解决小节点。** 编辑区跟着节点大小走；节点小就让用户先把画布放大再编辑。第一版不做「放大成独立大面板」。编辑区必须拦住画布的拖拽、缩放和节点拖拽手势，不让它们穿透到画布。
- **同一时刻只有一个编辑态。** 进入切分、涂鸦、扩图中的任何一个，会先退出另一个（含其它节点上的），不会同时存在；做法照 `startTrim` 先退出选帧。每种编辑态一个自己的 store，仿 `store/outpaint.ts`。
- **前置条件沿用现有功能区**：节点正在生成、或没有素材时，按钮本来就是禁用的（`toolbarGate.actionsDisabled`）。切分和涂鸦是纯前端，**不检查模型清单**。
- **退出规则与扩图一致，切分和涂鸦都一样**【用户】：取消选中、多选、点到画布别处、点「取消」或「×」都会退出编辑态；只有点「确认」（切分）或「保存」（涂鸦）才产出新节点。
- 退出时没保存的切分线、涂鸦笔迹**直接丢弃，不弹确认**。这一点我按「和扩图一致」处理，用户没有单独说过；如果觉得误点空白处丢笔迹太可惜，再改成涂鸦有内容时先确认。

## 6. 文本节点功能区

【用户】删除「润色」「扩写」「缩写」，保留「复制」和「放大预览」。

- `NODE_TOOLBAR.script.actions` 变成空数组，`tail` 不变（`["copy", "zoom"]`）。`NodeActionBar` 在 `actions` 为空时已经不画分隔线（`node-action-bar.tsx:206`），导演台就是这样用的，预计无需改组件，实现时验证。
- **放大预览现在点了没用**：`node-overlays.tsx` 里 `zoom` 只对图片和视频接了 `previewNode`，文本节点落到「敬请期待」。需要为文本新做放大查看。
- 【我的决定】放大查看是**只读弹窗**：居中显示节点全文，内容可滚动、可选中复制，Esc 或点遮罩关闭，视觉和动效跟现有灯箱（`media-lightbox.tsx`）和对话预览（`components/conversation/preview-dialog.tsx`）保持一致，能复用就复用；不能编辑。
- 没有正文时功能区本来就不出现（`toolbarGate`），无需额外处理。

## 10. 追加需求：生成面板的参考图

> 2026-10-21 追加。前面 §1 到 §9 是功能区（选中节点上方），这一节是节点下方的**生成面板**和它的「编辑提示词」弹窗。两件事都只改前端，不改后端和数据。

### 10.1 参考图悬停放大

【用户】鼠标放在参考图上时弹出放大的大图，效果参考首页参考图的悬停（用户在图中用红框标了**两处**：顶部缩略图、提示词里的「图片 7」小标签）。

- **触发位置**：① `RefStrip` 里每个参考缩略图（含上游连线来的和手动上传的）；② 提示词里的 `MentionChip` 引用标签（面板里和弹窗里的都算）。【用户】
- **效果**：照首页现有写法。【用户】首页的事实参数：图片用 `<img>`、视频用静音循环的 `<video>`；最大 256×288，圆角、描边、阴影，`object-contain`；在缩略图正上方 14px；`pointer-events: none`；0.24 秒、缓动 `[.22, 1, .36, 1]`，从底部为原点缩放加透明度；悬停即显示，没有延迟；只响应鼠标，触屏不触发。
- **哪些不弹**【我的决定】：文本、音频来源的引用不弹；已断开（`gone`，标签变灰带删除线）的标签不弹；上传中、没有地址的不弹。
- **位置**【我的决定】：默认在目标正上方；上方放不下就翻到下方，左右不出屏幕。
- **键盘聚焦也显示**【我的决定】：缩略图聚焦时和悬停同样弹出，Esc 或失焦收起，预览本身不抢焦点。
- **与现有悬停联动共存**：现在悬停缩略图会让画布上的源节点画虚线（`useRefHighlight`），这条保持不变。
- **共用一个展示组件**【我的决定】：把「大图/视频 + 动画 + 尺寸」抽成首页和画布共用的组件，首页改用它且行为不变，避免两份样式漂移。
- **定位方式**【我的决定】：首页是绝对定位、没有 portal，会被祖先的 `overflow` 剪裁。画布面板在 xyflow 里，弹窗在 Dialog 的 portal 里，所以画布这边的预览要 **portal 到 `body`、用固定定位**，不被剪裁。实现可基于 base-ui 的 `preview-card`（`@base-ui/react` 1.8.0 自带，项目里还没人用，**未验证**是否满足需求）或自写 portal，留给实现者。

### 10.2 「编辑提示词」弹窗里显示参考图和底栏

【用户】弹窗顶部也要有参考图那一排（用户在图中用红框标了弹窗头部），并选了**和面板里的完全一样**。

- **位置**【我的决定】：在标题行下面、文本区上面，一排缩略图，样式和面板里同款。
- **功能**【用户】：和面板一样。
  - 点缩略图：把引用插到**弹窗里的编辑器光标处**（弹窗打开时面板被遮住，所以插入目标是弹窗里的那个编辑器）。【我的决定】
  - ×：断开连线，同时删掉提示词里引用它的标签，同一步可撤销（沿用 `vm.unlink`）。
  - +：从画布里选素材或上传参考素材（沿用 `vm.linkSource` / `vm.addRef`）。
  - 悬停放大，悬停高亮画布源节点，同 10.1。
- **底栏**【用户】用户给了一张带红框底栏的图（选模型「Seedream 5.0 Lite ▾」、「1:1 · 2K · 3 ▾」比例分辨率张数、`@` 按钮、「✦ 3 / 张」积分、圆形发送键），说“下面这些选模型什么的也都需要有”。**我的理解（未单独确认）是指弹窗**：弹窗现在的底部只有「⌘↵ 发送，Esc 收起」和字数，要换成和面板一样的一整条底栏。
  - 底栏内容（事实，`node-prompt-input.tsx` 里同一个组件）：模型下拉（`选择模型`）、`toolbarExtra` 插槽（参数摘要、批量）、`@` 按钮、积分与发送键；提交被拒的 `notice` 提示行在底栏上方。
  - 【我的决定】弹窗里的底栏**复用同一段**，不复制一份：模型、参数、批量、积分和面板共用同一份状态，在弹窗里改了，面板里同步变。
  - 【我的决定】弹窗里点发送键，和现有 `⌘↵` 一致：先收起弹窗再提交。`notice` 提示行也在弹窗里显示。
  - 【我的决定】原来那行「⌘↵ 发送，Esc 收起」的提示和字数保留，放在文本区下方、底栏上方。
  - 注意：`toolbarExtra` 里的参数摘要有自己的下拉；弹窗是 Dialog 的 portal，下拉要能在弹窗之上正常弹出，实现时验证层级。**未验证**。
- **显隐**【我的决定】：面板里这排显示时，弹窗里也显示；面板里不显示时（当前生成方式不收参考图），弹窗里也不显示，保持一致。
- **实现要点**【提案】：`RefStrip` 依赖的 `vm` 数据只在 `pages/canvas/video-node.tsx` 里拿得到，而 `NodePromptInput` 的 `children` 只渲染在面板里。做法是让弹窗也渲染一份同样的参考图排（例如给 `NodePromptInput` 加一个传给弹窗的插槽，或让 `children` 在弹窗里再渲染一份），两处共用同一份数据，不复制状态。`RefThumb`、`usePromptRefs` 都在 provider 之内可复用。
- **高度**：多出一排约 48px，弹窗文本区现在是 `min-h-72 max-h-[60vh]`，实现时要保证加了这一排后整体不超出视口，具体数值留给实现者。
