# 助手卡片消息设计（画布 + 后台小镜）

状态：设计稿，未实现。日期 2026-11-03。原型：`助手卡片消息-原型.html`。

## 1. 问题

后台小镜回答「这个网站有没有可复用的插件」时，输出了三段文字：结论、为什么核对不了、最后一句反问。用户读完才知道哪些已经有、卡在哪、自己要做什么，回答问题还得自己在输入框打字。

现状（事实）：

- 助手正文只渲染 Markdown（`web/src/pages/canvas/agent/markdown.tsx`）。
- 提问工具 `ask_user` 已存在（kind=choice | model），但小镜可以不调它、直接在正文里反问。截图里就是这种情况。
- 提问、变更单、生成审批、删除审批的操作界面都钉在输入框上方的决定框（`decision-dock.tsx`）。消息流里只有一行记录（`approval-row.tsx`，旧设计稿 6.12）。
- 变更单执行后，消息流里只剩「变更单 #xx · 已应用 3 项」，看不出改了哪个页面的哪个字段。

## 2. 用户已定（2026-11-03）

| 问题 | 决定 |
|---|---|
| 渲染方式 | **预置卡片组件**：小镜只给结构化数据，前端用清透风格组件渲染；不让模型写 HTML |
| 提问与审批的位置 | **都挪进消息流**，作答 / 确认后原地变成结果；不再使用决定框 |
| 范围 | **后台和画布都改**（共用 AgentPanel） |

## 3. 卡片清单

一共四种卡。前两种是新的展示卡，后两种是已有审批搬进消息流。

### 3.1 结论卡 `summary`（新）

用来回答「查到了什么」。一张卡 = 一个标题 + 一个状态 + 若干行 + 至多 3 条提示。

```jsonc
{
  "kind": "summary",
  "title": "有可复用的插件",
  "tone": "ok",                // ok | warn | bad | info，决定标题前的图标颜色
  "rows": [
    { "label": "插件", "value": "New API 视频 · new-api-video", "badge": "已启用", "tone": "ok",
      "ref": { "type": "plugin", "key": "new-api-video" } },
    { "label": "渠道", "value": "newapi.vbing.site", "tone": "ok", "ref": { "type": "channel", "key": "12" } },
    { "label": "模型", "value": "MiniMax-H3", "badge": "已绑定", "ref": { "type": "model", "key": "minimax-h3" } }
  ],
  "notes": [ { "tone": "warn", "text": "价格页是动态加载的，没能读到模型清单" } ],
  "sources": [ { "title": "价格页", "url": "https://newapi.vbing.site/pricing" } ]
}
```

### 3.2 对比卡 `table`（新）

用来展示「多行同构数据」，例如价格页模型清单和本地已配模型的对照、几家上游的报价。列不超过 5 个，行不超过 20 行，超出的部分折叠起来、点开再看。单元格可以带 `tone`（显示成绿 / 黄 / 红点）和 `ref`。

### 3.3 提问卡（`ask_user` 扩展）

- **一张卡可以列多个问题**（2026-11-03 用户定）：`ask_user` 改为接收 `questions[]`，1 到 5 题，一次提交。旧的单题参数（`question` + `kind`）继续兼容，等同于只有一题。
- 每题有一个 `kind`：
  - `choice`：给 2 到 4 个选项，可以 `multi` 多选，默认多带一个「其他，我来说」的输入项；
  - `model`：从已发布的模型里选一个（沿用现有逻辑）；
  - `text` / `url` / `number`：直接填写。
  - 每题可以设 `required`。选项可以带 `follow`，选中后原地展开一个输入框，比如选「告诉你模型名称」就出现名称输入框。
- 题目按编号竖着排，必填题都答完后「提交」才能点；可以只答选填题之外的部分。
- 卡片插在消息流里小镜问话的位置，输入框上方不再出现决定框。
- **等回答时在输入框打字，算新消息**（2026-11-03 用户定）：这张卡标为「已跳过」，收成一行「↳ 跳过了 N 个问题」，你的消息作为新的一轮发给小镜。小镜收到的工具结果是「用户没有回答，改发了新消息」。
- 回答之后，卡片原地收起，每题一行「↳ 问题　你的回答」（沿用现有 ApprovalRow 的回答样式）。
- 回传给模型：`{ answers: [{ id, question, answer: "人类可读的一句", value }] }`，未答的选填题 `answer` 为空。

### 3.4 变更单卡 / 审批卡（已有，搬家）

- 现在 `AdminChangeDetail`、生成审批、删除审批、密钥卡、试跑卡的内容，都整体搬进消息流里那条审批的位置。勾选、批准、拒绝的逻辑不变。
- **执行后原地变成结果卡**（这一节是新的）：
  - 按「页面 → 对象」两层分组：`模型配置 › MiniMax-H3`、`定价设置`、`插件 › new-api-video`。
  - 每个对象一行标题，标题后面是 `↗`，点了跳到后台对应页面，并定位、闪一下改动的那一行（沿用原型里的 flash 效果）。
  - 下面逐字段列出 `字段名  改前 → 改后`，删除用红色删除线，新增用绿色。
  - 失败或跳过的条目单独列出，写明原因。
  - 右上角放「回滚」（现有 rollbackMessage 逻辑）。
- 画布的生成 / 删除审批，执行后的结果卡列出节点名，点击就在画布上定位到该节点（复用 `useAgentHighlight`）。

## 4. 跳转引用 `ref`

模型只能给 `{type, key}`，不能给 URL。前端按白名单把它换成路由，未知类型显示成纯文字：

| type | 去向 |
|---|---|
| `model` | 后台模型配置页，选中该模型 |
| `channel` | 后台渠道页，选中该渠道 |
| `plugin` | 后台插件页，打开该插件 |
| `pricing_settings` | 后台定价设置 |
| `node` | 画布内定位节点（只在画布里有效） |

外部链接只允许出现在 `sources` 里，限 http(s)，新窗口打开（复用 `safeResultLink`）。

## 5. 链路

```
模型调用 show_card(args)
  → agent/ durable-tools 本地校验（照 plan_update 的写法：不经过 Go、没有副作用）
  → 引擎发 card.shown 事件并持久化（和 plan.updated 同一条路，翻历史能回放）
  → 前端 store 把它变成消息流里的独立条目 { type: "card", card }，不折进活动组
```

- 新工具名 `show_card`，加进 `tool_registry.go`、`platformExcluded`；admin 和画布模式都注册。
- 校验不过（列太多、ref 类型未知、字段超长）就返回 `IsError`，让模型自己修，不渲染半张卡。
- 提问和审批不新增事件，只改前端渲染位置；`ask_user` 的 `form` 要在 Go 的 `ProposeApproval(ask)` 里补上校验。

## 6. 提示词规则（`system.md` 和 `admin.md` 都加）

1. 有结构的结论（查到的对象、状态、清单、对比）用 `show_card`，正文只留 1 到 2 句过渡或下一步，不重复卡片里的内容。
2. **需要用户补信息时必须调用 `ask_user`，禁止在正文里反问；要问的一次问完，放进同一张卡。**
3. 引用后台对象时，在卡片里带 `ref`，不要在正文里写路径。
4. 一轮最多 3 张展示卡。

## 7. 不做的事

- 不让模型输出 HTML / JS，也不开 iframe。
- 不做自由布局，卡片的样式全部由前端控制。
- 不改审批的后端语义（签名、复核、部分批准都不动）。

## 8. 实现顺序

1. 前端：审批和提问搬进消息流，删掉决定框，加变更单结果卡（不依赖后端，可以单独验收）。
2. `ask_user` 支持多题 `questions[]` 和 `text / url / number` 题型（Go 校验 + agent 工具声明 + 前端表单），并实现「打字即跳过」。
3. `show_card` 两种卡：agent 工具 + 事件 + 前端渲染 + 跳转引用。
4. 提示词规则，用截图里这个问题回归一遍。

每一步都先写失败测试（前端 `web/src/tests/`、后端 `backend/internal/tests/`、agent `agent/test/`）。

## 9. 已确认（2026-11-03）

- 审批卡里条目多时（生成节点、变更单条目超过 3 个），**默认只露前 3 个**，其余收在「还有 N 项」里，点开再看；批准的范围始终是全部勾选项，不受折叠影响。
- 等回答时在输入框打字，**算新消息**，这张提问卡标为已跳过（见 3.3）。
- **其他审批**（变更单、生成、删除等）等确认时打字：**卡片留着不动**，这句话先扣着，等你决定之后、运行继续时，以「用户在等待期间补充了」的形式交给小镜。实现上 agent 的 `interject` 放开了 `waiting_approval` 状态，只写库、不交给 Pi，续跑时从事件里恢复出来。
- 提问卡**支持一次列多个问题**（见 3.3），提示词里加一条：需要补的信息一次问完，不要分多轮问。
