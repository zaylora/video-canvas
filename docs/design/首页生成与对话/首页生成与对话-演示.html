首页生成与对话

首页一句话直接出图、出视频、出音频，结果按对话归档

首页输入卡片和对话页现在只有样式。这次把它们接上真实的生成任务：选模式和模型、写提示词、看积分、发送，进对话页看进度，再对结果重新编辑、再次生成、用作参考、发到画布。 生成 tab 不做 Agent（Agent 只在画布里），本期不做提示词模板和 @ 引用资产，模型必须手选，没有「自动」。

阅读说明。项目现状来自仓库代码（2026-10-09）；竞品来自公开页面检索；原型里的模型名、价格、耗时都是示意。阶段 1 已按本设计实现（后端 + 前端 + 测试，尚未在浏览器里手点验证），下面的原型是设计演示，不是真实页面。完整依据见 首页生成与对话.md。

主线：一次发送怎么走

从首页按下发送，到结果出现在对话页，中间经过哪几层。

输入卡片模式 + 模型 + 参数 + 参考 + 提示词；前端用 quote() 算积分
POST 记录后端建一条 conversation_record，保存完整输入快照
生成任务复用现有 GenerationTaskService.Create，拆成 1–4 个任务各自冻结积分
对话页每个任务一格，进度走现有 WS task.updated + 对账
设计：记录只存「这次提交了什么」，任务状态仍然只认 generation_tasks。这样不新增 WS 消息，断线恢复也直接复用现有对账。
出问题时（兜底）：请求级错误（参数不合法、模型下线）不创建记录，草稿保留；单个任务失败（积分不足、并发满、审核不过）只影响那一格，可以单格重试；网络断开时草稿保留，任务进度在重连后由对账补齐。

用户把结果「发到画布」时，会发生什么

分新建画布和已有画布两种；已有画布可能正被另一个标签页打开。

  1. 在结果上点「发到画布」单个结果，或记录 ⋯ 里发送这条记录全部成功的结果
  2. 选目标：新建画布 / 最近 10 张画布复用 useRecentCanvases，可搜索标题
  3. 新建：前端带节点调用 createCanvas，然后跳转节点带产物、提示词、模型、参数，可直接在画布里再次生成
  4. 已有：后端 POST /canvas/:id/imports 写入并推送 canvas.patch放在现有内容右侧一行；乐观锁冲突重试 3 次；toast「已发到《X》· 打开」，不自动跳转
边界：只发成功的结果，产物以后端任务为准
  • 后端只接受属于当前用户、状态为成功的任务，不信任前端传来的地址。
  • 打开着这张画布的标签页靠现有 canvas.patch 三方合并收下新节点 未验证：run_id 为空时前端是否接受
  • 发过去的节点不能用画布的 Ctrl+Z 撤掉，要在画布里直接删除。

发到画布在阶段 2 交付；阶段 1 先保证能生成、能回看。

数据在内存里，刷新复原，所有请求都是模拟。已预置「默认创作」和「雨夜霓虹」两段对话，可以直接在首页发送一条走完整流程。 想看失败：提示词里写「失败」会让最后一格生成失败；下面的控制条可以把余额调低、让下一次发送断网、让下一次上传失败、把一个视频模型下线。

关系

谁绑谁，以及为什么任务状态不复制到记录里。

对象关系为什么
用户 → 对话1 : N，其中恰好一个 is_default首页发送总有去处；部分唯一索引保证只有一个默认创作
对话 → 记录1 : N，按 id 倒序分页一次发送一条记录；再次生成、单格重试都是新记录
记录 → 生成任务1 : 1–4，task_ids 数组，失败位置为 null状态只读 generation_tasks，避免两处不一致；任务的 node_id 写 rec:{recordId}:{i} 便于反查
记录 → 画布无持久关系发到画布是一次性复制节点，之后两边独立

提交记录的后端流程（提案）

// ConversationService.Submit（提案）
func Submit(userID, convRef, key, req):
    conv := resolve(convRef)            // default → get-or-create；new → 创建，标题 = prompt 前 16 字
    if rec := findByIdem(userID, key); rec != nil { return rec }   // 幂等
    rec := insertRecord(conv, req, taskIDs = [])                    // 先拿 recordId
    n := fanoutCount(req.input)
    nodeIDs := ["rec:{rec.id}:0", …, "rec:{rec.id}:{n-1}"]
    resp, err := generationTasks.Create(userID, key, {kind, model_id, input, node_ids: nodeIDs})
    if err != nil {                     // 请求级错误：一个任务也没建
        softDelete(rec); return err
    }
    rec.task_ids, rec.submit_errors, rec.quote_credits = fromItems(resp.items)   // 部分失败落到格子上
    touch(conv.last_record_at, record_count+1)
    return 202, view(rec, tasks)

已确认的决定

  1. 生成 tab 去掉 Agent 模式，只留图片 / 视频 / 音频：Agent 只在画布里。
  2. 默认创作一段 + 可手动新建对话：首页发送进默认创作，对话页发送进当前对话。
  3. 统一 conversations + conversation_records 两张表。
  4. 不要「自动」，必须选模型：按钮显示模型名，按模式记住上次。
  5. 参数收进参数按钮，发送键旁显示预估积分。
  6. @ 引用资产第一期不做。
  7. 提示词模板先不做：技能按钮和快捷条隐藏。
  8. 结果可发到画布：已有画布或新建。
  9. 实现时的出入（主文档第 13 节已回写）：提交请求多了 count；记录表多了 idempotency_key；对话列表不分页、阶段 1 不做封面。
  10. 已搁置：Agent 会话脱离画布——用户先选了它，随后决定生成 tab 不做 Agent；将来首页做 Agent 时可用 conversations.kind=agent 关联 agent_sessions。
