# 首页生成与对话设计

> - **范围**：首页「生成」tab 的输入卡片（模式、模型、参数、参考、积分、发送），以及提交后的对话页（生成记录流、结果卡片、重新编辑 / 再次生成 / 发到画布）和侧栏「对话」列表。把现在只有样式的界面接上真实数据和生成任务。
> - **日期与状态**：2026-10-09。**阶段 1 已实现**（后端、前端、测试，见 13 实现记录；未在浏览器里手点验证）；阶段 2（发到画布、资产页改读真实数据）待实现。
> - **证据约定**：**事实**附文件路径或来源链接；**推断**是基于事实的判断；**提案**是尚未实现的设计。
> - **方案演进**：
>   1. 第一轮把 Agent 模式当作主路径，用户先选了「Agent 会话脱离画布」（独立的对话工具集）。
>   2. 讨论「Agent 花积分的节奏」时，用户决定**生成 tab 去掉 Agent 模式**，只保留图片 / 视频 / 音频直接生成，Agent 只留在画布里。「Agent 会话脱离画布」随之作废，记录在 11.2 已搁置的决定。
>   3. 技能按钮原定改成「提示词模板」，用户随后决定**模板第一期也不做**；「@ 引用资产」第一期也不做。
> - **配套演示**：[首页生成与对话-演示.html](首页生成与对话-演示.html)（建议先读它）。

## 1. 设计摘要

**问题**：首页输入卡片和对话页已经按原型做好界面，但提交只弹「生成功能即将上线」，对话列表和生成记录是写死的样例。用户无法在首页一句话出图、出视频，也无法回看和复用生成结果。

**目标**：用户在首页选模式和模型、写提示词、可选上传参考图，看到预估积分后发送；进入对话页看到生成进度和结果；能对结果重新编辑、再次生成、下载、用作参考、发到画布。

**推荐结论**：

1. **生成 tab 只做直接生成**：模式只剩 图片 / 视频 / 音频，每次提交 = 一条生成记录 = 1–4 个生成任务。Agent 只在画布里。
2. **对话是「生成记录的文件夹」**：每个用户有一个置顶的「默认创作」，首页提交都进它；用户可以手动新建对话按项目归类，在某段对话底部发送就进那一段。
3. **新增两张表**：`conversations` 和 `conversation_records`。记录保存完整输入快照，任务状态仍以 `generation_tasks` 为唯一事实来源，前端沿用现有的任务 WS 推送和对账。
4. **必须选模型，不做「自动」**：按钮直接显示模型名，按模式记住上次的选择；参数收进一个参数按钮；发送键旁显示前端预估积分，余额不足时禁止发送。
5. **结果发到画布**：可以发到已有画布或新建画布。发到已有画布由后端写入，并推送现有的 `canvas.patch`，打开着这张画布的标签页按现有三方合并收下。
6. **第一期不做**：Agent 模式、提示词模板（技能按钮和快捷条隐藏）、@ 引用资产（按钮置灰）。

### 2.2 设计约束

- 任务状态的唯一事实来源是 `generation_tasks`，记录表不复制状态，只保存任务 id（**推断**：复制状态会出现两处不一致）。
- 生成任务必须带 `node_ids` 且数量等于生成数量；对话没有节点，需要约定一套占位 id（见 8.3）。
- 所有资源按 `user_id` 隔离；列表不返回大字段。
- 写画布必须走 `revision` 乐观锁；打开着的画布标签页可能有未保存修改。

### 2.3 当前缺口

- 后端没有对话和记录的存储与接口。
- 前端输入卡片没有模型、参数、积分和上传逻辑。
- 没有把生成结果放进画布的入口。

## 3. 用户与场景

- **用户**：做短视频和 AI 影像的创作者，大多已经知道自己要用哪个模型；新手第一次来会先试图片。
- **触发场景**：
  1. 打开首页，想快速出一张角色图或一段镜头，不想先建画布。
  2. 为某个项目连续出一批素材，希望它们归在一起（新建对话「雨夜霓虹」）。
  3. 出了满意的结果，想放进画布继续搭镜头链路。
- **主任务**：首页 → 选模式和模型 → 写提示词（可选参考图）→ 看积分 → 发送 → 对话页看进度 → 用结果（下载 / 再来一次 / 发到画布）。
- **成功指标（提案）**：首页发送成功率 ≥ 98%（不含积分不足）；从结果到画布 ≤ 3 次点击；刷新或断线后记录和进度能完整恢复。

## 5. 设计原则

1. **记录即快照**：每条记录保存完整输入，重新编辑和再次生成都从快照复原，不依赖当前模型配置。（来源：「重新编辑」已在前端回填 prompt，需要扩展到模型和参数）
2. **任务只有一个事实来源**：状态只读 `generation_tasks`，沿用现有 WS 和对账。
3. **花钱前看得见**：发送前显示积分，余额不足不让发。（来源：用户选择「参数条 + 发送键旁显示积分」；Lovart）
4. **不做的功能不占位**：模板不做就隐藏技能入口；@ 保留按钮但置灰并写原因，与现有 `SoonTip` 一致。
5. **对话轻、画布重**：对话页只做线性的生成和复用；搭镜头链路去画布。（来源：Runway Chat Mode 的边界）

## 6. 推荐方案

### 6.1 信息架构

```
首页 /（生成 tab）        对话页 /conversations/:id         对话页 /conversations/new
  输入卡片(page)  ──发送──▶  默认创作的记录流 + 输入卡片(dock)
侧栏「对话」 + 新对话 ─────────────────────────────────────▶  空对话，第一次发送才创建
       默认创作（置顶）/ 雨夜霓虹 / …  ──点击──▶ 对应对话页
```

- **首页发送**：一律进「默认创作」，然后跳到它的对话页，滚到底部看到新记录。
- **对话页发送**：进当前对话。
- **新对话**：侧栏「对话」标题右侧的 `+`。跳到 `/conversations/new`（不立即建库，避免空对话堆积），第一次发送时创建对话并替换地址为真实 id。标题默认取第一条提示词前 16 字，可重命名。
- **侧栏对话列表**：默认创作置顶（不可删除、可改名），其余按最近记录时间倒序，最多显示 20 条，可滚动；缩略图阶段 1 统一用图标（封面放后续，见 8.3）；有进行中的任务时显示一个小圆点。悬停出现 `⋯`：重命名、删除。

### 6.2 输入卡片

自上而下：参考区 + 文本框，底栏一行。

| 控件 | 行为 |
| --- | --- |
| 参考区（左侧 `+`） | 点击、拖入、粘贴图片都可上传；用 `uploadAsset`。允许的数量和种类读当前模型 capabilities（`REF_KEYS`）；模型不支持参考时 `+` 置灰，提示「当前模型不支持参考图」。每张缩略图右上角 `×` 移除；上传中显示进度，失败显示重试 |
| 文本框 | 自动增高；Enter 发送，Shift+Enter 换行，输入法组字时 Enter 不发送 |
| 模式 | 图片生成 / 视频生成 / 音频生成。默认图片；按用户记住上次（localStorage，读写失败用默认）。切换模式时模型换成该模式记住的模型，不兼容的参考图标黄 |
| 模型 | 按钮显示「厂商图标 + 模型名」。弹层列出该类已发布模型：名称、hint、tags、起价。按模式记住上次的选择；没有记录时取列表第一个（后台排序）。该类没有已发布模型时按钮显示「暂无可用模型」并禁止发送 |
| 参数 | 按钮显示摘要，如「16:9 · 5s · 1080p · ×2」（复用 `paramSummary`）。弹层由 `openParams(caps)` 生成，含生成数量 1–4（模型有 fanout 参数时）。按模型记住上次的参数；换模型时用 `switchModelParams` 迁移 |
| @ | 置灰，Tooltip「引用资产即将上线」 |
| 技能 | **隐藏**；首页技能快捷条整行**隐藏** |
| 积分 | 发送键左边「✦ 8」= `quote()` × 生成数量。悬停：「预估，按实际扣费为准；可用 22」。余额不足时数字变红，发送键置灰，Tooltip「余额不足（需 8，可用 5）」 |
| 发送键 | 提示词为空时置灰（参考图不能代替提示词：模型要求提示词必填）；参考上传中置灰（「等待参考上传完成」）；请求中显示转圈 |

- **全站只有一份输入卡片**（原型已定）：模式、模型、参数、参考、草稿在首页和对话页之间跟着走，存 `store/composer.ts`。
- **发送成功（202）后**才清空文本和参考，保留模式、模型和参数；失败时一律保留草稿。

### 6.3 对话页

- **顶部**：对话标题（点击重命名）+ `⋯`（重命名、删除；默认创作没有删除）。
- **记录流**：时间正序，按日期分组，打开时滚到底；向上滚到顶自动加载更早的 20 条。用户不在底部时有新结果，底部出现「回到最新」胶囊。
- **一条记录**：
  1. 头部：`模式 | 模型名 | 参数摘要 | ✦ 积分`（积分：全部结束后显示实际扣费合计，进行中显示冻结合计）。
  2. 参考图缩略图（如有）+ 提示词（超过 3 行折叠，可展开）。
  3. 结果区：每个任务一格，状态见 7.1。
  4. 操作行：**重新编辑**、**再次生成**、**取消**（只在有进行中任务时）、`⋯`（发到画布、下载全部、复制提示词、删除记录）。
- **单个结果悬停**：放大预览、下载、用作参考、发到画布。
  - **用作参考**：把这个结果的 asset 加进输入卡片参考区；当前模型不支持这类参考时加进去但标黄并提示。
- **重新编辑**：把记录的模式、模型、参数、参考、提示词全部回填进输入卡片并聚焦，不发送。记录里的模型已下线时，模型按钮回到该模式默认，并 toast「原模型已下线，已换成 X」。
- **再次生成**：用记录快照原样再提交一次（新的 Idempotency-Key），作为**新记录**追加到当前对话底部。模型已下线时按钮禁用，Tooltip「原模型已下线，请重新编辑」。
- **单格失败的重试**：失败格子上有「重试」，只重提这一格（生成数量 1），作为新记录追加，避免改写历史。

### 6.4 发到画布

1. 触发：单个结果的「发到画布」，或记录 `⋯` 里的「发到画布」（发送这条记录全部成功的结果）。
2. 弹出选择框：顶部「新建画布」，下面是最近 10 张画布（复用 `useRecentCanvases`），可搜索标题。
3. **新建画布**：`createCanvas({title: 对话标题, graph})`，graph 由前端按 8.4 的规则构造节点；成功后跳到 `/canvas/:id`。
4. **已有画布**：调用 `POST /canvas/:id/imports`。后端把节点放在现有内容包围盒右侧 120px、顶部对齐的一行（每个节点间隔 40px），乐观锁冲突时重读重试最多 3 次，成功后推送 `canvas.patch`（`kind=import`）。前端 toast「已发到《X》」+「打开」按钮，不自动跳转。
5. 打开着这张画布的其他标签页：沿用现有 `canvas.patch` 三方合并收下新节点（**推断**：新增节点不会和本地修改冲突；`run_id` 为空时前端是否接受需在实现时核对，见 12.3）。

### 6.5 侧栏、首页与资产页

- 侧栏「对话」改读 `GET /conversations`。
- 首页「最近上新」不变；技能快捷条隐藏。
- 资产页「生成历史」：阶段 2 改读 `GET /conversation-records`（跨对话），阶段 1 保持现状（样例数据），并在 12.3 标注。

## 7. 状态与异常

### 7.1 结果格子的状态

由任务状态推出，任务状态取值以 `generation_tasks.Status` 为准。

| 任务状态 | 格子表现 | 允许的操作 |
| --- | --- | --- |
| 提交失败（item.error，未创建任务） | 灰底 + 错误文案（如「积分不足」「进行中的任务已达上限」） | 重试 |
| queued | 「排队中」+ 骨架动画 | 取消 |
| running | 进度条（有 progress 时）或「生成中 · 已用 0:42」 | 取消 |
| succeeded | 图片 / 视频封面 / 音频波形条 | 预览、下载、用作参考、发到画布 |
| failed / expired | 红色图标 + `error_message`，下面一行「积分已退回」 | 重试 |
| canceled | 「已取消 · 积分已退回」 | 重试 |

整条记录的状态：全部终态 = 完成；任一进行中 = 生成中（侧栏圆点亮）。

### 7.2 页面与操作状态

| 场景 | 表现 |
| --- | --- |
| 侧栏加载中 | 3 条骨架 |
| 对话列表加载失败 | 侧栏「对话」下一行「加载失败 · 重试」 |
| 对话页加载中 | 记录骨架 2 条，输入卡片可用 |
| 对话不存在或已删除（62001） | 空状态「这段对话不存在或已删除」+「回到默认创作」 |
| 新对话空状态 | 「在下方输入，开始这段对话」 |
| 发送中 | 发送键转圈，输入卡片只读 |
| 发送请求级失败（10001 参数、40003 模型不可用） | toast 原因；保留草稿；40003 时刷新模型列表 |
| 发送部分失败 | 记录照常创建，失败的格子显示「提交失败」，可单格重试 |
| 网络断开 | 发送失败 toast「网络异常，草稿已保留」；断线期间任务进度由重连后的对账恢复 |
| 余额不足 | 发送前拦截（6.2 积分规则）；后端仍可能返回 40001（并发扣费），按部分失败处理 |
| 删除记录 | 有进行中任务时确认框「将取消 N 个生成并退回积分」；删除后结果仍保留在资产里 |
| 删除对话 | 确认框「对话里的记录将一起删除，生成的素材仍在资产里」；进行中的任务继续跑完（只是不再显示） |
| 发到画布失败 | 30001 画布不存在：从列表移除并 toast；62004 写入冲突重试仍失败：toast「画布正忙，请稍后再试」 |
| 多标签页 | 任务进度靠 WS 同步；另一标签页新发的记录在窗口回到前台时重拉最新一页 |

### 7.3 撤销

对话里的操作不做撤销；删除是软删除，后台可恢复（**提案**，本期不做恢复界面）。发到画布后的节点用画布自己的 Ctrl+Z 撤不掉（它不是本地操作），用户在画布里直接删除即可。

### 8.2 接口

前缀 `/api/v1`，全部需要登录、按 user_id 隔离。id 用现有 `idcodec` 编码。

| 方法与路径 | 请求 | 返回 | 业务错误 |
| --- | --- | --- | --- |
| `GET /conversations` | — | `[{id,title,is_default,record_count,last_record_at,active,created_at}]`，一次返回全部（每人最多 200 段，不分页）；默认创作总在第一条，没有时自动创建 | — |
| `POST /conversations` | `{title?}` | 对话 | 62002 对话数已达上限（200） |
| `PATCH /conversations/:id` | `{title}`（1–50 字） | 对话 | 62001 |
| `DELETE /conversations/:id` | — | 204 | 62001；62003 默认创作不能删除 |
| `GET /conversations/:id/records` | `?before=recordId&limit≤50`（默认 20） | `{items:[Record], next}`，Record 内嵌 `tasks: TaskView[]`（按 task_ids 顺序，null 位置为 null） | 62001 |
| `POST /conversations/:id/records` | Header `Idempotency-Key`（≤ 126 字符）；`{kind, model_id, prompt, input, count 1–4, title?}`；`:id` 可为 `default` 或 `new`（`new` 时同时创建对话，可带 `title`） | 202 `{conversation_id, record}` | 10001、40003、62001、62002 |
| `DELETE /conversations/:id/records/:rid` | `?cancel_active=true` | 204 | 62001、62005 记录不存在 |
| `GET /conversation-records` | `?kind&cursor&limit`（阶段 2，资产页） | 同 records | — |
| `POST /canvas/:id/imports` | `{items:[{task_id, output_index?}] ≤ 20}` | `{revision, node_ids}` | 30001；40004 任务不存在或不属于你；62004 画布写入冲突；10001 任务未成功 |

- 取消沿用 `POST /generation-tasks/:id/cancel`，前端对记录内的每个进行中任务各调一次。
- 积分余额沿用 `GET /credits`。
- WS 不新增消息类型：进度沿用 `task.updated`；发到画布沿用 `canvas.patch`。

新增错误码段 62xxx（核对过现有段为 10/20/30/40/50–55/60/61）：62001 对话不存在（404）、62002 对话数已达上限（409）、62003 默认创作不能删除（409）、62004 画布写入冲突重试仍失败（409）、62005 记录不存在（404）。

### 8.3 提交记录的后端流程（提案）

```
POST /conversations/:id/records
1. 解析 :id（default → get-or-create；new → 创建，标题取 prompt 前 16 字）
2. 幂等：同一用户 + Idempotency-Key 已有记录 → 直接返回
3. 插入 record（task_ids 先为空），拿到 recordId；幂等键撞唯一索引 → 返回先到的那次提交
4. n = 生成数量；node_ids = ["rec:{recordId}:0" … ]
5. GenerationTaskService.Create(userID, key, {kind, model_id, input, node_ids})
   - 请求级错误 → 软删除 record，原样返回错误
   - 逐项结果 → 写 task_ids / submit_errors / quote_credits
6. 更新 conversation.last_record_at、record_count
7. 返回 202 + RecordView（内嵌任务视图）
```

封面：**阶段 1 不做**，侧栏统一用图标。以后要做时有两条路：任务成功事件里更新对话的封面列，或列表接口里现查最近一条成功结果。

### 8.4 发到画布的节点构造

每个成功结果一个 `canvas` 节点：

| 节点字段 | 取值 |
| --- | --- |
| `data.kind` | 结果的 media_type（image / video / audio） |
| `data.label` | 「提示词前 12 字」 |

## 9. 方案取舍

### 9.1 决策矩阵

权重来自用户回答：花钱可控与实现成本优先（去掉 Agent、模板、@，必须选模型）。

| 维度（权重） | A 两张表（采用） | B 只查 generation_tasks | C Agent 会话承载 |
| --- | --- | --- | --- |
| 重新编辑 / 再次生成的完整性（3） | 好：快照完整 | 差：一次提交拆成多任务，要前端拼 | 中 |
| 列表和分页（2） | 好 | 中 | 差：要扫事件 |
| 实现成本（3） | 中 | 好 | 差 |
| 与画布 Agent 解耦（2） | 好 | 好 | 差 |

### 9.2 已搁置的方案

- **Agent 会话脱离画布**：`agent_sessions.canvas_id` 可空 + 对话专用工具集，产出写进对话记录。用户先选了它，后来决定生成 tab 不做 Agent。将来要在首页做 Agent 时可复用：`conversations` 增加 `kind=agent` 并关联 `agent_sessions`。
- **提示词模板**：模板 = 模式 + 推荐参数 + 带空位的提示词骨架，前端常量起步，二期进后台。
- **@ 引用资产**：需要新增素材列表接口，可与资产页一起做。

### 9.3 明确放弃（本期）

- 「自动」选模型（用户明确不要）。
- 每次首页提交都新开对话（用户选了默认一段 + 手动新建）。
- 对话里的撤销。

## 13. 实现记录

### 13.1 阶段 1（2026-10-09，已实现，未提交，未在浏览器里手点验证）

**后端**（`backend/`）

- 新增表 `conversations`、`conversation_records`（注册进 `model.All()`，AutoMigrate 建表）；错误码 62001 / 62002 / 62003 / 62005（62004 留给发到画布）。
- 分层：`repository/conversation.go` → `service/conversation.go`（依赖 `ConversationRepo` 和 `ConversationTasks` 两个接口）→ `handler/conversation.go` → `router.go` / `initialize/app.go`。
- 给 `GenerationTaskService` 加了 `ViewsByIDs`（批量取任务快照，按 100 个一批），其余任务逻辑原样复用。
- 与设计的出入：
  1. 提交请求多了 `count`（任务服务要求 `node_ids` 数量等于生成数量，后端不知道模型的数量参数名，所以由前端传）。
