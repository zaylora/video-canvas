画布对齐线演示

拖一个节点靠近另一个，自动吸齐并画一条线

拖动单个节点时，它的左/中/右、上/中/下与其他节点对应位置相差不到 4 个屏幕像素就吸过去，并画细点线，只画在两个节点之间的空隙里；拖远到 8 像素才松开。对齐常开，没有开关，也没有临时关闭键；多选、拖组时不吸附。同时把设置里的“对齐网格”整个移除。

一次拖动是怎么走的

回答：吸附逻辑放在哪里、什么时候算、松手时会不会跳。

开始拖动只在单选、非组时建目标索引
每帧：改写坐标在 applyNodesChange 之前，按原始坐标算两轴吸附
更新辅助线写独立 store，只有覆盖层重渲染
松手：复用修正量xyflow 会再发一条原始坐标，必须一并改写
设计：不替换现有 onNodesChange（它还管保存判定和取消上传），只在入口处改写拖动变更；辅助线不进 nodes，所以不触发保存、不进撤销栈。参考稿漏掉了“松手那一条”，会让节点在松手瞬间跳回未吸附位置，这一点在原型里可以勾选复现。
附近没有可吸附的目标时（回退，永远可用）：没有已测量的普通节点、或拖的是多选 / 组时，节点坐标就是鼠标算出来的原始坐标，和今天完全一致。

什么时候吸，什么时候不吸

三类情形，由“拖了什么”决定；对齐常开，不能关闭。

单个节点
吸附 + 画线

普通节点和组成员都可以，目标是其他普通节点；组框不当目标。

多选 / 拖组本身
不介入

整体平移，不破坏已排好的相对布局。多选整体吸附留到后续。

细点线

当用户把节点拖到另一个节点旁边时，会发生什么

一次典型的整理动作分五步，以及一个需要提前说清的边界。

  1. 按下并拖动节点 A单选、非组节点才会建立目标索引
  2. A 的上边靠近 B 的上边，相差 3px小于 4px，立刻吸齐，并在 A 和 B 之间的空隙里出现细点线（顶 / 中 / 底同时对齐就是多条）
  3. 继续向下拖 6px，仍在 8px 内保持吸附，线不消失——这就是“黏性”
  4. 拖出 8px释放，线消失，A 回到鼠标所在位置
  5. 松手A 停在最后一帧的位置，不跳；位置作为普通坐标走现有保存流程
边界：只和“已测量尺寸”的普通节点对齐
  • 刚加载、还没量出宽高的节点不参与，不会被当成 0×0。
  • 组框再大也不当目标，节点不会被吸到组框的边上。
  • 线只连被拖节点和锁定的那一个目标；同一目标上多个锚点同时对齐就同时出现多条。

交付时要提前告知：对齐常开、无法关闭；“对齐网格”设置项会消失，用过的用户需要知道新的对齐方式。

谁参与吸附

哪些节点能当被拖对象、哪些能当目标，以及为什么。

对象被拖时当目标原因
普通节点吸附是核心场景
组成员吸附是用 absolutePosition() 换算成绝对坐标再比较；位移量对相对/绝对坐标相同
组节点不介入否用户已确认：组框又大又带内边距，会造成误吸附
未测量节点不介入否宽高缺失或为 0，不能当 0×0
多选拖动不介入—用户已确认：不破坏相对布局

alignment.ts
findAxisSnap		入参：被拖矩形、目标矩形数组、轴、enter、release、上次的锁。返回 { delta, lock } | null。进入阈值用严格小于；释放阈值用小于等于
alignment.ts
alignmentGuides		入参：吸附修正之后的被拖矩形、目标矩形、轴。返回这条轴上所有对齐锚点（相差 ≤ 0.5）各一条 Guide，按位置从小到大；线只覆盖两节点之间的空隙，贴着没有空隙返回空数组
use-align-guides.ts
adjustChanges		入参 NodeChange[]，返回改写后的数组。只改“被拖节点”的 position 变更：同时改 position 和 positionAbsolute（若有）；包含 dragging:false 的那一条。其余变更原样返回

onNodeDragStop结束会话，清锁清线

// use-align-guides.ts（提案）
adjustChanges(changes):
  if !session: return changes
  c = changes.find(type==='position' && id===session.id && c.position)
  if !c: return changes

  if c.dragging === false:                 // 松手那一条：xyflow 给的是原始坐标
    return apply(changes, session.lastDelta)   // 不重算，复用最后一次修正量

  cur  = lookup(session.id)
  raw  = translate(session.rect, c.position - cur.position)   // 原始绝对矩形
  enter   = ENTER_PX / zoom
  release = RELEASE_PX / zoom
  sx = findAxisSnap(raw, session.targets, 'x', enter, release, locks.x)
  sy = findAxisSnap(raw, session.targets, 'y', enter, release, locks.y)
  locks = { x: sx?.lock, y: sy?.lock }
  session.lastDelta = { x: sx?.delta ?? 0, y: sy?.delta ?? 0 }
  snapped = translate(raw, session.lastDelta)          // 辅助线按吸附之后的位置算
  guides = []
  for (axis, snap) of [('x', sx), ('y', sy)]:
    if snap: guides += alignmentGuides(snapped, session.rects[snap.lock.targetId], axis)
  setGuides(guides)                                    // 浅比较，没变就不写
  return apply(changes, session.lastDelta)   // position 与 positionAbsolute 同时 + delta

已确认的决定

  1. 一期做边/中心对齐 + 磁吸：不做等间距、也不做只画线。
  2. 组框不作为吸附目标：避免大边框造成误吸附。
  3. 对齐常开、不可取消：不监听 Ctrl，也不提供设置开关。用户后来改了主意，取代此前“按住 Ctrl/Cmd 临时关闭 + 设置总开关”。
  4. 多选拖动不吸附不画线：不破坏已排好的相对布局；整体吸附列为后续。
  5. 辅助线只连两个节点范围，浅灰色：画面干净，节点多时不被满屏长线干扰。颜色取主题令牌 --muted-foreground（初版用品牌色，用户要求改浅灰），需用户打开页面确认视觉。
  6. 移除“对齐网格”：用户在“与网格关系”一题中直接给出，取代了原本的让位/优先方案。已搁置：网格开时对齐线让位或优先。
  7. 辅助线样式参照用户给的三张参考截图：只画在两个节点之间的空隙里，细点线（0.75 屏幕像素宽）；顶 / 中 / 底同时对齐时同时出现多条。
  8. 性能是硬约束：不得让画布拖动变卡。辅助线状态独立于 Flow、覆盖层只在有线时挂载、拖动开始 O(n) 建索引、回调引用稳定。
  9. 默认值（非用户决定）：4px 进入 / 8px 释放（初版 6/14，用户试玩后反馈太强而下调），实现后仍可凭手感调。
  10. 主文档已回写：松手那一帧的处理、辅助线 store 独立于 Flow 状态，均已写入 Markdown §6.7 与 §7。
