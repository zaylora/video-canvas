# 画布对齐线（智能对齐与磁吸）设计

> **范围**：拖动单个节点时，与其他节点的边、中心自动磁吸并显示辅助线；同时移除设置里的"对齐网格"。
> **日期与状态**：2026-10-14，已实现（未提交），待真机验证手感。
> **证据约定**：**事实**附文件路径或来源链接；**推断**是基于事实的判断；**提案**是尚未实现的设计。
> **方案演进**：起点是用户给的 ChatGPT 对话稿（仓库根目录 `画布对齐线实现原理_6acef472_20261014_1118.md`）。对照 xyflow 源码和项目代码后，改了四处（见 §6.7）；访谈中用户又提出**移除"对齐网格"**，见 §11。
> **配套演示**：[画布对齐线-演示.html](画布对齐线-演示.html)（含可拖动的原型，用的是本文的真实算法）。

## 1. 设计摘要

- **问题**：节点多了以后，手动把两个节点摆齐很难，目前只有"对齐网格"一个粗粒度辅助。
- **目标**：拖动一个节点靠近另一个节点的边或中心时，自动吸过去并画一条线，让整理布局一次到位。
- **推荐结论**：**自研**一个纯函数核心 + 一个只在拖动单节点时介入 `onNodesChange` 的 Hook + 一个独立覆盖层。不引入依赖。
- **同时**：把"对齐网格"整个移除，不做二者协调。

**xyflow 拖动机制（读源码核对，12.12.0 / system 0.0.83）**：

- 拖动中每个 pointermove 经 `updateNodePositions(dragItems, true)` 发出 `NodePositionChange`，其 `position` 来自 `dragItem.position`，是**由指针算出的原始坐标**，不受我们改写 `change` 的影响。（`node_modules/@xyflow/react/dist/esm/index.mjs:3504`、`@xyflow/system/.../index.mjs:2209`）
- 松手时 xyflow **再发一次** `updateNodePositions(dragItems, false)`，`dragging: false`，`position` 仍是**原始坐标**。（`@xyflow/system/.../index.mjs:2328-2331`）
- `NodePositionChange` 类型含 `position?`、`positionAbsolute?`、`dragging?`。

**当前缺口**：没有节点间对齐。**需要用户确认**：无（已全部确认，见 §11）。

## 3. 用户与场景

- **用户**：在无限画布上摆放图片、视频、文本等节点的创作者。
- **场景**：整理布局——把几个节点摆成一列、一行，或让一个节点和另一个居中对齐。
- **主任务**：拖一个节点靠近另一个，松手时两者的边或中心刚好对齐。
- **成功指标（可验收）**：见 §10 验收条件。

## 5. 设计原则

1. **不动现有骨架**：不替换 `onNodesChange`，只在它调用 `applyNodesChange` 之前改写拖动中的坐标。
2. **从原始坐标算吸附**：吸附基于 xyflow 给的原始坐标，不在已吸附位置上累加，所以不会反馈抖动。
3. **拖动每帧零额外重渲染**：辅助线状态放独立 store，只有覆盖层订阅，`FlowCanvas` 不重渲染。
4. **纯视觉层**：辅助线不进 `nodes`、不触发保存、不进撤销栈。
5. **阈值按屏幕像素**：缩放后手感一致。

## 6. 推荐方案

### 6.1 行为

| 项 | 取值 | 依据 |
| --- | --- | --- |
| 触发 | 只在**拖动单个非组节点**时 | 用户已确认：多选不吸附 |
| 目标 | 其余所有**非组、可见、已测量**节点 | 用户已确认：组框不作为目标 |
| 锚点 | X 轴 左/中/右，Y 轴 上/中/下，各 3×3 种配对 | 用户已确认：一期做边/中心对齐 + 磁吸 |
| 进入吸附 | 4 屏幕像素 | 提案；初版 6，用户试玩演示后反馈吸附太强，下调 |
| 释放吸附 | 8 屏幕像素 | 提案；初版 14，"黏"的感觉主要来自释放距离，同步下调；保留双阈值以防边界抖动 |

| 辅助线样式 | **细点线**：0.75 屏幕像素宽、点距 2/2 屏幕像素，**浅灰色**（取主题令牌 `--muted-foreground`，深色主题下偏浅、浅色主题下偏中灰，两种底色上都看得清）；线宽和点距按 `1/zoom` 换算成恒定屏幕像素 | 用户已确认（参照其给的三张参考截图，并要求"线再细一些"） |
| 辅助线长度 | **只画在被拖节点和目标节点之间的空隙里**，不贯穿节点、不留白；另一轴上有重叠就画重叠那一段；贴着没有空隙就不画 | 用户已确认（参考截图） |
| 线的条数 | 对同一个目标，顶/中/底（或左/中/右）有几个锚点同时对齐就画几条 | 用户已确认（参考截图里三条线同时出现） |

### 6.2 流程

```text
dragStart(单选、非组) → 建目标矩形索引（绝对坐标）
   ↓
每帧 position 变更 → 取原始坐标 → 算两轴最近吸附（带滞回锁）→ 改写 position/positionAbsolute → 更新辅助线 store
   ↓
松手 dragging:false 变更 → 复用最后一次的修正量 → 清辅助线与锁
```

### 6.3 算法

**坐标**：被拖节点的原始绝对矩形 = 当前绝对矩形 + （原始 `position` − 当前 `position`）。对组成员，`position` 是相对坐标，但位移量相同，所以不需要读 `positionAbsolute`；目标矩形用 `absolutePosition()` 换算一次。

**单轴吸附 `findAxisSnap`**：

1. 若上一帧已有该轴的锁，且锁定的目标还在，且 `|锁定值 − 被拖锚点当前值| ≤ release`，则保持锁，修正量 = 锁定值 − 当前值。
2. 否则遍历 目标 × 被拖锚点(3) × 目标锚点(3)，取 `|delta| < enter` 的最小者；平手取先遇到的（目标按节点顺序，锚点按 start、center、end 顺序，保证确定性）。
3. 返回 `{ delta, lock, guide }`，无结果返回 `null`。

**换算**：`enter = ENTER_PX / zoom`，`release = RELEASE_PX / zoom`，`zoom` 取 `getViewport().zoom`，下限 0.01。

**辅助线**：吸附后（用修正后的位置）对锁定的那个目标，把两个节点在这条轴上所有对齐的锚点各画一条（相差不到 0.5 画布单位算对齐）；线沿另一轴只覆盖两个节点之间的空隙，有重叠画重叠段，贴着没有空隙不画。

### 6.5 不提供开关与临时关闭

对齐常开：没有设置项，也不监听键盘。多选、拖组、没量出尺寸时本来就不介入（§6.1）。因此不需要读修饰键，也消除了与 xyflow 多选键（Ctrl/Meta）冲突的风险。

### 6.6 渲染与性能

- `guides` 存独立 store，`FlowCanvas` 不订阅，拖动中不会因为辅助线重渲染（与 P1 优化一致）。
- `setGuides` 做浅比较：吸附状态不变时不写入。
- 目标索引在拖动开始时一次建好，拖动中只读。
- 每帧计算量 ≈ 2 轴 × 9 配对 × 目标数；几百个节点无压力。**1000+ 节点未验证**，留作后续（空间索引或视口过滤）。

### 6.7 与参考稿的差异

| 参考稿做法 | 本项目做法 | 原因 |
| --- | --- | --- |
| 自己重写 `onNodesChange` 并在 Hook 内维护 `nodesRef` | 保留现有 `onNodesChange`，只在 `applyNodesChange` 前改写拖动变更 | 现有函数已承担保存判定、取消上传 |
| 只处理 `dragging !== false` 的变更 | **同时处理松手那一条 `dragging:false`**，复用最后修正量 | xyflow 松手时会再发一次原始坐标，不处理会让节点在松手瞬间跳回未吸附位置 |
| 跳过 `parentId` 节点 | 用 `absolutePosition()` 换算，组成员参与 | 项目有组，成员常需要对齐 |
| `guides` 放 Hook 的 `useState` | 放独立 zustand store | 避免整个 Flow 每帧重渲染 |
| 辅助线颜色写死 | `--muted-foreground` 令牌 | 随主题；不写死浅灰，免得在浅色画布上看不见 |

## 7. 状态与异常

| 状态 | 行为 |
| --- | --- |
| 初始、无拖动 | 不渲染任何东西 |
| 拖动中、未靠近目标 | 无线，坐标原样 |
| 拖动中、进入 4px | 吸附并画线（同一目标上对齐的锚点各一条） |
| 已吸附、继续拖到 8px 以外 | 释放，线消失，坐标回到原始 |
| 松手 | 复用最后一次修正量，**不跳变**；清线清锁 |
| 被拖节点或目标未测量（尺寸 0/缺失） | 跳过，不当作 0 |
| 多选拖动、拖的是组 | 不介入 |
| 拖动途中目标被删除/隐藏 | 锁失效，回到重新找最近；目标索引不实时刷新，下次拖动重建 |
| 拖动中按 Esc/切走窗口 | xyflow 会结束拖动，走松手路径，清状态 |
| 保存 / 冲突 / 撤销 | 不涉及。最终坐标是普通节点位置，随现有流程保存；拖动中不存、不入历史（`use-canvas-history.ts:102`） |
| 权限 / 只读 | 只读状态下节点不可拖（现有 `nodesDraggable`），自然不触发 |

## 8. 数据与工程影响

- **payload / API / revision**：无影响。辅助线不进 `nodes`，不序列化；节点坐标是既有字段。
- **设置存储**：删 `snapToGrid`（字段、`partialize`、设置面板"对齐网格"一行），**不新增设置项**。已有用户 localStorage 里残留的 `snapToGrid` 键不会再被写回，zustand 合并后留在内存里无害；若要彻底清除可加 `version` + `migrate`，**提案：不做**，成本不值。
- **`GRID_SIZE`**：保留（背景点阵在用），注释从"吸附网格的步长"改为"背景点阵的间距"。
- **新增 store**：`align-guides.ts`，不持久化。
- **实现难点**：松手那条变更的处理、组成员坐标换算。

## 9. 方案取舍

| 方案 | 说明 | 结论 |
| --- | --- | --- |
| A（推荐）自研纯函数 + 改写 `onNodesChange` 入参 + 独立 store 覆盖层 | 见 §6 | 采用 |
| B 引入 React Flow Pro Helper Lines | 官方实现 | 付费，放弃 |
| C 只画线不吸附 | 最稳 | 整理时仍需手动对像素，放弃 |
| D 在 `onNodeDrag` 里 `setNodes` 改位置 | 实现直观 | 与 xyflow 内部拖动状态争抢坐标，会抖；且每帧整图 `setNodes`，放弃 |

**明确放弃项**：等间距吸附、多选整体吸附、组框作为目标、"线贯穿整个视口"、对齐开关与临时关闭键。

## 10. MVP 与后续

**MVP（本期）及验收条件**：

1. 拖动单个节点，左/中/右与上/中/下任一配对距离 < 4 屏幕像素时吸附，并画出品牌色细点线（只在两个节点之间的空隙里，对齐的每个锚点一条）；距离 ≥ 8 屏幕像素时释放。
2. 在任意缩放下（0.14–2），触发距离的**屏幕像素**一致。
3. 松手时节点**不跳变**，位置等于松手前最后一帧。
4. 组成员与组外节点、组成员与同组成员都能互相对齐；组框不参与；拖组本身不吸附。
5. 多选拖动不吸附不画线。
6. 对齐常开，设置里没有开关；"对齐网格"设置项和 `snapToGrid` 代码已移除。
7. **性能**：拖动中 `FlowCanvas` 不因辅助线重渲染；每帧只做 O(目标数) 的计算，拖动开始建索引为 O(节点数)；`onNodesChange` 与拖动回调的引用保持稳定。
8. 拖动过程中 `FlowCanvas` 不因辅助线重渲染。
9. 辅助线不被保存、不进撤销栈（撤销一次回到拖动前的位置）。
10. 单测覆盖：9 种锚点配对、进入/释放阈值、滞回、zoom 换算、平手确定性、组成员坐标、辅助线只连空隙与多条线、松手不跳变、单选才介入；辅助线 store 浅比较。

**后续阶段（本期不做）**：等间距吸附并标数字；同值目标同时连线；多选整体包围盒吸附；缩放节点/组框时对齐；1000+ 节点的空间索引；`snapToGrid` 迁移清理。

## 11. 待确认问题与已确认事项

**已确认（用户回答）**

1. 一期做**边/中心对齐 + 磁吸**，不做等间距、不做只画线。
2. **组框不作为吸附目标**。
3. ~~按住 Ctrl/Cmd 临时关闭 + 设置总开关~~ **已取消**：用户后来决定对齐**常开、不可取消**，不监听 Ctrl，也不提供设置开关。

5. 辅助线**只连两个节点范围**；颜色初定品牌色，**后改为浅灰色**（用户反馈）。
6. **去掉"对齐网格"功能**（用户在"与网格关系"一题中直接给出此答案，取代了原本的协调方案）。

- "网格开时对齐线让位 / 优先"两种协调方案——网格已移除，不再需要。
