# 首页与画布列表

参考：Neowow 首页、Neowow「无限画布」页（用户 2026-10-03 提供截图）。原型：[首页原型.html](首页原型.html)。

## 1. 问题和目标

现在 `/` 是一个朴素的三列卡片网格（`pages/canvas-list`），打开后不知道“下一步做什么”，也没有任何品牌感。

目标：

- 首页一眼看到三件事，顺序为 **创作 → 继续 → 浏览**：大输入框、最近画布、作品区。
- 继续上次的画布：最近画布卡在首屏，点一下就进。
- 新增「所有画布」页，搜索、调整网格疏密都能用。
- 没有后端能力的部分只搭结构、明确标「即将上线」，不放假数据冒充真功能。

## 3. 已定决定（访谈）

1. 大输入框**只做外观**：可以输入，发送按钮禁用，Tooltip 提示「即将上线」；快捷 chips 点击后只做按下反馈。
2. 下半区**做占位**：灰色 banner 轮播（3 张占位，手动切换），作品区的分类 tabs 可以切，内容一律是空状态「作品广场即将上线」。
3. 配色**跟随现有主题设置**，全部走 token，深浅两套都要能用。
4. **要有左侧侧栏**（用户第二轮反馈；变更：原为「本期不做侧栏」）。没有功能的菜单项先放着、禁用。

### 默认决定（未单独问，按推荐项定）

- 路由：`/` 是首页，新增 `/canvases` 是所有画布页；首页的「所有画布 >」和最近画布区里的「更多」都跳到这页。
- 侧栏（详见 4.0）：Logo、收起按钮、新建画布、导航（首页 / 无限画布 / 作品广场 / 创作活动），底部是 AI 配置（只有管理员能看到）和我的账户。首页、所有画布两页共用这个侧栏，画布页不显示。
- 顶栏只留右侧的积分胶囊（复用画布页的 `CreditsPill`）和头像菜单（主题、管理后台、退出登录）。窄屏时左侧多一个汉堡按钮。
- 最近画布最多显示 5 张，加上新建卡共 6 格，放不下时横向滚动。
- 「全部 / 个人 / 协作」：全部和个人展示同一份数据（目前只有个人画布），协作禁用并标「即将上线」。
- 卡片右上角的「⋯」菜单只放「删除」。删除不能撤销，所以要弹确认框（AlertDialog）。
- 所有画布页的疏密切换是纯前端：小 / 中 / 大 三档，对应列数 6 / 4 / 3，选择记在 `localStorage`。排序按钮先占位禁用（后端默认按更新时间倒序）。
- 封面：有 `coverUrl` 就用图片；没有就按 id 的哈希在 3 种节点线框布局里挑一种，保证同一张画布每次看到的样子不变。

## 10. 首页 → 后台的过渡（2026-10-03 追加）

原型：[进入后台过渡原型.html](进入后台过渡原型.html)

### 问题

点头像菜单的「管理后台」后，页面会瞬间换掉：配色从中性灰跳成后台的 zinc 冷灰，侧栏内容整块替换，接着是后台角色检查的骨架屏，再一闪变成正文。一次跳转闪了三下。

### 方案：「沉入后台」

用浏览器原生的 View Transitions（React Router `navigate(to, { viewTransition: true })`），把一次跳转变成一个连续的动作：

1. **先加载再走**：点「管理后台」后菜单不关，这一项的盾牌图标立刻（<100ms）换成转圈，同时预取后台角色（`useAdminStore.load()`）。拿到结果再跳转，后台第一帧就是正文，没有骨架屏闪一下。角色已缓存时直接走。
2. **骨架不动，只换内容**：侧栏、顶栏在两页里各有一个共享名（`app-sidebar`、`app-header`）。浏览器把它们当成同一块东西：位置不变，内容和底色交叉淡化（从首页配色过渡到后台的冷灰）。
3. **内容区沉下去 / 浮上来**：首页内容略微缩小、淡出，后台内容从下方 24px 浮上来、淡入，比旧内容晚 60ms，形成「往里走一层」的空间感。
4. **原路返回**：在后台点「返回画布」时方向相反：后台内容向下沉、淡出，首页内容从 0.96 放大回 1。从哪来，就回哪去。

## 13. 点「更多」：卡片飞到画布列表页（2026-10-15 追加）

### 问题和目标

首页「画布」tab 点「更多」进入 `/canvases` 现在是硬切：整页换掉，用户看不出「这三张卡就是那三张卡」。目标：新建画布卡和最近的 3 张画布卡从首页位置平滑移动、缩放到列表页里对应的位置，其余内容淡入淡出，让这次跳转像一个连续动作。

### 方案：浏览器原生 View Transitions（共享元素转场）

- 用 React Router 的 `<Link viewTransition>`：点击时它自己调 `document.startViewTransition`，不用手写 `navigate` + 动画编排。不装新依赖。
- 同一个元素在新旧两页上给相同的 `view-transition-name`，浏览器自己截下旧、新两张快照，对位置和大小做补间，同时把两张快照交叉淡化。动画只走合成层的 transform / opacity，不碰布局属性。
- 名字只在转场进行时才挂：用 `useViewTransitionState("/canvases")`，返回 true 才给元素加 `view-transition-name`。平时不挂，不产生额外的层，也不会出现同名冲突（同名元素一页里只能有一个，否则整个转场被浏览器放弃）。
- 命名：新建画布卡 `canvas-card-new`，画布卡 `canvas-card-<id>`（id 里不是字母数字、`-`、`_` 的字符去掉）。首页的 3 张最近画布和列表页前 3 张是同一批、同一排序，所以一一对得上。

### 数据要先到位（关键）

列表页现在进来先是 7 张骨架，数据要等接口回来才有卡片。转场的「新页面快照」是在页面第一次渲染后立刻拍的，那时列表页还没有卡片，就没有终点可飞。解决：

- `useCanvasList` 加一份模块级缓存，记下最近一次成功拉到的列表；初始就用缓存渲染，页面一进来就有卡片，同时照常重新请求，回来后覆盖。（首页已经拉过 4 张，列表页拿它做起点。）
- 这是「先给旧数据、后台刷新」，列表页第一眼可能短暂地只有前几张，接口回来后其余的卡片补上，不触发动画。
- 新建、删除成功后同步更新缓存。
