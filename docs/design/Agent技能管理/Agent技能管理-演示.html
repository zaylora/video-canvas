Agent 技能管理演示
架构设计

让管理员把一个“技能包”导进来，Agent 就能用上里面的一切

现在的技能只有 5 个写死在程序里的说明文件。这次要做一个后台页：管理员可以导入压缩包、文件夹或单个 SKILL.md，技能里的脚本、参考文档、模板都跟着进来。导入后默认停用，要人工启用才生效；同名再导入是新版本，不会自动替换线上在用的版本。脚本的真正执行放第 2 期。

阅读说明。本页内容对应 Markdown 设计文档 Agent技能管理.md 的 §1、§4、§6、§10。外部调研数据来自官方文档和检索，访问日期 2026-10-07；这是设计稿，没有任何代码已实现；“可点击原型”里的上传、预检都是浏览器内示意，不会真的调用任何服务；第 2 期的执行输出也是示意。

一个技能从导入到被 Agent 用上，怎么走

这条链上有两道人工把关：确认导入，和启用。中间的“预检”由后端自动完成，会把问题指到具体文件。

1 选文件zip / 文件夹 / 单个 SKILL.md
2 预检解压、安全检查、解析头部、列文件、指出问题
3 确认入库生成不可变版本，默认停用
4 启用管理员看过文件后手动打开
5 Agent 发现名字+说明进提示词目录
6 按需使用读正文 → 读资源文件 →（第2期）跑脚本
设计：把“看见包里有什么”放在“生效”之前。社区技能带脚本等同安装软件（Anthropic 官方安全建议），而用户选了“所有管理员都能导入”，所以靠“默认停用 + 文件可预览”补偿，而不是限制谁能导入。
没有导入任何技能，或全部被停用时（回退，永远可用）：Agent 只用现有的 5 个内置技能，行为和今天完全一致。内置技能不能被停用、删除或覆盖。

三种导入形式

不管从哪种形式进来，后端都会整理成同一份规范化压缩包再存，所以后面的流程完全一样。

压缩包 .zip
最标准≤ 50 MB · ≤ 500 个文件

Claude、OpenAI 都支持。后端检查路径穿越、符号链接、压缩炸弹，自动去掉 __MACOSX 和 .DS_Store。

拖入文件夹
浏览器差异 · 需实测

省去手动打包。浏览器逐个文件带相对路径上传；大目录要分批读取，各浏览器行为需要实测。

单个 SKILL.md
只适合简单技能

没有脚本和资源的技能。现有 5 个内置技能就是这种形态。

管理员导入一个带脚本的压缩包时，会发生什么

用一个具体例子走一遍：包里有 SKILL.md、scripts/export_csv.py、references/FORMS.md、assets/template.png。

  1. 拖入 zip，自动预检后端解压、去掉系统垃圾文件、检查路径和大小、解析头部。
  2. 在第 2 步看到：识别结果、4 个文件及类型、两条提示“含脚本”“allowed-tools 本系统未支持”。没有错误，可以确认。
  3. 点“确认导入”：生成 v1，停用列表里出现新行；Agent 此时看不到它。
  4. 打开详情，逐个看文件，满意后打开启用开关之后新开始的运行目录里才会出现它。
  5. Agent 用到它：先读正文，再按需读 references脚本在第 1 期只能读源码；第 2 期才能运行。
边界：第 1 期脚本不会被执行。
  • 脚本会被存好、能预览、能被 Agent 当文本读，但 Agent 会被告知“当前环境暂不能执行脚本”。
  • 依赖脚本才能完成的技能，第 1 期只能完成它说明文字里的那部分。
  • 以后同名再导入是 v2，不会自动替换 v1：要在详情里点“设为生效”。

交付时要提前告知：第 2 期容器无外网、不能装包，脚本依赖要随包带或用预装的。

Agent 是怎么发现并用上一个技能的

选一个技能，看三层披露：目录 → 正文 → 资源文件。切换右侧“已启用”开关，看目录怎么变；切换“第 1 期 / 第 2 期”，看脚本怎么用。这里的工具输出文字是示意，工具名和格式是提案。

预检规则

“错误”阻断确认，“提示”不阻断。每条都带文件路径。

错误代码条件

核心流程伪代码

// 预检（提案）：纯函数，输入文件列表，输出规范化包 + issues
func Precheck(in []InFile, existing SkillLookup) Result {
  files, ign := normalize(in)          // 去 __MACOSX/.DS_Store；去唯一外层目录；路径统一为 "/"；GBK 文件名回退
  for f in files { checkPath(f); checkSymlink(f); checkSize(f); checkRatio(f) }   // PATH_ESCAPE/SYMLINK/FILE_TOO_LARGE/ZIP_BOMB
  checkCount(files); checkDup(files)
  md := findSkillMD(files)             // NO_SKILL_MD / MULTI_SKILL_MD
  fm, body, err := parseFrontmatter(md) // goccy/go-yaml；冒号未加引号时先兜底再重试 → BAD_YAML
  validate(fm.name, fm.description)    // BAD_NAME / BAD_DESCRIPTION
  if isBuiltin(fm.name)        { err(BUILTIN_NAME) }
  if sk := existing.Get(fm.name); sk != nil && sk.HasSHA(sha256(pack(files))) { err(SAME_AS_VERSION) }
  warn(unsupportedFields(fm), missingRefs(body, files), hasScripts(files), longBody(body))
  return Result{ pack: pack(files), manifest: classify(files), issues, plan: planFor(fm.name) }
}

// skill_read（提案）：file 为空读正文，否则读清单里的文本文件
func SkillRead(run Run, name, file string) ToolOut {
  v := run.PinnedVersion(name)         // 一次运行里首次读取时固定 name@vN
  if file == "" { return wrap(v.Body) + resourceList(v.Files, 100) }
  e := v.Files.Find(file)              // 只认清单里的路径
  if e == nil   { return fail("没有这个文件，可用文件：...") }
  if !e.Text    { return out("二进制文件，大小 N，无法读取") }
  return out(truncate(readFromPackage(v, file), 64<<10))   // 单次最多 64 KB（示意）
}

阶段与验收

第 1 期：管理 + 资源读取提案
  • 标准 zip（含脚本、references、二进制资源）一次导入成功，文件类型标对。
  • 每一种错误代码都能用构造包复现，且指到文件。
  • 多行 YAML 能解析；allowed-tools 标“未支持”。
  • 停用时目录 / 搜索 / @ 都看不到；启用后新运行才出现。
  • 同名导入是新版本，不自动生效；设为生效 / 回滚可用；运行中读旧版本。
  • 内置 5 个只读；admin 与 super_admin 都能操作，普通用户 403；写操作有审计。
第 2 期：脚本执行提案选型已确认Spike 待验证
  • 容器：无外网、不可装包、预装 Python / Bash / Node。
  • skill_run 能运行包内脚本并带回输出。
  • 超时、超内存、输出过大分别给明确错误。
  • 容器看不到其他技能与系统文件；管理页能看到最近执行结果。
  • 运行时：生产强制 gVisor（runsc），开发可显式降级；预装 Python 3 + PyYAML、Node 22、bash + jq；没有产物通道，脚本产出不能落画布。
  • 开工前先做 M0 Spike：在 Linux + runsc 上验证“runner 主动连接 backend 的 Unix socket”。详见《第 2 期执行选型调研》。

已确认的决定

  1. 脚本用独立容器多语言执行：和 Claude、OpenAI 的 hosted skills 行为对齐；用户明确选了最重的一档。因此拆成两期。
  2. 所有管理员都能导入，导入后先停用再人工启用：不限制谁能导，靠把关流程补偿信任。
  3. 不可变版本 + 可回滚：与协议插件、Claude、OpenAI 一致。
  4. 元数据入库，规范化 zip 存对象存储：可装下图片等资源，上限参考 OpenAI（50 MB / 500 文件 / 25 MB）。
  5. 导入形式：zip、拖入文件夹、单个 SKILL.md；不做在线编辑（已搁置）。
  6. 字段宽松接收 + 分类提示：只强校验 name / description。
  7. 内置技能只读展示，同名导入被拒。
  8. 容器断网、不可装包、预装解释器：与 Claude API 默认一致；网络白名单已搁置。
  9. 第 2 期选型：生产强制 gVisor，开发可显式降级；预装“标准库 + 少量工具”；脚本产出文件不能落画布；预览与下载不进入审计；命名沿用。
  10. M0 用 Mac 上的 Colima + gVisor 验证；CI 新增第三个镜像；管理页“试运行”纳入第 2 期；限额先用示意值；第 2 期不拆 Agent。
  11. 目录进提示词 + 保留搜索：已启用 ≤ 30 个才放目录；按任务模式绑定已搁置。
  12. 新建“Agent”分组，列表 + 右侧详情抽屉。
  13. 导入预检用居中大对话框 + 左右分栏（变更：原为抽屉内两步向导）：要同时看识别结果、问题、文件树和预览。
  14. 导入入口 = 全页拖放 + “导入技能”按钮：两条路径落到同一个预检界面。
  15. 启用只有开关：不弹确认、不强制先看文件；风险靠默认停用、“含脚本”标签和文件预览提示。
  16. 含脚本技能的启用权限不收紧：第 2 期容器上线后，所有管理员仍可启用；信任靠默认停用、文件预览、审计和无网络容器。
  17. 跨片段技能版本不要求一致；不强制私有桶：详见架构设计文档的 ADR-6 与安全页。
  18. 拖放引用 react-dropzone 20.1.2：递归读文件夹和全页拖放；文件树手写，高亮和 Markdown 用已有依赖。
