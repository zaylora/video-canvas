# 画布实时协作需求追踪矩阵

产品范围以[协作产品方案](产品方案.md)、[共享方案](../共享画布/一期方案.md)、[共享体验方案](../共享画布/体验完善方案.md)、[导入导出设计](../画布导入导出/画布导入导出.md)和[CLI 规格](01-CLI协作规格.md)为准。现有 AC 编号继续使用，表中用所属规格区分同名编号。版本状态见 [V1 实现状态](V1-实现状态.md)。

本表关联代码、历史证据和候选版本的关闭条件。历史证据保留原来的环境和范围。候选验收记录应包含代码或构建标识、环境、操作步骤、可观察结果与证据位置。标为待验证的发布阻断项需要实测结果；修复项先复现、再修复并复跑对应验收。

## 发布阻断项

| 阻断项 | 当前证据 | 关闭条件 |
| --- | --- | --- |
| 混合容量和性能 | [混载验证记录](01-CLI协作规格.md#验证记录)覆盖 4 CLI + 4 Chrome 30 分钟、分组图谱、断网和提交响应丢失。远端网页渲染 P95 为 263 ms。十会话协议矩阵四布局两种竞争模式连续两轮通过，最高 P95 为 266 ms；检查点数据库内聚合、活跃记录顺序索引和通知到达即回放已落地。 | 补服务重启、队列恢复、慢连接和正式候选环境的 WAL 指标。 |
| 真实供应商与创作任务 | 夹具验证了部分计费、权限、生成、拆镜、音色和媒体行为。 | 实际测试供应商完成生成、音色和人声分离，核对计费明细、产物和成员授权；完成小镜端到端。 |
| 人工端验收 | 已有本地浏览器及部分输入法记录。 | 补齐其他目标平台的原生输入法、触控、共享同版逐节点对照、三平台 CLI 与真实媒体流程。 |
| 发布候选与恢复演练 | 四端检查已通过，迁移结构检查已通过。 | 当前环境尚未完成同一候选版本的数据备份恢复、服务回滚和已受理任务继续对账。 |
