# 营销工作室一期 · 前后端接口契约

> 前后端并行开发的唯一约定。设计依据见同目录 `营销工作室.md`（v2，§6–§8、§11）与两份原型 `营销工作室原型.html`、`环节技能-后台原型.html`。
> 改契约必须两边同时知道：在本文件末尾「变更记录」追加一行，不要静默改。

## 1. 通用约定

- 所有接口在 `/api/v1` 已登录分组（后台接口在管理员分组 `/api/v1/admin`），响应外壳沿用 `pkg/response`（`{code, msg, data}`），按 `user_id` 隔离；别人的资源一律按「不存在」处理。
- 营销项目、轮次、脚本、环节运行、试跑的 ID：`idcodec.ID`，JSON 里是**十六进制字符串**（同短剧）。
- 素材 ID：数字（`uploadAsset` 返回的 `id`，与 `assets.id` 一致）。
- 模型：用 `GET /models` 返回项的 `key`（字符串）。`text_model` 空串 = 后端按能力自动选（§2.4）。
- 字段 snake_case；前端在 `web/src/api/marketing/index.ts` 里 map 成 camelCase。时间是 ISO 字符串。
- 列表分页沿用 `OKPage`：`{list, total, page, page_size}`。

| 名称 | 取值 |
| --- | --- |
| `platform` | `douyin` `xhs` `tmall` `tiktok` `amazon` `reels` `generic` |
| `angle` | `pain` `feature` `lifestyle` `compare` `unbox` `mood`；跟拍脚本的 angle 固定为 `follow` |
| `language` | `zh` `en` |

| 脚本 `status` | `draft` `rewriting`（重写跟拍中） `rendering` `done` `failed` |
| 脚本 `kind` | `follow` `create` |
| `product_role` | `none` `dynamic` `hero_real` `package_text` |
| flag `type` | `forbidden`（广告法极限词） `claim`（背书无依据） `brand`（第三方品牌） |
| 方法 `source` | `builtin` `skill` |

## 6. 错误码

68001 营销项目不存在 · 68002 商品图数量不对或素材无效 · 68003 没有可用的看图文本模型 · 68004 视频模型不可用或不支持所需参考 · 68005 参考视频超出模型限制 · 68006 脚本正在出片 / 重写，不能修改 · 68007 这个项目正在写脚本 · 68008 提示词超出模型上限 · 68009 内容已在别处修改 · 68010 有进行中的任务，不能删除 · 68011 发到画布失败 · 68012 环节不存在 · 68013 生效前需要该候选试跑通过 · 68014 技能或版本不可用 · 68015 拆解内容不合法 · 68016 没有可用的拆解，不能重写跟拍 · 68017 该环节已有试跑在进行 · 68018 转写提示词失败。积分不足复用 40001。

## 变更记录

- 2026-11-11：初版。
- 2026-11-11（前端完成后澄清，后端 2 照此实现）：
  1. `flags[].shot` 是**从 0 起的镜头下标**（契约 §2.4 示例的 3 即第 4 个镜头）。
  2. `StepDetail.history[].from` / `to` 是对象 `{ source, skill_name, skill_title, version }`（内置时只有 `source: "builtin"`）。
  3. 后台环节技能的写操作（发起试跑、设为生效）权限照现有技能管理的写权限（`SkillService.writable` 那套）；前端不按角色禁用，靠后端报错。
  4. 失败的轮次一定带至少一条 `failed` 的环节运行记录；对事实卡环节调用 `POST /marketing-step-runs/:id/retry` 会**连同依赖它的后续环节一起重跑**（等于整轮重试），不另加整轮重试接口。
  5. `TaskLite.id` 是 `GenerationTaskView.id`（数字），`task_ref` 是十六进制任务编号；`progress` 是 0–100 或 null。
  6. 试跑的文本模型清单用 `GET /models?kind=agent`（管理员同样能读），按 `vision` / `video` 能力过滤。
  7. `POST /marketing/quote` 的 `steps` 按本次设置**列出全部会跑的环节**：无参考 `facts`、`create`；有参考再加 `reverse`、`follow`；项目已有事实卡时 `facts` 的 credits 为 0 但仍列出。「重写跟拍版」的积分取其中 `follow`。
  8. 新一轮不传 `model_asset_id` 时**沿用项目已有的模特图**；传了就替换项目的模特图。
  9. 参考视频时长上限：模型能力没有时长字段，后端默认 **15 秒**（常量，Seedance 2.x 上限），用 `videoframe.Duration` 校验，超出 68005；`GET /marketing/options` 增加 `ref_video_max_seconds: 15` 供前端提示。
