## 1. 设计摘要

- **问题**：电商卖家给商品做投放视频，今天只能自己写 Seedance 提示词；好的带货片有固定套路（钩子、痛点、卖点证明、促单）和硬约束（外观不能变、不能编造卖点），普通用户写不出来，也难以一次做多个角度去测。复刻爆款更难：把参考片拆准、再换成自己的商品，任何一步丢了动作或细节，成片就不像。
- **目标**：
  1. 上传商品图、写一句话，拿到 2–4 条**创意角度不同**、外观一致、可直接投放的 10–15 秒有声短视频。
  2. 传一条爆款参考片，额外拿到一条**结构不变、只换成自己商品**的跟拍版。
  3. 中间结果（参考拆解、脚本）看得见、改得动；改脚本不再花钱；成片可单条重出或发到画布精修。
  4. 某个环节效果不好时，管理员**只换这个环节的技能**，试跑通过即生效，不改代码、不改格式。
- **推荐结论**：
  - **生成框 + 脚本确认 + 一次出整条**（v1 已确认）。
  - **四个文本环节**：①商品事实卡 ②拆解参考片 ③跟拍改写 ④创意脚本。①②并行，③④并行；③和④输出同一种脚本结构，后面的提示词拼装共用。
  - **三层架构**：协议层（固定：输入、本步职责、输出 Schema、校验、重试）/ 方法层（可替换：内置方法或绑定的技能某个版本）/ 格式化层（固定：结构化脚本 → 各视频模型提示词，纯代码）。技能只能影响「怎么想、怎么写」，影响不了输出结构。
  - **后台「环节技能」页**：每个环节一个绑定；换技能前先用内置样例试跑，格式校验通过才能「设为生效」；绑定钉死技能版本，每轮记录用的是哪个方法。
  - **爆款复刻**照 daihuo-fanpai（MIT）的做法：用能看视频（含声音）的模型拆整段参考片，分镜字段写到「动作发力过程、商品怎么出现、关键颜色、前 3 秒、为什么火」；拆解可看可改，改了可重写跟拍版；跟拍只换商品、卖点、数字，去掉第三方品牌，原片背书在事实卡里找不到就标红。
  - hypit 是程序化剪辑路线，一期不接（§4.3）。

- 没有营销相关表、job、提示词。

## 3. 用户与场景

- **用户**：国内电商卖家（抖音、小红书、淘宝天猫）和跨境卖家（TikTok Shop、亚马逊、Instagram）。不会写提示词。上新、投放测素材时集中使用。
- **主任务**：「我有一个商品，给我几条能直接发的带货视频」；「这条爆款很火，用我的商品拍一条一样的」。
- **次要用户**：管理员（运营），负责给各环节挑技能、换技能、看试跑结果。
- **成功指标（提案）**：上传到看到脚本 ≤ 60 秒（P90，无参考片）/ ≤ 90 秒（有参考片）；一轮中至少一条被下载或发到画布的比例 ≥ 50%；换技能后首轮格式校验失败率 ≤ 2%。

## 5. 设计原则

1. **商品外观是红线**：商品图是外观唯一依据，提示词每次都写「禁止改动」，镜头默认少动、商品不出画。
2. **只说商品有的**：卖点只来自用户描述和图片；原片里的促销、背书在事实卡里找不到就标红。
3. **方法可换，格式不变**：技能只决定怎么想、怎么写；输入、输出结构、校验、提示词拼装归系统，换技能不需要任何适配。
4. **一步看得见，其余自动**：用户只在「拆解 / 脚本」处停下；其余环节自动推进、可单独重试。
5. **复用优先**：入口、生成框子组件、积分、任务、视频理解、画布写入都照现有先例。

### 6.3 主流程（四个环节）

```
          ┌─ ① 商品事实卡（看商品图）──────┐
写脚本 ──┤                                ├─→ ③ 跟拍改写（有参考时，1 份）─┐
          └─ ② 拆解参考片（有参考时）──────┘                               ├─→ 用户看 / 改 → 出片
                                            ④ 创意脚本（N 份，按角度）────┘
```

1. **建轮次**（`scripting`），按各环节预估冻结积分，入队 River `marketing_round`。
2. **第一层并行**：① 商品事实卡（项目已有事实卡时跳过，原样复用）；② 拆解参考片（有参考视频时）。
3. **第二层并行**：③ 跟拍改写（需要 ①②，1 份）；④ 创意脚本（需要 ①；有 ② 时只借节奏；份数 = 改编数或角度数）。
4. 每个环节按 §6.9 运行：拼提示词 → 调用 → 解码 → 校验 → 不过带原因重写一次 → 落库 → 按实际用量结算。环节之间互不拖累（§7.1）。
5. 全部结束：轮次 `ready`（只要有一份脚本成功）或 `failed`（全部失败），WS 推 `marketing.round`。
6. **看与改**：拆解卡（§6.10）可改，改后可「按拆解重写跟拍版」，只重跑 ③；脚本卡可改旁白，即时保存、免费。
7. **出片**：按 §6.6 由格式化器拼提示词，以 `node_id = mkt:{脚本id}` 调现有生成任务（`op=omni`，图片 = 商品图 + 模特图，视频 = 参考视频；跟拍版和改编版都带参考视频，`generate_audio=true`）。

### 6.4 创意角度

角度是**协议的输入枚举**，不是技能。内置 6 个：`pain` 痛点-解决、`feature` 卖点拆解、`lifestyle` 生活方式种草、`compare` 前后对比（不点名竞品）、`unbox` 开箱体验、`mood` 质感大片；「自动」由模型按商品挑。v2 起技能不再出现在角度菜单里（§6.9）。

| --- | --- | --- | --- |

### 6.6 格式化层：视频提示词格式化器

格式化器是**纯代码**，按视频模型 `PromptFormat` 注册，输入「事实卡 + 脚本 + 轮次设置 + 素材清单」，输出提示词字符串。技能碰不到这一层；跟拍版和改编版共用。

```go
type VideoFormatter interface {
    Key() string                                    // seedance / h3 / generic
    Render(in FormatInput) (string, error)          // 超出模型提示词上限时按规则删减，仍超返回 68008
}
```

- `seedance`：分区块（YouMind 结构）：

```
[基本参数] {画幅}，{时长} 秒，有声，无字幕
[参考素材] @图片1…@图片{k}：{商品名}，外观的唯一依据，禁止重新设计、改色、改形、改 logo。
           @图片{k+1}：出镜人物的唯一依据，全片出镜的都是这位模特，脸、发型、肤色与之一致（如有）。
           @视频1：只参考节奏、构图与运镜，不照搬其中的人物外貌、商品、品牌与画面文字（如有）
[整体视觉] {平台写法要点}；{角度或「跟拍」}
[商品] {外观锚点逐条}
[分镜] 镜头1（0–3s）{景别}，{运镜}：{主体 + 动作（原样）}，{场景}。旁白：「…」
[音乐与配音] 旁白：{语言}，{音色}；配乐：{配乐}
[硬性约束] 商品外观与参考图一致；商品不出画；不加字幕：旁白只配音，除商品本身印刷的文字外画面不出现任何文字、字幕、花字或水印；
           出镜人物始终是 @图片{k+1} 的模特，不出现 @视频1 里的人物（有模特图时）；{禁用说法}；{关键颜色}
```

分镜里画面描述写的「模特图」会换成 @图片{k+1}，让模型对上具体是哪张图。成片一律不加字幕：模型生成的文字不稳定，字幕留给后期。

- `generic` / `h3`：同内容写成段落（**默认值**：H3 先用通用写法）。
- **待实测**：daihuo-fanpai 认为 Seedance 2.0「用镜头序号、不写秒数」效果更好；上线前用同一脚本 A/B 两种写法，再定 `seedance` 格式化器是否去掉秒数。因为是代码层，改动不影响任何技能。
- 镜头的「主体 + 动作」放在每镜开头（daihuo-fanpai：开头位置最值钱）。

### 6.7 发到画布

脚本卡「发到画布」：后端用 `canvasgraph` 新建画布（标题 = 商品名 · 角度 / 跟拍），写入素材节点（商品图、模特图、参考视频）、该脚本最新成片节点（如有）、每个镜头一个**未生成**的视频节点（提示词 = 该镜头单独格式化的稿，已从素材连线）。不自动生成。**待实现核对**：`canvasgraph` 能否在空画布一次写入节点与连线。

### 6.8 用户端界面规格（[营销工作室原型.html](营销工作室原型.html)）

> 2026-11-12：详情页的呈现与交互由 [界面改版.md](界面改版.md)（v2）重做：信息项全部保留，只改样式；新增原片 / 成片原位播放、镜头点击跳转与高亮、原片对比层、「再写一轮」胶囊。列表页与生成框不变。

沿用首页外壳（`home-theme` 令牌、侧栏 + 浮起圆角内容页、顶栏 `ChromePill`）。均为**提案**。

- **详情页**：左栏 260px 清透卡（返回、素材缩略、商品名 + 编辑、事实卡四段）；右侧轮次倒序；底部吸附生成框。

- **参考拆解卡**（有参考视频时，轮次头下方，默认折叠）：一行摘要（N 个镜头 · 时长 · 为什么火）+ 品牌 / 背书提示；展开后是镜头表（时间、景别 · 运镜、主体 + 动作可改、商品怎么出现下拉、台词可改、前 3 秒标记、关键颜色）；有改动时出现「按拆解重写跟拍版 ✦N」。
- **脚本卡**：左成片区（待出片 / 出片中环形进度 / 已出片可播放与切换第几条 / 失败原因）；右侧角度标签（跟拍版为「跟拍」，每镜显示「对应参考 镜头 n」）+ 状态 +「已修改」、标题、镜头列表（旁白可改，失焦或回车保存，问题旁白描红）；底部：配乐 · 音色、问题标签（禁用说法 / 背书无依据 / 第三方品牌）、方法小字（如「方法：daihuo-fanpai v2」）、「提示词」、「⋯」（下载、发到画布、恢复原稿）、「出片 / 重出 ✦N」。
- **环节失败**：失败的环节在对应位置显示原因 +「重试」，只重跑这个环节。
- **弹窗**：提示词预览、发到画布确认、事实卡编辑、删除确认、播放器。

### 6.9 环节协议层：技能与格式化分开（通用，营销先用）

#### 6.9.1 三层

| 层 | 内容 | 谁维护 | 能否被技能改变 |
| --- | --- | --- | --- |
| 协议层 | 环节 key、本步职责、输入变量、媒体需求（看图 / 看视频）、输出 JSON Schema、校验函数、重试规则、方法正文上限 | 代码 | 否 |
| 方法层 | 「怎么想、怎么写」：内置方法正文，或绑定的技能（钉死版本） | 管理员在后台绑定 | — |
| 格式化层 | 结构化输出 → 视频模型提示词（§6.6）；以及由 Schema 自动生成的「输出格式说明」 | 代码 | 否 |

换技能 = 改一条绑定。只要新技能产出的内容能通过同一份 Schema 和校验，下游（落库、界面、格式化器）完全不变。

#### 6.9.2 环节定义（新包 `backend/internal/stepkit`）

```go
type Step struct {
    Key        string            // "marketing.facts"
    Title      string            // 「商品事实卡」
    Duty       string            // 本步职责，1–3 句，固定
    Inputs     []Var             // 输入变量声明（名称、类型、说明）
    Media      MediaNeed         // None / Images(需 Vision) / Video(优先 Video，退回 Vision + 截帧)
    Schema     json.RawMessage   // 输出 JSON Schema，固定
    Validate   func(out json.RawMessage, in Input) (Flags, error) // error = 硬错误（重写/失败）；Flags = 软问题（落库后在界面标红）
    Builtin    string            // 内置方法正文（可替换的那一块）
    MethodMax  int               // 方法正文上限，默认 16000 字
    Samples    []Sample          // 后台试跑样例
}
func Run(ctx, step Step, method Method, model Snapshot, in Input) (Result, error) // 拼提示词→调用→解码→校验→重写一次
```

营销注册四个环节：`marketing.facts`、`marketing.reverse`、`marketing.follow`、`marketing.create`。短剧以后迁移时注册 `drama.plan` 等（本期不做）。

#### 6.9.3 提示词拼接顺序

```
## 本步职责        ← 协议
## 输入            ← 协议（变量 JSON；图片 / 视频作为多模态 Parts 附在同一条消息）
## 方法            ← 方法层：内置正文，或
                     【写作方法：{技能标题} v{版本}】
                     以下是本步骤必须遵循的方法与标准，按它决定取舍、粒度与写法。输出仍只能是下方 JSON 结构；
                     方法与结构冲突时以结构为准，方法里要求的其他输出格式一律不输出。
                     <skill>{SKILL.md 正文 + 正文引用到的文本文件，按出现顺序，截断到 16,000 字}</skill>
## 输出格式        ← 协议（由 Schema 生成的字段说明 + Schema 原文）
## 校验规则        ← 协议
```

协议块放在方法之后，保证结构要求最后出现。技能里的脚本、工具调用不执行；`has_scripts = true` 的技能在后台标「仅用正文」。

#### 6.9.4 绑定、版本与兜底

- 每个环节一条绑定：`builtin`，或 `skill`（技能名 + 版本号）。**钉死版本**：技能发新版本后绑定不跟随，后台提示「有新版本 vN」，试跑通过后才能切。
- **生效条件**：同一候选（环节 + 来源 + 技能版本）在 24 小时内有一次通过的试跑（§6.9.5），否则拒绝（68013）。
- **兜底**：绑定的技能被停用、版本被删时，环节自动退回内置方法，后台页顶部提示、写审计；不会让用户端失败。
- **快照**：每轮每个环节的运行记录里存方法快照（来源、技能名、版本、正文 sha256），界面脚本卡显示「方法：…」，便于追查哪个技能出的问题。
- 绑定的修改、试跑、生效写操作审计（照技能管理先例）。

#### 6.9.5 试跑

- 样例随代码发布（`stepkit` 注册时带 `Samples`，素材打包进二进制）：营销三组——「晨雾香水 · 抖音 · 无参考」「便携榨汁杯 · TikTok · 英文」「护手霜 · 抖音 · 带 10 秒参考片」。依赖上游环节的样例自带上游输出（如 follow 的样例带一份拆解和事实卡），保证只测本环节。
- 一次试跑可同时跑「候选」和「当前绑定」，并排对比：格式校验（通过 / 硬错误列表）、软问题、耗时、输入输出 token、积分、输出预览。
- 只有格式校验通过才能「设为生效」；软问题只提示。
- 试跑走 River（可能超过 50 秒），后台轮询结果；费用从操作的管理员账户扣，流水关联 `step_trial_id`。

#### 6.9.6 与短剧现状的关系

短剧的五段模板和「写作方法」块就是这套协议的前身。本期只新建 `stepkit` 并让营销使用；短剧以后迁移时：把四个环节注册为 Step、把开拍设置里的「技能」选项改为读绑定或保留用户可选（届时再定）、`agent_skills.drama_steps` 废弃。迁移前两边并存，互不影响。

### 6.10 爆款复刻

#### 6.10.1 拆解参考片（`marketing.reverse`）

- **输入**：参考视频、时长、镜头切点（ffmpeg 场景检测，新增 `videoframe.Cuts`；漏切比过切安全）。
- **看视频方式**：文本模型（或第一个可用的）`Video=true` 时整段内联给模型（≤20MB，超出先转码压缩；仍超退回截帧）；否则退回 `Vision` + 截帧：切点处各 1 帧 + 每秒 2 帧，上限 32 帧，此时没有声音，轮次标警告「拆解未包含声音，台词按画面推断」。
- **输出 Schema**（字段改写自 daihuo-fanpai `shotlist.json`，MIT）：

```json
{
  "overall": { "style": "", "narrative_arc": "", "why_viral": "", "transcript": "", "category": "" },
  "shots": [{
    "id": 1, "start": 0, "end": 2.5, "is_opening_3s": true,
    "shot_size": "特写", "camera": "手持推近",
    "subject": "", "action": "主体 + 动作，写到发力过程，不写结果",
    "scene": "", "lighting": "", "person": "",
    "product_in_frame": "商品如何出现 + 占画面比例",
    "product_role": "none | dynamic | hero_real | package_text",
    "dialogue": "", "onscreen_text": "", "key_colors": ["橙色液体"]
  }],
  "brands": ["画面或台词里出现的第三方品牌 / IP"],
  "claims": ["促销、销量、权威背书类话术原文"]
}
```

- **校验**：镜头首尾相接、覆盖时长（容差 0.5 秒）；前 3 秒的镜头必须标 `is_opening_3s`；`action` 非空且不只是名词；镜头数 / 时长比合理（平均每镜 ≥ 0.4 秒）；`product_role` 取值合法。
- **可看可改**：拆解存进轮次（`reverse` jsonb + `reverse_revision`），用户可改 `action`、`product_role`、`dialogue`、`key_colors`；改动按同一份 Schema 校验（不合法 68015）。改后出现「按拆解重写跟拍版」，只重跑 ③，按文本模型计费。

#### 6.10.2 跟拍改写（`marketing.follow`）

- **输入**：拆解（含用户修改）、事实卡、平台、语言、成片时长、素材清单。
- **输出**：与创意脚本相同的脚本结构，外加 `follow_map: [{ref_shot, shot}]`。
- **规则**（改写自 daihuo-fanpai B 模式，内置方法正文）：镜头结构、节奏、钩子不动，只换商品、卖点、数字；`action` 原样带入，只把原片商品替换成我们的商品；`product_role = hero_real / package_text` 的镜头注明必须以商品图为准；原片第三方品牌 / IP 一律去掉；人物只用模特图或重新描述，不沿用原片人物外貌；参考片比成片长时按比例压缩、短时按比例拉伸。
- **校验**：硬错误——脚本结构不合法、`follow_map` 没覆盖全部参考镜头；软问题（写入 `flags`）——旁白或画面出现 `brands` 里的品牌、出现 `claims` 里且事实卡没有依据的背书、国内平台极限词。

#### 6.10.3 创意脚本（`marketing.create`）

输入事实卡、平台、语言、时长、角度列表、可选拆解（只借节奏和前 3 秒钩子手法）；输出 `scripts[]`。校验同 v1：份数 = 角度数、角度不重复、镜头 2–6 个且首尾相接、旁白长度（中文 ≤ 时长 × 4.5 字，英文 ≤ 时长 × 2.6 词，**默认值**待校准）、语言一致、极限词。

#### 6.10.4 商品事实卡（`marketing.facts`）

输入商品图、描述、平台、语言；输出 `{name, category, anchors[], selling_points[{text, proof, source: description|image}], prohibited[], audience, cta}`。只写图里看得见、描述里说过的；项目已有事实卡时整个环节跳过。

### 6.11 后台「环节技能」页（[环节技能-后台原型.html](环节技能-后台原型.html)）

- **入口**：后台「AI 配置」组，「技能」之后，`/admin/agent/steps`。
- **列表**：按工作室分组。「营销工作室」四行：环节名、当前方法（内置 / 技能名 vN，有新版本时带角标）、最近一次试跑（通过 / 失败 · 时间）、近 7 天失败率。「短剧工作室」四行灰显「待迁移」。下方「视频提示词格式化器」只读三行（seedance / h3 / 通用，标「代码维护」）。页顶在有环节被自动退回内置时显示提示条。
- **详情抽屉**，三个标签：
  - **协议**（只读）：本步职责、输入变量表、媒体需求、输出 Schema（可折叠代码块）、校验规则。
  - **方法**：当前绑定 + 绑定历史（谁、何时、从什么换成什么，可「恢复」，恢复也须试跑）；候选下拉：内置方法 + 已启用的导入技能（每个技能可选版本；`has_scripts` 标「仅用正文」；超过 1.6 万字标「会截断」）。
  - **试跑**：选样例、选文本模型、勾选「同时跑当前绑定对比」→ 运行 → 两列结果：格式校验、软问题、耗时、token、积分、输出预览。候选通过时「设为生效」可点。
- 不加操作说明小字；空状态与错误照后台现有组件。

## 7. 状态与异常

### 7.1 环节失败不互相拖累

| 失败环节 | 结果 | 界面 |
| --- | --- | --- |
| ① 事实卡 | ③④无法进行，轮次 `failed`，全额解冻 | 轮次红色行 + 原因 +「重试」 |
| ② 拆解 | ③ 跳过；④ 照常（不借节奏） | 拆解卡位置显示失败原因 +「重试拆解」；跟拍卡不出现 |
| ③ 跟拍 | 只这一份失败 | 跟拍卡显示原因 +「重试」 |
| ④ 创意 | 这几份失败 | 对应卡显示原因 +「重试」 |
| 截帧不可用且模型不能看视频 | ② 失败（原因「服务器无法读取参考视频」） | 同 ② |

「重试」只重跑该环节，用该轮快照里的设置，方法用**当前绑定**（快照记录新方法）。

### 7.2 状态迁移

| 对象 | 状态 | 迁移 |
| --- | --- | --- |
| 轮次 | `scripting` → `ready` / `failed` / `canceled` | 所有环节结束：有成功脚本 `ready`，否则 `failed`；取消时停止未完成环节、解冻 |
| 环节运行 `marketing_step_runs` | `queued` → `running` → `succeeded` / `failed` / `skipped` / `canceled` | 依赖失败则 `skipped`；重试新建一条运行记录 |
| 脚本 | `draft` → `rendering` → `done` / `failed` → `rendering`… | 同 v1；`rendering` 时不能改、不能重写跟拍 |

### 7.3 界面状态

| 场景 | 表现 |
| --- | --- |
| 没有项目 | 生成框 +「还没有营销片」 |
| 写脚本中 | 环节进度条 + 骨架卡 +「取消」 |
| 有问题的脚本 | 旁白描红 + 问题标签；改掉后才能出片（`PUT` 后端重扫） |
| 拆解被改过 | 拆解卡出现「按拆解重写跟拍版」；跟拍版出片中时禁用 |
| 编辑冲突 | 68009：提示并载入最新版 |
| 余额不足 | 发送 / 出片 / 重写禁用；服务端兜底 40001 |
| 删除项目 | 有进行中任务时拒绝（68010） |
| 后台：候选未试跑或未通过 | 「设为生效」禁用 |
| 后台：绑定的技能被停用 | 页顶提示条；该环节显示「已退回内置」 |

### 7.4 撤销与恢复

脚本保存 `original`，可「恢复原稿」；拆解保存模型原稿，可「恢复原稿」；成片历史全部保留；后台绑定可「恢复」到历史某项（须试跑）。

- 改旁白后「提示词」立即反映，积分不变。
- 后台把「创意脚本」从内置换成某技能：未试跑时「设为生效」禁用；试跑通过后可生效；下一轮脚本卡显示新方法；停用该技能后自动退回内置并出现提示。
- 换一个只会输出 Markdown 的技能做试跑，结果显示「格式校验失败」及原因，不能生效。
- 拆解环节失败时，创意脚本照常产出，跟拍卡不出现，「重试拆解」可用。
- `bash scripts/check.sh` 全过。
