## 要做的

1. **包 `backend/internal/stepkit/`**（不依赖营销）：
   - `Step` 结构（Key、Title、Studio、Duty、Inputs、Media: none/images/video、Schema、Validate 返回 `(flags, err)`、Builtin 方法正文、MethodMax 默认 16000、Samples）与注册表 `Register(step)` / `Get(key)` / `List()`。
   - `Method`：`builtin` 或 `skill`（名、标题、版本、正文、sha256）；`ResolveMethod(binding)`：技能停用 / 版本不存在时退回内置并标 `fallback=true`。
   - 提示词拼接：`## 本步职责` → `## 输入`（变量 JSON） → `## 方法`（内置正文，或「写作方法」块：照短剧 resources.go 的包裹文字，正文 + 引用文本文件，截断到 MethodMax） → `## 输出格式`（由 Schema 生成字段说明 + Schema 原文） → `## 校验规则`。技能脚本不执行。
   - `Run(ctx, step, method, model, input)`：附多模态 Parts（图片 / 视频；视频按 `Capabilities.Video` 判断，具体降级由调用方准备好输入）→ 调用 → 解码 JSON → `Validate`；硬错误带原因重写一次；返回输出、flags、用量、尝试次数、方法快照。调用失败与校验失败要区分。
   - 绑定读取：从 `step_bindings` 取，没有记录时 = 内置。
2. **迁移 `0034_step_bindings.sql`**：`step_bindings`、`step_binding_history`、`step_trials`（字段见设计 §8.1）；`credit_ledger` 加 `step_trial_id`。先确认迁移最新编号（当前 0033）。
3. **试跑**：River job `step_trial`（新 queue 或复用现有调度方式，照 drama 写法）；`POST /admin/steps/:key/trials` 建 1–2 条试跑（compare 时第二条是当前生效方法，`compare_of` 互指）并入队；同一环节已有进行中的试跑返回 68017；按模型预估冻结操作管理员积分，结束按用量结算，流水关联 `step_trial_id`。样例由 Step.Samples 提供（`Sample{Key, Name, NeedsRef, Build(ctx) (Input, error)}`），本任务用一个测试用 Step 验证即可。
4. **生效**：`PUT /admin/steps/:key/binding` 要求 `trial_id` 指向同一候选、`passed=true`、24 小时内，否则 68013；技能或版本不可用 68014；写 `step_binding_history` 与审计。
5. **后台接口**：`GET /admin/steps`、`GET /admin/steps/:key`（含 history、candidates：已导入技能及其版本、has_scripts、正文字数、enabled）、`GET /admin/step-trials/:id`。`fail_rate_7d` 由调用方提供统计函数（营销以后接 `marketing_step_runs`），本任务给接口留口子、没有数据时返回 0。
6. **错误码** 68012、68013、68014、68017 加到 `errcode.go`（68 段新开，照现有段的写法）。
7. 路由、依赖装配（`initialize`）、`backend/README.md` 接口表补上。
