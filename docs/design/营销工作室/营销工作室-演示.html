营销工作室

上传商品图，拿到几条不同角度的带货视频；传一条爆款，再多一条跟拍版

首页侧栏新增「营销工作室」。系统按四个文本环节写出脚本给你看、让你改，确认后视频模型一次出整条有声成片。每个环节的「方法」可以由管理员在后台换成别的技能，输出格式和后面的提示词拼装都不变。一期只做营销短视频，不做数字人口播、主图和文案单品。

阅读说明。本页对应 营销工作室.md（v2，准绳）。项目现状来自 2026-11-11 代码扫描；即梦、竞品、GitHub 项目来自官方页面与仓库文档；原型里的数据、积分、耗时都是示意；设计尚未实现。

卖家拿一条护手霜爆款，复刻成自己的香水，会发生什么

一轮完整的复刻，以及一个要提前说清的边界。

  1. 上传香水图 + 10 秒护手霜爆款，平台抖音角度变成「跟拍 + 改编 ×1」
  2. 事实卡和拆解同时跑拆解出 4 个镜头：手背干纹钩子 → 挤膏体慢动作 → 搓手 → 举包装说「全网销量第一」；标出第三方品牌和背书
  3. 跟拍版和改编版同时写跟拍每镜对应参考镜头，动作原样带入、把护手霜换成香水
  4. 跟拍版第 4 镜「全网销量第一」被标红事实卡里没有这条依据，也是极限词；改掉才能出片
  5. 发现拆解漏了一个动作，改拆解 → 按拆解重写跟拍版只重跑跟拍环节，只扣一次文本费用
  6. 两份一起出片出片时参考视频也交给视频模型借节奏
边界：复刻的是结构和节奏，不是原片的人和品牌。
  • 原片品牌一律去掉，人物不沿用原片外貌。
  • 原片的促销、背书在事实卡里找不到就标红，系统不替你编。
  • 参考片要在视频模型上限内（Seedance 2.x 为 15 秒）。
  • 拆解准不准取决于看视频模型，需要用真实片子校准。

上线时告诉用户：复刻有版权风险的参考片由用户负责；成片没有字幕。

换技能，不换格式

每个环节拆成三层：协议层规定输入、输出结构和校验；方法层决定怎么想、怎么写，可以是内置方法或某个技能的某个版本；格式化层把结构化脚本拼成各视频模型的提示词。管理员只在方法层换技能，试跑通过就生效，下游一行代码都不用改。这套协议是通用层，营销先用，短剧以后迁移。

三层分工

技能碰不到协议层和格式化层，所以换技能不需要「重新适配格式」。

协议层

固定 · 代码
  • 本步职责（1–3 句）
  • 输入变量 + 媒体需求（看图 / 看视频）
  • 输出 JSON Schema
  • 校验：硬错误重写一次；软问题落库标红

方法层

可替换 · 后台绑定
  • 内置方法正文，或技能 vN（钉死版本）
  • 以「写作方法」块注入，冲突时以结构为准
  • 技能里的脚本不执行；超 1.6 万字截断
  • 换之前必须用样例试跑通过

格式化层

固定 · 代码
  • 按视频模型 prompt_format 注册
  • seedance 分区块 / 通用段落（h3 暂用通用）
  • 跟拍版与改编版共用
  • 改写法要改代码发版
短剧开拍设置已有「固定协议 + 可替换正文」的五段模板，这里把它抽成通用的 stepkit，并把「谁选技能」从用户挪到后台，加上试跑和版本钉死。

提示词怎么拼

协议块放在方法之后，保证结构要求最后出现。

## 本步职责        ← 协议
## 输入            ← 协议（变量 JSON；图片 / 视频作为多模态附件）
## 方法            ← 方法层：内置正文，或
                     【写作方法：{技能标题} v{版本}】
                     以下是本步骤必须遵循的方法与标准……输出仍只能是下方 JSON 结构；
                     方法与结构冲突时以结构为准，方法里要求的其他输出格式一律不输出。
                     <skill>{SKILL.md 正文 + 引用的文本文件，截断到 16,000 字}</skill>
## 输出格式        ← 协议（由 Schema 生成的字段说明 + Schema）
## 校验规则        ← 协议

管理员把「创意脚本」换成另一个技能时，会发生什么

以及换了一个不守格式的技能会怎样。

  1. 后台「AI 配置 / 环节技能」→ 创意脚本 → 方法选候选技能和版本；带脚本的技能标「仅用正文」，超长标「会截断」
  2. 试跑：选样例和文本模型，勾「同时跑当前绑定」两列并排：格式校验、软问题、耗时、token、积分、输出预览
  3. 候选通过 → 设为生效之后新开始的环节都用它；进行中的不受影响；写入绑定历史和审计
  4. 用户下一轮的脚本卡显示新方法出问题时能追到是哪个技能、哪个版本
边界：格式由系统兜底，质量要靠试跑和对比。
  • 只会输出 Markdown 的技能试跑会「格式校验失败」，不能生效（原型里的 old-ad-writer）。
  • 技能发新版本不会自动跟随，要再试跑。
  • 技能被停用或版本被删，环节自动退回内置方法，页顶提示。
  • 格式校验只保证结构，不保证写得好，需要看预览、对比当前绑定。

格式化层：脚本怎样变成视频提示词

左边选创意角度，改平台、视频模型写法、时长，右边实时看到结构化脚本和格式化器拼出的提示词。这一层是纯代码、确定性的，和技能无关：换了写脚本的技能，只要脚本结构不变，这里拼出来的格式就不变。脚本内容是示意，拼装规则与 Markdown §6.6 一致。

// stepkit.Run（提案）
func Run(ctx, step, method, model, in):
  if method.skill != nil and (skill disabled or version deleted): method = Builtin(step); markFallback(step)
  prompt := Section("本步职责", step.Duty) + Section("输入", in.Vars) + MethodBlock(method, 16000)
          + Section("输出格式", DescribeSchema(step.Schema)) + Section("校验规则", step.RuleText)
  for attempt in 1..2:
    out := llm.Stream(model, Message{Parts: text(prompt) + in.Media})
    flags, err := Decode(out) then step.Validate(out, in)
    if err == nil: return Result{out, flags, usage, method.Snapshot()}
    prompt = WithFeedback(prompt, err)
  return Failed(err)
