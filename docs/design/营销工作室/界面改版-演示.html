核心交互：文字和画面联动

凡是写了时间的镜头，点一下就能看到那一段。

读拆解第 2 镜「蹲下放篮，抽出一瓶推向镜头」
点这一行左上原片跳到 3.2s 开始播
看脚本卡第 2 镜点镜头 → 成片跳到 2.5s
点「参考 2」对比层打开，两边同时从这一镜播
设计：用户认可分析内容，痛点是「读到了却看不到」。所以不删文字，而是让每段文字都能一键对上画面——这是剪辑软件里「转录稿 ↔ 时间线」的通用做法。
例外：点在输入框、下拉、标签里不跳转（避免改字时画面乱跳）；原片地址失效时只高亮不跳转，对比入口禁用并写原因；成片还没出时，「参考 n」改为滚动到拆解卡的对应镜头并让原片跳过去。

用户想检查「跟拍版第 2 镜拍得像不像」时，会发生什么

不开任何弹窗也能完成大部分检查。

  1. 在跟拍版脚本卡点第 2 镜成片跳到这一镜开始播放，这一镜左侧出现紫色竖条
  2. 点这一镜的「参考 2」对比层打开，原片和成片同时从这一镜播放
  3. 发现原片动作拆得不准，直接改左侧「主体 + 动作」失焦保存；拆解卡和对比层底部都出现「按拆解重写跟拍版 ✦N」
  4. 点重写跟拍卡进入「重写中」，写完回到待出片，用户再点出片
边界：对比只能做到镜头级对齐
  • 映射靠脚本里的镜头时间；模型实际节奏偏差大时只能「大致同一段」。未验证
  • 改编版不照拆解写，对比时按时长比例对齐，拆解只读。
  • 两边不同时出声。跟拍版出片中不能重写。

验收时用 3 条真实 Seedance 跟拍成片人工核对对齐效果。

镜头联动 useShotSync

// 每张卡一个（提案）
function useShotSync(shots) {
  const player = useRef(null)
  const [current, setCurrent] = useState(-1)
  const onTime = (t) => setCurrent(shotIndexAt(shots, t))      // 播放 → 高亮
  const jump = (i, e) => {                                       // 点行 → 跳转
    if (e.target.closest("input, textarea, select, [contenteditable], button")) return
    player.current?.seek(shots[i].start); player.current?.play()
  }
  return { player, current, onTime, jump }
}
// shotIndexAt：返回第一个 t < end 的镜头；t 恰好等于最后一镜 end 时返回最后一镜

对比层的时间映射与同步

原型的对比层用的就是这段逻辑。

function refTimeAt(t, script, reverse, refDuration) {
  const s = script.shots[shotIndexAt(script.shots, t)]
  const r = s.refShot != null ? reverse?.shots.find(x => x.id === s.refShot) : null
  const raw = r ? r.start + (t - s.start) / (s.end - s.start) * (r.end - r.start)   // 跟拍：分段线性
                : t * refDuration / scriptDuration(script)                          // 改编：按比例
  return clamp(raw, 0, refDuration - 0.05)
}
// useSyncedVideos：主时钟 = 成片；原片 playbackRate = 当前镜头时长比（0.5–2）
// 每 250ms 偏差 > 0.15s 直接 seek；任一边 waiting 两边暂停；声音二选一
