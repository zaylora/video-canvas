# 画布角色卡重设计：角色卡是画布里的普通节点，数据只属于当前画布

> - **范围**：重新设计画布里的「角色卡」节点：它不再引用全局的角色卡，而是和图片、视频一样的**普通节点**，数据存在画布 payload 里，**只属于当前画布**。包含：节点外观与状态、空节点的创建入口（上传 / 素材库 / 生成）、详情页（角色名、形象名、音色、补充图）、连线与 `@` 引用、短剧画布的对接、旧数据处理。不含：个人资产库里的全局角色（**本期不做**，见 §9.2）、文字转语音以外的新语音能力、协作、角色卡版本管理。
> - **日期 / 状态**：2026-10-29 · 设计已确认关键决定，仍有 7 项待确认（§11.4），未实现。
> - **证据约定**：**事实**附文件路径或来源链接；**推断**是基于事实的判断；**提案**是尚未实现的设计；**默认值**是用户没被问到、由本文暂定的做法，实现前可推翻。
> - **方案演进**：本文**推翻**旧设计 [角色卡.md](角色卡.md) 的这些已确认决定：角色卡是用户私有的全局实体（§11.1-前提）、画布节点只存 `characterId` 实时引用（§11.1-6）、双击菜单弹选择框放置（§11.1-2）。访谈中用户一度说「全局角色卡去掉」，随后又改为「全局角色先不做」，最终口径见 §11.1。旧设计里**仍然沿用**的：节点连线到图片 / 视频节点时形象展开为参考图、声音展开为参考音频；模型不收参考音频时不阻断，只提示；设定文字只展示。
> - **配套演示**：[画布角色卡重设计-演示.html](画布角色卡重设计-演示.html)（建议先读，里面有可点击原型，截图来自用户 2026-10-29 提供的两张界面图）。

## 1. 设计摘要

- **问题**：现在的角色卡是后端 `character_cards` 表里的全局实体，画布节点只存 `characterId`。想在一张画布里随手做个角色，必须先去资产页建卡、再回画布选择；卡被删了节点就「已失效」，还要有缓存、重新选择、失效提示一整套机制。短剧里每个角色也要同时建一张带 `drama_id` 的卡，形象图生成后还要回写主图。
- **目标**：
  1. 在画布里新建角色卡和新建图片节点一样直接：一个空节点，放下就能用。
  2. 角色的全部数据（名称、形象图、声音）都在画布里，复制、导出、撤销都和普通节点一致。
  3. 一个角色可以有多个形象（造型），连线和 `@` 时都能精确到某一个形象。
- **推荐结论**：
  - 角色卡节点 = 图片类节点 + 一份 `character` 元数据（角色名、形象名、设定、补充图、音色）。主图沿用图片节点自己的 `assetId / src`，生成面板沿用 `TaskPromptPanel`，生成的图直接成为主图。
  - **一个节点 = 一个角色的一个形象**；同一角色的不同造型各建一个节点，靠相同的角色名归在一起（详情页「角色名称」可选画布里的已有角色）。
  - 空节点的入口：**上传、素材库（只选图片）、直接生成**。外层生成图片；进入详情页后可设置音色，音频音色支持上传、AI 生成、绑定已有音频。
  - 画布里不再有全局引用：去掉角色卡选择框、缓存、「已失效 / 重新选择」、提交前刷新角色卡。
  - 全局角色（个人资产库）**本期不做**；旧角色卡数据**不迁移、清掉**。

### 2.2 设计约束

1. 画布保存靠 `revision` 乐观锁，payload 内部结构后端不校验（事实，见上表）：内嵌角色数据没有服务端校验，素材归属 / 种类要在写入入口（上传、素材库选择）保证。
2. 生成任务要求 `node_id`；没有画布节点的生成靠前缀约定（`rec:`、`seg:`）。音频生成放在详情页，`node_id` 怎么写要先核对（§11.4-4）。
3. 项目约定：先写失败测试；改 `web/` 用仓库自带的 oxfmt / oxlint。

### 2.3 当前缺口

- 画布里没有「自包含」的角色数据：形象、声音都在后端另一张表里。
- 角色节点没有空状态的创建入口（上传 / 素材库 / 生成）；普通画布的角色节点不能生成，只有短剧的可以。
- 一个角色多个形象只能靠多张卡（短剧里用 `look_name`），没有「同一角色」的轻量归组。

## 3. 用户与场景

- **用户**：在无限画布里做 AI 视频的创作者；也包括短剧工作室里管理角色形象的人（推断：来自旧设计 §3 和短剧设计）。
- **场景**：
  1. 做一支几个镜头的片子，随手建一个主角，传一张图，连到几个视频节点保持同一张脸。
  2. 没有现成的图，直接在角色节点上用提示词生成形象，再给它配一段声音。
  3. 同一个人物要「日常装、礼服」两个造型，各建一个节点，`@` 引用时选对造型。
- **主任务**：新建空节点 → 补一张形象图（上传 / 素材库 / 生成）→（可选）配音色 → 连线或 `@` 到生成节点。
- **成功指标（提案）**：
  - 从加号菜单到拿到一个有形象的角色节点，不离开画布、不打开选择框，≤ 3 步。
  - 复制画布、导出再导入后，角色形象和声音都在，不出现「已失效」。
  - 同一个角色的两个造型，连线 / `@` 时参考图互不串。

## 5. 设计原则

1. **角色卡就是节点**：不单独发明一套生命周期；创建、复制、撤销、导出都走普通节点的路径（来源：用户要求「和图片、视频一样」）。
2. **数据留在画布里**：节点自带全部内容，打开画布不依赖任何外部实体（来源：用户「只属于当前画布」）。
3. **空节点先能用**：没有图也能放下、连线前给出明确的「待补充」，入口就在节点上（来源：用户提供的界面）。
4. **一个节点只表达一个形象**：连线和 `@` 的语义始终是「这一张脸」（来源：用户确认）。
5. **复用现有能力**：生成面板、素材选择、参考展开规则、`@` token 都不重写（来源：项目约束）。
6. **未验证的不当事实**：不引入尚未核对的模型能力（来源：本文证据约定）。

## 6. 推荐方案

### 6.1 节点形态

- **外层节点**（和图片节点同尺寸体系，3:4 封面）：
  - 上方标题行：人形图标 + `角色名`，右上是出现集数 / 标签图标。
  - 封面区：有主图显示主图；空节点显示居中的「上传」「素材库」两个按钮；生成中显示流光与进度；失败显示原因和重试。
  - 封面下一行：**音色格**（有音色显示播放；没有显示空格）和 **「+」补充图格**（已加的补充图按缩略图依次排开，最多 4 张）。
  - 底部：`形象名`（默认「基础形象」）+ 状态标签（`待补充` / `生成中` / `生成失败`）；短剧画布再显示「出现集数」；右侧「…」菜单（编辑、替换主图、复制、删除）。
  - 左右各一个端口：**输出口**连到图片 / 视频节点；**输入口**接收参考图 / 文本（按图片节点规则，供「参考图建角色」类生成使用，推断自用户界面图左侧有「+」端口）。
- **生成面板**：选中节点时在下方出现，**复用图片节点的 `TaskPromptPanel`**（模型、风格、比例 / 分辨率、预设、积分、发送）。预设默认选「角色设计」（界面图里的预设名；具体内容待设计）。生成成功的图成为主图，历史结果沿用节点历史对话框，可换回。
- **详情页**（双击节点或「…→编辑」打开，弹框）：
  - 左：大图区，底部「上传源素材」「拼图」（拼图含义待确认，§11.4-2）。
  - 右：角色名称（输入或下拉选画布里的已有角色）、形象名称、（短剧画布）出现集数、形象音色。
  - 形象音色是互斥的单选：**文本音色**（一段音色描述，≤500 字）或 **音频音色**（上传音频 / AI 生成 / 绑定已有音频）。

### 6.2 核心流程

1. **创建**：加号菜单「角色卡」→ 在落点直接放一个空角色节点（不弹选择框），名称默认「未命名角色 N」，形象名「基础形象」，状态 `待补充`；算一次撤销。
2. **补主图**（三选一，也可事后替换）：
   - **上传**：选本地图片 → 上传为素材 → 写入节点 `assetId / src`；
   - **素材库**：打开素材选择框，**只列图片**，选一张作为主图；
   - **生成**：选中节点，下方面板写提示词、选模型与比例，提交；成功后结果成为主图。
3. **补充图**（可选）：外层「+」格或详情页「上传源素材」，最多 4 张，去重，不含主图。
4. **配音色**（可选）：详情页「形象音色」选文本或音频；音频可上传、绑定素材库里已有音频、或 AI 生成（提交生成任务，成功后自动绑定）。
5. **多个形象**：复制节点或再建一个空节点，角色名填同一个（或从「已有角色」里选），形象名改成「礼服」等；两个节点互相独立。
6. **连线**：角色节点 → 图片 / 视频生成节点。下游按顺序带入「主图、补充图」为参考图、音频音色为参考音频；超出模型上限按顺序截断并在下游提示「第 N 张起未带入」。
7. **`@` 引用**：提示词输入 `@` 候选里有画布上的角色节点，token 仍是 `@[节点显示名](节点id)`，不新增语法；显示名为 `角色名 · 形象名`。等价于连线。
8. **提交生成**：下游节点提交时，直接按角色节点此刻的数据取图和音频（数据在画布里，不再读缓存 / 刷新）。

### 6.3 关键交互规则

| 规则 | 说明 | 来源 |
| --- | --- | --- |
| 空节点可连线但无内容 | 没有主图时连到下游：不带入任何参考，下游参考条给出「角色节点还没有形象图」；不阻断 | 默认值 |
| 声音不支持 | 目标模型当前方式不收参考音频：只带形象，角色节点与下游均显示「当前模型不支持参考音频，声音未生效」，不阻断 | 沿用旧设计 §6.3（用户已确认） |
| 文本音色 | 文本音色描述只展示，**不**当作参考音频；是否拼进视频提示词待定（§11.4-3） | 推断 |
| 展开顺序 | 主图在前，补充图依次在后，最多 4 张补充图 | 沿用旧设计 |
| 同名角色 | 角色名允许重复；「已有角色」下拉按画布里角色节点的名字去重列出，选中只是复用这个名字，**不是**建立关联实体 | 推断自用户界面图的「已有角色」下拉 |
| 改角色名 | 只改当前节点；批量改名待确认（§11.4-5） | 默认值 |
| 生成中锁定 | 生成中提示词锁定、按钮转圈；主图不允许同时被替换 | 沿用图片节点 |
| 素材种类 | 主图 / 补充图只能选 image，音频只能选 audio；不合格的素材在选择框里置灰并写原因 | 沿用素材选择规则 |

### 6.4 短剧画布的对接

- 短剧拆解直接写**带 `character` 元数据的角色节点**（角色名、形象名、设定、音色描述），不再建卡；`data.drama`（类型、集数）保持不变，「出现集数」控件沿用。
- 形象图生成成功就是节点主图，不再有 `patchCharacter` 回写；失败的提示就在节点上。
- 片段生成从画布节点直接取参考图和音频，不需要读缓存；`@` 的角色节点没有主图时，片段提示词只用文字（沿用「无图资产标记」）。
- 删短剧时画布整体删除，不再有孤儿角色卡要清理。

## 7. 状态与异常

| 对象 | 状态 | 界面与行为 |
| --- | --- | --- |
| 主图 | 空 / 生成中 / 就绪 / 失败 | 空：两个入口按钮 + `待补充`；生成中：流光 + 进度，锁定提示词；就绪：封面；失败：红色提示 + 重试，**不扣积分**沿用生成任务规则 |
| 上传 | 上传中 / 成功 / 失败 | 沿用上传节点的进度与失败提示；格式或大小不合规在节点上就地说明 |
| 素材库选择 | 种类不符 | 置灰写原因（「只能选图片」「只能选音频」），不隐藏 |
| 补充图 | 达上限 | 「+」格变灰，提示「最多 4 张」 |
| 音色 | 无 / 文本 / 音频就绪 / 音频生成中 / 音频生成失败 | 音频生成中：音色格转圈，可离开；失败：详情页显示原因与重试；刷新页面靠任务对账恢复 |
| 参考素材被删 | 主图 / 补充图 / 音频的素材记录已被清理 | 读取时降级：主图缺失按「待补充」；补充图直接略过；音频缺失按「无音色」；节点上给出一次提示 |
| 保存冲突 | revision 冲突 | 沿用画布冲突弹窗；角色数据是 payload 的一部分，没有单独的冲突路径 |
| 撤销 / 重做 | 角色元数据变化 | 计入撤销栈（`history.ts` 的内容判断要认 `character` 字段）；生成任务写入的字段取当前，用户改的取快照（沿用现有规则） |
| 权限 | 素材归属 | 上传和选素材入口校验素材属于当前用户；payload 里的素材 id 不额外校验（后端不校验 payload 内部） |

## 8. 数据与工程影响（提案）

### 8.1 节点数据（payload，不需要数据库迁移）

```ts
/** 角色卡节点（kind: "character"）：图片类节点 + character 元数据 */
data: {
  kind: "character";
  label: string;                 // 节点标题，默认「未命名角色 N」，展示 = character.name
  assetId?: string; src?: string; mediaType?: "image";   // 主图，沿用图片节点字段
  status; outputs; prompt; params;                        // 生成与历史，沿用图片节点
  character: {
    name: string;                // 角色名，1–64 字
    look: string;                // 形象名，≤64 字，默认「基础形象」
    description: string;         // 设定，≤500 字，只展示
    extras: { assetId: string; src: string }[];   // 补充图，≤4，去重，不含主图
    voice:
      | { mode: "text"; text: string }                                         // 文本音色，≤500 字
      | { mode: "audio"; assetId: string; src: string;
          origin: "upload" | "generated" | "library" }                          // 音频音色
      | null;
  };
  drama?: NodeDrama;             // 仅短剧画布：{type, name, look, episodes}，沿用
}
```

- 去掉的字段：`characterId`、`labelCache`。
- 序列化白名单（`canvas-persistence.ts:110-112`）要加入 `character`。
- **素材引用收集**：导出和素材清理凭 `data.assetId` 找引用，`extras[].assetId`、`voice.assetId` 要加入，否则导出漏文件、清理误删（§11.4-6，需核对）。

### 8.2 要拆除 / 要改的模块（清单，非实现）

- **前端拆除**：`CharacterPickerDialog` 在画布的挂载、`store/characters.ts`、`hooks/use-characters.ts`、`store/character-reselect.ts`、`utils/characters/refs.ts` 的缓存逻辑、`fresh-input.ts` 的 `characterIdsOf` 刷新、`use-task-node.ts` 里角色卡刷新与失效过滤、`history.ts` 对 `characterId` 的判断、`prompt-mention.tsx` 的缓存取名。
- **前端改**：`character-node.tsx`（新节点形态）、`use-canvas-menu.ts`（「角色卡」直接放空节点）、`link-rule.ts` / `capabilities.ts`（展开改读节点数据）、`canvas-persistence.ts`（白名单）、详情页（新组件）、`add-node-items.tsx`。
- **后端**：画布保存无需改；`canvasdoc` 去掉 `characters` 字典与 `characterRef`（节点内嵌后随节点导出）；`drama_canvas.go`、`canvasgraph/drama.go` 改为写角色节点而非建卡；`repository/drama.go` 删除短剧不再清卡；`canvasgraph/apply.go:239` 的 Agent 禁令是否放开见 §11.4-7。
- **后端 `/characters` 与 `character_cards` 表、资产页「角色卡」标签**：本期画布不再使用。用户回答是「不迁移、直接清掉旧角色卡」；资产页入口、接口、表**本期是下线还是保留不动**待确认（§11.4-1）。
- **测试**：旧设计的角色卡相关测试按上面拆除项同步调整；新增节点数据、展开规则、旧画布兼容的测试（先写失败测试）。

### 8.3 旧画布兼容

- 旧节点有 `characterId` 而没有 `character`：**默认值**——打开画布时前端把它规整为空角色节点，保留位置，`character.name` 取 `labelCache.name`（保留名字是几乎零成本的体面做法），其余为空，状态 `待补充`；下次保存即落盘。不做服务端 SQL 迁移。
- 之后可用 `labelCache.coverAssetId` 当主图吗？**不做**：用户明确「不迁移」。

### 8.4 接口

本期**没有新增后端接口**：上传、素材库、图片生成、音频生成都沿用现有接口。音频生成的提交方式（`node_id`、音频模型来源）待核对（§11.4-4）。

## 9. 方案取舍

### 9.1 决策矩阵

默认权重（用户未单独排序，按访谈倾向推定）：创建速度 30%、画布自包含 30%、实现成本 25%、跨画布复用 15%。

| 方案 | 创建速度 | 自包含 | 实现成本 | 复用 | 合计 |
| --- | --- | --- | --- | --- | --- |
| A. 画布内嵌节点（推荐） | 5 | 5 | 3 | 2 | 4.15 |
| B. 保持全局实体 + 引用 | 2 | 2 | 5 | 5 | 3.20 |
| C. 内嵌 + 全局并存 | 5 | 3 | 1 | 5 | 3.40（用户选择先不做全局，见下） |

### 9.2 明确放弃（本期）

- **个人资产库的全局角色**：用户决定先不做；将来要做时，数据结构可以直接复用本节点的 `character` 元数据，「从资产库添加」做成**复制一份进画布**（用户在访谈中选过这个方向）。
- 画布间同步 / 实时引用。
- 角色训练（Soul ID 类）。
- 「角色设定板 / 参考图建角色 / 角色特写组」三个快捷模板：作为「角色设计」预设的具体内容之后设计。
- 提示词里 `@` 直接引用不在画布上的角色。

## 10. MVP 与后续

### 一期：画布内角色卡节点

- 范围：新节点形态、三个入口（上传 / 素材库 / 生成）、详情页（含文本音色、音频上传 / 绑定已有音频）、补充图、`@` 与连线展开、旧画布兼容、短剧拆解与片段生成对接、导入导出、拆除旧机制。
- 验收：
  1. 加号菜单「角色卡」在落点放一个空节点，不弹选择框；撤销一次即消失。
  2. 空节点「上传」选图后成为主图，`待补充` 消失；「素材库」只能选图片，选视频 / 音频的项置灰并写原因。
  3. 选中空节点在下方面板提交生成，成功后主图出现；生成失败显示原因，可重试。
  4. 详情页能改角色名（含从「已有角色」选）、形象名、出现集数（短剧画布）、音色；补充图最多 4 张，第 5 张被拒并提示。
  5. 连到视频节点：参考图依次是主图、补充图；音频音色带入参考音频；模型不收音频时只带图并提示「声音未生效」，生成不被阻断。
  6. 同一角色的两个造型节点，分别连到两个视频节点，参考图互不串。
  7. `@` 候选里出现角色节点，选中后 chip 显示 `角色名 · 形象名`，提交时与连线结果一致。
  8. 复制粘贴节点、撤销重做、刷新页面后，角色内容都在；导出再导入画布，主图、补充图、音频都在。
  9. 旧画布里的角色节点打开后变成带原名字的空节点，不报错、不弹「已失效」。
  10. 短剧拆解直接得到带角色名和形象名的空角色节点；形象图生成后自动成为主图，不再请求 `/characters`。

## 11. 待确认问题与已确认事项

### 11.1 已确认（用户的回答，2026-10-29）

0. **前提说明**：用户先说「全局角色卡去掉，只能在当前画布创建」，随后补充「全局角色卡只有在『从资产库添加』里才能引入；创建节点只在当前画布」，最后确定「**全局的角色卡先不做，先做画布中的**」。以最终口径为准。
1. 画布里的角色卡是**普通节点**，创建时是**空节点**，可上传图片或在素材库选择；**只属于当前画布**。
2. **一个节点 = 一个角色的一个形象**（访谈选择）；同一角色的不同造型各建节点。
3. 空节点**可以直接生成**：外层默认生成图片；点入详情后**可以生成音频**。
4. **个人资产库的全局角色本期不做**。
5. 旧角色卡：**不迁移，直接清掉**（用户在访谈中的回答；注意这是在「去掉全局角色卡」的口径下给出，与最终口径不冲突）。
6. 「从资产库添加」若将来引入全局角色，方式是**复制一份进画布**（用户在访谈中选择，现已随全局角色一起搁置）。

### 11.2 已搁置的决定

- 全局角色（个人资产库）与「从资产库添加」复制进画布：见 §9.2、§10 三期。
- 实时引用 / 「保持同步」开关：访谈中作为备选提出，未采用。

### 11.3 默认值（未问用户，可推翻）

- 角色名 1–64 字，形象名 ≤64 字、默认「基础形象」，设定与文本音色 ≤500 字，补充图 ≤4 张。
- 空节点默认名「未命名角色 N」，状态标签 `待补充`。
- 节点输入口按图片节点规则接收参考图 / 文本。
- 旧节点打开后规整为空节点，保留 `labelCache.name`。
- 缺失素材降级：主图缺失按待补充，补充图略过，音频按无音色。
- 角色名允许重复，「已有角色」只是复用名字。

1. **旧全局体系的去留**：资产页「角色卡」标签、`/characters` 接口、`character_cards` 表，本期是**下线并清掉**，还是保留不动、只是画布不再用？建议：下线入口并清空数据，表和接口等下一期定全局角色结构时一并重做。
2. **「拼图」按钮**（详情页左下）是什么：把多张源素材拼成一张角色设定板当主图？还是别的？一期建议先不做。
3. **文本音色**是否拼进视频提示词（现在只展示）？
4. **音频生成怎么提交**：生成任务要求 `node_id`，详情页音频生成用什么 id（如 `voice:{节点id}`）；以及「音频」类别模型从哪里选。需先核对 `service/generation_task_create.go` 的 `node_id` 校验；一期可只做上传 / 绑定。
