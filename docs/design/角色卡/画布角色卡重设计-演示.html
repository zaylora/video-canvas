画布角色卡重设计 演示

角色卡变成画布里的普通节点，数据只属于这张画布

现在的角色卡是全局实体，画布节点只存一个 ID 去引用它，所以才有「已失效」「重新选择」「缓存」这一整套机制。新设计把角色卡做成和图片、视频一样的节点：新建就是一个空节点，上传、从素材库选、或直接 AI 生成就能补上形象，音色放在详情里。个人资产库里的全局角色本期不做，旧角色卡数据不迁移。

主线：从加号菜单到连线，一个角色怎么做出来

全程不离开画布、不弹选择框。每一步都可以跳过，空节点也能放着。

1 加号菜单 →「角色卡」落点直接出现一个空节点，可撤销
2 补主图（三选一）上传 / 素材库（只选图片）/ 下方面板生成
3 详情：补充图、音色补充图 ≤4；文本音色或音频音色
4 连线或 @主图和补充图当参考图，音频当参考音频
设计：角色卡不再是「外部实体的影子」，而是图片节点加一份 character 元数据。所以生成面板、素材选择、复制撤销、导出都直接复用，不新造一套生命周期。
没有形象 / 素材被删时（降级，永远可用）：空节点可以放着、可以连线，只是不带入任何参考，下游会写「角色节点还没有形象图」；素材被清理时主图按「待补充」、补充图略过、音频按「无音色」，不会再出现「已失效」，也不阻断生成。

节点的三种形态

同一种节点，随内容不同看起来不同；多个形象靠「同一个角色名」归在一起。

空节点
待补充

封面是「上传」「素材库」两个按钮。选中后下方面板可以直接生成。

有形象的节点
就绪

封面是主图，下面有音色格和补充图格；连到视频节点时展开为参考图和参考音频。

同一角色的多个形象
按角色名归组

一个节点 = 一个形象。日常装、礼服各建一个节点，详情里「角色名称」选已有角色即可。

用户打开一张旧画布时，会发生什么

旧画布里的角色节点只存了一个 ID。你决定「不迁移、直接清掉旧角色卡」，所以它们会变成空节点。

  1. 打开画布前端发现节点有 characterId 但没有 character
  2. 规整为空角色节点保留位置和连线；character.name 取原来缓存的名字（默认值，几乎零成本）
  3. 显示「待补充」不弹「已失效」，下游连线不带参考
  4. 下次保存时落盘不做服务端 SQL 迁移
边界：旧角色的形象图和声音不会自动回来
  • 只有名字被保留；图片和音频文件本身还在素材库里，需要重新选。
  • 已经连好线的视频节点，下次生成会少掉这些参考，要重新补图。
  • 资产页「角色卡」入口是否同期下线，还没有定（见「数据与接口」页待确认 1）。

发布时要提前告知：升级后旧画布里的角色卡需要重新补形象图。

数据模型：画布 payload 里的角色节点

沿用现有「payload 只校验是 JSON 对象」的机制，不需要数据库迁移；主图沿用图片节点的字段。

节点 data（kind: "character"）
label字符串。节点标题，默认「未命名角色 N」，展示 = character.name
assetId / src主图素材 id 与地址，沿用图片节点；为空即「待补充」
status / outputs / prompt / params生成状态、历史结果、提示词、参数，沿用图片节点和 TaskPromptPanel
character.name字符串，1–64 字，允许重复
character.look字符串，≤64 字，默认「基础形象」
character.description字符串，≤500 字，只展示，不注入提示词
character.extras[]{assetId, src}，≤4，去重，不含主图，必须是图片素材
character.voicenull | {mode:"text", text}（≤500 字）| {mode:"audio", assetId, src, origin:"upload"|"generated"|"library"}；两种互斥
drama仅短剧画布：{type, name, look, episodes}，沿用
去掉characterId、labelCache
两个需要核对的点：序列化白名单（canvas-persistence.ts:110-112）要加入 character；导出和素材清理凭 data.assetId 找引用，extras[] 和 voice 里的素材 id 要加入收集，否则导出漏文件、清理误删（未验证）。

已确认的决定

  1. 角色卡是画布里的普通节点，数据只属于当前画布：用户要求，和图片、视频一样。
  2. 新建为空节点，可上传或从素材库选图：用户要求。
  3. 一个节点 = 一个角色的一个形象：访谈选择；不同造型各建一个节点。
  4. 空节点可直接 AI 生成：外层默认生成图片，点入详情可生成音频（用户回答，并附界面截图）。
  5. 个人资产库的全局角色本期不做：用户最终口径；此前「去掉全局角色卡」「只在素材库引入」两次表述已由它取代。
  6. 旧角色卡不迁移、直接清掉：用户回答（在「去掉全局」的口径下给出，与最终口径不冲突）。
  7. 已搁置：全局角色 + 「从资产库添加」复制进画布：用户访谈中选择「复制」而非「实时引用」，随全局角色一起搁置，将来启用时可复用。
  8. 主文档已回写：以上全部在 Markdown §11.1–11.2；HTML 中没有新增未回写的决定。
