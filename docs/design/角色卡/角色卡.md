# 角色卡设计：把人物形象和声音绑成一个可复用的角色

> - **范围**：新增「角色卡」——把一组人物形象图和一条声音（参考音频）绑定成一个可命名、可复用的角色。包含：(1) 资产页新增「角色卡」管理；(2) 画布双击添加菜单新增「角色卡」入口，放上画布后是一种可连线的节点；(3) 连到图片 / 视频生成节点时自动把形象当参考图、声音当参考音频；(4) 第二期支持在提示词里 `@角色名`。不含文字转语音（TTS）、音色克隆、`voice_id`、协作共享、角色卡版本管理。
> - **日期 / 状态**：2026-10-22 · 一期和二期已实现。
> - **证据约定**：**事实**附文件路径或来源链接；**推断**是基于事实的判断；**提案**是尚未实现的设计；**默认值**是用户没被问到、由本文暂定的做法，实现前可推翻。
> - **方案演进**：无转向。调研时曾考虑「只在提示词里 `@角色名`、不做节点」（对标可灵 / Sora），用户选择「节点 + `@` 两者都要」，分两期交付，见 §10。
> - **配套演示**：[角色卡-演示.html](角色卡-演示.html)（建议先读，里面有可点击原型）。

## 1. 设计摘要

- **问题**：同一个人物想在多个镜头里保持「同一张脸、同一个声音」，现在要每次手动找图、找音频、分别连线，容易漏、容易错。项目里没有任何「人物」实体：资产只有 image / video / audio 三种（`backend/internal/model/asset.go:15`），也没有跨形象和声音的绑定结构。
- **目标**：
  - 创建一次角色卡，之后在任何画布里一步引入。
  - 连一根线，形象和声音一起进入下游生成任务。
  - 修改角色卡一次，所有画布里引用它的节点一起更新。
- **推荐结论**：
  - 新增后端资源 `character_cards`（用户私有），只**引用**已有素材 ID，不复制文件、不新增素材种类。
  - 角色卡 = 名称 + 1 张主形象图 + 最多 4 张补充图 + 0~1 条声音（音频素材）+ 文字设定（只展示，不自动注入）。
  - 资产页新增第三个范围「角色卡」；画布双击菜单新增「角色卡」，点开选择框，多选后在双击位置放置节点。
  - 画布上的角色卡节点只存 `characterId`，**实时引用**：改卡全画布生效，删卡后节点变「已失效」。
  - 连线时，节点把形象展开成「参考图片」、声音展开成「参考音频」；目标模型不收参考音频时只用形象，并提示「声音未生效」，不阻断生成。
  - 分两期：一期 = 管理页 + 节点 + 连线；二期 = 提示词 `@角色名`。

### 2.2 设计约束

1. 素材只有三种，声音只能是一条 audio 素材（用户已确认，§11.1）。
2. 一个节点只提供一种东西（`PORT_OF_KIND`），而角色卡要同时提供图片和音频——这是本设计唯一需要动连线 / 绑定核心的地方（§8.2）。
3. 画布保存靠 `revision` 乐观锁；节点只存 `characterId` 不影响它。
4. 资产查询一律带 `user_id`；角色卡同理，引用的素材必须属于当前用户。
5. 本机项目约定：前端文案中文、测试在 `web/src/tests/`、后端测试在 `backend/internal/tests/`，先写失败测试。

### 2.3 当前缺口

- 无「角色」实体和 API；无资产页入口；无画布节点；无「一个节点同时提供图片和音频」的绑定能力；无「引用已被删除」的节点失效状态。

### 2.4 需要用户确认

均已在 §11 收敛，无遗留阻塞项。

## 3. 用户与场景

- **用户**：用 AI 做短剧 / 分镜 / 广告片的创作者，一个项目里有 2~6 个反复出场的人物（推断：来自项目 3D 导演台、「角色三视图」预设的使用场景，`web/src/constants/presets.ts:776-793`）。
- **触发场景**：
  1. 出新人物：做三视图 → 选一条声音 → 存成角色卡。
  2. 开新镜头：双击画布 → 选「角色卡」→ 连到视频节点 → 生成。
  3. 人物换声音 / 补图：在资产页改一次，所有画布跟着变。
- **主任务**：「建一次，连一根线，形象 + 声音都带上」。
- **成功指标（提案）**：
  - 有角色卡的人物，新镜头从「找图 + 找音频 + 连两根线」降到「双击选卡 + 连一根线」。
  - 连线后下游任务输入里同时有形象图和参考音频（单元测试可验证，§10 一期验收）。

### 4.3 依赖框架调研

- **结论：未发现需要新引用的依赖。** 画布已是 React Flow，节点、连线、选择框、列表均有现成组件（`AssetPickerDialog`、`Segmented`、`LibraryAssetCard` 风格）。角色卡只是数据结构与规则扩展，没有「无限画布 / 时间线 / 拖拽」这类需要新库的能力。
- 因此无需向用户征求引用决定（skill §3.1）。

## 5. 设计原则

1. **引用，不复制**：角色卡只存素材 ID。删素材的规则沿用资产库（移出库不删文件）。
2. **一个概念，两个入口**：资产页是唯一管理处，画布只是引用，不在画布里偷偷创建只存在于画布的角色。
3. **不阻断**：声音用不上、素材失效，只提示不拦截生成。
4. **所见即所发**：设定文字只展示，不静默改写提示词（用户已确认）。
5. **沿用现有机制**：端口、绑定、`@` token、资产选择器都复用，不另起一套。

## 6. 推荐方案

### 6.1 信息架构

- **资产页**（`/assets`）：范围改为「生成历史 / 个人资产库 / **角色卡**」。角色卡页是卡片网格 + 「新建角色卡」按钮 + 搜索框。
- **角色卡卡片**：主形象图（封面）、名称、补充图数量、声音标识（有 / 无）与试听按钮、「编辑 / 删除」。
- **新建 / 编辑弹框**：名称（必填）→ 形象主图（必填，从资产选择器选 image）→ 补充图（可选，最多 4）→ 声音（可选，选 audio）→ 角色设定（可选，≤ 500 字，只展示）。
- **画布双击菜单**：新增「角色卡」条目（图标区别于生成节点，同「上传素材」「从资产库添加」一类动作项）。
- **画布节点**：角色卡节点显示主形象图、名称、声音试听、状态角标；右侧一个输出口。

### 6.2 核心流程

1. **创建**：资产页 → 角色卡 → 新建 → 选图 / 声音 → 保存。
2. **放上画布**：画布空白处双击 → 「角色卡」→ 选择框（列出我的角色卡，可多选，含「新建角色卡」入口，新建完自动选中）→ 确认 → 在双击位置整齐排布节点，算一次撤销。
3. **连线**：角色卡节点 → 图片 / 视频生成节点。下游自动按「形象 = 参考图片、声音 = 参考音频」绑定；必要时 `opForLink` 切到收这些参考的生成方式（如「文生视频」→「全能参考」）。
4. **生成**：提交任务时按角色卡**当前**内容取形象和声音（实时引用）。
5. **修改 / 删除**：在资产页改卡或删卡；画布节点下次读取时更新 / 变失效。

### 6.3 关键交互规则

| 规则 | 说明 | 来源 |
| --- | --- | --- |
| 可连目标 | 角色卡 → 图片、视频生成节点；**不能**连音频、文本、导演台节点 | 默认值（音频节点做配乐音效，不吃人物参考） |
| 展开顺序 | `images` = 主图在前，补充图依次在后；`audios` = 声音 | 默认值 |
| 超出上限 | 目标模型参考图上限小于角色图数量时，按顺序截断，并在目标节点提示「第 N 张起未带入」 | 默认值 |
| 声音不支持 | 目标当前方式不收参考音频：只带形象，角色卡节点与目标节点均显示「当前模型不支持参考音频，声音未生效」；不阻断 | 用户已确认 |
| 没有声音 | 卡片未绑定声音，只带形象，无提示 | 推断 |
| 多角色 | 一个目标节点可连多个角色卡，各自展开后依次追加；超出上限按顺序截断 | 默认值 |
| 设定文字 | 只在卡片和节点详情展示，不拼入提示词 | 用户已确认 |

### 6.4 界面细节（与 HTML 原型一致，提案）

- **资产页角色卡网格**：3:4 竖版封面（主图）；左上叠放最多 3 张补充图缩略图；底部渐变遮罩里是名称 + 声音试听条（播放键 + 波形 + 时长），没有声音时显示「未绑定声音」；悬停出现「⋯」菜单（编辑 / 删除）；第一格是虚线「新建角色卡」。点封面直接打开编辑。
- **编辑弹框左图右文**：左列是 3:4 主图槽（角标「主图」，悬停「更换」）和下方 4 个方形补充图槽（悬停出现「设为主图」「移除」）；右列依次是名称、声音（试听卡片：播放键 + 文件名 + 波形 + 时长 +「更换」+ 移除）、角色设定（字数计数）。新建时按钮叫「创建」，编辑时叫「保存」。
- **选素材**：点任一槽位打开资产选择器（复用 `AssetPickerDialog` 的「个人资产库 / 生成历史」两栏），**按种类过滤**（选图只列图片、选声音只列音频）。已用素材禁用并标原因：「已是主图」「已添加」「已达上限」，不隐藏。主图可从现有补充图里选，选中后原主图退回补充图第一位。
- **错误就地显示**：名称为空 / 重复显示在名称框下；没选主图时主图槽描红；保存失败在弹框底部给横幅，已填内容保留。
- **画布节点**：和现有节点同一套外观——节点名在卡片上方（人形图标 + 角色名），卡片是 3:4 封面 + 底部声音条，右侧 `+` 输出口拖线；「声音未生效」标签挂在节点名旁，不遮封面。
- **目标节点参考条**：带入的图按顺序标「图1…图N」；超出上限的图变灰并划线；不被接收的声音划线显示；下方各给一行原因。
- **双击选择框**：竖版卡片网格，可多选，已在当前画布上的角色标「画布中已有」（仍可再放）；右上「新建角色卡」打开同一个编辑弹框，创建后回到选择框并自动选中。

### 6.5 第二期：提示词 `@角色名`（提案）

- 输入框里输入 `@` 的候选列表里，除现有节点外，加入**画布上已有的角色卡节点**，写入的 token 仍是 `@[角色名](节点id)`，**不新增 token 语法**。
- `expandPrompt` 解析到指向角色卡节点的 ref 时，换成角色名，并确保该节点的形象和声音被带入（与连线等价）。
- 为什么引用节点而不是 `characterId`：沿用 `prompt-tokens.ts` 现有语义（引用节点 id），解析、撤销、复制粘贴都不用变；代价是 `@` 的角色必须先放到画布上（已确认，§11.4）。

## 7. 状态与异常

| 状态 | 行为 |
| --- | --- |
| 资产页加载中 / 空 | 骨架卡片；空时显示「还没有角色卡」+ 新建按钮 |
| 保存中 | 保存按钮禁用并转圈，弹框不可关闭 |
| 保存失败 | 弹框内就地提示业务错误（名称重复、素材不可用、超出数量上限），已填内容保留 |
| 删除确认 | 告知「引用它的画布节点会显示已失效，素材仍保留」；**不显示被几个画布引用**——引用存在各画布 `payload_json` 里，后端不做反查（默认值，避免为此扫全部画布） |
| 画布节点加载中 | 先显示节点骨架，批量 `GET /characters?ids=` 回来后填充 |
| 节点正常 | 主图 + 名称 + 声音试听 |
| **角色卡已删除** | 节点显示「角色卡已失效」，灰显；连线保留但不参与提交；提供「重新选择」和「删除节点」 |
| 素材已不可用 | 引用的素材被清理（`GET /assets/:id` 找不到）：对应部分灰显并提示「形象 / 声音不可用」；主图不可用等同卡片失效，补充图 / 声音不可用只跳过 |
| 声音不被支持 | 见 §6.3，非阻断提示 |
| 撤销 / 重做 | 放置节点、删除节点、换角色卡都进画布现有撤销栈；角色卡本身的增删改**不**进画布撤销（它是资源，不是画布内容） |
| 画布冲突（`revision`） | 不受影响，节点只是 payload 里多一个 `characterId` |
| 权限 | 角色卡与引用素材都按 `user_id` 隔离；他人的角色卡不可见 |
| 离线 / 请求失败 | 节点保留上次读到的名称和缩略图（见 §8.2 `labelCache`），提示「角色卡信息暂时读取失败」 |

### 8.2 前端（提案）

**节点数据**：`CanvasNodeData` 新增 `characterId?: string` 与 `labelCache?: { name: string; coverAssetId?: string }`（只用于请求失败 / 加载前的占位，不作为事实来源）。

**需要改动的位置**（对照 §2.1，沿用 gemini 扫描给出的八点清单，已核对）：

1. `constants/canvas/node-library.ts`：`NODE_LIBRARY` 新增 `character`；一期决定 `ADD_NODE_MENU` 是否出现——**不出现**，角色卡入口走 `buildAddNodeItems` 的动作项（因为需要先选卡再建节点，不能像生成节点那样直接落一个空节点）。
2. `types/canvas.ts`：节点字段。
3. `utils/tasks/capabilities.ts`：**核心改动**。`PORT_OF_KIND.character` 不能是单值。方案：新增 `PORTS_OF_KIND`（多值），`character` 提供 `["image", "audio"]`；`resolveBindings` 遇到角色卡上游时，**展开成虚拟连线**追加到 `images`（主图 + 补充图）和 `audios`（声音）。`IncomingLink` 增加可选 `fromCharacter?: { id: string; part: "avatar" | "extra" | "voice" }` 供提示词展开和提示使用。
4. `utils/canvas/canvas.ts`：`DOWNSTREAM_KINDS.character = ["image", "video"]`。
5. `utils/canvas/link-rule.ts`：`canLinkNodes` 对 `character` 上游，只要目标当前或可切换的方式收图片（或音频）即放行；`opForLink` 优先选能同时收图片和音频的方式。
6. `utils/canvas/node-label.ts` 与 `hooks/use-canvas-menu.ts`：新建时的默认标号与落点（多选整齐排布复用 `planAssetNodes` 的排布思路，`utils/canvas/asset-nodes.ts:38-75`）。
7. `pages/canvas/canvas-node.tsx` + 新增 `character-node.tsx`：渲染（主图、名称、试听、失效 / 声音未生效角标）。
8. 新增 `components/characters/character-picker-dialog.tsx`（双击选择框）与 `character-editor-dialog.tsx`（资产页新建 / 编辑，内部复用 `AssetPickerDialog` 并限制种类）。
9. `pages/assets/index.tsx`：`AssetsTab` 增加 `characters`，`Segmented` 增加「角色卡」。
10. 新增 `api/character.ts` 与 `store/characters.ts`（画布里按 ID 批量读并缓存，监听资产页的改 / 删后失效缓存）。

**实时引用的实现要点**：

- 画布打开时收集所有 `characterId` 批量读一次，写入 store；节点从 store 渲染。
- 提交任务时再读一次最新（或使用刚拉的缓存且未过期），避免用旧图生成。（待实现时按现有 `use-asset-urls` 缓存策略定 TTL，默认值：提交前强制刷新该角色卡。）
- 资产页保存 / 删除后，store 里对应项失效，画布节点自动刷新。

**实现难点**：(a) 节点同时提供图片与音频（§8.2-3）；(b) 参考图上限截断与提示要在 `resolveBindings` 之后判断；(c) 二期 `@` 需让 `expandPrompt` 认识「引用的是角色卡节点」。

## 9. 方案取舍

### 9.1 决策矩阵

权重来自用户已确认的优先级：**易用性（连一根线）> 与现有机制一致 > 实现代价**。

| 方案 | 易用性（权重 3） | 与现有一致（权重 2） | 实现代价（权重 1，越低分越高） | 加权 |
| --- | --- | --- | --- | --- |
| A 引用素材 + 节点 + `@`，分两期（推荐） | 5 | 4 | 3 | 26 |
| B 只做 `@`，不做节点 | 3 | 3 | 4 | 19 |
| C 角色卡自成模型（`voice_id` / 身份训练） | 4 | 1 | 1 | 15 |

### 9.2 明确放弃

- 文字转语音、音色克隆、模型侧 `voice_id`（现有任务输入表达不了，§2.1）。
- 公开 / 共享 / 授权他人使用角色卡。
- 角色卡版本管理与「画布节点锁定某一版」（用户选择实时引用，§11.1）。设定文字自动注入提示词。
- Agent 创建 / 编辑角色卡节点（一期不做）。

## 10. MVP 与后续

### 一期：管理页 + 节点 + 连线

- 范围：`character_cards` 表与 CRUD 接口；资产页「角色卡」范围与新建 / 编辑 / 删除；双击选择框与角色卡节点；连线展开形象 / 声音；失效、声音未生效等状态。

## 11. 待确认问题与已确认事项

### 11.1 已确认（用户的回答）

1. 角色卡在画布上**既是可连线的节点，也能在提示词里 `@角色名`**（两者都要）。
2. 画布空白处双击选「角色卡」→ **弹出角色卡选择框**。
3. 「声音」= **一段参考音频素材**，不新增后端语音能力。
4. 形象 = **1 张主图 + 可选多张补充图**。
5. 目标模型不支持参考音频时：**只用形象，节点上提示声音未生效**。
6. 角色卡被修改 / 删除后，画布节点**实时引用，跟随修改**（删除后节点失效）。
7. 角色设定文字：**有，但只展示、不自动注入提示词**。
8. 分期：**两期，先管理页 + 节点 + 连线，再做 `@`**。

### 11.2 已搁置的决定

- 节点存快照、手动「同步最新」（用户选了实时引用；如将来出现「旧画布生成条件被悄悄改变」的反馈，可回头启用，数据上只需在节点上加 `snapshot` 字段）。
- `@` 直接引用 `characterId`（不要求先放到画布）：需要新增 token 语法，暂不启用。

### 11.3 默认值（不需要用户决定，实现前可推翻）

- 每用户最多 100 张角色卡；补充图最多 4 张；设定 ≤ 500 字；名称 ≤ 64 字、用户内忽略大小写唯一。
- 角色卡只能连图片、视频生成节点。
- 参考图超限按顺序截断并提示；提交前强制刷新该角色卡。
- 一期 Agent 不识别角色卡节点。

### 11.4 已确认

- 二期：`@` 的角色必须先放到画布上（§6.5 的默认做法已确认），不新增 token 语法。
