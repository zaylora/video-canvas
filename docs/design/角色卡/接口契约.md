# 角色卡一期 · 前后端接口契约

> 前后端并行开发的唯一约定。设计依据见同目录 `角色卡.md`（§6、§7、§8、§10 一期）与 `角色卡-演示.html`（可点击原型）。
> 改契约必须两边同时知道：谁需要改，在本文件末尾「变更记录」追加一行，不要静默改。

## 1. ID 与命名约定

- 角色卡 ID：`idcodec.ID`，JSON 里是**十六进制字符串**（同资产库文件夹 `id`）。
- 素材 ID：`uint64`，JSON 里是**数字**（同 `POST /asset-library/items` 的 `asset_id`）。
- 响应字段 snake_case；前端在 `web/src/api/character/index.ts` 里 map 成 camelCase（照 `api/asset-library` 的写法）。
- 所有接口在已登录分组，按 `user_id` 隔离；他人的角色卡一律按「不存在」处理。

## 2. 视图 `CharacterView`

```json
{
  "id": "1a2b3c",
  "name": "林晚",
  "description": "28 岁，齐耳短发……",
  "avatar": { /* AssetView，必有；素材已不可用时为 null */ },
  "extras": [ /* AssetView[]，0~4 张，按保存顺序；不可用的素材直接略过 */ ],
  "voice": null,           // AssetView | null
  "created_at": "2026-10-22T08:00:00Z",
  "updated_at": "2026-10-22T08:00:00Z"
}
```

`AssetView` 即现有 `backend/internal/model/asset.go` 的 `AssetView`（`id` 数字、`kind`、`url`、`mime_type`、`byte_size`、`width`、`height`、`duration_ms`、`file_name`），前端用现有 `mapAsset` 转换。

## 3. 接口

| 方法与路径 | 请求 | 成功响应 | 业务错误 |
| --- | --- | --- | --- |
| `GET /characters` | `?q=` 名称模糊搜索（可选） | `{ "items": CharacterView[] }`，`updated_at` 倒序，不分页 | — |
| `GET /characters?ids=a,b,c` | 逗号分隔十六进制 ID，≤ 100 个；有 `ids` 时忽略 `q` | `{ "items": CharacterView[] }`，查不到的**缺席**（不报错） | `ids` 格式错误 → 参数错误 |
| `GET /characters/:id` | — | `CharacterView` | 66004 |
| `POST /characters` | `{ name, description?, avatar_asset_id, extra_asset_ids?, voice_asset_id? }` | `CharacterView`（201） | 66001 / 66002 / 66003 / 66005 / 参数错误 |
| `PATCH /characters/:id` | 同上字段，全部可选；`voice_asset_id: null` 表示清空声音；`extra_asset_ids: []` 表示清空补充图；未出现的字段不改 | `CharacterView` | 同上 + 66004 |
| `DELETE /characters/:id` | — | 204 / 空 | 66004 |

校验规则（后端强制，前端同样预校验）：

- `name`：去首尾空格后 1–64 字；同一用户内**忽略大小写**唯一。
- `description`：≤ 500 字，默认空串。
- `avatar_asset_id`：必填；素材存在、属于当前用户、`kind = image`。
- `extra_asset_ids`：≤ 4 个，去重，不能包含主图，每个都是当前用户的 image。
- `voice_asset_id`：可空；非空时是当前用户的 audio。
- 每用户最多 100 张。
- 删除只删角色卡行，**不删素材**，不反查画布引用。

## 4. 错误码（`backend/internal/pkg/errcode/errcode.go`，66xxx 号段）

| 码 | 名称 | HTTP | 文案 | 前端处理 |
| --- | --- | --- | --- | --- |
| 66001 | `ErrCharacterNameDup` | 409 | 已有同名角色卡 | 显示在名称框下 |
| 66002 | `ErrCharacterLimit` | 409 | 角色卡数量已达上限 | 弹框底部横幅 |
| 66003 | `ErrCharacterAssetInvalid` | 400 | 引用的素材不可用（Msg 写具体哪一项：主图 / 补充图 / 声音，及原因：不存在 / 种类不对） | 弹框底部横幅 |
| 66004 | `ErrCharacterNotFound` | 404 | 角色卡不存在 | toast；画布里视为已失效 |
| 66005 | `ErrCharacterInvalid` | 400 | 角色卡参数不合法（Msg 写具体原因：名称为空 / 过长、补充图超过 4 张 / 重复 / 含主图、设定过长） | 弹框底部横幅 |

## 5. 数据库

迁移 `backend/migrations/0009_character_cards.sql`（如编号已被占用，取下一个空号并在变更记录写明）：

- 表 `character_cards`：`id` bigint PK、`user_id` bigint not null、`name` varchar(64) not null、`description` text not null default ''、`avatar_asset_id` bigint not null、`extra_asset_ids` jsonb not null default '[]'、`voice_asset_id` bigint null、`created_at`、`updated_at` timestamptz。
- 唯一索引 `uk_character_cards_user_name` on `(user_id, lower(name))`；索引 `(user_id, updated_at desc)`。
- 不建到 `assets` 的外键。

## 6. 前端分工边界

- 前端只改 `web/`；后端只改 `backend/`。两边都不要动对方目录，也不要改 `docs/design/角色卡/` 下除本文件「变更记录」外的内容。
- 前端开发期间后端可能还没好：用测试里的 mock（`web/src/tests/`）验证，不要在业务代码里写假数据。
