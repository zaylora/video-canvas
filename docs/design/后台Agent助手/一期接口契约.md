# 后台 Agent 助手 · 一期接口契约

> - 范围：一期（模型参数与调价）前后端之间的接口约定。前端（`web/`）与后端（`backend/` + `agent/`）并行开发，**双方都以本文为准**；需要改契约时先改本文，再通知对方。
> - 上位文档：[后台Agent助手.md](后台Agent助手.md)（§6、§8、§10）。聊天框视觉：[后台助手聊天框原型.html](后台助手聊天框原型.html)（§6.2.1）。
> - 日期：2026-11-02。状态：已确认，开发中。修订：2026-11-02 联调前修正——无模型错误码改为 60002；补充事件 `canvas_id` 为 null、取整未变化条目、`rejected` 结果、audit_ids 来源、用户消息事件带回 `page_context`。
> - 字段约定：沿用画布 Agent 现有接口，snake_case；ID 是 agent 服务编码后的字符串；时间是 ISO 8601 字符串。

## 1. 已确认的产品决定（实现不得偏离）

1. 助手的一切写操作都只能通过「变更单」审批种类 `admin_change` 落库，用户确认后才执行。
2. 后台助手的运行**不扣管理员积分**，只记录 Token 用量。
3. 定价设置的读写：`admin` 和 `super_admin` 都可以。
4. 变更单里 `model`、`pricing_settings` 两类条目的 `required_role` 都是 `admin`（二期的 plugin、channel 是 `super_admin`）。
5. 联网复用现有的 `web_search` / `web_fetch`。
6. 会话不绑画布：`canvas_id = 0`，`mode = "admin"`。同一个用户同一时间最多一个活跃运行；不同管理员之间互不阻塞。

## 2. HTTP 接口

前端统一走 `/api/v1` 前缀（`service` 已带）。所有接口要求已登录；标注 RequireAdmin 的要求 `admin` 或 `super_admin`，否则返回 403。

### 2.1 会话（新增）

| 方法 路径 | 请求 | 返回 | 业务错误 |
| --- | --- | --- | --- |
| `GET /admin/assistant/sessions` | — | `AgentSessionDto[]`，只含本人 `mode=admin` 的会话，按 `updated_at` 倒序 | 403 |
| `POST /admin/assistant/sessions` | `{ title?: string; model_key?: string }` | `AgentSessionDto`，其中 `mode="admin"`、`canvas_id="0"` | 403；60002 无可用 Agent 模型（与画布一致；60005 只表示 Agent 服务不可用） |

`AgentSessionDto` 的结构与画布会话完全一致（`web/src/api/agent/type.d.ts`），`mode` 的取值新增 `"admin"`。新建时请求体用 `model_key`；发起运行时可用 `agent_model_key` 指定本轮模型。

**事件里的 `canvas_id`**：会话接口返回的 admin 会话 `canvas_id` 是 `"0"`，但 Go 推送的 WebSocket 事件和 HTTP 回放里，零画布按 idcodec 编成 `null`。前端识别 admin 会话的事件，靠 `session_id` 或者把 `null` 当作 `"0"`，不能依赖正数 `canvas_id`。

### 2.2 复用的 Agent 接口（不改路径）

以下接口对 admin 会话同样可用，行为与画布会话一致：

- `GET /agent/models`
- `GET /agent/sessions/:sid/events?after=`、`GET /agent/sessions/:sid/history`
- `PATCH /agent/sessions/:sid`（改名）、`DELETE /agent/sessions/:sid`
- `POST /agent/sessions/:sid/runs`
- `POST /agent/runs/:rid/cancel`、`POST /agent/runs/:rid/interject`
- `POST /agent/approvals/:aid/decision`

约束：

- 对 `mode=admin` 的会话，调用者当前必须是 admin 或 super_admin（Go 代理通过 `X-Agent-Role` 头传给 agent 服务，角色从 `RoleLookup` 实时取），否则返回 403。会话只能由创建者本人访问。
- `GET /canvas/:id/agent/sessions` 永远不返回 admin 会话。
- 同一用户已有活跃的 admin 运行时，再发起运行返回现有的「已有活跃运行」错误（60001），插话照常可用。

### 2.3 发起运行：新增 `page_context`

`POST /agent/sessions/:sid/runs` 的请求体新增一个可选字段（只对 admin 会话生效，画布会话忽略）：

```ts
page_context?: {
  route: string;          // 当前后台路由，如 "/admin/ai/channels"
  model_key?: string;     // 当前选中的模型
  channel_key?: string;   // 当前选中的渠道
  plugin_key?: string;    // 当前选中的插件
}
```

admin 会话不接受 `attachments`、`selection`、`viewport`（传了就忽略）。这条用户消息的事件 data 里会原样带回 `page_context`（确切的事件类型和路径见实现报告），刷新或回放后前端仍能显示引用标签。`mode` 不传则沿用会话的 `admin`；传其他值返回 400。

### 2.4 定价设置（新增，RequireAdmin）

```ts
// GET /admin/settings/pricing  →  PricingSettingsView
// PUT /admin/settings/pricing  body: PricingSettingsReq  →  PricingSettingsView
interface PricingSettingsReq {
  credits_per_yuan: number;          // 1 元 = N 积分；> 0，最多两位小数
  default_markup_pct: number;        // 整数 0–1000
  usd_cny_override: number | null;   // 手动覆盖美元汇率；null 表示使用实时汇率；> 0，最多四位小数
}
interface PricingSettingsView {
  credits_per_yuan: number | null;   // null = 尚未设置
  default_markup_pct: number;        // 缺省 30
  usd_cny_override: number | null;
  usd_cny: {
    rate: number | null;             // 当前生效的汇率（override 优先，否则为最近一次实时值）；从未拉到且无覆盖时为 null
    date: string | null;             // 汇率的日期（YYYY-MM-DD）；覆盖时为 null
    fetched_at: string | null;       // 最近一次成功拉取的时间
    source: "live" | "override" | "none";
    stale: boolean;                  // 实时值距今超过 7 天
  };
}
```

参数越界返回 400（通用参数错误码，带字段信息）。写入记 `admin_audit_logs`，action 为 `settings.pricing`。

### 2.5 运行记录：场景筛选（修改）

`GET /admin/agent/runs` 新增查询参数 `scene`：`canvas`（缺省，排除 admin 运行）或 `admin`（只看后台助手）。返回结构不变。

## 3. 事件与审批

事件仍走现有的 WebSocket `agent.event` 和 HTTP 回放，类型和结构不变。审批视图（`approval.created`、`approval.decided` 事件的 `data`，以及 history 里的审批）**新增 `result` 字段**，对所有审批种类都存在，执行前为 `null`。

### 3.1 审批种类 `admin_change`

`AgentApprovalDto.kind` 新增 `"admin_change"`，`quote_credits` 恒为 0。`payload` 的结构：

```ts
interface AdminChangePayload {
  order_no: string;                 // 展示用的变更单号，如 "CO-251102-7F3A"，同一实例内唯一
  title: string;                    // 一句话标题，如「视频模型按成本加价 30%」
  reason: string;                   // 为什么改（助手转述用户的要求）
  revert_of?: string;               // 如果是回滚单：被回滚的变更单号
  items: AdminChangeItem[];         // 至少 1 项；决定时用下标 index 指代
}

interface AdminChangeItem {
  target: "model" | "pricing_settings";
  key: string;                      // 模型 key；定价设置时固定为 "pricing"
  label: string;                    // 展示名，如「可灵 2.1」「定价设置」
  live: boolean;                    // 目标当前已上线（模型已启用 / 定价设置恒为 true）：应用即生效
  status: "ok" | "invalid" | "stale" | "mismatch";
                                    // ok 可应用；invalid 校验不通过；stale 提案时配置已和助手读到的不一致；mismatch 价格复算和助手给的不一致
  issues: string[];                 // status != ok 时的原因，给人看的中文
  warnings: string[];               // 不阻止应用的提醒：售价低于成本、汇率可能过期、取整后实际涨幅 +50% 等
  required_role: "admin" | "super_admin";
  diff: AdminChangeDiff[];          // 字段级差异；取整后完全没有变化的条目可以为空数组（此时 status = invalid，issues 含「取整后未变化」）
  basis: PricingBasis[];            // 价格的计算依据；不涉及价格时为空数组
}

interface AdminChangeDiff {
  path: string;                     // 如 "pricing.per_second"、"pricing.cost.per_second"、"pricing.tiers[1].unit"、"capabilities.params.duration.options"、"default_markup_pct"
  before: unknown;                  // 改前的值（JSON），null 表示原来没有
  after: unknown;                   // 改后的值（JSON），null 表示删除
}

interface PricingBasis {
  path: string;                     // 对应 diff 里售价那一条的 path
  mode: "cost" | "relative";
  // mode = cost
  upstream?: { amount: number; currency: "USD" | "CNY"; unit: string; source_url: string; note?: string };
  fx?: { rate: number; date: string | null; source: "live" | "override"; stale: boolean };
  credits_per_yuan?: number;
  yuan?: number;                    // 换算后的人民币（4 位小数）
  cost?: number;                    // ⌈yuan × credits_per_yuan⌉
  markup_pct?: number;
  // mode = relative
  from?: number;
  pct?: number;                     // 可为负数
  price: number;                    // 最终售价（整数积分）
}
```

计算规则（Go 端复算，前端只展示）：`cost = ceil(yuan × credits_per_yuan)`，`price = ceil(cost × (1 + markup_pct/100))`；相对调价时 `price = ceil(from × (1 + pct/100))`。浮点数先按 6 位小数四舍五入后再取整。

### 3.2 决定

沿用 `DecideAgentApprovalReq`：

- 批准部分条目：`{ decision: "approve", items: [{ index, approve: true|false }, ...] }`。不传 `items` 表示批准全部可应用的条目。
- 拒绝：`{ decision: "reject", answer?: string }`，`answer` 是给助手的理由。
- 批准了 `status != "ok"` 或角色不够的条目时，不报错，这些条目的结果记为 `skipped` 并附原因；显式不批准（`approve: false`）的条目记为 `rejected`。执行时 Go 按 user_id 从数据库实时查角色，不信任请求头。

### 3.3 执行结果 `result`

```ts
interface AdminChangeResult {
  items: Array<{
    index: number;
    status: "applied" | "failed" | "skipped" | "rejected";
    message?: string;               // failed / skipped 的原因，如「审核期间配置已被他人修改，未覆盖」
  }>;
  applied_by: string;               // 确认人的用户名
  applied_at: string;               // ISO 时间
  audit_ids: number[];              // 写入的审计记录 id（每个 applied 条目一条）。注意：模型条目来自 ai_audit_logs，定价设置来自 admin_audit_logs，两张表的主键可能重复，只作展示，不要当全局编号用
}
```

审批状态：全部 applied → `executed`；部分 applied → `partially_approved`；没有任何 applied（全部 failed / skipped）→ `failed`；拒绝 → `rejected`。

### 3.4 回滚

前端「回滚」按钮发一条普通消息：`回滚变更单 <order_no>`。助手调用 `admin_propose_changes({ revert_of: "<order_no>" })`，Go 从审计记录里找到该单已应用条目的改前值，生成一张反向变更单（`revert_of` 有值），同样要确认、同样做冲突检测。

### 3.5 页面刷新信号

前端在收到 `approval.decided`，且 `kind = "admin_change"`、`result.items` 中有 `applied` 时，派发 `window` 事件 `admin-config-changed`（`detail: { targets: Array<"model" | "pricing_settings"> }`），模型渠道页和定价设置页据此重新拉取数据。纯前端约定，后端不涉及。

## 4. 后端内部（前端不依赖，列出供后端实现与验收）

- agent 服务的工具：`admin_list_models`、`admin_get_model`（含 `body_sha256`）、`admin_list_channels`、`admin_get_pricing_settings`、`admin_quote_preview`、`web_search`、`web_fetch`、`plan_update`；审批工具 `admin_propose_changes` → kind `admin_change`。
- `admin_propose_changes` 的参数：`{ title, reason, revert_of?, items: [{ target, key, base_sha256, patch, pricing_basis? }] }`，`patch` 只允许 `pricing` / `capabilities` / `label` / `hint` / `tags` / `enabled` 这些顶层字段。
- 审计：模型条目写 `ai_audit_logs`（action 沿用或新增 `model.update`），定价设置写 `admin_audit_logs`（`settings.pricing`）；`detail_json` 包含 `{ via: "assistant", order_no, session_id, run_id, approval_id, diff, before }`。
