# 后台 Agent 助手 · 二期接口契约（插件全链路）

> - 范围：二期「对接新平台」：小镜搜文档 → 匹配或编写协议插件 → 静态验证 → 「插件 + 渠道 + 模型」组合变更单 → 密钥安全卡片 → 真实试跑卡片。前后端并行开发，**都以本文为准**；要改契约先改本文。
> - 上位文档：[后台Agent助手.md](后台Agent助手.md) §6.7、§10 二期验收。一期契约：[一期接口契约.md](一期接口契约.md)（本文只写新增和变化）。
> - 日期：2026-11-02。状态：已实现（未提交、未真实上游联调）。修订：2026-11-02 联调对齐——密钥决定统一为 `answer: "configured"`；试跑超时语义；审批 payload 带 `signature`（及试跑 `input`）由 Go 生成、前端原样保留；trace 摘要只进给模型的结果文字。
> - 字段约定与一期一致：snake_case；ID 为 agent 服务编码后的字符串；时间是 ISO 8601。

## 1. 已确认的产品决定（实现不得偏离）

1. 所有写操作仍只能经变更单 `admin_change` 落库；插件、渠道、模型可以放在**同一张单**里，执行时按依赖顺序（插件 → 渠道 → 模型）。
2. 插件和渠道条目的 `required_role` 是 `super_admin`（沿用现有接口权限）；新建模型条目是 `admin`。依赖的条目没有成功应用时，依赖它的条目记 `skipped`，原因写明「依赖的 xx 未应用」。
3. 插件代码草稿**只在变更单 payload 里**，确认后才调用现有 `AIPluginService.Upload`（仍走 runner 预检、自动分配版本号）。
4. **静态验证自动做**（不落库、不发网络请求）；**真实试跑必须由用户在卡片上同意**才发起（审批种类 `admin_test_run`）。
5. **密钥不经过 agent 服务、不写 SQLite、不进事件、不发给模型**：卡片（审批种类 `admin_secret`）里前端直接调用现有 `PUT /admin/ai/channels/:key/secret`（body `{ value }`），成功后再调审批决定 `{ decision: "approve", answer: "configured" }`。agent 服务拒绝任何其他 `answer`，防止决定字段被当成传密钥的通道。
6. 自动修复上限：同一插件在一次运行里最多 3 次静态验证失败后重写、最多 3 次真实试跑；超过后小镜停下，把 trace 摘要交给用户。上限由 Go 强制（不是只写在提示词里）。
7. 小镜的身份不变（同一个小镜），二期工具只在 `mode=admin` 下发。

## 2. 新增工具（Go 下发声明，`modes: [admin]`）

| 工具 | 种类 | 说明 |
| --- | --- | --- |
| `admin_list_plugins` | 读 | 插件列表：key、name、vendor、kind、auth.type、endpoints 摘要、最新版本、是否内置、是否启用 |
| `admin_get_plugin` | 读 | 某个插件某版本（缺省最新）的 meta 与完整代码，内置插件也能读，作写法样例 |
| `admin_plugin_check` | 读 | 静态验证一段**未上传**的代码，见 §3 |
| `admin_propose_changes` | 审批 `admin_change` | items 新增 `target: plugin`、`channel`、`model_create`，见 §4 |
| `admin_request_secret` | 审批 `admin_secret` | 请用户为某个渠道填 API Key，见 §5 |
| `admin_test_run` | 审批 `admin_test_run` | 请用户同意真实试跑，见 §6 |

`admin_list_channels`（一期已有）继续可用，用来判断渠道是否已存在、是否已配密钥（只返回 `secret_configured: boolean`，绝不返回密钥）。

## 3. `admin_plugin_check`（静态验证）

参数：

```ts
{
  code: string;                              // 插件源码（CommonJS），≤ 512KB
  ctx_sample?: Record<string, unknown>;      // 提交时的样例 ctx（input、channel.settings 等），缺省由宿主按 meta 生成最小样例
  responses?: {                              // 文档里的响应样例，用来跑解析钩子
    submit?: { status: number; headers?: Record<string, string>; body: unknown };
    query?: { status: number; headers?: Record<string, string>; body: unknown };
  };
}
```

返回给模型的结果文字（同时在工具结果里给结构化 JSON，前端工具行只显示摘要）：

```ts
{
  ok: boolean;                     // 预检通过且所有跑过的钩子没有抛错
  meta?: { key, name, version?, vendor?, auth, endpoints, channelSettings };  // 解析出的 meta
  issues: string[];                // 预检问题 / 钩子异常，中文
  request?: { method, url, headers, body };   // buildSubmitRequest 渲染出的请求；鉴权头、Key 一律脱敏为 "••••"
  parsed?: { submit?: unknown; query?: unknown };  // parse* 的返回
  logs: string[];                  // utils.log，最多 50 条
  attempt: number;                 // 本运行内对同一 meta.key 的第几次验证（从 1 起）
  attempts_left: number;           // 还剩几次（上限 3）；为 0 时 ok=false 也不再接受新验证，返回 issues「已达自动修复上限」
}
```

实现要点：复用 plugin-runner 现有预检和钩子执行（goja 沙箱、200ms 超时、1MB 上限），**不写 `ai_plugins` / `ai_plugin_versions`**，不发任何网络请求。

## 4. 变更单条目扩展（`admin_change`）

`AdminChangeItem.target` 取值扩展为：`"model" | "pricing_settings" | "plugin" | "channel" | "model_create"`。其余字段（`key`、`label`、`live`、`status`、`issues`、`warnings`、`required_role`、`diff`、`basis`）语义不变。新增两个可选字段：

```ts
interface AdminChangeItem {
  // …一期字段…
  depends_on?: number[];          // 依赖的条目下标（同一张单内）；执行时依赖未 applied 则本条 skipped
  detail?: PluginDetail | ChannelDetail | ModelCreateDetail;   // 按 target 展示用的摘要，前端渲染
}

interface PluginDetail {          // target = plugin
  plugin_key: string;
  version_before: string | null;  // 已有插件的最新版本；新插件为 null
  version_after: string;          // 上传后预计的版本号（服务端最终分配为准）
  meta: { name: string; vendor?: string; auth: string; endpoints: string };  // 一行摘要
  code_lines: number;
  code_diff: string;              // 与已有最新版本的 unified diff；新插件为空串（前端显示「新插件 · N 行」）
  check: { ok: boolean; request?: { method: string; url: string }; issues: string[] };  // 最近一次静态验证结论
}

interface ChannelDetail {         // target = channel（只做新建，不改已有渠道）
  base_url: string;
  headers: string[];              // 只列请求头名字，不列值
  rate_limit?: { rps?: number; concurrency?: number };
  secret: "configured" | "missing";   // 新建时恒为 missing；密钥走 §5 卡片
}

interface ModelCreateDetail {     // target = model_create（新建模型，默认 enabled=false）
  kind: string;
  channel: string;
  upstream_model: string;
  plugin: string;                 // plugin_key@version（version 可为 "latest"，执行时取刚上传的版本）
}
```

`diff` 对 plugin / channel / model_create 也要给（before 为 null），方便沿用一期的「字段 / 当前 / 变更后」渲染；代码本身不进 diff，只进 `detail.code_diff`。

执行顺序与结果：

- 执行器按 `depends_on` 拓扑序执行；`plugin` 调 `AIPluginService.Upload`，`channel` 调现有渠道创建服务，`model_create` 调 `SaveModel(Create=true)` 且 `enabled=false`。
- 每条仍是独立事务并写审计（`ai_audit_logs`，detail 里 `via=assistant`、`approval_id`、`order_no`）。
- `AdminChangeItemResult` 新增可选 `created?: { plugin_version?: string; channel_key?: string; model_key?: string }`，返回实际创建出的版本号 / key。
- 回滚（`revert_of`）对 plugin / channel / model_create 条目：二期**不支持自动回滚**，反向单里这些条目标 `invalid`，issues 写「新建的插件 / 渠道 / 模型请在对应页面手动删除」。

## 5. 密钥卡片（`admin_secret`）

工具参数：`{ channel_key: string; reason: string }`。审批 payload：

```ts
interface AdminSecretPayload {
  channel_key: string;
  channel_label: string;
  exists: boolean;                 // 渠道已存在；不存在时前端卡片置灰：「先应用建渠道的变更单」
  secret_configured: boolean;      // 当前是否已配密钥
  reason: string;                  // 小镜为什么要它
  required_role: "super_admin";
}
```

前端流程：用户在卡片的密码框里填 Key → 前端调 `PUT /admin/ai/channels/:key/secret`（现有接口，body 照现有格式）→ 成功后调 `POST /agent/approvals/:aid/decision`，body `{ decision: "approve", answer: "configured" }`；用户不填点「跳过」→ `{ decision: "reject" }`。

后端约束：决定为 approve 时，Go 在 execute 阶段**实时查库确认该渠道已配密钥**（`secret_configured=true`），否则结果为 failed「密钥未保存」。审批 payload、decision、result、事件、模型请求留存里都**不得出现密钥**。`result` 结构：`{ configured: boolean }`。

## 6. 真实试跑卡片（`admin_test_run`）

工具参数：`{ model_key: string; input: Record<string, unknown>; reason: string }`。审批 payload：

```ts
interface AdminTestRunPayload {
  model_key: string;
  model_label: string;
  input_summary: string;           // 一行，如「t2v · 5s · 720p · 提示词 32 字」
  estimate: {                      // 预估上游费用（示意，按模型 cost 和 quote 计算）
    credits: number | null;        // 按成本价算的积分；没配 cost 为 null
    yuan: number | null;           // 按定价设置换算的人民币；无法换算为 null
  };
  attempt: number;                 // 本运行内对该模型的第几次试跑
  attempts_left: number;           // 上限 3
  reason: string;
  required_role: "admin";
}
```

批准后 Go 调现有 test-run（不扣用户积分），**等任务结束**（沿用现有任务完成通知 / 对账，超时 10 分钟）后把结果喂回模型：状态、错误分类、首个产物 URL、trace 摘要（各钩子是否成功、上游 HTTP 状态码、`utils.log` 前 20 条，鉴权信息脱敏）。`result` 结构：

```ts
{ test_run_id: string; status: "succeeded" | "failed" | "timeout"; error?: string; output_url?: string }
```

- 决定接口在批准时立即返回 `status=approved`、`result=null`；最终 `result` 通过 `approval.decided` 事件和回放拿到，前端不能把首次 approved 当成成功。
- `timeout` 表示 Go 等满 10 分钟就交回结果，**上游任务没有取消、仍在运行**，审批状态为 `executed`。前端显示「试跑仍在运行（已等 10 分钟）」，不显示为失败。
- 错误分类、钩子成败、上游 HTTP 状态、`utils.log` 前 20 条只进给模型的结果文字，不进 `result`。前端类型里预留的 `duration_ms` / `error_class` / `trace_url` 是可选字段，后端目前不返回，前端缺省时不显示。
- payload 里还有 `input`（实际试跑输入快照）和 `signature`，`admin_secret` 的 payload 也有 `signature`：都由 Go 生成，前端原样保留，不修改。

超过 3 次时工具直接返回错误「已达试跑上限」，不再出卡片。

## 7. 前端要做的

- 决定区（`DecisionDock`）新增两种审批：`admin_secret`（密码框 + 保存 / 跳过；渠道不存在时置灰并写原因；保存中、失败的就地提示）、`admin_test_run`（模型、输入摘要、预估费用、第几次 / 剩几次，同意 / 不同意）。
- 变更单明细（`admin-change-detail.tsx`）支持 plugin / channel / model_create：插件显示 版本 before → after、meta 摘要、静态验证结论（渲染出的请求方法 + URL），代码 diff 可展开（等宽字体、增删行着色、默认折叠）；渠道显示 base_url、请求头名、密钥状态；新建模型显示 kind / 渠道 / 上游模型 / 插件。`depends_on` 在条目上显示「依赖第 n 项」，取消勾选被依赖项时，依赖它的条目自动取消勾选并禁用。
- 时间线审批行：`admin_secret` 显示「已配置密钥 / 已跳过」（不显示任何密钥字符）；`admin_test_run` 显示状态、耗时、产物链接。
- 页面上下文：插件页登记选中的 `plugin_key`（一期遗留）。
- 二期新工具的动作短语（`ADMIN_TOOL_PHRASES`）：查看了插件列表、读取了插件、验证了插件、请你填写密钥、请你同意试跑。
- `admin-config-changed` 事件在插件 / 渠道 / 模型被创建后同样派发，插件页、渠道页监听刷新。

## 8. 验收（来自主文档 §10 二期）

1. 对一个已有内置插件能覆盖的平台说「接一下」：小镜复用插件，只出「渠道 + 模型」的单。
2. 对一个没有插件的平台：小镜给出插件草稿、静态验证结果（渲染出的请求、样例解析结果），以及「插件 + 渠道 + 模型」组合变更单。
3. 密钥卡片保存后，agent 的 SQLite（`agent_events`、`agent_approvals`、`pi_entries`）和模型请求留存里都搜不到这个密钥（写自动化测试：用一个特征字符串当密钥，全库搜索）。
4. 真实试跑必须点同意才发起；失败后小镜最多自动修 3 轮，第 4 次被 Go 拒绝。
5. admin 账号：插件、渠道条目锁住显示「需 super_admin」，新建模型条目依赖它们，自动跳过并写明原因。
