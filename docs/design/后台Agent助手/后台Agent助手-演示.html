后台 Agent 助手

一句话改配置，确认后才生效

在后台任何页面都能唤出助手，比如说「视频模型按成本加价 30%」「按官方文档补齐可灵的参数」「接一下 xx 平台」。助手负责查文档、查价格、算数、写配置， 但它不会直接改线上配置：每个写操作都先整理成一张变更单，你逐条确认后才落库。 宿主复用项目现有的 pi agent（agent/ 服务），一期做模型参数与调价，二期做插件对接全链路。

助手能做的三类事

同一个助手、同一张变更单，按风险和期次分三类。

调价
一期admin 可确认

上游官方价 → 实时汇率 → 积分成本 → 加价。也支持「全体涨 10%」这种纯指令。每个价格都附算式。

调模型参数
一期admin 可确认

生成方式、参数选项、默认值、参考素材上限、规格价。按官方文档补齐，改已启用的模型要过启用检查。

对接新平台
二期super_admin 确认

搜文档 → 复用或写插件 → 静态验证 → 建渠道与模型。密钥走安全卡片；真实试跑要花钱，另外确认。

你说「视频模型按成本加价 30%」时，会发生什么

一期最典型的一条路径，以及交付前要先讲清楚的边界。

  1. 列出所有视频模型admin_list_models(kind=video)，并找出哪些还没填成本
  2. 逐个查上游官方价格web_search / web_fetch，复用画布 Agent 已有的联网能力（Exa → Bing → DuckDuckGo）
  3. 换算成积分美元先按实时汇率换成人民币，再乘以「1 元 = N 积分」，向上取整得到成本，再乘以 1.3 向上取整得到售价
  4. 提交变更单Go 重新算一遍价格，和助手的结果不一致就标「算错」；已启用的模型还要跑启用检查
  5. 你勾选、确认逐条在各自的事务里写入，写审计；模型页即时刷新
边界：助手找不到价格时不编，已启用的模型保存即生效。
  • 找不到官方价格的模型会被跳过并列出来，或者让你直接粘贴价格。
  • 有些价格页是 JS 渲染的，web_fetch 可能抓不到正文 未验证
  • 售价低于成本时只标红警告，不禁止勾选（有时是故意做活动）。
  • 「1 元 = N 积分」没设置时，助手拒绝按成本调价，会先让你去「定价设置」页填。

交付时要提前告知：国内平台（火山、可灵、阿里）的文档站能不能搜准还没实测，一期上线后要先验证。

调价怎么算

选一种调价方式，改几个数，就能看到助手写进变更单的算式和结果。Go 在提交变更单时会用同一套公式复算，助手算错的条目不能勾选。 汇率 6.6529 是 2026-10-30 欧洲央行的美元兑人民币汇率（2026-11-02 实测 Frankfurter 接口所得），其余数字都是示意。

可点击原型：后台右侧抽屉

数据在内存里，刷新复原；助手的回复用定时器模拟，不是真实调用。抽屉已经打开，当前页面是「模型渠道」。点输入框上方的快捷指令就能走一遍。 想看失败长什么样：确认前点模型表上方的「模拟他人修改 kling-v2-1」，或者打开「汇率源不可用」；把角色切到 admin 再试「对接新平台」，插件和渠道条目会锁住。

变更单执行（伪代码，提案）

// backend/internal/service/agent/admin_change.go（提案）
func ExecuteAdminChange(ctx, rc, payload, decision) Result {
  verifySignature(payload)                          // 篡改直接拒绝
  role := roleLookup(rc.UserID)                     // 实时查库，不信任请求头
  for item in payload.items where item.id ∈ decision.item_ids {
    if !roleSatisfies(role, item.required_role) { res.fail(item, "需超级管理员确认"); continue }
    tx {
      cur := loadBody(item.target, item.key)
      if sha256(cur) != item.base_sha256 { res.fail(item, "配置已被他人修改，请让助手重新读取"); rollback; continue }
      switch item.target {
        case model:            SaveModel(item.after)          // 已启用 → 启用检查不过就拒绝
        case pricing_settings: putSystemSettings(item.after)
      }
      audit(action, actor=rc.UserID, detail={via:"assistant", session, run, approval, diff})
    }
    res.ok(item, before=cur)                        // before 留给「撤销」生成反向变更单
  }
  return res.textForModel()                         // 「已生效 3 条；1 条失败：…」
}

已确认的决定

  1. 写操作一律出变更单：确认后才落库，可以逐条勾选。
  2. 调价依据是上游成本加加价率：也支持「全体涨 10%」这种纯指令。
  3. 联网复用现有的 web_search / web_fetch：你原本选的是「接搜索 API + 网页抓取」，核对代码发现已经有了，所以改为复用，不新接服务（已确认）。
  4. 宿主复用项目现有的 pi agent：在 agent/ 里加 admin 场景。
  5. 插件先自动做静态验证：真实试跑另出卡片确认，失败后自动修，最多 3 次。（二期）
  6. 入口是全后台右侧抽屉：自动带上当前页面的上下文。
  7. 权限沿用现有接口：确认时重新校验，admin 不能确认插件和渠道（二期）。
  8. 密钥走安全输入卡片：直达 PUT /channels/:key/secret，不进对话、不发给模型。（二期）
  9. 新增定价设置：「1 元 = N 积分」人工填，美元汇率实时获取。
  10. 一期做模型与调价，二期做插件。
  11. 已搁置：会话内授权全自动执行、付费搜索源、助手定时自动调价。
  12. 后台助手不扣管理员积分：只记录 Token 用量。
  13. 定价设置 admin 也能改：积分汇率、默认加价率、美元汇率覆盖，admin 和 super_admin 都能改。
