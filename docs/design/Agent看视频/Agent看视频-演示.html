Agent 看视频 演示

让 Agent 看懂上一段视频，并把尾帧接给下一镜

生成模型不能拿视频当参考，所以连续镜头要靠「上一镜的画面」衔接。结论：可行，而且不需要火山「长视频理解」——给 Agent 新增两个后端工具，用 ffmpeg 抽帧：一个抽几帧让模型看懂，一个把指定帧存成图片节点。截帧只是一个按需调用的工具，不是每次看视频后的固定动作：要不要看、要不要截、截几张（一次最多 6 张）、哪些帧连给下一镜当参考，全由 LLM 自己决定，后端只管上限和合法性。第一版只看 AI 生成的短片（约 5–15 秒），不做长视频。

阅读说明。第一期后端已按本设计实现（未提交、未真机验证，详见 Markdown §13）；原型是内存里的模拟，数字为示意。对应 Markdown 设计文档 Agent看视频.md。

主线：一次「续镜」怎么走

用户一句话，Agent 完成「看 → 选 → 截 → 连 → 写提示词」，真正花积分的只有最后的生成，仍走原来的确认卡片。

用户「接着上一段继续，镜头往前推」
canvas_inspect_video后端 ffmpeg 抽 6 帧，交给模型看（只读）
canvas_capture_frame（按需）仅当 LLM 判断要留下画面（如当参考图）：选帧（≤6）→ 存素材 → 建节点 → 要作参考的才连线
写衔接提示词canvas_apply_ops
generate_media确认卡片 + 积分预估
设计：虚线框的截帧是可选分支。这条是典型路径，不是固定流程——只问「拍了什么」就只看不截，用户明说「截尾帧」也可以不看直接截。看和写分开：看视频只读、不落库；截帧免费、可撤销。复用现有看图链路，抽出的帧就是图片，不另接模型。放弃了：让用户每次手动点「截取帧」。
抽帧失败时（回退，永远可用）：Agent 说明原因（超时、视频损坏、环境不支持），并引导用户改用现有的手动「截取帧」按钮；其他步骤不受影响。

三条路线

真正的分歧是「谁来看懂视频」和「截图从哪来」。

A 后端 ffmpeg 抽帧
推荐 · 已确认

抽出的帧交给 Agent 当前的看图模型。既能看懂又能直接截图；代价是镜像要装 ffmpeg。

B 方舟 video_url
未采用

让豆包模型直接看视频。不产出截图，仍需另抽帧；且绑定豆包渠道。

C 火山长视频理解
搁置

视频要先传进点播空间，输出只有文字总结。为 10 秒短片太重，适合以后分析长片。

当用户说「接着上一段继续」时，会发生什么

Agent 自己完成衔接，用户只在最后一步确认花积分。

  1. Agent 抽帧看视频首帧、尾帧必含，中间均匀取点；没有看图能力的模型拿不到这个工具
  2. Agent 判断结尾状态人物位置、动作、光线、运镜方向
  3. （仅在需要参考图时）Agent 才调用截帧工具，自己决定截几张、哪几帧一次最多 6 张，免费，出现在视频节点右侧
  4. Agent 决定哪些帧当参考只有它写了连线目标的帧才连到下一镜，其余只留在画布上
  5. 写衔接提示词，申请生成弹出原有确认卡片
边界：只管 AI 生成的短片。
  • 用户上传的数分钟长片、需要听懂对白的场景本期不做（需要语音转写，才轮到火山方案）。
  • 截帧没有确认卡片，靠撤销兜底。
  • 后端镜像要装 ffmpeg，打破了「后端不装 ffmpeg」的旧约定。

交付前要告知：升级后需重新构建镜像；ffmpeg 许可证与镜像体积待确认。

续镜原型

模拟对话与画布，数据在内存里，刷新复原。已预置一段「镜头 1」视频和空的「镜头 2」，点「下一步」走完整流程。想看失败：勾选「模拟抽帧超时」再走一遍。（耗时、帧数为示意，非真实调用）

canvas.example.com / 我的画布 / 分镜
设计：左画布右对话，让用户看到「帧图节点如何长出来、连到哪里」。不能看图的模型只能截帧，不能看视频——禁用的是「看」，不是「截」。

核心流程伪代码

// canvas_capture_frame（提案）
if len(frames) < 1 || len(frames) > 6: fail("一次最多截 6 帧")
ref   = canvasgraph.VideoRefs(graph, nodeId)            // 校验视频节点与产物 assetId
file  = Assets.Open(userID, ref.AssetID)                 // 归属校验
src   = file.Remote ? file.URL : spoolToTemp(file.Body)  // 本地存储落临时文件，尾帧要 seek
dur   = ffprobe(src)                                     // 超时即失败
for f in dedupe(frames):                                 // 同一时间点去重
  t     = f.at=="first" ? 0 : f.at=="last" ? dur-0.1 : f.at   // 尾帧不取正好等于时长（待实测）
  png   = ffmpeg(-ss t -i src -frames:v 1)               // 协议白名单 + 超时 + 并发上限
  asset = AssetService.Upload(userID, png)               // 存为用户素材
  node  = canvasgraph.AddUploadedImage(row(video, i), asset, label="视频名 · "+label(t))
  canvasgraph.Connect(video -> node)
  for x in f.connectTo: Connect(node -> x)               // 只有写了才连，是否作参考由 LLM 决定
return [{nodeId, at: t}]                                 // 图片不进历史与日志

已确认的决定

  1. 诉求是「理解已生成视频，并把截图交给后续镜头做参考」：生成模型不能引用视频，只能引用图片。
  2. 抽帧放在后端，装 ffmpeg：Agent 离线也能跑，不依赖浏览器。
  3. Agent 直接建图片节点，不弹确认卡片：截帧免费，靠撤销兜底，保证连续出片流程不被打断。
  4. 截帧是按需调用的独立工具，不是固定步骤；是否截帧、截几张、哪些帧当参考，都由 LLM 自己决定：一次最多 6 张；后端只校验上限与合法性，不写死流程。
  5. （实现时定的）截帧只在「全能创作」「分镜搭建」可用，看视频所有模式可用：截帧会新建节点，与剧本创编、提示词优化模式的限制一致。帧图放在视频节点右侧同一列、向下依次避让（不是横排），并用后端受信任的建图函数连 video → image 来源线。主文档已回写（§6.3、§7、§13）。
  6. 截好的帧放在画布中：是普通图片节点，不连线也保留，用户可拖动、预览、再拿去做别的；是否连线当参考另由 LLM 决定。
  7. 只看 AI 生成的短片：5–15 秒，抽 6 帧足够，不需要火山点播。
  8. 已搁置：火山长视频理解 / 方舟 video_url：以后分析长片或要听对白时再启用。
  9. 主文档已回写：以上均在 Markdown §11；默认值（看视频默认 6 帧、JPEG 1024）为设计默认，非用户回答。

仍待确认：只读任务模式是否放行截帧；Alpine ffmpeg 许可证与镜像体积。
