图片扩图设计

图片扩图：在画布上把一张图往外“画大”

选中一张图片，点功能区的「扩图」，在图外拖出一个更大的框，选好比例、模型、写几句提示词，发送后在右侧得到一张扩大了的新图片节点。 点「扩图」时只摆一个占位框，不生成任何图片；点发送之后才合成图片、上传、调用模型。 整个功能只改前端，后端接口和画布存档格式不变。

阅读说明。本页是设计稿，代码已按它实现（2026-10-11），但界面还没有在浏览器里实机验证，也没有拿真实模型跑过完整扩图。“项目现状”都来自读代码（标「已核对代码」）；界面样子以同目录的 图片扩图原型.html 为准，本页「可点击原型」里直接嵌入了它； 「比例与尺寸演示」里的数字用的是真实要写进代码的算法，但原图尺寸、模型支持的比例是演示用的假数据（示意）。 对应的 Markdown 主文档是 画布UI设计.md 的 6.17 节，已回写。

主线流程：从点“扩图”到拿到新图

这张图回答：什么时候花钱、什么时候花时间、哪一步最容易出问题。

1 点「扩图」摆出框和底部面板，不生成图片
2 调整拖手柄、选比例/倍数、选模型、写提示词
3 点发送右侧立刻出现“生成中”的新节点并连线
4 合成 + 上传原图贴进透明大图，导出 PNG 传到对象存储，拿到素材
5 提交任务图生图 i2i，参考图是合成图素材
6 回填走现有任务推送，结果写回新节点
设计：把重活（读原图、合成、上传）全部推迟到点发送之后，进入扩图模式只是摆几个 DOM 元素，所以拖框不卡。第 3 步先出节点再做第 4 步，是为了点下去 100ms 内就有反馈。
出错时（节点保留，可重试）：读不到原图、合成失败、上传失败，节点显示失败原因，点重试从第 4 步重来；任务提交或生成失败走现有的失败展示和退积分逻辑。 刷新页面会丢掉“还没上传完”的重试材料，此时提示“请回到原图重新扩图”。

现有规则下，连到图片节点的图片连线会自动成为参考图。扩图要的参考图只有“合成图”一张，所以要对这条线特殊处理。已选第一种。

为什么不把标记放在连线上：画布存档只保存连线的起止和连接点（canvas-persistence.ts），读档时还会用默认配置覆盖连线数据，标记会丢。放在新节点自己的数据里才存得住。

用户把 1920×1080 的图扩成 3 倍，会发生什么

一次最极端的操作，看看每一步有多大、哪里会被限制。数字见「比例与尺寸演示」。

  1. 框拖到 3 倍后再也拖不动弹一条“已到 3 倍上限”，框停在 5760×3240。
  2. 点发送，右侧立刻出现“图片 1-扩图”状态“生成中”，原图和它之间连一条线。
  3. 合成图被压到最长边 40965760×3240 → 4096×2304，原图部分等比缩小贴进去，其余是透明。
  4. 导出 PNG、上传、提交 i2i比例按 16:9 这种整数比写进模型的比例参数。
  5. 结果回来，节点按成片真实宽高比显示用的是现有的任务推送和回填，不新增轮询。
边界：模型最终出多大图由模型决定
  • 合成图只是“参考图 + 比例”，不保证输出像素等于框的尺寸；框上的尺寸角标是按原图像素换算的预期值。
  • 原图部分是否“一个像素都不变”取决于模型，我们只负责告诉它“保持原图内容不变”。
  • 积分在提交任务时冻结，合成或上传失败不会扣积分。

交付前要告知：扩图效果好坏主要看所选模型的图生图能力。

提交流程伪代码（提案）

// outpaint-run.ts —— 依赖都注入，测试里换成假的
async function runOutpaint({ source, frame, model, userPrompt, ratio }, deps) {
  // 1. 点发送的瞬间，先造节点和线（100ms 内有反馈）
  const node = buildOutpaintNode(source, { model, ratio, prompt })   // status: running，无 taskId
  deps.addNode(node); deps.addEdge(source.id → node.id)

  try {
    // 2. 合成：fetch 原图 blob → canvas 贴进透明大图 → PNG
    const plan = planCompose(naturalSize, frame, originNodeSize, MAX_EDGE = 4096)
    const png  = await deps.compose(source.src, plan)
    if (png.size > caps.refs.image.max_mb * MB) throw new UserError('合成图超过模型参考图大小上限')

    // 3. 上传 → 拿到素材 id
    const asset = await deps.upload(new File([png], 'outpaint.png', { type: 'image/png' }))

    // 4. 拼 input（含参数默认值与校验），提交 i2i
    const { input, errors } = buildTaskInput(caps, { prompt, images: [asset.id], [ratioKey]: ratio }, emptyBindings, 'i2i')
    if (errors.length) throw new UserError(firstError)
    const items = await deps.submit({ kind: 'image', model_id: model, canvas_id, node_id: node.id, input })
    // 5. 成功：写 taskId、params.images；之后完全由任务 store 回填
    deps.patch(node.id, { ...buildSubmittedPatch('image', taskId), params: {…, images: [asset.id]} })
  } catch (e) {
    deps.patch(node.id, { status: 'error', error: describe(e) })   // 节点保留，retryStash 留着合成参数
  }
}

// 提示词：
fullPrompt = INSTRUCTION + userPrompt   // INSTRUCTION = "保持原图内容不变，自然补全图片中的透明区域。"

// 比例：预设按预设名原样写（如 "21:9"）；原比例/自定义用 toRatio(w/h)
function toRatio(r) {            // 分子分母都在 1–24 里，找误差最小的；并列取和更小的
  best = argmin over p,q in 1..24 of |ln((p/q) / r)|, tie → smaller p+q
  return `${p}:${q}`
}
// 模型的比例参数是枚举时，取数值上最接近的一项（跳过 Auto 之类读不出比例的选项）

测试清单（先写失败测试，再实现；不用 Playwright）

  • outpaint-frame：框包住原图；最长边 ≤ 3 倍；角手柄等比；边手柄自由；平移不露出原图；预设框居中；倍数；识别当前比例；到上限返回“受限”。
  • 比例换算：1920×1080 → 16:9、1600×1200 → 4:3、极扁比例 24:1；预设原样输出；枚举取最接近；跳过 Auto。
  • 合成方案：像素换算、超过 4096 等比压缩、原图贴的位置。
  • outpaint-run（假上传、假提交）：先建节点再提交；各步失败后的节点状态；上传成功但提交失败时 images 已写入；重试；积分不足、并发已满的提示。
  • 连线例外：带 outpaintFrom 的节点，来自原图的连线不进参考图；其它连线照常。存档往返不丢字段。
  • 接线：「扩图」按钮不再弹“敬请期待”；没有 i2i 模型时的提示；模型默认值（沿用原图节点的模型，不支持则取第一个）。

已确认的决定

  1. 点「扩图」先摆占位，点发送之后才生成图片：否则拖框会很卡（用户）。
  2. 合成图先上传到对象存储拿到素材，再带着它走图生图：即调用现有的编辑/图生图能力（用户）。
  3. 面板里加模型选择，只列支持图生图的图片模型（用户）。
  4. 比例写进模型的比例参数，用 16:9、24:1 这种整数比，不用小数（用户）。
  5. 原图和新节点之间画线，但这条线不当参考图（用户）。
  6. 合成图不出现在素材库里（用户）：读代码确认素材库只列节点产物，所以无需额外处理。
  7. 跨域读原图不用考虑（用户）：对象存储的跨域已配好；读不到时仍给一句失败提示，不做降级。
  8. 合成和上传阶段不做取消（用户）：这段时间新节点不显示取消键，任务提交后沿用现有取消。

默认值（我按讨论定的，审阅时可改）

  1. 固定指令：“保持原图内容不变，自然补全图片中的透明区域。”，拼在用户提示词前面，提示词可以留空。
  2. 合成图最长边 ≤ 4096；PNG 超过模型参考图大小上限时提示。
