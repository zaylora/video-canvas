# 画布 UI 设计（外壳 + 节点 + 生成面板）

> 状态：提案 v1 · 2026-10-03 · 配套原型：[画布UI原型.html](画布UI原型.html)

## 1. 设计摘要

**问题**：画布页现在只有零散控件——右上角的积分和保存文字、底部 xyflow 自带的 Controls、左下的设置按钮。没有顶栏，回不到列表，也看不到标题；生成面板宽度固定 384px，节点多时会挡住别的节点；重新生成会直接覆盖旧结果；没有撤销/重做。

**目标**：参考 neoWow 的按钮摆放，用 shadcn/ui 的语言重做整套画布外壳和节点。以**生成效率**为第一优先：从选中节点到点击发送的路径最短，动效只用来给反馈、保持空间上的连贯。

**推荐结论**：

- **布局**：四角加底部中央的"五区布局"。左上是返回、标题和保存状态；右上是「…」菜单、积分和头像；底部中央放主工具条；左下是视图和缩放；右下是统计和告警。
- **生成面板**：节点下方的浮层，宽度跟随节点，空间不够时自动翻到节点上方；顶部用分段 Tabs 切换生成方式；底部是一排参数 chip，加上「积分 + 发送」组合按钮。
- **节点生成历史**：每个节点保存 `outputs[]`。选中节点时，上方的浮条可以展开缩略图来切换版本；下游节点永远读取当前选中的版本。
- **一期新增**：撤销/重做、复制粘贴。拖拽上传、右键菜单和命令面板放到二期。
- **动效**：统一使用已安装的 `motion@13`，全局只有三档时长和一条弹簧曲线，并尊重 `prefers-reduced-motion`。

### 2.2 约束

- 节点数据整体存在 JSONB `payload_json` 里，依靠 `revision` 乐观锁保存。新增字段要同步改 `serializeGraph` / `deserializeGraph` 两处的白名单，并兼容旧数据。
- 节点和连线目前直接用 `useNodesState` 管理，没有独立的 store；要做撤销/重做，必须先在这一层之上加一个操作历史。
- 只有一个节点类型 `canvas`，外观改动可以集中在 `node-card.tsx` / `base-node.tsx`，改动面小。

### 2.3 缺口

没有顶栏，没有撤销/重做和复制粘贴，没有生成历史，没有拖拽上传，没有右键菜单，也没有小地图；生成面板会遮挡其他节点；没有品牌或语义色 token。

### 2.4 不存在的能力（设计中不假设）

协作、会员体系、AI 整理画布助手（neoWow 右侧的吉祥物）。顶栏不为这些预留占位。

## 3. 用户与场景

- **用户**：做 AI 短片和广告素材的创作者，中高频使用，熟悉"提示词 + 参考图"的工作方式。
- **主任务**（按频率排序）：
  1. 选中节点 → 写或改提示词 → 调整模型和参数 → 发送 → 等待 → 对比结果 → 选定版本 → 连到下游。
  2. 从节点 ⊕ 拉出下游节点 → 自动带入参考 → 生成。
  3. 整理画布：框选、复制、对齐、删除，写错时撤销。
- **成功指标**（可验收）：
  - 从选中一个已有提示词的节点到发送：**鼠标 1 次点击，或按 1 次 ⌘↵**。
  - 重新生成后，旧结果 **100% 可以找回**（历史数 ≥ 1）。
  - 误删节点或连线后，⌘Z 能**一步恢复**。
  - 画布上没有任何固定 UI 遮挡选中节点的生成面板（面板会自动翻转或避让）。
  - 面板出现/消失、Tab 切换、历史展开的动画都 ≤ 250ms，交互期间 60fps（Chrome Performance 面板中没有 >16ms 的长帧）。

## 5. 设计原则

1. **素材是主角，UI 退后**：外壳全部用半透明玻璃质感的胶囊，颜色只出现在素材里；彩色只给积分（金色）和状态（语义色）。*依据：用户选择"深色优先 + 中性白"。*
2. **最短生成路径**：选中节点即出面板，并聚焦提示词；⌘↵ 发送；发送按钮上直接显示要花的积分，不需要二次确认。*依据：优先级是"生成效率"。*
3. **动效只服务连续性**：元素从哪里来就回到哪里去（transform-origin 指向触发点）；切换用共享 `layoutId`；任何动效都不阻塞输入。*依据：用户要求"丝滑"，同时效率优先。*
4. **不丢东西**：生成有历史，操作可撤销，保存失败时明确可见。*依据：MVP 选了历史 + 撤销。*
5. **按需出现**：⊕、历史浮条、节点工具只在悬停或选中时出现，平时保持画布干净。*依据：neoWow 的做法，以及 FLORA 被评"学习曲线陡"的反面教训。*

## 6. 推荐方案

### 6.1 外壳布局（五区）

```
┌──────────────────────────────────────────────────────────────────────┐
│ [◆ ▾] 画布名 ▾  ✓已保存                 [··· ] [● ✦ 25] [头像]        │  ← 顶部 12px 边距, 高 40
│                                                                      │
│                       (节点生成历史浮条)                               │
│                         ┌─────────┐                                  │
│                      ⊕  │  节点   │  ⊕                               │
│                         └─────────┘                                  │
│                      ┌───生成面板───┐                                 │
│                                                                      │
│ [▦ ▤ 🔍78%] [⊞] [?]   [ + │ ↖ ✋ │ ↶ ↷ │ 🗀 ◷ ]        [→0 ▦2 ⚠]      │  ← 底部 12px 边距
└──────────────────────────────────────────────────────────────────────┘
```

| 区域 | 内容 | 交互 |
|---|---|---|
| **左上** | Logo 下拉（返回项目列表 / 新建画布）、画布名、保存状态 | 画布名点击后原地变成 Input，Enter/失焦提交，Esc 取消；保存状态有四种：`● 未保存`（有改动但还在等停手，可点击立即保存）、`◌ 保存中`、`✓ 已保存`（2 秒后淡成图标）、`⚠ 保存失败·重试`（红色，可点击） |
| **右上** | 「…」菜单（设置、快捷键、主题、帮助）、积分胶囊、头像 | 积分胶囊左侧是 WS 状态点（绿色=已连接，琥珀色闪烁=重连中），点击打开积分明细 Popover；数值变化时数字滚动；头像菜单里有后台入口和退出 |
| **底部中央** | `[+ 添加]` ｜ `选择 V / 抓手 H` ｜ `撤销 ⌘Z / 重做 ⇧⌘Z` ｜ `素材库` `任务历史` | 「+」是白色实心主按钮，点击后向上弹出节点类型菜单（图片/视频/文本/音频/上传）；选择和抓手用 `layoutId` 滑块；撤销/重做在不可用时 disabled；素材库和任务历史从底部升起抽屉（Sheet） |
| **左下** | 视图切换（点阵/网格/无背景）、缩放 `78%`（点击弹出：放大、缩小、适应 ⇧1、100% ⇧0）、小地图开关、帮助 | 缩放数字在滚轮缩放时实时更新，用 tabular-nums 防止抖动 |
| **右下** | 统计：连线数、节点数、告警（失败节点数） | 点击告警依次定位到失败节点（viewport 平滑飞行） |

**视觉规格**：所有胶囊统一使用 `bg-popover/80 backdrop-blur-xl border border-white/8 shadow-lg rounded-full`（菜单是 `rounded-xl`），高 40px，图标按钮 32px、图标 16px，按钮之间用 1px 竖分隔线。

**窄屏（<768px）**：左下和右下收起；底部工具条只保留 + / 撤销 / 更多；生成面板改为底部 Sheet。

### 6.2 节点卡

- **标题行**（卡片外、上方 8px）：类型图标 + 可双击重命名的标题；运行中时右侧显示 `生成中 42%`。
- **卡片**：`rounded-2xl`，`bg-card`；空状态是虚线描边，中间是类型图标和"输入提示词生成视频"。
  - 选中时描边变成 `ring-2 ring-white/70`（中性白，不用彩色）。
  - 悬停时描边提亮到 `white/20`。
- **⊕ 连接点**：左右各一个，距卡片 24px。悬停或选中时以 `scale 0.6→1 + opacity` 出现，沿用现有"跟随指针"的逻辑。
  - 点击 ⊕ 打开添加菜单，新节点自动接在这一侧。
  - 拖动 ⊕ 拉线；拉线过程中，不兼容的节点降到 40% 透明度，兼容的节点描边高亮（借鉴 Krea）。
- **单一输入口**：左侧只有一个 ⊕，不再按「提示词 / 图片 / 视频」拆成多个口。
  - 接进来的线派什么用，按上游种类定：文字进提示词，素材进对应的参考位。
  - 能不能连，要同时满足两条规则（`canLinkNodes`）：一是节点种类规则；二是下游当前的模型和生成方式收不收这种上游，比如「文生视频」不收图片。图片模型例外：生成方式自动切换（见 6.4），没有引用时也收图片，不然拉不进第一根图片线。模型清单还没加载时，只看种类规则。
  - 拖线到连接点、落在节点身上、落在空白处建节点、倾斜反馈，都走这同一套规则。
  - 旧画布里挂在具名口上的线，会自动迁回这个默认口。
- **生成中**：素材区显示 shimmer 骨架，下方 2px 进度条，进度宽度用弹簧过渡；取消按钮在悬停时出现。
- **失败**：素材区显示失败原因、`重试` 按钮和"积分已退回"的说明。

### 6.3 节点生成历史浮条

- **位置**：选中节点时，出现在标题上方 12px、水平居中的胶囊：`◷ 节点生成历史 3 │ ○`。右侧圆圈是"设为封面 / 当前版本"的状态指示。
- **展开**：点击后胶囊用 `layout` 动画变宽，横向列出缩略图（56×32，最多显示 8 个，超出部分可横向滚动）。当前版本带白色描边，`layoutId="history-active"` 让这个描边在缩略图之间滑动。
- **切换**：点击缩略图后，节点素材做 crossfade（150ms），同时写入 `activeOutput`，进入撤销栈。
- **拖出**：把缩略图拖到画布上，会生成一个"上传素材"类型的新节点（复用 duplicate 逻辑）。
- **下游**：连线读取的永远是 `activeOutput` 指向的素材。切换版本后，下游节点标题旁出现一个小点"上游已变更"（不自动重跑）。
- **没有历史时**（outputs ≤ 1）不显示计数，只显示"节点生成历史"。

### 6.4 生成面板

信息顺序与 neoWow 图 2 一致，从上到下：

1. **生成方式 Tabs**：分段控件，选中块用 `layoutId="op-tab"` 滑动。只显示当前模型支持的生成方式（来自 schema 里的 `params.op`）；只有一种时整行隐藏（对应图 3）。
   - **图片节点不显示 Tabs**：同时支持文生图和图生图的模型，生成方式自动切换——连着图片节点或手动加了参考图就是图生图，否则是文生图，节点里存的 `params.op` 不再生效。素材入口始终显示，加图即切换。视频的图生、全能参考要用户判断，仍保留 Tabs。实现见 `utils/tasks/capabilities.ts` 的 `isAutoOp` / `currentOp` / `refPanelOp`。
2. **引用条**（详见 6.7）：所有种类节点的面板顶部都有，列出接进来的全部上游；虚线「+」从画布里挑素材并自动连线。
   - **变更：原为**"参考素材行"只在图片 / 视频节点出现、过滤掉音频和文本，「+」打开素材库。
   - 图片模型额外显示"风格转绘"和"调色盘"两个 chip（是否显示由 schema 决定）。
3. **提示词**：自适应高度的编辑器，最小 2 行，最大 8 行，超出后滚动；右下角显示 `15/16000`，接近上限时变成琥珀色。输入 `@` 弹出引用菜单，选中的素材以 chip 形式嵌在文字里（详见 6.7）。
   - **变更：原为** textarea。
4. **底栏 chip 行**：`模型 ▾`（显示厂商头像）、`480p · 16:9 · 4s ▾`（参数摘要，点击弹出 `video-param-panel` 的 Popover）、`分镜栏编辑`（仅视频，二期）；右侧是 `批量 ×N`，以及 `[✦ 480 | ↑]` 组合发送按钮。
   - 积分不够时，组合按钮变灰，悬停提示"积分不足，还差 N"。
   - 没有提示词时，发送按钮是 disabled。
5. **展开按钮**（右上角 ↗）：把面板放大成居中的 Dialog（共享 `layoutId="prompt-panel"`，从原位置放大过去），用来写长提示词，Esc 收回。

**定位规则**（解决遮挡）：

- 宽度 = `clamp(480px, 节点屏幕宽度 + 160px, 720px)`，**不随缩放变小**，保证可读。
- 下方空间不够时翻到节点上方（此时历史浮条移到节点下方）；水平方向会贴住视口边缘，保持 16px 边距。
- **只有点击才打开**：直接拖动一个还没选中的节点时，它会顺带被选中，但不打开历史浮条和生成面板，点它一下才打开。新建节点、从抽屉里定位到的节点照常直接打开。
- 拖动一个已经打开的节点时，历史浮条和生成面板整个收起，松手后再浮出来。
- 拖动画布或框选时，面板 `opacity → 0.35` 并且不响应指针，松手后恢复。

**键盘**：选中节点后按 `Enter` 聚焦提示词；在提示词里 `⌘↵` 发送、`Esc` 失焦（再按一次 Esc 取消选中）；`⌘⇧↵` 是批量发送。

### 6.5 多选（参考 neoWow）

- 选中 2 个及以上节点时，节点不再各自浮出生成面板和历史浮条，统一交给选区：
  - 节点外围画一个淡色圆角底框，跟着画布一起缩放；
  - 底框上方浮出选区工具条，大小不随缩放变化：`N 个节点 | 整理布局 ▾ | 复制 | 下载 | 删除`。
- **引用选中节点生成**：选框右侧垂直居中有一个「+」，大小不随缩放变化。拖出去松手，或直接点一下，弹出「引用选中的 N 个节点生成」菜单；拖动时每个被选节点从右侧出口各拉一根线汇到指针处。选种类后在松手处新建节点，并从每个**接得上**的被选节点各连一根线（规则同 `canLinkNodes`）；接不上的跳过并 toast 告知数量，种类菜单里只要有一个被选节点接得上就可点，「上传素材」整项禁用。实现见 `pages/canvas/selection-fan-handle.tsx`、`hooks/use-canvas-menu.ts` 的 `openGroupMenu`。
- **整理布局**：有横向、纵向、网格三种排列，以选区左上角为起点，用 260ms 缓动移到新位置；整个过程在撤销栈里只算一步。
- **打组**、**批量高清**：要先有分组数据结构和超分模型，放到二期。

### 6.7 引用条与 @ 引用

**问题**：节点引用了哪些上游，原来只有图片 / 视频的面板里看得到，而且音频、文本上游不显示；写提示词时也没法指明"这句话说的是哪张图"。用户只能对着连线猜。

**目标**：
1. 不论文本、音频、图片、视频，以及以后加的节点种类，面板最上面都是引用条，一眼看到"这个节点吃进了什么"。这是所有节点共用的基础规则。
2. 在提示词里输入 `@`，就能点名画布上的素材；当前节点接不了的素材不出现在菜单里。

**控件说明**

|---|---|---|---|

**哪些素材能出现在 @ 菜单（"接不了的不显示"）**

同时满足才列出，否则直接不显示（不置灰）：
1. 不是当前节点自己；
2. 已经有产出（文本有正文；图片 / 视频 / 音频有当前版本）；
3. 能接到当前节点：节点种类规则 + 当前模型和生成方式收这种上游，就是 `canLinkNodes`。比如「文生视频」时菜单只剩文本，切到「全能参考」后图片、视频、音频都回来了；
4. 不在当前节点的下游（再连回来会成环）。

**@ 未连线的素材 = 自动连一根线**：选中「画布中」的素材时，在插入 chip 的同时补一根 `素材 → 当前节点` 的连线，引用条末尾多出它的缩略图并 toast "已连线「X」"。连线加上插 chip 在撤销栈里只算**一步**，并且会吞掉正在防抖中的打字步，⌘Z 一次就回到输入 `@` 之前。

**提示词存储**：仍是纯文本，引用写成 `@[素材名](节点 id)`，编辑器负责把它渲染成 chip（显示画布上的最新标题，节点被删后才用存下的名字）。字数按素材名计。

**提交时的展开**（`buildTaskInput`）：
- 图片 / 视频 / 音频引用换成「图片1」「视频2」「音频1」，序号是它在提交的 `images / videos / audios` 里的位置；
- 文本引用换成那个文本节点的正文；
- 连线已断、或当前生成方式没提交这份素材的，退回成素材名。
- **变更：原为**"上游文字优先于手填，接了文本节点提示词框就禁用"。现在提示词框始终可写：手填的优先，没手填才用第一个文本上游的正文，占位文字会说明"留空就用上游「X」的文字"。

| 触发 | 属性 | 时长 / 曲线 | 方向 |

**用户反馈后的修订（2026-10-03）**

- **每格右上角加 ×**：连线来的点 × 断开连线，**提示词里引用它的 chip 一起删掉**（连同 chip 后面那个空格）；⌘Z 一次，线和 chip 一起回来。手动上传的点 × 移除素材。× 常驻显示，不用悬停。**变更：原为**"连线来的不能删，只能断开连线"。删除线样式只留给节点被删掉的情况。
- **节点默认名**，让 @ 菜单里分得清：
  - 新建节点：画布里没有同名的就用种类名，有了就依次叫「图片 2」「图片 3」。
  - 上传的素材：用文件名，去掉扩展名，重名同样编号。
  - 复制节点（⌘D、⌘C/⌘V、批量生成复制出的节点）：复制一份叫「X 副本」，已被占用就叫「X 副本二」；一次复制好几份叫「X 副本一」「X 副本二」……复制副本时按原名续编，不会叠成「副本 副本」。**变更：原为**复制出「X 2」「X 3」。
- **节点可改名**：双击节点标题，原地变成输入框，Enter 或失焦提交、Esc 取消。名字会去掉首尾空白，换行收成空格，最长 40 字，清空就退回原名。@ 菜单按节点名搜索，chip 显示最新的名字。名字存在画布 payload 的 `label` 里，后端不用改。
- **还没出图的上游不再报错**：提交时直接跳过，引用条里仍是虚线格加"还没生成"的提示。图片节点连着的图如果都还没出图，就按文生图提交。**变更：原为**提示"上游「X」还没有可用的素材"并且不让发送。
- chip 改成 `vertical-align: middle`，缩略图不同的 chip 高度一致。

### 6.9 双击节点预览原图（媒体预览弹层）

**问题**：节点里的图只有 384px 宽，低缩放时还只加载缩略图，没法看细节；视频在节点里播放也太小。画布上双击节点目前什么也不发生（标题除外，双击标题是改名）。

**目标**：双击有图片或视频的节点，弹出沉浸式预览，直接看原图 / 原视频；不离开画布就能连续翻看整张画布的成果，看完一键回到节点。

**已定（访谈）**：
- 范围：画布上所有有素材的**图片、视频**节点，混排，按位置排序（先按行从上到下，同一行内从左到右；行高容差取 `节点高度 / 2`，避免略有错位的节点来回乱序）。

#### 键鼠

| 键 | 作用 |
|---|---|
| 双击节点（图片 / 视频区域） | 打开预览；标题上的双击仍是改名，输入框、按钮、视频控制条上的双击不触发 |

| Esc | 关闭 |

双击不能和已有行为冲突：画布空白双击弹菜单已经排除了 `.react-flow__node`，节点上的双击是干净的。节点内的视频控制条、按钮、标题输入框都带 `nodrag` 或自己拦截了事件，在它们上面的双击不触发预览；视频画面区域的双击会先触发两次单击（播放状态切两次，最终不变），再打开预览，预览打开时节点里的视频暂停。

## 7. 动效规范（Motion）

| Token | 值 | 用途 |
|---|---|---|
| `dur.fast` | 120ms `ease-out` | hover 状态、按钮按下（`scale 0.96`） |
| `dur.base` | 180ms `[0.2, 0, 0, 1]` | 菜单、Popover、浮条出现/消失（`opacity + scale 0.96 + y 4`） |
| `dur.slow` | 240ms | Sheet、Dialog |
| `spring.snappy` | `{ type: "spring", stiffness: 500, damping: 38, mass: 0.8 }` | `layoutId` 滑块、面板 layout 变宽、进度条 |

- **出现的方向**：底部工具条的菜单向上弹出（`origin-bottom`），顶部菜单向下弹出，生成面板从节点方向弹出（`y: -6 → 0`）。
- **退出比进入快**：退出时长 = 进入的 70%。
- **只做 transform 和 opacity 动画**：不对 `width/height/top` 做动画，宽度变化用 `layout`。
- **数字变化**（积分、缩放百分比、进度）：用 `useSpring` 插值，配合 `tabular-nums`。
- **按下反馈**：所有按钮 `whileTap={{ scale: 0.96 }}`。
- **画布飞行**（定位到失败节点、适应视图）：使用 xyflow `setViewport({ duration: 300 })`。
- **`prefers-reduced-motion`**：通过 `<MotionConfig reducedMotion="user">` 全局降级为只做淡入淡出。
- **进入画布（已定：聚焦显影）**：
  - 加载层是点阵底，中间是白色取景框 logo，下面写产品名和「正在打开「画布名」」，它们由虚到实、由大到正聚焦出来（0.9s，名字晚 0.12s）。
  - 数据到了、并且加载层至少停留了 650ms，logo 和名字再虚掉、缩小一点（0.32s），整层随后淡出（0.38s）。
  - 退场开始时画布内容入场：节点按顺序浮上来，顶栏落下、底栏升起，连线稍后淡入。
  - 性能约束：
    - 加载和入场全部用 CSS 关键帧，只动 transform、opacity，logo 再加一个 filter；这样在合成线程上跑，画布挂载时主线程再忙也不掉帧。
    - 节点入场不做 blur，节点里有大图，blur 太贵。
    - 入场靠直接在 DOM 上挂 `data-entering` 触发，不经过 React state，免得整张画布重渲染。
- **连线流光（已定：光带）**：
  - 一段两头渐隐的亮带，沿连线从上游扫到下游，平时一趟 2.6s；下游在生成时换成运行色，一趟 1.1s。
  - 做法是渐变描边加平移渐变，不移动任何形状，所以拖动节点时不会跳帧。
  - 系统开了「减少动态效果」时只显示静止的底线。
- **不做**：常驻的循环动画（连线流光保留，但只在生成中的边上显示）。

## 9. 状态与异常

| 场景 | 表现 |
|---|---|
| 画布加载中 | 外壳先渲染（标题显示骨架），画布区域显示点阵；节点就绪后整体淡入 |

## 10. 数据与工程影响（建议，未改代码）

### 10.1 生成历史 → payload 字段

在 `CanvasNodeData` 中新增：

```ts
/** 历次产出，新的在后；src/mediaType/assetId 仍保留为"当前版本"的镜像以兼容旧代码 */
outputs?: Array<{ id: string; src: string; mediaType: NodeMediaType; assetId?: string;
                  taskId?: string; model?: string; createdAt: number }>;
/** 当前选中的 outputs[].id */
activeOutputId?: string;
```

- `serializeGraph` / `deserializeGraph` 的白名单要加上这两个字段。旧数据没有 `outputs` 时，用 `src` 合成一条记录。
- `use-task-backfill.ts` 在回填时改成 **push 进 outputs，并设为当前版本**，同时镜像到 `src`。
- **保留上限**：每个节点最多 20 条，超出时丢掉最旧的（只删引用，不删素材），避免 payload 膨胀。
- 后端不需要改：整个 payload 存在 JSONB 里，结构对后端是透明的。

### 10.2 撤销 / 重做

- 新建 `store/canvas-history.ts`（zustand），保存 `past/future` 两个快照栈，每个快照是 `{nodes, edges}` 的浅拷贝。上限 100 步。
- **入栈时机**：拖拽结束（`onNodeDragStop`）、增删节点或连线、粘贴、切换历史版本、修改标题。提示词输入以失焦或 800ms 防抖为一步，不按键入逐字入栈。
- **不入栈**：任务进度和回填（服务端事件），以及视口变化。
- 撤销不会取消已经提交的生成任务。

### 10.3 复制粘贴

- 序列化选中的节点，以及**两端都在选区内**的连线，写入剪贴板（`application/x-video-canvas` + 纯文本兜底）。
- 粘贴时重新生成 id，清空 `taskId/status`，保留 `outputs`。

### 10.4 组件拆分建议

```
components/canvas/chrome/   top-left-bar.tsx  top-right-bar.tsx  bottom-toolbar.tsx
                            view-controls.tsx  stats-bar.tsx  chrome-pill.tsx
components/canvas/node/     node-history-strip.tsx  generate-panel.tsx  op-tabs.tsx
                            ref-strip.tsx  prompt-mention.tsx  send-button.tsx
lib/motion.ts               dur / spring 常量 + 常用 variants
```

`chrome-pill.tsx` 遵循 shadcn 的平铺可组合写法（`ChromePill` / `ChromePillButton` / `ChromePillSeparator`），页面直接组合使用。

### 10.5 风险

- **面板定位**：NodeToolbar 不支持自动翻转，需要自己根据节点的屏幕矩形计算位置（`useStore` 订阅 transform）。要注意在拖动时节流。
- **快照式撤销的内存**：100 步 × 大画布的开销。节点 data 不深拷贝，靠不可变更新共享引用来控制。
- **`backdrop-blur` 的性能**：同屏不超过 6 个模糊层；在低端设备上可以用 `@supports` 或设置项降级为纯色背景。

## 11. 方案取舍

| 决策 | 选择 | 放弃 | 理由 |
|---|---|---|---|
| 面板形态 | 节点下方浮层 | 底部 Dock、右侧栏 | 空间关系最强，和现状一致；遮挡问题用翻转和避让解决 |
| 历史 | 节点内 outputs[] | 生成兄弟节点、只放素材库 | 不让画布变乱，又能保证 100% 找回 |
| 生成方式 | 顶部 Tabs | 底栏下拉 | 切换一步完成，并且当前方式一眼可见 |
| 主题 | 深色 + 中性白 | 品牌强调色 | 让颜色留给素材；白色主按钮的辨识度已经足够 |
| 设置入口 | 右上「…」菜单 | 底部工具条 | 设置是低频操作，底部工具条只放高频操作 |
| 吉祥物助手、协作、会员 | 不做 | — | 本项目没有这些能力，不做空的占位 |

## 12. MVP 与后续
