# 用户个人中心设计

> - **范围**：给已登录用户一个独立的 `/profile` 页面，包含：资料（昵称、头像）、安全（修改密码）、活跃热力图（GitHub 风格）、统计卡片、积分流水。不含管理员侧功能。
> - **日期 / 状态**：2026-10-09 · 设计已确认，待实现。
> - **证据约定**：**事实**附文件路径或来源链接；**推断**是基于事实的判断；**提案**是尚未实现的设计。
> - **方案演进**：访谈过程中用户追加了“修改账号名称、修改头像”。“账号名称”经确认指昵称 `nickname`，`username` 保持不可改（见 §11）。看过原型后，用户要求积分流水从“加载更多”（游标分页）改为页码分页，见 §6.5 和 §8.2。
> - **配套演示**：[个人中心-演示.html](个人中心-演示.html)（建议先读）。

## 1. 设计摘要

- **问题**：系统没有任何面向用户本人的账户能力。用户不能改密码、昵称、头像，也看不到自己的创作活跃度和积分去向。侧栏里的“个人中心”一直是禁用状态，标着“即将上线”。
- **目标**：
  - 用户能自助完成改密码、改昵称、换头像。
  - 能直观看到过去一年的创作节奏（热力图）和关键累计数据。
  - 能查到自己每一笔积分的去向。
- **推荐结论**：
  - 在 HomeLayout 下新增独立页 `/profile`，顶部是身份卡，下面分 4 个 tab：概览、积分、资料、安全。
  - 后端新增一组 `/api/v1/me/*` 接口。
  - 改密码复用现成的 `token_version` 失效机制，同时给当前浏览器续签 token。
  - 热力图手写 SVG，统计生成任务数（不含试跑），按浏览器时区分天。
  - 头像用 react-easy-crop 做圆形裁剪，导出 512×512 WebP 后上传，存进现有对象存储。

### 2.2 设计约束

- 后端分层为 router → handler → service → repository，service 不能 import gin 或 gorm；用户数据查询必须带 user_id 条件（`backend/AGENTS.md:50-75`）。
- 已发布的错误码不能改，新增错误码放到新号段。
- User 结构会进 Redis，新增字段要带 json 标签。旧缓存里没有新字段时会反序列化成零值，可以接受。
- 后台用的 `admin-ui` 和画布、首页用的 `components/ui` 分开维护（项目记忆）。个人中心属于首页一侧，使用 `components/ui`。

### 2.3 当前缺口

- 没有用户自助账户接口，也没有前端的“当前用户”状态。
- 没有头像字段和头像存储约定。
- 热力图需要的 `(user_id, created_at)` 索引不存在。
- 改密码没有防爆破机制。登录接口本身也没有，但不在本期范围。

## 3. 用户与场景

- **目标用户**：使用画布创作的普通用户（role=user），也包括管理员本人。
- **触发场景**：
  1. 首次登录后想设置昵称和头像，在画布协作、Agent 对话里露出。
  2. 拿到管理员重置的临时密码后，自己改成新密码。
  3. 积分比预期少了，想查清每一笔积分的去向。
  4. 想看看自己这一年的创作节奏，获得一点成就感。
- **成功指标**（提案）：
  - 用户无需联系管理员即可完成改密码。
  - 积分疑问可以自助查明。
  - 个人中心页首屏加载（P75）不超过 1 秒。

### 4.3 安全实践

- OWASP Authentication Cheat Sheet：改密码需要在已登录状态下验证当前密码；新密码要拦截常见和已泄露的密码；不强制字符组合；要有失败计数和退避。<https://cheatsheetseries.owasp.org/cheatsheets/Authentication_Cheat_Sheet.html>
- OWASP Session Management：密码变化后要轮换会话，服务端要真正作废旧会话。<https://cheatsheetseries.owasp.org/cheatsheets/Session_Management_Cheat_Sheet.html>
- NIST SP 800-63B-4：只用密码登录时最短 15 位（本项目经用户确认采用 8 位，见 §11）；不得强制字符组合；必须做黑名单检查；应允许粘贴和显示密码。<https://pages.nist.gov/800-63-4/sp800-63b.html>

## 5. 设计原则

1. **能自助就不找管理员**：改密码、改资料、查积分，用户都能独立完成，不依赖后台。
2. **身份稳定**：`username` 是登录凭据、写在 JWT 里，不开放修改。对外展示的身份交给 `nickname` 和头像。
3. **安全动作有即时效果**：改密码后，其他设备立即失效；当前设备无感续签。
4. **数据口径单一可解释**：热力图只统计“提交的生成任务”，tooltip 里说明口径。
5. **复用现有机制**：token_version、InvalidateUser、对象存储、ledger 查询与筛选、TaskStats 都直接复用，不另起一套。

## 6. 推荐方案

### 6.1 信息架构

```
HomeLayout
└── /profile                      个人中心（新页面）
    ├── 身份卡（常驻顶部）        头像 · 昵称 · @username · 邮箱 · 角色徽标 · 加入时间
    └── Tabs（?tab= 同步到 URL）
        ├── 概览 overview（默认）  统计卡片 ×4 + 活跃热力图（含年份切换）
        ├── 积分 credits           余额卡 + 积分流水（类型筛选 + 页码分页）
        ├── 资料 profile           昵称表单 + 头像（上传 / 裁剪 / 移除）
        └── 安全 security          修改密码表单
```

**入口**：
- 侧栏账号菜单里的“个人中心”改为可用，跳转 `/profile`（`app-sidebar.tsx:322`）。
- 画布右上角的账户菜单新增“个人中心”项（`top-right-bar.tsx:198`）。
- 身份卡上的头像可以点击，直接跳到“资料”tab。

### 6.2 身份卡

- 左侧 64px 圆形头像；没有头像时显示首字母兜底，取 nickname 或 username 的第一个字符，背景色按 user_id 哈希出固定色。
- 主标题显示 `nickname`，为空时回落到 `username`；副标题为 `@username · email`。
- 角色徽标只对 admin / super_admin 显示。
- 加入时间格式为“2025-03-12 加入”。
- 右侧有一个“编辑资料”按钮，切到“资料”tab。

### 6.3 概览：统计卡片

4 张卡片，数据来自 `GET /me/stats`：

| 卡片 | 主数字 | 副文案 |
|---|---|---|
| 累计生成 | `total` | 近 7 天 `last7d` 次 |
| 成功率 | `success / (success + failed)`，分母为 0 时显示“—” | 成功 `success` · 失败 `failed` |
| 画布 | `canvas_count` | 未删除的画布数 |
| 累计消耗积分 | `spent_credits` | 当前可用 `available`，来自 `/credits` |

统计口径与后台的 TaskStats 一致：排除 `is_test`；进行中、已取消的任务只计入 total。

### 6.4 概览：活跃热力图

- **口径**：`generation_tasks` 中 `is_test = false` 的任务，按 `created_at` 在用户时区的日期计数。成功和失败都算，因为它统计的是“创作行为”，不是“产出”。
- **范围**：
  - 默认显示“最近一年”，即今天往前 52 周补齐到周日，共 53 列。
  - 右侧有年份切换：最近一年，以及从注册年份到今年的各个自然年。
- **布局**：
  - 7 行（周日到周六，与 GitHub 一致）× 53 列，格子 11px、间距 3px、圆角 2px。
  - 上方标月份，左侧标“一、三、五”。
  - 宽度不够时横向滚动，并自动滚到最右（最近）。
- **分档**（与 GitHub 同类做法）：
  - 0 次为 level 0。
  - 非零天按次数排序后取 Q1、Q2、Q3：≤Q1 为 1 档，≤Q2 为 2 档，≤Q3 为 3 档，>Q3 为 4 档。
  - 非零天少于 4 天时退化处理：1 次为 1 档，其余按最大值线性分到 2–4 档。
  - 分档在前端计算，后端只返回原始计数。
- **颜色**：
  - 用 5 个 CSS 变量 `--heat-0..4`，明暗主题各一套，基于 primary 色相做透明度梯度。
  - 0 档为 `muted`。
- **tooltip**（复用 shadcn Tooltip）：
  - 有活动的日子显示“2026年10月8日 星期四 · 12 次生成”，第二行显示“图片 8 · 视频 3 · 音频 1”。
  - 0 次的日子显示“2026年10月8日 · 无生成”。
  - 未来日期的格子不渲染。注册之前的日期照常渲染为 0 档，与 GitHub 一致。
- **汇总行**：
  - 左下显示“过去一年共 N 次生成 · 活跃 X 天”，选了年份时为“2025 年共 N 次”。
  - 右下显示“最长连续 L 天 · 当前连续 C 天”，以及“少 ▢▢▢▢▢ 多”图例。
  - 连续天数：从“今天”往前数，今天为 0 时从“昨天”开始数（与 GitHub 一致）；选了年份时不显示当前连续天数。
- **键盘与无障碍**：
  - 网格为 `role="grid"`，用 roving tabindex。
  - 方向键逐格移动，Home/End 跳到行首/行尾，PageUp/PageDown 跳到列首/列尾。
  - 聚焦时显示 tooltip；每格的 `aria-label` 与 tooltip 文案相同。
- **本期不做**：点击格子筛选任务列表（见 §10 后续阶段）。

### 6.5 积分 tab

- 顶部余额卡：可用 / 余额 / 冻结，数据来自 `GET /credits`。
- 流水列表：
  - 筛选：全部 / 生成任务 / 管理员调整，对应后端 `type=all|task|admin`。
  - 每行显示：类型图标与名称、金额、关联任务、时间。
    - 金额：按**余额变化**展示，只有余额真的变了才带正负号。
      - 结算 settle：`−n`，正文色，表示真实扣减。
      - 管理员调整：`±n`，加为绿色，减为正文色。
      - 初始积分：`+n`，绿色。
      - 冻结 freeze、退回 refund：只改变冻结额、不改变余额，灰色显示为“冻结 n”“解冻 n”，不带正负号。这样可以避免一次生成在“冻结 −n”和“结算 −n”两行里看起来像被扣了两次。
    - 关联任务显示 `#task_id`；Agent 调用显示“Agent 对话”。
    - 时间用浏览器时区格式化。
  - **页码分页**（用户确认，参考 LiblibAI 积分明细）：
    - 底部左侧显示“共 N 条”；右侧依次是每页条数选择（10 / 20 / 50，默认 20）、上一页、页码、下一页。
    - 页码最多显示 7 个，超出的部分用省略号折叠，例如 `1 … 4 5 6 … 12`；首页、末页总是显示。
    - 切换筛选或每页条数时回到第 1 页；翻页后列表滚动到卡片顶部。
    - 翻页加载时保留当前页内容并降低透明度，不闪成骨架；失败时保留当前页，在分页条旁显示“加载失败，重试”。
    - 当前页码同步到 URL：`?tab=credits&page=3`，刷新后停在原页。
    - 页码超出范围时（例如流水被清理后总页数变少），自动跳到最后一页。
    - 只有 1 页时隐藏页码，只显示“共 N 条”。
  - 空状态：“还没有积分记录”。
- 管理员调整的 **`note` 向用户展示**（用户确认），`operator_id` 不展示：
  - 行内副标题显示备注原文，例如“国庆活动补发”；超过一行时截断，悬停显示全文。备注最多 100 字（沿用后台的 `validateNote`）。
  - 备注作为纯文本渲染，不解析链接和 HTML。
  - 不显示是哪位管理员操作的，只显示“管理员调整”。
  - **后台同步改动**：既然备注对用户可见，后台的两个备注输入框要明确告知管理员。
    - 单个调整：`web/src/pages/admin/users/credit-popover.tsx:217` 的 placeholder 改为“备注（必填，用户可见）”。
    - 批量发放：`web/src/pages/admin/users/bulk-bar.tsx:188` 的 placeholder 改为“备注（必填，用户可见，如：国庆活动补发）”。
    - 两处输入框下方加一行小字：“该备注会显示在用户的积分流水中”。
  - **存量备注**：上线前写的备注也会对用户可见。上线前需要管理员抽查一遍历史备注，确认没有内部信息（见 §10 验收）。

### 6.6 资料 tab

**昵称**
- 单行输入，预填当前昵称，placeholder 为 username。
- 规则：去掉首尾空白后长度 0–32 个字符（按 rune 计）；不能包含控制字符和换行。
- 允许清空，清空后回落显示 username。
- 值有变化时“保存”按钮才可用；保存中禁用并显示 spinner。
- 成功后 toast“昵称已更新”，身份卡和所有头像菜单同步刷新。

**头像**
1. 点击“上传新头像”或把图片拖到头像区（复用 react-dropzone）。
2. 前端校验：类型 png/jpeg/webp/gif，原文件不超过 10MB；不符合时就地显示错误，不打开裁剪框。
3. 弹出裁剪 Dialog（react-easy-crop）：
   - 圆形遮罩，固定 1:1 比例。
   - 缩放滑块 1–3 倍，支持拖拽，支持方向键微调。
   - 底部按钮为“取消 / 保存”。
4. 保存时，前端用 canvas 把选区导出为 512×512 WebP（quality 0.9），浏览器不支持 WebP 编码时导出 PNG，然后 `POST /me/avatar` 上传。
5. 成功后关闭 Dialog，全站头像更新。失败时 Dialog 保持打开并显示错误，用户可以重试。
6. 已有头像时显示“移除头像”（二次确认），调用 `DELETE /me/avatar`，恢复首字母头像。

GIF 经过 canvas 导出后会变成静态图，界面上提示“动图会保存为静态图”。

### 6.7 安全 tab：修改密码

**表单**

三个字段：当前密码、新密码、确认新密码。每个都带显示密码开关；允许粘贴；`autocomplete` 分别为 `current-password`、`new-password`、`new-password`。

**前端即时校验**（只做提示，以后端为准）：
- 新密码 8–72 字节，显示“已输入 n / 至少 8 位”。
- 与当前密码相同时提示“新密码不能与当前密码相同”。
- 两次输入不一致时提示“两次输入不一致”。
- 不做字符组合要求，也不显示强度条（强度计放到后续阶段）。

**提交前提示**：“修改后，其他设备上的登录会立即失效，当前设备保持登录。”

**提交**：调用 `PUT /me/password`。

**成功**：
1. 用响应里的新 token 调用 `setToken`。同一浏览器的其他标签页共享 localStorage，所以也会自动用上新 token。
2. 当前页的 WS 会被服务端断开，自动重连流程用新 token 申请 ticket 后恢复。
3. toast“密码已修改，其他设备已退出登录”，清空表单。

**失败**（错误码见 §8.3）：
- 当前密码错误：在“当前密码”字段下方报错，并显示剩余尝试次数。
- 错误次数过多：在表单顶部显示错误提示框“尝试过于频繁，请 15 分钟后再试”，提交按钮禁用并倒计时。
- 新密码太常见：在“新密码”字段下方报错。

### 6.8 统一密码规则：注册与改密码完全一致

用户确认：**注册时的密码规则与改密码完全相同**，前后端各只保留一份实现，多个入口共用。

| 规则 | 注册 | 个人中心改密码 | 后台重置（手填新密码时） | 登录 |
|---|---|---|---|---|
| 长度 8–72 字节（UTF-8） | ✓ | ✓ | ✓ | **仍接受 6–128**，保证老用户能登录 |
| 不在弱密码表中（不区分大小写） | ✓ | ✓ | ✓ | — |
| 不等于用户名 | ✓ | ✓ | ✓ | — |
| 不能与当前密码相同 | —（没有旧密码） | ✓ | — | — |
| 不要求字符组合，不显示强度条 | ✓ | ✓ | ✓ | — |

**统一的提示文案**（前后端一致）：
- 输入框 placeholder：“至少 8 位”。
- 太短：“密码至少 8 位”；太长：“密码最多 72 字节（约 24 个汉字或 72 个英文字符）”。
- 等于用户名：“密码不能与用户名相同”。
- 命中弱密码表：“这个密码过于常见，请换一个”（55003）。
- 两次不一致：“两次输入的密码不一致”（沿用现有文案）。

**实现落点**：
- 后端：`service/password_rules.go`（提案）提供 `validateNewPassword(username, pw string) error`，由注册、改密码、后台重置三处调用。弱密码表用 `go:embed` 内置，约 1000 条。
  - 现有的 bcrypt 72 字节校验（`admin_user_security.go:163-171`）并入这个函数，不再单独维护。
- 前端：改造 `web/src/utils/auth/register-rules.ts` 里现有的 `validatePassword(value)` 为 `validatePassword(value, username)`：长度按 `new TextEncoder().encode(value).length` 计算，同时检查是否等于用户名。注册表单和个人中心的安全 tab 都调用它。
  - 弱密码表**只放在后端**，前端不内置，避免包体积增大，也避免两份表不一致。注册接口返回 55003 时，注册表单把错误显示在“密码”字段下方，而不是 toast。
  - 注册表单的 placeholder 从“至少 6 位”改为“至少 8 位”（`web/src/pages/login/register-form.tsx:200`）。
- 后台重置密码不传新密码时，系统生成 16 位临时密码，不受影响；手填的新密码按同一规则校验（`ResetPasswordReq.NewPassword` 的 binding 从 `min=6` 改为 `min=8`）。

**对存量用户的影响**：已有的 6–7 位密码继续有效，可以正常登录；只有下次修改密码时才需要满足新规则。本期不强制老用户改密码。

**并发与冲突**：
- 资料修改是“后写覆盖”，不加 revision（只有用户本人能改，冲突概率极低）。
- 改密码与后台重置同时发生：两边都会 `token_version+1`，后到的结果生效。如果后台的重置后到，用户新拿到的 token 也会失效，需要重新登录。这个行为可以接受。

### 8.3 核心流程

**改密码**（`service.ChangePassword`）：

```
ChangePassword(uid, old, new, ip):
  if limiter.Locked(uid)                    → 55004
  validateNewPassword(new):                 // 与注册共用
    len([]byte(new)) in [8,72] else 10001
    lower(new) ∉ weakList(go:embed，约 1000 条) && new != username else 55003
  u := repo.Get(uid)
  if !bcrypt.Compare(u.Password, old):
    left := limiter.Fail(uid)              // 15 分钟窗口内 5 次，超过锁 15 分钟
    → 55001（附剩余次数）
  if bcrypt.Compare(u.Password, new)        → 55002
  limiter.Reset(uid)
  repo.ResetPassword(uid, bcrypt(new))      // 复用：同一条 UPDATE 改哈希并 token_version+1
  InvalidateUser(uid)
  hub.DisconnectUser(uid)                   // 断开所有 WS，当前页会用新 token 重连
  return issueToken(reloadedUser)           // 新 token 带最新的 token_version
```

- 限流器参照 `RegisterCodeStore` 的 Redis 计数实现，key 为 `pwchg:fail:<uid>`。
- **Redis 未启用时**：退化为进程内计数（单实例部署可以接受），在实现时写明。

**热力图查询**（repository）：

```sql
SELECT to_char((created_at AT TIME ZONE $tz)::date, 'YYYY-MM-DD') AS d,
       COUNT(*) AS count,
       COUNT(*) FILTER (WHERE kind='image') AS image,
       COUNT(*) FILTER (WHERE kind='video') AS video,
       COUNT(*) FILTER (WHERE kind='audio') AS audio,
       COUNT(*) FILTER (WHERE kind='text')  AS text
FROM generation_tasks
WHERE user_id = $uid AND is_test = FALSE
  AND created_at >= $startUTC AND created_at < $endUTC
GROUP BY d ORDER BY d;
```

- service 用 `time.LoadLocation(tz)` 校验时区，非法时回落到 `Asia/Shanghai`，不报错。
- 再用该 location 算出 `[start 00:00, end+1 00:00)` 对应的 UTC 边界。
- **必须** `import _ "time/tzdata"`：容器镜像里可能没有系统 tzdata，没有它 LoadLocation 会失败。

**头像上传**：
1. 读取最多 2MB + 1 字节，超出返回 55006。
2. 复用 `asset_probe` 的内容嗅探，只允许 png/jpeg/webp/gif，否则返回 55005。
3. 解码出图片尺寸，超过 2048×2048 返回 55006。服务端不做缩放，因为前端已经裁成 512。
4. 写入存储，然后更新 `avatar_key`。
5. 尽力删除旧 key，失败只记日志，不报错。
6. 调用 InvalidateUser。

**注册规则同步**（详见 §6.8）：
- `RegisterUserReq.Password` 的 binding 改为 `min=8,max=128`，service 里再调用同一个 `validateNewPassword`，按字节检查上限。
- **`LoginUserReq` 保持 `min=6`**，否则老用户的 6–7 位密码将无法登录。
- `ResetPasswordReq.NewPassword` 改为 `omitempty,min=8,max=128`，并接入 `validateNewPassword`。
- 注册接口新增可能返回的错误：55003（过于常见）。“等于用户名”也归入 55003，文案为“密码不能与用户名相同”。

| 维度（权重） | A. 独立页 + /me 接口（推荐） | B. 设置弹窗 | C. 独立页展示 + 弹窗编辑 |
|---|---|---|---|
| 热力图展示（0.3） | 5 | 2 | 5 |
| 实现成本（0.25） | 4 | 3 | 2 |
| 可直达 / 可分享（0.2） | 5 | 1 | 4 |
| 入口一致性（0.15） | 4 | 4 | 2 |
| 画布内便捷（0.1） | 3 | 5 | 3 |
| **加权** | **4.4** | 2.75 | 3.55 |

权重说明：用户选了“独立页”，热力图是本期亮点，所以展示空间权重最高。

**明确放弃**：
- 修改 username：会影响登录凭据和 JWT，GitHub 的经验表明代价大。
- 综合活动口径：要查 4 张表、建 4 个索引，口径难以解释。
- 15 位密码下限：对国内用户门槛过高。
- 热力图第三方库。
- 头像进入素材库。
- 本期不做登录记录、退出所有设备、改邮箱、改密码邮件通知。

**与设计的出入**
1. `users` 表额外增加内部字段 `avatar_storage_id`。`/files/<key>` 原来靠 assets 表反查存储，头像不进 assets 表，所以改为对 `avatars/` 前缀按用户表反查。被替换或移除的旧头像 key 一律返回 404。对外契约不变。
2. 流水的 `amount` 带正负号，与后台口径一致：freeze/settle 为负，refund/initial 为正，admin_adjust 用原值。前端按 §6.5 取绝对值展示，展示效果不变。
3. 改密码第 5 次输错仍返回 55001，文案为“尝试次数已用完，请 15 分钟后再试”；第 6 次起返回 55004，文案带剩余分钟数。前端在收到 55004 时锁定，并按 15 分钟倒计时。倒计时存在内存里，刷新后丢失，但后端仍会拦截。
4. 改密码时先读用户、再校验新密码，因为“不等于用户名”这条需要用户名。不合规的新密码不计入失败次数。
5. 首页侧栏使用后台共用的 `admin-ui/nav-user.tsx`。已给它加了可选的 `avatarSrc` 属性：不传或图片加载失败时仍显示首字母，后台侧栏的行为不变。首页侧栏传入 `me.avatarUrl` 后，侧栏、画布右上角、身份卡三处都会显示真实头像。后台侧栏显示的是角色身份（运维 / 运营），这次没有改动。
6. 热力图 tooltip 直接用 `@base-ui/react/tooltip`，只挂一个受控实例，锚定当前格子，样式与 shadcn tooltip 一致。原因是 `components/ui/tooltip.tsx` 不支持 anchor，而每格挂一个 tooltip 太重。
7. 每页条数和类型筛选只保存在页面状态里，不进地址栏；`?page=` 按设计同步到地址栏。
