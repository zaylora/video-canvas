# 公告设计

> **范围**：首页外壳窗口最顶部的轮播公告通栏，以及后台发布、编辑、排序、定时上下线公告的管理页。
> **日期和状态**：2026-11-10，已确认待实现。
> **证据约定**：**事实**附文件路径或来源链接；**推断**是基于事实的判断；**提案**是尚未实现的设计。本文所有新增的表、接口、组件都是提案。
> **方案演进**：v1 把公告放在内容区顶栏下方、圆角半透明细条、每种类型配彩色图标并带进度条；用户评价「太丑、不专业」，并要求放到最顶部。v2（本版）改为**整个窗口最顶部的实色通栏**，居中一句话 + 类型小标签 + 「了解更多 →」，去掉类型图标和进度条，控件收到右侧弱化（§6.1）。v1 的外观已整体替换，不再保留。v3：用户要求「类型暂时只要通知，只要一个颜色」——去掉 `kind` 字段与类型小标签、去掉「警告」琥珀底和 B / C 配色备选，只保留深色通栏一种配色（即原推荐的 A）。将来要加类型见 §11「已搁置的决定」。v4（实现后验收）：用户要求去掉通栏上的「了解更多 →」和后台的「链接」字段——**链接功能整体删除**（表、接口、前端都不再有 `link_url`），有详情的公告改为**点标题打开详情弹窗**；后台列表铺满宽度。下文 §6、§8 中关于链接与「了解更多」的描述均已作废，以 §13 为准。
> **配套演示**：[公告-演示.html](公告-演示.html)（先读它）。

## 1. 设计摘要

- **问题**：平台没有任何渠道把「新模型上线、活动、停机维护」告诉已登录用户，只能靠群通知或更新日志。
- **目标**：运营在后台写一条公告，几分钟内所有用户在首页顶部看到；能定时上下线，能标记重要（不可关闭）。
- **推荐结论**：沿用「登录页展示（showcase）」那套后台配置 + 公开读取的结构，新增一张 `announcements` 表；前端在首页外壳 `HomeLayout` 的**整个窗口最顶部**加一条 40px 实色通栏（横跨侧栏和内容区、始终可见），一次显示一条，5 秒切换，悬停暂停；标题之外可选 Markdown 详情（弹窗看）和跳转链接；普通公告可关闭（本机记住，内容改了会重新出现），重要公告不可关。

### 设计约束

- 界面统一半透明「清透」风格（`web/docs/coding-standards.md` 6.1），不加操作说明小字（6.2）。
- 后端分层 `router → handler → service → repository`，测试放 `backend/internal/tests/`，前端测试放 `web/src/tests/`。
- 画布编辑器有性能硬约束，不应在其中常驻额外轮询和动画。

### 当前缺口

- 没有表、没有接口、没有前端组件。
- 没有全站广播通道，公告无法秒级推送（见 §7 默认值）。

## 3. 用户与场景

- **读者**：所有已登录用户，进入首页外壳时被动看到。
- **作者**：运营管理员（admin）或超级管理员（super_admin），低频（一周几条）。
- **典型场景**：
  1. 新模型上线：「Seedance 2.5 已上线，生成速度提升 40%」+ 详情 + 链接到创作页。
  2. 停机维护：「11 月 12 日 22:00–24:00 系统维护，期间无法生成」，标为重要、提前排好开始时间、结束后自动消失。
  3. 运营活动：「充值送 20% 积分，至 11 月 30 日」+ 链接到个人中心。

  三种场景本期都用同一种「通知」样式，区别只在是否「重要」。
- **成功指标**：发布后 ≤5 分钟内用户可见；到结束时间后用户端立即不再展示；普通公告关闭后同一浏览器不再出现，内容修改后重新出现。

### 依赖框架调研

- 候选：`embla-carousel`、`swiper`、`react-fast-marquee`。
- 结论：**不引用**。一次一条的竖向切换只需定时器 + `motion` 的 `AnimatePresence`，约 100 行；轮播库带来的拖拽、循环、懒加载在这里都用不上。Markdown 详情复用已有 `react-markdown`。无需向用户征询引用决定。

## 5. 设计原则

1. **不打扰创作**：只在首页外壳出现，画布编辑器和短剧工作台不显示；单行、可关闭。
2. **像站点横幅，不像组件示例**：实色通栏、居中一句话、一个文字链接；不堆图标、标签、进度条、阴影和圆角卡片；只有一种配色。
3. **重要的事关不掉，其他的一次关掉**：可关闭与否由管理员按条决定。
4. **公告的生命周期由时间决定，而不是记得去关**：起止时间到点自动上下线。
5. **照抄已有先例**：后台结构、接口命名、审计、排序都对齐 showcase，降低实现和维护成本。
6. **到点就消失要即时，上新允许几分钟延迟**：结束时间在客户端也判断；开始时间靠下一次拉取。

## 6. 推荐方案

### 6.1 用户端：顶部通栏

- **位置**：整个窗口最顶部的通栏，横跨侧栏和内容区，**始终可见**（不随页面滚动）。新组件 `AnnouncementBar`（`web/src/components/home/announcement-bar.tsx`），在 `HomeLayout` 里放在 `SidebarProvider` 之前。
  - 实现方式：通栏 `position: sticky; top: 0; z-index: 40`；`HomeLayout` 根据通栏是否显示，在外壳上设 CSS 变量 `--announcement-h`（显示 = `40px`，隐藏 = `0px`）；
  - 侧栏容器 `[data-shell="home"] [data-slot="sidebar-container"]` 覆盖为 `top: var(--announcement-h); height: calc(100svh - var(--announcement-h))`（shadcn 侧栏原本是 `fixed inset-y-0 h-svh`，见 `web/src/components/ui/sidebar.tsx:230`）；
  - `SiteHeader` 的吸顶改为 `top: var(--announcement-h)`；
  - 变量变化时侧栏和顶栏跟随 200ms 过渡，关闭最后一条时整体平滑上移。
- **外观（只有一种配色：B 浅黄，见下方「配色」）**：
  - 高 40px，全宽实色底，无圆角、无阴影、无模糊；
  - 内容**居中**、最大宽 960px：`标题  了解更多 →`；
  - 右侧只有一个 `×`（仅非重要，距右 12px），60% 不透明度，悬停 100%；**不提供上一条 / 下一条翻页和 `1/3` 计数**（用户要求去掉），多条公告只靠自动轮播；
  - 文字 13px，标题 500 字重，单行不换行；标题放不下时从右往左滚动（见「轮播」），不截断；「了解更多 →」带下划线偏移 3px，悬停箭头右移 2px；
  - 结构：`[标题视窗]`（可收缩、溢出裁切）`[了解更多 →]`（固定）。滚动的只有标题，链接不跟着跑，随时点得到；
  - 标题溢出时，整行改为左对齐，标题视窗左右两端各加 12–16px 渐隐遮罩（`mask-image`），表示还有内容；
  - 窄屏（<640px）：内容改为左对齐，保留 ×。
- **配色：已定 B 浅黄**（2026-11-10 用户从 5 个候选中选定）。

  | token | 亮色主题 | 暗色主题 |
  | --- | --- | --- |
  | `--announcement-bg` | `oklch(0.95 0.06 92)` | `oklch(0.26 0.05 78)` |
  | `--announcement-fg`（标题、链接、控件） | `oklch(0.36 0.08 70)` | `oklch(0.9 0.11 88)` |
  | `--announcement-line`（底部 1px） | `oklch(0.86 0.1 88)` | `oklch(0.36 0.07 78)` |

  链接「了解更多 →」与标题同色、80% 不透明度、下划线 35% 透明度；控件 60% 不透明度、悬停背景为 `currentColor` 12%。亮色主题下浅黄与暖米色页面明度接近，**底部细线不能省**，靠它和下方页面分界。

  候选记录：用户要求「换几个颜色选，考虑主题黄」。主题黄取自 `web/src/index.css` 的 `.drama-theme --primary`（亮 `oklch(0.67 0.14 78)` / 暗 `oklch(0.81 0.15 82)`，「暗房片场」钨丝灯琥珀）；暖米色取自 `.home-theme`（`--background oklch(0.95 0.007 85)`、`--sidebar oklch(0.925 0.009 85)`）。五个候选如下（已选 B，其余仅作记录）。

  | 候选 | 亮色主题（底 / 字 / 底边） | 暗色主题（底 / 字 / 底边） | 取舍 |
  | --- | --- | --- | --- |

  所有公告同一配色，轮播时底色不变。不使用图标和类型标签。文字对比度要求 ≥ 4.5:1（以上候选按 OKLCH 明度差估算均满足，实现后用浏览器工具实测）。
- **轮播**：一次一条；末条之后回到第一条；切换动画为旧文案上移 6px 淡出、新文案从下方 6px 淡入，200ms；不显示进度条。
  - **标题放得下**：静止显示，停留 5 秒后切下一条。
  - **标题放不下**（`scrollWidth > clientWidth`，窄屏常见）：先静止 1.5 秒让人读开头 → 以 60px/秒匀速从右往左平移，直到标题末尾露出（位移 = 溢出宽度 + 16px）→ 在末尾停 1.5 秒 → 切下一条。这条的停留时长 = `max(5 秒, 1.5 + 位移/60 + 1.5 秒)`。
  - 只有一条且放不下：滚到末尾停 1.5 秒后回到开头重新开始，循环。
  - 用 Web Animations API（`element.animate`）或 `motion` 实现平移，便于暂停 / 继续；窗口宽度变化（`ResizeObserver`）时重新测量，下一条生效。
  - 暂停时滚动和计时一起停在原位，恢复后从原位继续，剩余时长接着算。
  - 系统开「减少动态效果」：不平移，放不下的标题用省略号截断，完整内容在详情弹窗或悬停 `title` 提示里看。
  - 以下情况暂停：鼠标悬停在通栏上、键盘焦点在通栏内、详情弹窗打开、页面不可见（`document.hidden`）。只有一条时不切换。没有手动翻页，想看某条只能等它轮到（最多 5 条，一圈约 25 秒以上）。系统开「减少动态效果」时只做淡入淡出（`MotionConfig reducedMotion="user"` 外壳已有，通栏需放在 `MotionConfig` 内）。
- **动作**：
  - 有正文（`body` 非空）：动作文案「了解更多 →」，点击打开详情弹窗；弹窗内（若重要则带「重要」标）标题 + Markdown 正文 + （若有链接）底部「前往」按钮。
  - 无正文、有链接：动作文案同为「了解更多 →」，点击直接跳转。
  - 都没有：无动作，纯通知。
  - 整条标题本身不可点，只有「了解更多」可点，避免误触。
  - 链接跳转：`/` 开头的站内路径用 router `navigate`；`http(s)://` 外链新窗口打开，`rel="noopener noreferrer"`。
- **关闭**：点 × 只关当前这条；写入本机记录后通栏立即切到下一条；没有剩余时 `--announcement-h` 过渡到 0，整页平滑上移（200ms）。重要公告不显示 ×。
- **首屏不跳**：本机缓存上一次拉到的公开列表（`localStorage["announcement-cache"]`），进入外壳时先用缓存（再经关闭记录与结束时间过滤）立即渲染，后台静默拉取后再更新；这样已有公告的用户每次进入不会看到整页下跳 40px。没有缓存时（首次）拿到数据后再展开。
- **排序**：重要的在前，其次按后台排序，再按 ID。最多展示 5 条（服务端截断）。
- **无障碍**：外层 `role="region" aria-label="公告"`；自动切换期间 `aria-live="off"`，避免读屏反复播报；关闭按钮有 `aria-label`「关闭这条公告」。键盘焦点进入通栏时轮播暂停，读屏用户可以读完当前这条。

### 6.2 后台：公告管理页

- **入口**：后台导航「系统设置」组，「登录页展示」之上新增「公告」（`settings/announcements`，图标 `megaphone`）。
- **列表**（表格）：拖动手柄 · 状态 · 标题（含「重要」小标）· 生效时间（「不限」或 `11-12 22:00 → 11-13 00:00`）· 启用开关 · 编辑 / 删除。右上「新建公告」按钮。
- **状态**（派生，不入库）：

  | 状态 | 条件 |
  | --- | --- |
  | 已停用 | `enabled = false` |
  | 待上线 | 启用，`starts_at > now` |
  | 已过期 | 启用，`ends_at <= now` |
  | 超出上限 | 启用且在生效期内，但排在第 5 条之后 |
  | 展示中 | 其余启用且在生效期内的 |

- **编辑弹窗**（新建与编辑共用）：顶部是一条实时预览的通栏（与用户端同一组件）；字段依次为
  - 标题：必填，1–60 字，右侧字数计数；
  - 详情：可选 Markdown，≤5000 字，「编辑 / 预览」切换；
  - 链接：可选，`/` 开头的站内路径或 `http(s)://` 外链，≤512 字；
  - 重要：勾选后用户不能关闭，并排在最前；
  - 生效时间：开始、结束两个日期时间输入，空 = 不限；按浏览器本地时区输入与显示，入库为 UTC；
  - 启用：开关，新建默认开启。
  - 底部：取消 / 保存。校验错误显示在对应字段下。
- **删除**：确认弹窗（沿用 `admin-ui/confirm-dialog`），软删除。
- **空状态**：图标 + 「还没有公告」+「新建公告」按钮。

### 6.3 核心流程

1. 管理员在后台新建公告 → `POST /admin/settings/announcements` → 入库 + 审计。
2. 用户进入首页外壳 → `GET /announcements` → 服务端筛出启用、生效期内、未删除的，按顺序取前 5 条返回（`Cache-Control: private, max-age=60`）。
3. 前端过滤掉本机已关闭的（按 `id + version`）和 `ends_at` 已过的 → 渲染公告条。
4. 窗口重新获得焦点且距上次拉取 ≥5 分钟 → 重新拉取；每 30 秒本地检查一次 `ends_at`，过期的立即移除。

## 7. 状态与异常

| 情形 | 行为 |
| --- | --- |
| 首次加载中 | 有本机缓存：先用缓存渲染；无缓存：不占位、不显示骨架，拿到数据后通栏展开（整页下移只发生在首次） |
| 缓存里的公告服务端已下线 | 拉取完成后移除，`--announcement-h` 过渡收起 |
| 无公告 / 全部已关闭 | 不渲染，零高度 |
| 拉取失败（网络 / 5xx） | 静默：保留上一次成功的数据，没有则不显示；不弹错误提示 |
| 接口 401 | 由全局请求层处理（跳登录），本组件不处理 |
| 公告在用户看时被后台删除或下线 | 下一次拉取后消失；若详情弹窗正开着，不强制关闭 |
| 结束时间到达 | 客户端 30 秒内移除；服务端之后的请求不再返回 |
| 开始时间到达 | 下一次拉取时出现（最迟：60 秒缓存 + 回到窗口 5 分钟节流） |
| 管理员改了已关闭公告的内容 | `version` 变化 → 本机关闭记录不再匹配 → 重新出现 |
| localStorage 不可用（隐私模式） | 关闭只在本次会话内存里生效，刷新后再出现；不报错 |
| 后台保存校验失败 | 400，字段级错误显示在表单对应字段下 |
| 后台编辑的公告已被别人删除 | 404，toast「公告不存在或已删除」，刷新列表 |
| 两位管理员同时编辑同一条 | 后写覆盖先写（不加乐观锁，见 §11 默认值） |
| 排序请求的 ID 集合与现有不一致（并发增删） | 400「列表已变化，请刷新后重试」，前端自动刷新列表 |
| 非管理员调用后台接口 | 403（`RequireAdmin` 已有） |

## 8. 数据与工程影响（提案）

### 8.1 迁移 `backend/migrations/0029_announcements.sql`

CREATE TABLE announcements (

    body text NOT NULL DEFAULT '',                    -- Markdown，≤5000 个字符，可空

    ends_at timestamptz,                              -- 空 = 不过期
    sort integer NOT NULL DEFAULT 0,

表很小（预计 <100 行），公开查询全表扫描即可，不额外建组合索引。

### 8.2 模型 `backend/internal/model/announcement.go`

- `Announcement`（嵌 `BaseModel`，字段同上表）。
- `AnnouncementPublic`：`id, title, body, link_url, important, ends_at, version`。`version = updated_at` 的 Unix 毫秒，用于本机关闭记录。不返回 `starts_at`（返回的都已开始）、`created_by` 等内部字段。
- `AnnouncementAdmin`：全部业务字段 + `status`（§6.2 五种：`disabled / scheduled / expired / overflow / live`）+ `created_at, updated_at`。
- `SaveAnnouncementReq`（新建与编辑共用、整体替换）：`title, body, link_url, important, enabled(*bool, 必填), starts_at(*time), ends_at(*time)`。
- `SetAnnouncementEnabledReq`：`enabled *bool`（必填）。
- `ReorderAnnouncementsReq`：`ids []uint64`（必须恰好覆盖全部未删除公告各一次）。

### 8.3 接口

| 方法与路径 | 权限 | 说明 | 业务错误 |
| --- | --- | --- | --- |
| `GET /api/v1/announcements` | 已登录 | 生效中的公告，排序后取前 5；`Cache-Control: private, max-age=60`；`items` 永不为 null | — |
| `GET /api/v1/admin/settings/announcements` | admin+ | 全部未删除公告（含派生 `status`），按 `sort, id` 升序 | — |
| `POST /api/v1/admin/settings/announcements` | admin+ | 新建，排最后（`MaxSort+1`），返回 `AnnouncementAdmin` | 400 校验 |
| `PUT /api/v1/admin/settings/announcements/:id` | admin+ | 整体替换，返回最新 | 400 校验；404 |
| `PUT /api/v1/admin/settings/announcements/:id/enabled` | admin+ | 列表里的启用开关 | 404 |
| `DELETE /api/v1/admin/settings/announcements/:id` | admin+ | 软删除 | 404 |
| `PUT /api/v1/admin/settings/announcements/order` | admin+ | 整体重排 | 400「列表已变化」 |

**校验规则（service 层）**：

- `title` 去首尾空白后 1–60 个字符（按 rune），否则 400「标题需要 1–60 个字」。
- `body` 去首尾空白后 ≤5000 个字符。
- `link_url` 去首尾空白；为空放行；否则必须以单个 `/` 开头（拒绝 `//`）或以 `http://` / `https://` 开头且能被 `url.Parse` 解析出 host，≤512 字符；否则 400「链接需要以 / 或 http(s):// 开头」。
- `starts_at`、`ends_at` 都给时要求 `ends_at > starts_at`，否则 400「结束时间要晚于开始时间」。允许保存已过期的时间（状态显示「已过期」），不拦截。

**审计**：新增常量 `AdminAuditTargetAnnouncement = "announcement"`，动作 `announcement.create / update / enable / delete / reorder`；detail 记 `title, important, enabled, starts_at, ends_at`（无敏感信息，正文不记）。

### 8.4 公开查询（提案伪代码）

```go
func (s *AnnouncementService) Public(ctx context.Context) (*model.AnnouncementPublicView, error) {
    now := s.now()
    rows := s.repo.ListActive(ctx, now) // enabled AND (starts_at IS NULL OR starts_at <= now) AND (ends_at IS NULL OR ends_at > now)
    sort.SliceStable(rows, func(i, j int) bool {
        if rows[i].Important != rows[j].Important { return rows[i].Important }
        if rows[i].Sort != rows[j].Sort { return rows[i].Sort < rows[j].Sort }
        return rows[i].ID < rows[j].ID
    })
    if len(rows) > maxPublicAnnouncements { rows = rows[:maxPublicAnnouncements] } // 5
    return toPublicView(rows), nil // Items 永不为 nil
}
```

`status = overflow` 的判定在后台视图里复用同一套排序：对生效中的取第 6 条起标 `overflow`。

### 已确认（用户回答）

1. **显示范围**：首页外壳所有页（创作、所有画布、资产、短剧列表、对话、个人资料）；画布编辑器、短剧工作台不显示。
2. **形态**：~~顶栏下细条~~（v1，用户否决：太丑、不专业）→ **整个窗口最顶部通栏**，横跨侧栏和内容区，始终可见；一次一条，切换，悬停暂停。
3. **滚动方式**：用户问「不是从右往左滚动的吗」，确认后选定**放得下不动、放不下才从右往左滚完再切下一条**；放弃了「所有公告首尾相接连续跑马灯」（难读、链接会跑）。

3a. **不要翻页控件**：用户看过原型后要求去掉右侧的 `‹ 1/3 ›`（上一条 / 下一条 + 计数），只靠自动轮播，右侧只留 ×。
3. **内容**：标题一句话 + 可选 Markdown 详情（弹窗）+ 可选链接。
4. **关闭**：普通公告可关（本机记住，内容改了重新出现）；管理员可标「重要」使其不可关。
5. **上下线**：启用开关 + 可选开始 / 结束时间。
6. **类型与配色**：~~通知 / 活动 / 警告三种~~ → 用户改为**暂时只要「通知」一种、只要一个颜色**。不存 `kind`，不显示类型标签。之后用户要求围绕主题黄再给几个颜色选，从 5 个候选中**选定 B 浅黄**（淡黄底 + 深琥珀字 + 底部细线，色值见 §6.1）。
7. **权限**：admin 和 super_admin 都能增删改排序，全部写操作进审计。

### 已搁置的决定

- 公告类型（通知 / 活动 / 警告）：将来要加时，新迁移 `ALTER TABLE announcements ADD COLUMN kind varchar(16) NOT NULL DEFAULT 'notice'`，存量数据自动成为「通知」；界面上在标题前加类型小标签，「警告」可换整条琥珀底（浅琥珀底 + 深琥珀字），通知与活动共用深色底以免轮播闪色。

- 定向投放：可在表上加 `audience jsonb`，公开查询按当前用户过滤（届时缓存头改 `private` 已兼容）。

### 默认值（不需要用户决定）

- 切换间隔 5 秒，动画 200ms；最多展示 5 条；标题 ≤60 字、正文 ≤5000 字、链接 ≤512 字。

- 并发编辑后写覆盖，不加乐观锁（作者少、频率低）。
- 时间按浏览器本地时区录入与显示，入库 UTC。
- 后台入口放「系统设置」组，紧挨「登录页展示」。

- **v4：去掉链接与「了解更多」**（用户验收后要求）：`announcements` 表不再有 `link_url` 列：0029 保持原样（开发库已执行过，改它会因 checksum 不一致拒绝启动），另加 `0031_announcements_drop_link.sql` 删列（0030 已被另一项改动占用），接口、校验、前端表单全部移除；通栏上整句标题在有详情时可点，悬停出下划线，点开详情弹窗；没有详情就是纯通知。后台列表去掉宽度上限，铺满内容区。

- **启停、排序不刷新版本**：`version` 只随内容编辑（PUT 整体替换）变化；`SetEnabled` 与 `SetSort` 不改 `updated_at`。原因：停用再启用、调整顺序都不是内容变化，不应让用户已关闭的公告重新出现。
- **本机关闭记录改为有序数组** `[[id, version], …]`，不是设计里的 `{id: version}` 对象：JS 对象里整数样子的键总按数值升序排列，无法实现「挤掉最早关闭的」（单测发现）。
- **标题滚动只在右侧渐隐**（16px），左侧不加：左侧遮罩在滚动开始前会把第一个字也淡掉。
- **不用 ResizeObserver**：每换一条（或单条重播）时重新测量一次，窗口宽度变化自然在下一条生效，与设计效果一致。
- **详情 Markdown** 直接复用 `pages/canvas/agent/markdown.tsx`（不渲染原始 HTML），无需另抽组件。
- 后台删除用全局 `confirm()` 确认框；新建 / 编辑用右侧抽屉（与登录页展示一致），顶部是与首页同一组件的实时预览。
