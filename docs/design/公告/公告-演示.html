回答：管理员点了保存之后，用户多久、在哪里、以什么样子看到。

设计：「何时生效」由服务端统一判断，客户端只额外判断「结束时间」——下线要即时（维护结束还挂着会误导），上线允许几分钟延迟。照抄登录页展示（showcase）的后台 + 公开接口结构，不另起一套。
拉取失败、没有公告、全部关掉时：公告条不出现，零高度，页面和今天完全一样；拉取失败时保留上一次成功的内容，不弹错误。

它长什么样 · 配色已定 B 浅黄

只有一种类型、一种颜色：浅黄底 + 深琥珀字 + 底部细线，居中一句话 + 「了解更多 →」。下面保留了 5 个候选作对比记录；点其他候选只是临时预览，原型默认用 B。右上角可切明暗主题。

设计：主题黄取自短剧工作台「暗房片场」的琥珀色（index.css 的 .drama-theme --primary），暖米色取自首页 .home-theme。你选了 B 浅黄：比 A 实色黄柔和、不像警告，又比黑底更贴近米色首页的气质。代价是亮色主题下浅黄和米色页面明度接近，所以底部那条细线必须保留，它负责把通栏和页面分开。

今晚要停机维护时，会发生什么

最典型也最需要「准时」的场景：提前发、到点出现、结束自动消失。

  1. 下午建一条公告，勾「重要」标题「今晚 22:00–24:00 系统维护，期间无法生成」，开始 20:00、结束 24:00。后台状态显示「待上线」。
  2. 20:00 之后用户打开首页即可看到已经开着页面的用户：回到窗口时（距上次拉取 ≥5 分钟）出现；刷新则最多受 60 秒缓存影响。
  3. 它排在所有公告最前，没有 ×用户可以点「查看详情」看维护内容。
  4. 24:00 一到，30 秒内从所有人页面上消失客户端自己判断结束时间，不等下一次拉取。后台状态变「已过期」。
边界：上线不是秒级的
  • 项目没有全站广播通道，公告不会「推」到已打开的页面；最迟约 5 分钟可见。
  • 已在画布编辑器里的用户看不到公告，回到首页才会看到。
  • 关闭记录存在本机浏览器，换电脑会再看到一次。

交付时要告诉运营：紧急公告请把开始时间设得比实际早几分钟。

可点击原型

用户首页和后台共用一份内存数据，刷新复原。已预置 6 条公告，覆盖「展示中 / 待上线 / 已过期 / 已停用」。 在后台改了什么，切到「用户首页」立刻能看到效果；用下面的模拟时钟拨快时间，看定时上下线。 想看失败：新建公告时链接填 javascript:alert(1) 或 //evil.com、标题留空、或结束时间早于开始时间；或打开「模拟拉取失败」。

数据模型

一张小表，预计永远不到 100 行，不分页、不建组合索引。

announcements 表
idbigserial 主键
title去首尾空白后 1–60 个字符（service 校验）

后台状态（派生，不入库）条件
已停用enabled = false
待上线启用，starts_at > now

超出上限启用且生效中，但按顺序排在第 5 条之后

// 后端：公开查询（提案）
func (s *AnnouncementService) Public(ctx) (*AnnouncementPublicView, error) {
    now := s.now()
    rows := s.repo.ListActive(ctx, now)
    // enabled AND (starts_at IS NULL OR starts_at <= now) AND (ends_at IS NULL OR ends_at > now) AND deleted_at IS NULL
    sortStable(rows, important desc, sort asc, id asc)
    return toPublic(rows[:min(5, len(rows))])   // Items 永不为 nil
}

// 前端：本机过滤（提案，web/src/utils/home/announcement.ts，纯函数便于测试）
function visibleAnnouncements(items, dismissed, now) {
  return items.filter(a =>
    (a.ends_at == null || Date.parse(a.ends_at) > now) &&
    (a.important || dismissed[a.id] !== a.version))
}
