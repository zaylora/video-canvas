画布 Agent 助手

在画布里说一句话，Agent 帮你把影视链路搭出来

用户贴一段剧本或一句创意，Agent 读懂画布，按「剧本 → 角色/场景 → 分镜 → 关键帧 → 视频」建好节点组、连好参考、填好提示词。 建节点、连线、改提示词、排版直接生效，可一键「撤销本轮」；花积分的生成和删除必须你点批准；已生成的产物永远不会被覆盖。 底层用 pi agent，跑在 Go 拉起的 Node 进程里，Node 不持有任何密钥。

阅读说明。项目现状来自仓库代码（2026-10-07 核对）；竞品来自调研，影策读了源码，其余多为搜索摘要。 本设计尚未实现，原型里的数字、耗时、积分都是示意。完整依据见同目录的 画布Agent助手设计.md（准绳）。

一条请求怎么走

从你在浮窗里发出一句话，到画布上出现节点，经过哪几层、各自负责什么。

① 浮窗发送附带选中节点、@ 的节点、视口、本轮预算
② Go 建 run校验单运行、模型、余额；组装「上下文帧」
③ Node 跑 pi 循环零密钥；模型、工具、事件都经反向桥交回 Go
④ Go 执行工具校验 → 按 revision 写 payload → 记改动日志
⑤ WS 推 patch前端三方合并，对齐 revision 基线
设计：照搬影策的「反向桥」——pi 只管对话循环和会话压缩，密钥、计费、画布写入、审批全部留在 Go。 放弃了「浏览器里跑 pi」（实现最省，但关页即中断），因为你选择了关页也能继续跑。
兜底：没有已发布的 Agent 模型 → 入口按钮置灰并说明原因，画布照常用； Node 运行时挂了 → 发送时提示「Agent 暂不可用」（60005），正在跑的 run 标为「已中断」，回来点「继续」，审批过的生成不会重复扣费； 页面关了 → run 继续跑，重开时按事件序号回放消息、拉最新画布。

Agent 能做的三类事

差别只在于「要不要你点头」。

读
直接

画布目录、节点详情、看图、查模型和任务、读技能。默认只看目录 + 选中/@ 的节点，需要时再精读。

编辑
直接生效可撤销本轮

建节点 / 组、连线、改标题提示词参数、排版。每次最多 30 项；不能写产物字段（src、outputs、taskId…）。

生成 · 删除
审批卡片受本轮预算约束

发起生成、删节点或连线。卡片列出模型、数量、预估积分或要删的东西；你批准后才执行，拒绝不扣分。

你贴一段剧本说「拆成分镜」时，会发生什么

主路径一共 8 步，其中两处会停下来等你。

  1. 读技能「剧本拆镜」仓库内置的方法文档，告诉它镜号/景别/运镜怎么拆
  2. 信息不够就问你ask_user 卡片：画幅 16:9 还是 9:16？——本轮暂停等你选
  3. 列计划计划卡片：角色 → 场景 → 镜头组 → 生成角色图
  4. 建角色组、镜头组并连好参考每个镜头一组：镜头文本 → 关键帧图 → 视频；节点紫色闪一下
  5. 整理布局与现有「排列」算法一致
  6. 申请生成角色图审批卡片：模型、张数、预估积分、本轮剩余预算——本轮暂停
  7. 你批准 → 走现有生成任务幂等键 = 审批 id；结果照常经 WS 回填
  8. 结束，出现「撤销本轮」撤销只撤 Agent 的改动；你改过的字段、已有产物的节点会跳过并列出
边界：Agent 跑的时候画布不锁，你的修改永远优先。
  • 同一字段你和 Agent 都改了：保留你的，面板提示一句。
  • 运行中自动保存撞上 409：自动合并重试，不再弹冲突对话框。
  • 撤销本轮不会取消已批准的生成，也不会删掉已有产物的节点。
  • 预算用尽或到 40 步：暂停，可「追加预算并继续」。
  • 同一画布同时只能有一个 Agent 在跑（60001）。

交付时要提前告知：Agent 的对话本身按 token 扣积分，并计入本轮预算；私有部署需要多一个 Node 22 运行时。

// Go：工具执行器（提案）
func ExecTool(run, call) Result {
  switch call.Name {
  case "generate_media", "canvas_delete", "ask_user":
    appr := approvals.Create(run, call)            // 报价、预算、余额预检
    push(agent.event{approval.created})
    return Result{content: "已提交用户确认，等待决定", terminate: true}   // 结束本 turn，run → waiting_*
  case "canvas_apply_ops", "canvas_arrange":
    for attempt := 0; attempt < 3; attempt++ {
      cv := canvas.Get(run.CanvasID)                 // payload + revision
      ops, err := canvasgraph.Validate(cv, call.Args) // 连线规则、字段白名单、≤30 项
      if err != nil { return ToolError(err) }        // 逐项原因回给模型
      next, diff := canvasgraph.Apply(cv, ops)        // diff 每项带 before/after
      if canvas.Update(cv.ID, cv.Revision, next) == ErrRevisionConflict { continue }
      m := mutations.Insert(run, call.ID, diff, cv.Revision, cv.Revision+1)
      ws.Publish("canvas:"+id, canvas.patch{m})
      return Result{content: summary(diff), details: idMap}
    }
    return ToolError(60006)
  }
}

for (const op of patch.ops) for (const [field, after] of op.after) {

已确认的决定

  1. 第一版主任务是影视链路搭建：工具和提示词围绕剧本 → 分镜 → 生成。
  2. 编辑直接执行，生成需要审批：花钱必须过人手，其余靠撤销兜底。
  3. pi 跑在影策式 Node sidecar + 反向桥：你优先要关页可继续、与影策同构；浏览器方案已搁置。
  4. 后端落库 + 前端三方合并：前端对齐 revision 基线，运行中保存 409 自动合并。
  5. 复用后台模型配置：新增 agent 用途，按 token 计费。
  6. 可拖动浮动面板。
  7. 可删可改，删除需要审批；产物不覆盖，重做新增。
  8. 撤销走面板「撤销本轮」（后端），不进 Ctrl+Z。
  9. MVP 用现有节点 + 打组表达分镜，分镜表节点放二期（访谈中你改过这一题）。
  10. 每画布多会话，存后端。
  11. 护栏：步数上限 + 每画布单运行 + 单轮积分预算。
  12. MVP 包含插话/取消、看图、ask_user、影视技能库。
  13. 技能库仓库内置，后台管理放二期。
  14. Agent 对话 token 计入本轮预算；私有部署接受多带 Node 22；撤销栈 rebase 成本过高时退化为清空 Ctrl+Z 栈并提示（原待确认三项，已确认）。
  15. 浮窗按参考截图重做：顶栏 = 标题 + 新对话 / 历史 / 设置 / 最小化（不做分享、连接、停靠侧栏）。
  16. 输入框左下做任务模式：全能创作 / 剧本创编 / 分镜搭建 / 提示词优化，每种 = 追加提示词 + 默认技能 + 工具子集。
  17. 模型是写在提示词里的行内 chip，可多个（如角色用 A、场景用 B）；没指定时 Agent 弹「选择模型」卡片。
  18. ✋ 开关：开 = 生成需审批，关 = 自动生成；本版只做「开」，「关」禁用。
  19. 未完成的计划一直悬浮在输入框上方，默认一行摘要，点开展开；完成后收起并留在消息流。
  20. 已搁置：浏览器跑 pi、运行中锁画布、后端只产 ops、并入 Ctrl+Z、三档权限模式、停靠侧栏、分享。
  21. 主文档已回写：6.2、6.4、6.7、8.2、11。
