# 协议插件简化设计

> **范围**：降低协议插件契约的复杂度，让 AI 拿着平台 API 文档更容易一次写出能用的插件。具体包括：去掉结果下载域名白名单 `allowedHosts`；删掉渠道开关“允许访问内网”（`trusted_internal`）；统一结果支持简写；放开现代 JS 语法；插件提示词拆成“核心 + 进阶附录”；上传时版本号自动递增；失败时可一键复制修复信息。
> **日期 / 状态**：2026-10-11，已确认；第 1、2 期都已实现（见 §13）。
> **证据约定**：**事实**附文件路径或来源链接；**推断**是基于事实的判断；**提案**是尚未实现的设计。
> **方案演进**：
> - 绝对地址请求一开始选了“允许且照常带 Key”，随后改成“**允许但不带 Key**”（用户在同一轮会话里更正）。
> - “信任内网”开关原本打算收窄成“只放行 base_url”。向用户解释开关的作用后，用户决定**直接删掉**。
> - 被放弃的方案见 §9。
> **配套演示**：[插件简化-演示.html](插件简化-演示.html)

## 1. 设计摘要

- **问题**：AI 写插件经常要来回调好几次。原因有三类：
  1. 契约里有一些 AI 很难从 API 文档推出来的“宿主专属”规则，比如结果域名白名单、统一结果的精确结构。
  2. 提示词约 28.6KB，规则太多，还要求 AI 只写 ES5，跟 AI 平时的写法冲突。
  3. 每改一次代码都要手动升版本号；出错以后，用户得自己把问题和追踪信息整理给 AI。
- **目标**：AI 生成的插件**首次上传预检通过、首次试跑成功**的比例明显提高；修一个问题的来回成本降到“点一下复制，发给 AI，再上传”。
- **推荐结论**（均已确认）：
  1. 删除 `meta.allowedHosts`。结果下载不限域名；绝对地址请求可以发往任意公网域名，但**只有发往渠道 base_url 本身时才注入 Key**。
  2. 删除渠道开关“允许访问内网”（`trusted_internal`），所有出站请求一律拦截内网地址。
  3. 统一结果支持简写：`outputs` 可以写成字符串数组，`error` 可以直接写字符串，`class` 缺省为 `terminal`。
  4. 提示词放开现代 JS 语法，拆成“核心 + 进阶附录”；保留“信息不全先提问”和“必须实现检查与导入”。
  5. 上传同一个 key 时，版本号冲突或缺失就自动递增。
  6. 预检失败、试跑失败、渠道检查失败时，可以一键复制“修复信息”发给 AI。

### 2.2 设计约束

- 插件仍然**拿不到 Key**（`custom` + `allow_credentials` 除外）。去掉白名单以后，靠“只给 base_url 注入 Key”继续守住这条线。
- 内网防护（SSRF）不能因为删白名单而失效。删掉“允许访问内网”以后，所有出站请求都拦截内网地址。
- 已登记的插件版本不可变；旧版本的 `meta_json` 里留着 `allowedHosts`，必须能正常读取（直接忽略）。
- 契约改动要同时改 `backend/docs/plugin-contract.md` 和 `plugin-prompt.ts`（F10）。

### 2.3 当前缺口

- 很多结果文件放在 OSS/CDN 上，域名 AI 从文档里看不出来，只能试跑失败后补白名单（用户截图里的 YSWG 插件就补了 3 个域名）。
- 统一结果的写法是 AI 最容易写偏的地方（F7），一点小格式问题就算整个插件故障。
- 版本号不可变 + 手动升号，每修一次都多一步；漏了就被拒（F11）。

## 3. 用户与场景

- **用户**：后台管理员（通常是站长本人），不一定熟悉插件契约。写插件的方式是“复制提示词 + 粘贴平台文档 → 发给 AI → 上传生成的 `.js`”。
- **触发场景**：接入一家新的图片、视频或文本平台；平台接口改了需要修插件。
- **主任务**：复制提示词 → AI 提问、补信息 → AI 出代码 → 上传（预检）→ 绑定渠道 → 检查连通性 → 导入模型 → 试跑 → 启用。
- **成功指标**（提案，需要在实现后统计）：
  - 首次上传预检通过率；
  - 首次试跑成功率；
  - 从第一次上传到试跑成功的上传次数（目标中位数 ≤ 2）。

## 5. 设计原则

1. **宿主能推断的，不让插件声明**：结果域名、媒体类型、默认错误分类都由宿主处理。（来源：n8n 声明式、Zapier 默认行为；F1、F7）
2. **Key 只跟着渠道走**：去掉白名单以后，Key 只注入到发往 base_url 的请求。（用户回答；设计约束）
3. **安全默认，不留看不懂的开关**：内网一律拦截，删掉“允许访问内网”。（用户回答）
4. **简写和完整写法并存，旧插件零改动**：新规则只放宽、不收紧；已有插件不用重新上传。（F15、设计约束）
5. **出错时的修复成本要低**：问题和追踪一键复制给 AI，版本号不用人管。（用户回答；F11-F13）

## 6. 推荐方案

### 6.1 去掉 `allowedHosts`（提案）

| 场景 | 现在 | 改后 |
| --- | --- | --- |
| `meta.allowedHosts`（就是白名单） | 预检逐项校验 | **删除**：`Meta` 结构体、预检校验、宿主的请求/产物/下载校验、详情页展示、类型定义、提示词、契约文档、内置 newapi.js 里的这个字段全部删掉。为了兼容，插件代码里还写着它时不报错，直接忽略（已登记的旧版本不可修改，`meta_json` 里还留着它；AI 也可能照旧写上） |
| 请求描述用 `path` | 只能去 base_url | 不变 |
| 请求描述用 `url`（绝对地址） | 主机必须在白名单或是 base_url 主机 | **任意公网 http/https 主机**；仍然禁止用户名密码、禁止 `..` 段、拦截内网 IP |
| 绝对地址请求注入 Key | 只要通过白名单就注入 | **只有 `url` 的 scheme + host + port 与 base_url 完全一致时才注入**；否则不注入，并在试跑追踪里记一条“目标不是渠道地址，未注入 Key” |
| 请求级 `auth` 覆盖（bearer/header/query） | 同上 | 同上规则：发往非 base_url 时不注入，覆盖设置也不生效 |
| `url` 类型产物校验 | 主机在白名单或是 base_url 主机 | 只要求 http/https、不含用户名密码 |
| 下载产物 | 白名单 + 内网拦截 + 重定向 ≤3 + 大小上限 + 超时 | **去掉白名单**，其余不变；重定向到的每一跳同样拦截内网 |
| `custom` + `allow_credentials` 插件自己写 `Authorization` | 只能发往白名单域名 | 可以发往任意公网域名。这类插件本来就持有 Key，“允许插件读取 Key”是超级管理员才能开的开关，风险已在开启时告知；本期不改 |

**“同源”判断**：`strings.EqualFold(u.Scheme, base.Scheme) && strings.EqualFold(u.Host, base.Host)`。`Host` 含端口，`https://api.x.com` 和 `https://api.x.com:8443` 算不同源。

### 6.2 删掉“允许访问内网”（提案）

- 插件宿主的 `Executor` 只保留一个守卫 Transport（原来是普通和 trusted 两套，`transports [2]`）。
- Agent 大模型网关 `llmgateway` 同步删掉 `TrustedInternal`，只用守卫 Transport。
- 删掉渠道接口的 `trusted_internal` 字段（创建、更新、详情）、`ChannelSnapshot.TrustedInternal`，以及渠道弹窗里的开关和确认弹窗。
- 数据库：在 `repository/migrate.go` 里新增一个“AutoMigrate 前执行”的收敛步骤，先查出 `trusted_internal = true` 的渠道，逐个打 **WARN** 日志（渠道 key + base_url 主机，提示“升级后这个渠道不能再访问内网”），然后 `DROP COLUMN`。表或列不存在时跳过，可重复执行。
- 审计常量 `AuditChannelTrusted` **保留**：历史审计记录里还有这个动作，展示时要认得。不再产生新记录。
- 历史任务快照里的 `trusted_internal` 字段在 JSON 反序列化时被忽略，进行中的任务继续用守卫 Transport（推断：快照结构体删掉字段后，`encoding/json` 会忽略多余键）。
- 本地开发和测试用的 `httptest`（127.0.0.1）仍然通过 `Options.IPAllowed` 注入放行，不受影响（`executor.go:784`）。

### 6.3 统一结果简写（提案）

宿主在 `parseQueryResult` 里先**规范化**，再走原来的校验：

| 写法 | 规范化后 |
| --- | --- |
| `outputs: ["https://a.com/x.png"]`（非文本模型） | `[{ type: "url", url: "https://a.com/x.png", media_type: <模型 kind> }]` |
| `outputs: ["正文"]`（文本模型） | `[{ type: "text", text: "正文" }]` |
| `outputs: [{ url: "https://..." }]`（对象缺 `type`，但有 `url`） | `type` 补成 `"url"` |
| `outputs: [{ text: "..." }]`（对象缺 `type`，但有 `text`） | `type` 补成 `"text"` |
| `error: "上游说审核未通过"` | `{ class: "terminal", message: "上游说审核未通过" }` |
| `error: { message: "..." }`（缺 `class`） | `class` 补成 `"terminal"` |
| `error.class` 不是四个合法值之一 | **仍然算插件故障**（写了就要写对，不静默改） |
| `status` 大小写不对、写成 `success`/`completed` 等 | **不放宽**，仍然报错（避免宿主替插件猜状态） |

- 非文本模型的字符串产物不是 http/https 地址时，按 `url 产物地址不合法` 报插件故障。
- `immediate` 用同一套规范化。
- `mime` 继续可选：下载结果时 `Download` 会带回响应的 `Content-Type`（`executor.go:302`，现状）；最终用哪个值，以实现时核对入库逻辑为准。

### 6.4 提示词：放开现代语法 + 拆成“核心 + 进阶”（提案）

- **运行环境一节改成**：可以用 ES2020 的常见语法（`const/let`、箭头函数、模板字符串、`?.`、`??`、解构、展开、`class`）。**钩子不能是 `async`、不能返回 Promise**，没有 `require`、网络、文件、定时器、`eval`/`Function`。
- **保留不变**（用户确认）：“零、先检查信息是否完整”整节；必须实现 `buildCheckRequest`、`meta.import`、`buildImportRequest`/`parseImportResponse`。
- **核心部分**只讲：meta（去掉 `allowedHosts`、`poll` 写成“可选，一般不写”）、必选钩子、ctx、请求描述（只讲 `path`、`query`、`headers`、`json`、`multipart`、`__fileRef as:url`、`timeout`）、响应对象、统一结果（**先教简写**，再给完整写法）、错误分类的三条判断规则、导入草稿的最小写法、输出要求、自查清单。
- **进阶附录（遇到再看）**：`buildPrepareRequests`、`form`、`responseType: binary` 与 `asset` 产物、请求级 `auth` 覆盖、`auth: custom` 与签名函数、`buildCancelRequest`、`classifyError`、`state`、`providerCost`、`paramHints`、档位对照表、工作流节点映射、绝对地址 `url`（说明**不会注入 Key**）。
- 删除所有和 `allowedHosts` 相关的句子（目前有 4 处：meta 示例、请求描述、统一结果、自查清单）。
- 自查清单删掉“改了代码就升 meta.version”，改成“版本号可以不改，上传时会自动递增”。
- 目标长度：正文（不含附录）≤ 现在的 50%（**估算**，以实现后实测为准）。前端测试断言提示词里不出现 `allowedHosts`，也不出现“不要用可选链”之类的旧限制。

### 6.5 版本号自动递增（提案）

只对**上传的插件**生效，内置插件不变（内置插件靠 sha256 校验提醒开发者升号，F15）。

规则（按顺序判断）：

1. 新 key：`meta.version` 合法就用它；缺失或不合法就用 `1.0.0`。
2. 已有 key，代码 sha256 和某个已有版本完全相同：拒绝，问题挂在 `meta`：“代码与 v1.3.1 完全相同，没有产生新版本”。
3. 已有 key，`meta.version` 合法、未被占用、并且大于已有的最高版本（按 semver 比较）：用它。
4. 其他情况（缺失、不合法、已被占用、比最高版本低）：取已有最高版本，补丁位 +1，去掉预发布后缀。例：最高 `1.3.1` → `1.3.2`；最高 `2.0.0-rc.1` → `2.0.1`。
5. 并发上传撞上唯一索引：重新计算一次，最多重试 3 次，还撞就按“版本号已存在”拒绝（现状）。

- 登记的是最终版本号，`meta_json.version` 同步写成最终版本号；**代码原文不改**，sha256 按原文计算（现状）。
- 上传结果新增 `version_adjusted: { from: "<代码里写的，可能为空>", to: "<登记的>" }`；没有调整时不返回这个字段。
- 前端上传成功后，有调整就提示：“代码里写的是 v1.3.1，已自动登记为 v1.3.2”。
- 渠道不会自动切到新版本，仍然走现有的“升级渠道”流程（`upgrade-channels.tsx`）。

### 6.6 一键复制修复信息（提案，纯前端）

三个入口，都用已有数据拼一段纯文本：

| 入口 | 什么时候出现 | 数据来源 |
| --- | --- | --- |
| 上传对话框“预检结果” | `Accepted=false` 时 | 上传响应里的 `issues` |
| 模型试跑结果面板 | 试跑任务 `failed` 时 | 试跑任务的错误码与文案 + 追踪里标为失败的步骤 |
| 渠道“检查连通性”失败 | 检查不通过时 | `CheckResult.message` |

文本格式（示例）：

```
我的 video-canvas 协议插件出错了，请按插件契约修复，输出完整的 .js 文件（版本号不用改，上传时会自动递增）。

插件：yswg-image v1.3.1
阶段：试跑（图片模型 yswg-gpt-image）
错误：plugin_error · 统一结果的 status 不合法

失败步骤：
[3] parseQueryResponse
  输入 resp.body（截断到 2KB）：{ "state": "SUCCESS", ... }
  输出：{ "status": "SUCCESS", ... }
```

- 每个块截断到 **2KB**，全文截断到 **16KB**。追踪本来就已脱敏（F13），前端不再另外处理 Key。
- 预检问题按 `路径：说明` 每行一条。
- 不附提示词全文：用户和 AI 的对话里通常已经有了。

### 6.7 后台界面（提案）

- 插件详情“概览”：删掉“允许下载结果的域名”（F3）。
- 渠道弹窗：删掉“允许访问内网”开关和对应的确认弹窗。
- 上传对话框：显示版本自动调整的提示；预检失败时显示“复制修复信息”。

## 7. 状态与异常

| 情况 | 行为 |
| --- | --- |
| 旧插件写了 `allowedHosts` | 忽略，照常运行 |
| 产物地址是内网 IP 或解析到内网 | 拨号时拦截 → `ssrf_blocked`（terminal） |

| 上传的代码与已有版本完全相同 | 拒绝，提示没有产生新版本 |

## 9. 方案取舍

| 选项 | 结论 | 原因 |
| --- | --- | --- |
| 绝对地址请求：允许但不带 Key | **采用** | 用户更正后的选择；Key 不会离开渠道域名 |
| 绝对地址请求：允许且带 Key | 放弃 | 写错的插件可能把 Key 发到任意域名 |
| 绝对地址请求：只允许 base_url | 放弃 | 做不了直传 OSS 预签名地址这类上游 |
| 允许访问内网：只放行 base_url | 放弃 | 用户选择直接删掉开关，他们不在内网自建网关 |
| 允许访问内网：保留并全部放行 | 放弃 | 去掉白名单以后，等于整个内网对插件开放 |
| 去掉 endpoints 的 sync/async 声明 | **本期不做** | 用户未选；继续沿用现状 |
| 文件引用直接写字符串 | **本期不做** | 用户未选 |
| 支持 base64 产物 | **本期不做** | 用户未选；需要调高返回值和响应体的大小上限 |
| 提示词改成“直接出码” | 放弃 | 用户选择保留“先提问” |
| `status` 同义词放宽 | 放弃（默认） | 宿主替插件猜状态，出错时更难排查 |

### 第 2 期（2026-10-12，已实现，未发版）

**版本号自动递增（§6.5）已实现**

- 规则按设计的 1–5 条实现；`pluginmeta.Validate` 不再把 `version` 当必填项（缺失、不是 semver、写成数字都放行），`Meta.UnmarshalJSON` 对非字符串的 `version` 当作没写；内置插件登记时仍要求合法 semver，否则启动报错。
- `version_adjusted.from` 只在代码里写了**合法**版本号时才有值：写成 `v1.0`、`1.0`、数字等不合法写法一律按“没写”，`from` 为空串。设计文档原来写“代码里写的，可能为空”，这里把“不合法”也归到“空”，前端据此用“代码里没有写合法的版本号”的文案。
- 登记的版本号用 `metaWithVersion` 回写 `meta_json`，只搬运顶层字段，`channelSettings` 内部的书写顺序不变（有测试守着）。
- 并发冲突重试最多 3 次，每次重新读版本列表；`aiconfigfake.MemRepo` 新增 `SaveVersionConflicts` 来模拟。
- “版本号已存在”这个拒绝原因基本消失，只有 3 次重试后仍冲突才会出现；新增拒绝原因“代码与 vX.Y.Z 完全相同”，问题路径是 `meta`。
- 版本决定的函数放在 `service/ai_plugin.go`，没有拆成独立文件：`.golangci.yml` 里 service 层的 depguard 规则按前缀 `provider/plugin` 匹配，会把 `provider/pluginmeta` 一并拦下，新建文件的 import 会被 `--new-from-merge-base` 检出，而 `ai_plugin.go` 里的是存量。这条规则本身偏宽（service 里已有 5 个文件 import `pluginmeta`），留给你决定要不要收紧，本次没动。

**评审后补的几处（与最初设计的出入）**

- **试跑后用户落在“追踪”标签**：面板在试跑结束后会自动切到“追踪”，按钮若只在“结果”标签里要切回去找。现在两个标签都有，追踪标签通过 `TraceTimeline` 新增的通用 `actions` 插槽放置，组件本身不认识修复信息。
- **只有 `failed` 才给试跑的复制按钮**：过期、取消不是插件的问题，原来跟着“测试失败”提示一起显示，已收窄。
- **渠道检查也覆盖“插件本身出错”**：AI 写的插件最常见的毛病是钩子抛异常或返回非法请求，检查时后端回 502 / 50022，原来只有 `ok=false` 才有按钮。现在 `classifyCheckError` 认出 50022，带上后端文案并给按钮；这类结果仍不允许保存渠道，保存闸门不变。
- **剪贴板不可用**：`CopyButton` 原来写入失败时静默，页面不是 https 时 `navigator.clipboard` 是 `undefined`，按钮点了没反应，而修复文本不在界面上。现在先用剪贴板 API，失败退回隐藏文本框加 `execCommand('copy')`，两条都失败时三个入口会 toast 说明；原有 16 处调用不传 `onError`，失败仍静默。
- **“代码与已有版本完全相同”不给复制按钮**：没有哪里要改，发给 AI 没有意义。判断是“每个问题都是 `meta` 路径且文案含‘完全相同’”，宁可漏判也不误判（误判会把‘没导出 meta’的按钮藏掉）。

**已知限制**

- 试跑修复信息里的插件版本取自“模型当前所选渠道固定的版本”，不是任务快照（任务视图里没有插件版本）。试跑后有人把渠道升了版本，复制出来的版本号会和实际跑的不一致。
- 上传预检未通过时拿不到插件 key；后端以后在拒绝时带上 key，文本里会自动出现。
- 没有在浏览器里看过实际界面（项目约定不用浏览器自动化），上传对话框、结果面板里新增的 JSX 只靠类型检查、渲染到字符串的测试和读代码保证，需要人工打开确认。
