画布保存：本地优先，再同步云端

改动先高频写进浏览器 IndexedDB，再以较长的间隔上传云端。关页、断网、崩溃都不丢内容；云端保持停手 3 秒、最长 10 秒（现状是 3 秒 / 30 秒）。下面有一个可以操作的模拟器，先玩一遍再看设计。

1设计摘要

问题：现在改动要等云端窗口（停手 3 秒、最长 30 秒）才保存。窗口内关页、崩溃、断网，改动就没了；窗口调短又会让云端请求变密（每次都是整张图谱全量 PUT）。

方案：保存拆成两层，各管一件事。

内存（编辑器）

用户正在操作的图谱，随时变。

0.3 秒合并窗口

本地 IndexedDB 草稿

防丢层。几乎每次操作都落盘，不依赖网络。

停手 3 秒最长 10 秒

云端 PUT /canvas/:id

共享层。带 revision 乐观锁，成功后清掉草稿。

已确认的决定

  • 用户确认本地 0.3 秒、云端停手 3 秒且最长 10 秒（用户后改：原先定的是 10 秒 / 60 秒）。
  • 用户确认下次打开发现草稿比云端新：基准版本一致就自动恢复并补传。
  • 用户确认状态栏只有「正在保存 / 已保存」，云端上传时不额外提示；只有失败、冲突才变色。
  • 用户确认同一画布在两个标签页打开：后打开的只读，提示「已在另一个标签页打开」。
  • 用户确认退出画布必须强制保存一次；移动视窗不触发保存，刷新后仍停在移动之后的位置（视口单独存本机，见 4.5）。

4推荐方案

4.1 触发规则

4.2 打开画布：对账规则

本地草稿条件行为
无—直接用云端版本，与现在一致
有，且已同步（cloudDirty=false）—丢弃草稿，用云端版本
有，未同步草稿的 baseVersion = 云端当前 revision自动恢复并补传，右上角提示「已恢复上次未同步的改动」（用户确认）
有，未同步baseVersion ≠ 云端 revision云端在别处被改过：弹现有冲突弹窗（加载最新 / 另存为），草稿保留为备份，不静默覆盖

4.3 状态栏（用户确认）

正在保存
改动后立即出现，转圈；连续编辑期间一直保持，不随每次 0.3 秒写入来回闪。
已保存
最后一次写入后静默 0.8 秒才出现，2 秒后收成对勾。云端上传在后台静默进行，不额外提示。
云端保存失败 · 重试 / 存在冲突
只有异常才变色。云端失败要重试一次仍失败才变红；冲突立即显示。内容都在本地，可点重试。

状态栏防抖（用户确认）

转换规则
已保存 → 正在保存立即：改动一发生就显示，用户操作后马上有反馈。
正在保存 → 已保存防抖：最后一次本地写入完成后，静默 0.8 秒才切换；期间又有改动或写入，计时重来。
云端失败延后显示（用户确认）：第一次失败不变色，第一次自动重试（约 5 秒后）仍失败才变红「云端保存失败 · 重试」。变红后保持到成功才恢复，避免红色闪烁。内容此时已在本地草稿，晚几秒提示不会丢内容。
冲突（409）立即显示：不是瞬时问题，重试也不会好，不延后。

0.8 秒是我定的初值（比 0.3 秒写入窗口略长一个节拍，足以盖住连续编辑的间隙），可以调。「已保存」收成对勾的 2 秒计时从切换那一刻开始。

要注意：「已保存」现在指「已存到这台浏览器」，不代表云端已有。换设备立刻打开可能看不到最新改动，最久滞后 10 秒。这是你选择安静状态栏的代价，在第 8 节里列为已接受的取舍。

4.4 多标签页（用户确认）

每张画布用 Web Locks（navigator.locks）加锁，键为 canvas:{userId}:{canvasId}。先打开的标签页持有锁可编辑；后打开的拿不到锁，进入只读，底部提示「已在另一个标签页打开」。先开的标签页关闭后，后开的可以接管并读取最新草稿。

4.5 视口：只移动、刷新后仍停在原位置

视口是「这台设备此刻看哪里」，属于视图状态，不是画布内容。所以不走保存链路，单独存一份：

项做法
存哪localStorage，键 viewport:{userId}:{canvasId}，值 {x, y, zoom}，几十字节。
何时写平移缩放结束（onMoveEnd）后约 200ms 防抖写入。
不触发什么不标脏、不排云端、不动 revision、不显示「正在保存」、不写草稿。
打开时取哪个本机视口 > 云端 payload.viewport > 默认视图。
云端视口仍随内容保存一起带上，只用于「这台设备第一次打开」和换设备时的初始位置。
刷新、关页、返回列表都不需要额外动作，因为每次移动已经落地。
  • 用户确认需求：只移动视口、刷新窗口后仍停在移动之后的位置。
  • 提案为什么用 localStorage 而不是 IndexedDB：同步写入，pagehide 里也一定写得完；视口只有几十字节，不需要异步。
  • 提案为什么不放进草稿：草稿在云端同步成功后会被清除，刷新时就只剩云端旧视口，位置会跳回去。
  • 提案本机视口指向的区域已经没有任何节点（比如别的设备删光了）：自动「适应全部内容」，避免一片空白。
  • 提案清理：退出登录清该用户全部视口记录；画布删除时一并清；超过 30 天未打开的清理。
  • 提案localStorage 不可用（隐私模式等）：退回云端视口，即只有内容保存时才更新，用户基本无感。
  • 换设备打开，看到的是云端最近一次内容保存时的视口，不是最后移动的位置。视口本来就是每台设备自己的视角，作为已接受的取舍。
  • 事实影策比较内容时排除 viewport（canvas-content.ts），做法一致；tldraw 的 document/session 划分未验证。

5数据结构

草稿存同一份图谱 JSON，和云端 payload_json 一致，不需要改后端、不改 payload。

// IndexedDB: 库 video-canvas，对象仓库 canvas-drafts，主键 `${userId}:${canvasId}`
{
  schemaVersion: 1,
  graph: CanvasGraphDto,     // 与 PUT 的 payload_json 同构；其中 viewport 只是上次内容保存时的值，打开时以本机视口为准
  baseVersion: number,       // 这份草稿基于云端哪个 revision
  cloudDirty: boolean,       // true = 还没上传成功
  savedAt: number            // 本地写入时间，用于清理过期草稿
}
  • 提案云端确认成功后，若期间没有新改动，把 cloudDirty 置 false 并删除草稿；有新改动就保留，baseVersion 更新为新 revision。
  • 提案主键带 userId：换账号看不到上一个人的草稿；退出登录时清空该用户全部草稿（草稿含用户创作内容，共享电脑上必须清）。
  • 提案清理：打开画布列表时，删除 savedAt 超过 30 天且已同步的草稿。
  • 提案容量：单个草稿写入失败（配额、隐私模式禁用 IndexedDB）时降级为仅云端保存，并在状态栏保持原样；见第 6 节。

6状态与异常

首次打开 / 无草稿与现在完全一致。

7数据与工程影响

可复用
  • use-canvas-persistence.ts 的 exclusive 串行、重试、冲突流程原样保留。
  • save-schedule.ts 的 nextSaveDelay 是纯函数，两层各用一组参数即可复用。
  • getGraph() 发请求那一刻才序列化，本地写入和云端上传共用。
  • 现有冲突弹窗、canKeepalive 不变。
需要新增
  • 草稿存取模块：读、写、删、按用户清空（IndexedDB 薄封装）。
  • 第二个调度器：本地 0.3 秒/最长 1 秒。
  • canvas/index.tsx 加载时对账（4.2）。
  • 卸载与 pagehide 强制写入；useBlocker 非必需（本地兜底后不用拦截路由）。
  • Web Locks 多标签页只读态。
  • API / payload / revision：本阶段不改。云端最长窗口从 30 秒缩到 10 秒，请求会比现在更密，单次大小不变（仍是整图替换，见第 3 节）。
  • 主要难点：对账的边界（4.2 第四行）、baseVersion 在上传成功后要及时更新、本地写入与云端上传各自的在途控制。
  • 测试（TDD）：对账规则、调度窗口、草稿清理、冲突期间继续写草稿都是纯逻辑，可在 web/src/tests/ 用假 IndexedDB 做单测；真实浏览器行为（pagehide 写入、Web Locks）需人工点测。

阶段四预研：差量上传

用户确认差量上传排到阶段四，草稿层先上。以下是预研，不是本次范围。

PATCH /canvas/:id
{ revision, ops: [
  { op: "upsertNode", node },  { op: "removeNode", id },
  { op: "upsertEdge", edge },  { op: "removeEdge", id },
  { op: "setMeta", appearance }          // 视口不在这里，见 4.5
]}
  • 提案前端：发请求那一刻，拿「上次云端确认的快照」和当前图谱按节点 id 比对算出 ops，不需要追踪每个事件；与「发请求时才序列化」的现有思路一致。
  • 提案后端：事务内读 payload_json、校验 revision、按 id 套用 ops、写回、revision + 1。数据库写入仍是整列，省的是网络上传和前端序列化，不是数据库开销。
  • 提案幂等：upsert / remove 按 id，重发不会重复。「请求成功、响应丢了」时重试会拿旧 revision 撞自己的写入，全量 PUT 现在也有这个问题，需要幂等键或「版本相同视为已应用」。
  • 提案顺带收益：差量包通常很小，大画布关页时 keepalive 的 60KB 上限基本不再是问题。
  • 代价：前后端都要新写，要测 diff 与套用和全量结果一致；ops 仍基于确切 revision，不一致仍 409，「改不同节点自动合并」是后续能力，不是白送的。

8方案取舍

A. 本地优先两层（推荐）

本地 0.3 秒落盘，云端 3 秒 / 10 秒。

B. 只缩短云端窗口

你上次撤销的做法：云端 0.3 秒。简单，但请求变密，大画布关页仍丢。

C. 影策式完整同步层

本地库为主，云端是副本，字段级三方合并。最强，改动量也最大。

明确放弃

  • 字段级三方合并：冲突仍整体二选一，沿用现有弹窗。
  • 增量/patch 保存接口：本阶段云端仍全量 PUT，已排入阶段四（见第 9 节）。
  • 两个标签页同时编辑同一画布。
  • 状态栏区分「本地已存 / 云端已同步」。

已接受的代价

  • 云端最多落后 10 秒，换设备立刻打开可能看不到最新改动。
  • 草稿存在浏览器里，换浏览器或清站点数据就没了；它只是防丢层，不是备份。
  • 共享电脑上草稿含创作内容，靠「按用户隔离 + 退出登录清空」缓解。

9MVP 与后续

阶段范围验收条件
一草稿存取 + 本地调度 0.3 秒 + 云端窗口改 3s/10s + 退出强制落盘 + 视口单独存本机编辑后 0.5 秒内草稿已写入；云端上传在停手 3 秒后、连续编辑最长 10 秒内发出；只移动视窗后刷新、返回再进来，视口仍在移动之后的位置，且全程没有网络请求。
二打开对账：自动恢复并补传；冲突沿用现有弹窗；退出登录清草稿上传前关页再打开，改动完整恢复并在后台补传；版本对不上时不静默覆盖；换账号看不到上一个人的草稿。
三Web Locks 多标签页只读；写入失败降级；过期草稿清理第二个标签页只读且有提示；禁用 IndexedDB 时仍能正常保存到云端。
四差量上传：新增 PATCH /canvas/:id，按节点 id 传 ops（第 7 节）只改一个节点时请求体只含该节点；大画布关页 keepalive 能发出；幂等重发不产生重复数据；与全量 PUT 的结果逐字段一致。
后续字段级自动合并、跨设备实时同步不在本次范围。

10待确认问题

原先的 4 项已全部由用户确认：

  1. 已确认退出不再阻塞等云端：只强制写本地，云端后台补传，不拦截跳转。
  2. 已确认IndexedDB 封装：引用库，选定 idb（见第 7 节）。
  3. 已确认云端请求量：最长窗口 30→10 秒，连续编辑时请求最多变成现在的 3 倍，用户接受。后端承受能力仍未压测。
  4. 已确认草稿保留期：已同步的草稿 30 天后清理。
