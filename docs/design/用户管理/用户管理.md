# 用户管理

> 交互与界面方案，落地到像素和动效。产品层面的规则（权限、积分、封禁、注册）见 [用户管理与注册设计.md](../用户管理与注册设计.md)，本文只覆盖后台「用户管理」页。
> 原型：[用户管理原型.html](用户管理原型.html)，直接用浏览器打开。
> 状态：待确认，未写代码。日期 2026-10-05。

## 1. 问题和目标

上一版演示（[用户管理与注册-演示.html](../后台管理设计/用户管理与注册-演示.html)）是「表格 + 居中弹窗 + 三个页签」，有这些问题：

| # | 问题 | 后果 |
|---|---|---|
| 1 | 加积分要三步：点行 → 切「积分」页签 → 填表 | 最高频的操作最慢 |
| 2 | 弹窗盖住整张列表 | 处理下一个用户要先关弹窗，没法连续处理 |
| 3 | 「管控」页签把并发和封禁、改角色、重置密码混在一起 | 日常操作和危险操作的风险等级没有区分 |
| 4 | 封禁先弹确认框 | 封禁可逆，按项目规则应该给撤销；确认框只该留给不可逆的部分 |
| 5 | 没有批量操作 | 清理刷号账号只能一个一个封 |
| 6 | 选中的用户不在 URL 里 | 刷新就丢了，也没法把某个用户的链接发给同事 |
| 7 | 看不到用户用了什么、什么时候登录的 | 处理投诉和发现刷号时没有依据 |

**目标**：

- 加积分 1 步完成（点积分格 → 输入 → 回车）。
- 抽屉打开时列表仍然可用，↑↓ 就能连续处理多个用户。
- 封禁 1 次点击，5 秒内可撤销；只有不可逆的「取消任务」才弹确认框。
- 能批量封禁、启用和发积分。
- 能看每个用户的生成记录和登录记录。

## 2. 已确认的决定（2026-10-05）

| 题目 | 决定 |
|---|---|
| 布局 | 表格 + 右侧详情抽屉（变更：原为居中弹窗） |
| 行内操作 | 点「可用积分」格就地调整；其余操作放行末「⋯」菜单 |
| 批量 | 批量封禁 / 启用 + 批量发积分 |
| 封禁确认 | 直接封禁 + 5 秒撤销；「封禁并取消任务」才弹确认框（变更：原为始终弹确认框加勾选项） |
| 使用日志 | 生成记录（读已有的 `generation_tasks`）+ 登录记录（新增表） |
| 抽屉结构 | 顶部摘要常驻 + 四个页签「概览 / 生成 / 积分 / 登录」，宽 560px（变更：原为弹窗三个页签「概览 / 积分 / 管控」） |

### 4.3 积分浮层（行内和抽屉共用）

从积分格（或抽屉里的「调整积分」按钮）正下方弹出，宽 288px；下方放不下时翻到上方，`transform-origin` 指向触发点。

```
┌──────────────────────────────┐
│ [增加 | 扣减 | 设为]          │
│ [+50] [+100] [+500] [+1000]   │  ← 只在「增加」时出现
│ ┌──────────────────────────┐ │
│ │ 100                      │ │  ← 自动聚焦，只接受整数
│ └──────────────────────────┘ │
│ ┌──────────────────────────┐ │
│ │ 备注（必填）              │ │
│ └──────────────────────────┘ │
│ 24 → 124                ⏎ 确认│  ← 预览实时计算
└──────────────────────────────┘
```

- 快捷档点击即填入数值，焦点跳到备注框；再点同一档是累加（+100 再点 +100 = 200）。
- 三种模式都以**可用积分**为准：增加 / 扣减是在可用积分上加减；「设为」是把可用积分设为指定值（后端换算为 余额 = 指定值 + 冻结额），所以不会出现「不得低于冻结额」这类让人困惑的报错。变更：产品文档 §6.3 原为「设为余额，不得低于冻结额」。
- 预览一行实时显示「当前可用 → 调整后可用」；扣减超过可用时，预览变 destructive 并写出原因（「最多可扣 24」），确认按钮禁用。
- Enter 提交（备注框内也是），Esc 关闭；点浮层外关闭但**保留已填内容**，10 秒内重新打开同一个用户的浮层会恢复。
- 提交中：确认按钮转圈，浮层不关、不可重复提交。
- 成功：浮层关闭（退出动画），表格和抽屉里的数字用 `NumberFlow` 滚到新值；toast「已为 zhangsan 增加 100 积分」+「撤销」（5 秒）。撤销 = 写一笔反向的 `admin_adjust` 流水，备注「撤销：原备注」，不删除原流水。
- 失败：全局 toast 由拦截器弹；浮层保持打开，内容不丢。

### 4.4 抽屉

基于 `components/ui/sheet`，`modal={false}`、**无遮罩**：抽屉打开时表格仍可滚动、点击，点另一行直接切换抽屉内容，不先关再开。

**头部**（固定，不随页签滚动）

| 控件 | 说明 |
|---|---|
| 身份行 | 头像 40px + 用户名（16px semibold）+ 角色 Tag + 状态 Tag；下一行邮箱 · ID · 注册时间（12px muted），邮箱后有 `CopyButton` |
| 上一个 / 下一个 | 右上角两个图标按钮 `ChevronUp` `ChevronDown`，快捷键 ↑ ↓ 或 K / J（焦点不在输入框时生效），Tooltip 写明；到首尾时禁用。按当前表格的筛选和排序切换，跨页时自动翻页 |
| 关闭 | `X`，Esc；关闭后焦点回到原来那一行 |
| 摘要 | 三格等宽：可用积分（`text-credit`，`NumberFlow`）/ 冻结 / 并发 `2/2` + 进度条 |
| 操作行 | 「± 调整积分」（打开 §4.3 浮层）、「并发上限」（浮层：数字输入 + 「使用默认（4）」开关）、「封禁」/「启用」、`⋯`（修改角色、重置密码、封禁并取消任务） |

**页签**：`Tabs`，下划线滑块用 `layoutId` + `SPRING`；同步 `?tab=overview|tasks|credits|logins`。「生成」页签有进行中任务时带数字徽标。

| 页签 | 内容 | 筛选 / 分页 |
|---|---|---|
| 概览 | `DescriptionList` 两列：注册时间、邮箱验证、最近登录（时间 + IP）、生成总数、成功率、累计消耗积分、近 7 天生成数；下方「最近管理员操作」最多 3 条（来自审计），「查看全部」跳积分页签 | 无 |
| 生成 | 每行：时间 · 类型图标 + 模型名 · 状态 Tag · 扣费 · 耗时；失败行可展开看错误信息；任务 ID 可复制 | `Segmented`：全部 / 成功 / 失败 / 进行中；滚到底部「加载更多」（游标分页，每次 20 条） |
| 积分 | 每行：类型 Tag（赠送 / 冻结 / 结算 / 退款 / 管理员调整）· 变动（正数 `status-success`、负数 destructive，带正负号）· 说明（备注或任务 ID）· 操作人 · 时间 | `Segmented`：全部 / 管理员调整 / 任务；加载更多 |
| 登录 | 每行：时间 · 结果（成功 / 密码错误 / 账号已停用 / 注册）· IP · 设备（由 UA 解析成「Chrome · macOS」） | `Segmented`：全部 / 失败；加载更多。**提案**：同一 IP 关联多个账号时在 IP 后标「关联 5 个账号」，用来发现刷号 |

### 4.5 行菜单（⋯）与权限

```
查看详情                 ⏎
调整并发上限…
────────────────
封禁                     （或「启用」）
封禁并取消 2 个任务…     ← 只在有进行中任务时出现，destructive
────────────────
修改角色             ▸   ← 仅 super_admin
重置密码…                ← 仅 super_admin
```

- 无权限的项**禁用**，不隐藏；hover 用 `ReasonTooltip` 写原因：「admin 不能操作管理员账号」「不能对自己执行此操作」（封禁、改角色）「仅超级管理员可用」（改角色、重置密码）「admin 不能给自己调整积分」。
- 「admin 不能给自己调整积分」是本方案新增的规则，防止运营给自己发积分；super_admin 不受限。产品文档 §6.2 的权限表需同步。
- 菜单按 Base UI 规则：`DropdownMenuLabel` 必须包在 `DropdownMenuGroup` 里。

### 4.6 封禁与启用

| 操作 | 流程 |
|---|---|
| 封禁 | 立即生效 → 状态 Tag 切换 → toast「已封禁 zhangsan」+「撤销」，5 秒。撤销 = 调用启用接口 |
| 封禁并取消 N 个任务 | `confirm()` 确认框（destructive）：写明「将取消 2 个进行中任务并退还 12 冻结积分，此操作无法撤销」→ 确认后执行，toast 不带撤销 |
| 启用 | 立即生效，toast「已启用 zhangsan」+「撤销」 |

### 4.7 批量

勾选 ≥1 行时，底部浮出 `DataTableBulkActions`（和模型页同一个组件）：「已选 N 个用户 │ 发积分… │ 封禁 │ 启用 │ ✕」。

- **发积分**：打开 `Dialog`，数值 + 快捷档 + 备注（必填）；底部预览「3 人 × 100 = 300 积分」。只支持「增加」，不支持批量扣减和设为（误操作代价太高）。
- **封禁 / 启用**：立即执行，toast「已封禁 3 个用户」+「撤销」。
- 选中里有当前身份无权操作的账号（admin 选中了管理员、选中了自己）时，自动跳过，toast 里写「已跳过 1 个：不能封禁自己」。
- 批量封禁**不提供**取消任务选项；要取消任务请逐个处理。
- 执行后清除勾选；Esc 也清除勾选。

### 4.8 快捷键

| 键 | 作用 | 生效范围 |
|---|---|---|
| `/` | 聚焦搜索框 | 页面，焦点不在输入框时 |
| `↑` `↓` / `K` `J` | 上一个 / 下一个用户 | 抽屉打开，焦点不在输入框时 |

## 5. 动效表

全部参数取自 `web/src/lib/motion.ts`，只动 `transform` 和 `opacity`。

| 触发 | 属性 | 时长 / 曲线 | 方向 / 原点 |
|---|---|---|---|
| 抽屉打开 | `x: 100% → 0`，`opacity 0 → 1` | `DURATION.slow`（240ms），`EASE_OUT` | 从右边缘滑入 |
| 抽屉关闭 | `x: 0 → 100%`，`opacity → 0` | **新增** `DURATION.slowExit`（168ms，即 240 的 70%），`EASE_OUT` | 回到右边缘 |
| 抽屉内切换用户（↑↓ 或点另一行） | 内容 `y: ±8px → 0`，`opacity 0 → 1` | `DURATION.base`（180ms），`EASE_OUT` | 下一个从下方进、上一个从上方进；抽屉外框不动 |
| 选中行竖条 | `layoutId` | `SPRING` | 跟着选中行移动 |
| 页签下划线 / Segmented 滑块 | `layoutId` | `SPRING` | — |
| 页签内容切换 | `opacity 0 → 1` | `DURATION.base` | 不做位移，避免和用户切换的位移混淆 |
| 积分 / 并发浮层出现 | `scale 0.96 → 1`，`opacity 0 → 1` | `DURATION.base`，`EASE_OUT` | `transform-origin` = 触发格的中心上沿（翻到上方时是下沿） |
| 浮层关闭 | 反向 | `DURATION.exit`（126ms） | 回到触发点 |
| 积分、并发数字变化 | `NumberFlow` 数位滚动 | 组件默认 | 增加向上滚、减少向下滚 |
| 状态 Tag 切换（封禁 / 启用） | 交叉淡入淡出 | `DURATION.fast`（120ms） | — |
| 批量条出现 | `y: 16px → 0`，`opacity 0 → 1` | `DURATION.base`，`EASE_OUT` | 从底部升起 |
| 批量条消失 | 反向 | `DURATION.exit` | 回到底部 |
| 按钮按下 | `scale 0.96` | `TAP` | — |
| 表格首屏骨架 | 等 `SKELETON_DELAY`（150ms）还没返回才出现，之后淡入 | `DURATION.base` | — |

> `SPRING` 数值积分到 1% 误差约 280ms，略长于 250ms 的验收线；但最后 30ms 的位移不到 1px，视觉上已停稳。原型按真实曲线播放，不截断。

**减少动态效果**（`prefers-reduced-motion: reduce`）：所有位移和缩放去掉，只保留 `opacity` 淡入淡出；`NumberFlow` 设 `animated={false}`；`layoutId` 滑块直接跳到位。

**不做的动效**：行 hover 不做位移；不做表格行依次入场（列表是工具，不是展示）；没有任何常驻循环动画（进行中任务的状态点除外）。

## 9. 已确认与待确认

**已确认（2026-10-05）**

1. `api/admin-users` 字段沿用 admin-ai 的例外：直接用后端 snake_case 与数字 id，不做 camelCase 映射。
2. 登录记录保留 180 天，超期由定时任务清理（后续已改为代码常量，不再提供配置项）。

3. 「同一 IP 关联多个账号」提示**不进 MVP**：登录记录里不记关联账号数，原型里的黄色标签实现时不做；注册时仍记 IP 到登录记录，为以后补这个提示留数据。

**仍待确认**

无。
