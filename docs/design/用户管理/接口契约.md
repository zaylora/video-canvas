# 用户管理与注册：接口契约

> 前后端共同遵守的单一事实来源。产品规则见 [用户管理与注册设计.md](../用户管理与注册设计.md)，界面见 [用户管理.md](用户管理.md)。
> 响应统一沿用项目现有包装：成功 `{code:0, data, msg}`，分页走 `response.OKPage`，业务错误 `{code, msg}` + 对应 HTTP 状态。字段一律 snake_case，id 为数字（`api/admin/users` 不做 camelCase 映射）。
> 角色：admin = 运营，super_admin = 运维。「SA」表示仅 super_admin。

## 1. 公开接口（无需登录）

### GET /auth/config

```json
{ "register_enabled": true, "email_verify_required": true }
```

- `register_enabled`：后台「开放注册」开关的值（2026-10-05 起不再受 SMTP 影响）。
- `email_verify_required`：SMTP 已启用 且 users 表非空时为 true（「邮件服务」页的启用开关就是是否验证邮箱的选择）。没启用 SMTP 时为 false：邮箱仍必填，但不验证、不写 `email_verified_at`；首个账号永远免验证。

### POST /auth/register/code

请求 `{ "email": "a@b.com" }` → `data: null`。

- 注册关闭 / 无 SMTP：`ErrRegisterClosed`。邮箱已被注册：`ErrEmailExists`。同邮箱 60 秒内重复：`ErrTooManyReqs`。同 IP 每小时超过 20 次：`ErrTooManyReqs`。
- 验证码 6 位数字，10 分钟有效，错误 5 次作废。存 Redis；Redis 未启用时进程内存。debug 模式把验证码打印到日志，release 绝不输出。

### POST /auth/register

请求：

```json
{ "username": "alice", "email": "a@b.com", "password": "secret1", "code": "123456" }
```

- `email` 必填；`code` 在 `email_verify_required=true` 时必填，否则忽略。
- 事务内：校验码 → 用户名唯一 → 邮箱唯一 → 判断 users 是否为空（为空 role=super_admin，且 email_verified_at 仅在验证过时写入）→ 建用户 → 建积分账户并写 `initial` 流水 → 写 `register` 登录记录。
- 返回：`{ "token": "...", "expire_at": 1730000000, "role": "user" }`（注册即登录）。
- 错误：`ErrRegisterClosed`、`ErrUserExists`、`ErrEmailExists`、`ErrCodeInvalid`（错误 / 过期 / 次数用尽统一）。

### POST /auth/login（行为变更）

- 返回体增加 `role`。
- 账号 `status=disabled`：`ErrAccountDisabled`（403）。登录成功更新 `last_login_at` 并写 `login` 登录记录；失败（密码错）写 `badpw` 记录，账号停用写 `blocked` 记录。写日志失败只记日志，不影响登录。
- 登录响应的 token 带 `token_version`（见 §5）。

## 2. 鉴权行为变更

- `JWTAuth` 之后新增 `RequireActive` 中间件（挂在所有 `auth` 分组上）：查用户状态，`disabled` 返回 `ErrAccountDisabled`（HTTP 403，前端据此清 token 跳登录页）；token 内的 `token_version` 与用户当前值不符返回 `ErrUnauthorized`。
- 状态查询复用 `cache.UserCache`（Redis `user:<id>`）；封禁、启用、改角色、重置密码、改并发时主动 `Delete` 缓存；无 Redis 直接按主键查库。
- `RequireAdmin` / `RequireSuperAdmin` 的角色查询改用同一套（去掉 30 秒内存缓存）。
- 封禁时断开该用户全部 WebSocket 连接（`Hub` 新增 `DisconnectUser(userID)`）。
- 收口：删除 `GET /users`、`GET /users/:id`（原先任何登录用户可调）。

## 3. 后台接口 `/admin/users`（RequireAdmin）

### 视图

```ts
UserListItem {
  id, username, email, role: "user"|"admin"|"super_admin", status: "active"|"disabled",
  balance, frozen, available,            // 无积分账户的老用户：balance=0 且 has_credit_account=false
  has_credit_account: boolean,
  max_active_tasks: number | null,       // 单用户覆盖，null = 用全局默认
  effective_max_active_tasks: number,    // 实际生效上限
  active_tasks: number,                  // 进行中任务数
  last_login_at: string | null, created_at
}
UserDetail = UserListItem + {
  email_verified_at: string | null, task_total, task_success, task_failed, spent_credits, tasks_last_7d,
  recent_audits: { actor_id, actor_name, action, detail_json, created_at }[]   // 最多 3 条
}
```

### 接口

| 方法 路径                                            | 权限  | 说明                                                                                                                                                                    |
| ---------------------------------------------------- | ----- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `GET /admin/users?q=&status=&role=&page=&page_size=` | admin | `q` 模糊匹配 username/email（ILIKE）；分页（page_size 最大 100）；按 id 倒序                                                                                            |
| `GET /admin/users/:id`                               | admin | `UserDetail`；不存在 `ErrUserNotFound`                                                                                                                                  |
| `GET /admin/users/:id/tasks?status=&cursor=&limit=`  | admin | 生成记录：`{ items:[{id,kind,model_key,model_name,status,credits,charged_credits,error,duration_ms,created_at}], next_cursor }`；`status` 为 all/success/failed/running |
| `GET /admin/users/:id/ledger?type=&cursor=&limit=`   | admin | 积分流水：`{ items:[{id,type,amount,task_id,note,operator_id,operator_name,created_at}], next_cursor }`；`type` 为 all/admin/task                                       |
| `GET /admin/users/:id/logins?result=&cursor=&limit=` | admin | 登录记录：`{ items:[{id,kind,result,ip,user_agent,created_at}], next_cursor }`；`result` 为 all/fail                                                                    |
| `POST /admin/users/:id/credits`                      | admin | `{ mode:"add"\|"sub"\|"set", amount:int>=0, note:string(1..100) }`，返回最新 `{balance,frozen,available}`；规则见 §4                                                    |
| `PUT /admin/users/:id/limits`                        | admin | `{ max_active_tasks: int(1..64) \| null }`                                                                                                                              |
| `PUT /admin/users/:id/status`                        | admin | `{ status:"active"\|"disabled", cancel_active?: boolean }`；`cancel_active` 仅封禁时有效，取消其进行中任务并退还冻结                                                    |
| `PUT /admin/users/:id/role`                          | SA    | `{ role }`                                                                                                                                                              |
| `POST /admin/users/:id/reset-password`               | SA    | `{ new_password?: string }`，缺省则生成临时密码；返回 `{ temp_password }`（仅此一次）；`token_version` +1                                                               |
| `POST /admin/users/batch/credits`                    | admin | `{ ids:int[], amount:int>0, note }`，只增不减；返回 `{ results:[{id, ok, error?}] }`                                                                                    |
| `PUT /admin/users/batch/status`                      | admin | `{ ids:int[], status }`（不支持取消任务）；返回 `{ results:[{id, ok, error?}] }`                                                                                        |

### 实际落地的形态（阶段二实现后补充，以代码为准）

- **游标分页**：`cursor` 是对「上一页最后一条 id」做 base64url 编码的不透明字符串，按 id 倒序；`limit` 缺省 20、超过 100 按 100；`next_cursor` 没有更多时是**空串 `""`**（不是 null）；游标非法 400/10001，用户不存在 404/20001。
- **流水 `amount` 带符号**（列表接口的响应层统一，库里存的值不变）：`freeze`、`settle` 为负，`refund`、`initial` 为正，`admin_adjust` 原值。
- **tasks 的 `status=failed`** 包含 `failed`、`expired`、`canceled`；详情里的 `task_failed` 统计口径不含 `canceled`。`duration_ms` = 完成时间 − COALESCE(提交时间, 创建时间)，未完成为 null。
- **`PUT /:id/status` 响应**：`{ status, canceled, cancel_failed, failed_task_ids, cancel_error? }`。封禁已生效后取消任务整体出错时不回滚封禁，写入 `cancel_error`。
- **`PUT /:id/limits`** 响应 `null`；`{}` 与 `{"max_active_tasks":null}` 效果相同（清除覆盖）。
- **积分调整**：`amount` 上限 1e8；`set` 缺 `amount` 返回 400；`set` 与当前可用积分相同（delta=0）仍写一条 amount=0 的 `admin_adjust` 流水与审计。审计 `detail_json`：积分 `{mode, amount, delta, note}`，封禁 `{from, to, cancel_active, canceled, cancel_failed}`，启用与并发 `{from, to}`。
- **批量**：`ids` 1..200，service 先去重；单项失败写进 `results[i].error`，内部错误只返回「操作失败，请稍后重试」并记日志；批量路由注册在 `/:id` 之前。
- 封禁时断开该用户全部 WebSocket（`Hub.DisconnectUser`，直接关闭底层连接，不发 close 帧）。

权限规则（service 层判断，违反返回 `ErrForbidden` 并写明原因 Msg）：

- admin 不能操作 role 为 admin / super_admin 的账号；任何人不能封禁或改自己的角色；admin 不能给自己调整积分（super_admin 可以）。
- 批量接口对每个 id 独立判断，无权限的写入 `results[i].ok=false` 与原因，不整体失败。

## 4. 积分调整规则

事务内：`EnsureCredit`（无账户则建并写 initial 流水）→ `LockCredit` 行锁 → 计算 delta：

- add：delta = amount；sub：delta = -amount，要求 amount ≤ available，否则 `ErrCreditAdjustInvalid`（Msg 含"最多可扣 N"）；set：把**可用积分**设为 amount，delta = amount − available（后端余额 = amount + frozen）。
- `AddCredit(delta, 0)` → 写流水 `type=admin_adjust, amount=delta, task_id=NULL, operator_id, note`。
- amount=0 的 add / sub 返回 `ErrCreditAdjustInvalid`；set 允许 0。

`credit_ledger` 变更：`task_id` 改可空；唯一索引改为仅对 `task_id IS NOT NULL` 生效（部分唯一索引）；新增 `operator_id`（可空）、`note`（text）；type 新增 `admin_adjust`、`initial`。迁移需幂等、可重复执行、全新库可直接建。

## 5. 数据模型增量

- `users`：`status`(active/disabled，默认 active)、`max_active_tasks`(可空)、`email_verified_at`(可空)、`last_login_at`(可空)、`token_version`(int，默认 0)；`email` 部分唯一索引（`WHERE email <> ''`，需大小写不敏感地存小写）。
- `user_login_logs`：id、user_id（可空，登录失败且用户不存在时为 0）、kind(`login`/`register`)、result(`ok`/`badpw`/`blocked`)、ip、user_agent、created_at；索引 (user_id, created_at desc)；保留 180 天（代码常量 `DefaultLoginLogRetentionDays`，不再可配置），后台定时任务清理。
- `admin_audit_logs`：id、actor_id、action、target_type、target_id(uint64)、detail_json、created_at；只增不改不删。动作：`user.credit_adjust`、`user.ban`、`user.unban`、`user.role`、`user.reset_password`、`user.limit`、`settings.register`、`settings.smtp`。
- `system_settings`（键值）：`register_enabled`(默认 true)、`initial_credits`(库里没有值时回落代码常量 `DefaultInitialCredits = 50`)、`default_max_active_tasks`(回落 `DefaultMaxActiveTasks = 4`)。库值优先，代码常量兜底；配置文件里不再有这些项（2026-10-05 已删除 `ai.max_active_tasks_per_user`、`ai.initial_credits`、`user.login_log_retention_days`）。
- `smtp_settings`（单行）：host、port、encryption(`none`/`starttls`/`tls`)、username、password_enc（沿用 `ai_secrets` 的加密方式，需要 `APP_AI_SECRET_KEY`）、from_address、from_name、enabled、last_check_at、last_check_ok、last_check_error、updated_by。
- 并发上限：`insertAndFreeze` 中用 `COALESCE(users.max_active_tasks, system 默认)`；无设置时回落代码常量 `DefaultMaxActiveTasks`。

## 6. 设置接口 `/admin/settings`（读 admin，写 SA）

| 方法 路径                           | 说明                                                                                                                                                     |
| ----------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `GET /admin/settings/register`      | `{ register_enabled, initial_credits, default_max_active_tasks }`                                                                          |
| `PUT /admin/settings/register`      | SA，同上字段；`initial_credits>=0`，`default_max_active_tasks` 1..64；写审计                                                                             |
| `GET /admin/settings/smtp`          | `{ host, port, encryption, username, has_password, from_address, from_name, enabled, last_check_at, last_check_ok, last_check_error }`，**密码永不返回** |

| `POST /admin/settings/smtp/test`    | SA，`{ to }`，发一封测试邮件，更新 last_check_*；失败 `ErrSMTPSendFailed`（Msg 已脱敏，不含密码）                                                        |

## 8. 实施分期

- **阶段一**：数据模型与迁移、注册（含验证码、首个超管、注册即发积分）、`/auth/config`、SMTP 与注册设置、`/admin/users` 列表与详情、`/users` 收口、`RequireActive` 与缓存。
- **阶段二**：封禁 / 启用（含取消任务、断 WS）、并发覆盖、积分调整与流水、生成记录、登录记录、批量接口、审计。
- **阶段三**：角色调整、重置密码（token_version）、登录记录清理任务。
