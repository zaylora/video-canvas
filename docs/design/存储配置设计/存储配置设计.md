# 存储配置设计（对象存储接入）

> 范围：给素材存储加上**后台可配置的对象存储**，支持阿里云 OSS、腾讯云 COS、AWS S3、Cloudflare R2（及其他 S3 兼容服务），后台新增“存储配置”页。
> 配套：[存储配置设计-演示.html](./存储配置设计-演示.html)（讲解用幻灯片）· [存储配置原型.html](./存储配置原型.html)（可点击的后台页原型）。
> 日期：2026-10-03。状态：设计稿，未改任何代码。所有“提案”项在实现前仍可调整。

---

## 1. 设计摘要

**问题**：需求原话是“画布只有本地存储”。读完代码后发现，后端其实已经有 S3 兼容实现（minio-go），真正的问题是下面四个：

1. **配不了**：存储只能写在 `config.yaml` / 环境变量里，启动时创建一次，换存储要改 env 再重启；后台没有入口。
2. **换不了**：`assets` 表只记了 `storage_key`，没记“存在哪套存储里”。一旦切换存储，旧素材全部读不到。
3. **会过期**：私有桶返回 1 小时的签名 URL，前端却把它写进画布 payload 的 `src` 持久化，一小时后画布上的图和视频就失效了。
4. **兼容细节没处理**：OSS 只接受虚拟主机寻址，COS 的桶名带 APPID，现有代码和配置对此都没有专门处理。

**推荐结论**（均已与需求方逐题确认）：

| # | 决定 | 一句话 |
|---|---|---|
| D1 | **多套命名存储 + 一个默认** | 素材记 `storage_id`，切默认只影响新上传，旧素材原地可读 |
| D2 | **稳定路由 `/files/<key>` + 302** | payload 只存稳定地址，后端按素材所属存储即时签名跳转，永不过期 |
| D3 | **YAML 只保留 `local`** | 本地磁盘作为“内置存储”兜底；对象存储只能在后台配 |
| D4 | **后端中转 + 浏览器直传，按存储开关** | 中转永远可用；勾选“允许直传”的存储走直传。直传方式由服务商预设决定：POST Policy 或预签名 PUT（R2 只支持后者） |
| D5 | **迁移放二期** | 被素材引用的存储不能删除 |
| D6 | **继续用 minio-go** | 四家都走 S3 协议，按厂商预设参数，不新增依赖 |
| D7 | **定位字段锁定** | 有素材引用后，服务商、endpoint、bucket、前缀、region 不可改；换桶就新建一套存储 |

### 2.2 设计约束

- 分层固定为 `router → middleware → handler → service → repository`，测试放在 `backend/internal/tests/`，先写测试（TDD）。
- 密钥不进仓库、不进日志、不回显。复用 `ai_secrets` 的加密方式，不另起一套。
- 现有 local 部署产生的 `/files/...` 地址已经写进大量画布 payload，**必须继续可用**。
- 素材是用户隔离的（`user_id`），但文件路由目前不鉴权，新方案的安全等级不能比现在低。

### 2.3 当前缺口

见 §1 的四个问题。另有两点：local 模式下的 `/files/...` 是相对地址，上游 AI 平台访问不到，所以“参考图以 URL 传给上游”在 local 模式下本来就跑不通；接入对象存储后，这条链路才能真正可用。

## 3. 用户与场景

| 角色 | 场景 | 频率 |
|---|---|---|
| super_admin（运维 / 部署者） | 首次上生产：建一套 OSS/COS/S3，测试连接，设为默认 | 低频，但一次配错影响全站 |
| super_admin | 轮换 AK/SK、换 CDN 域名、调签名有效期 | 低频 |
| super_admin | 换云厂商 / 换桶：新建一套，设为默认，老的留着继续读 | 很低频 |
| admin | 查看当前用的是哪套存储、连通是否正常、各存储有多少素材 | 偶尔 |
| 画布用户（间接） | 上传、看图、播视频、把素材给模型做参考；**完全感知不到存储切换** | 高频 |

**成功指标**

- 运维从零配好一套对象存储并设为默认 ≤ 3 分钟，全程不用重启、不用改 env。
- 切换默认存储后，历史画布里的素材 100% 可显示。
- 私有桶下打开 7 天前的画布，素材正常显示（不再有“1 小时后裂图”）。
- 配错（密钥错、桶名错、寻址方式错）时，在“测试连接”阶段就能拦下，并指出是哪一步失败。

## 4. 调研

### 4.1 主流方案（访问日期 2026-10-03）

| 产品 | 配置入口 | 多套存储 | 切换后旧文件 | 文件访问方式 | 对本项目的启发 |
|---|---|---|---|---|---|
| **Cloudreve** | 管理面板 → 存储策略 → 新增 | ✅ 多套策略，按用户组绑定 | 留在原策略 | 公有直链 / 私有签名 / 中转；文档明确指出私有签名直链在 OSS、S3 上“不能长期有效” | 按厂商分类型的配置向导；**创建策略时可以自动帮桶配置 CORS**；按厂商列出能力差异表 |
| **Memos 0.31** | 实例设置（也可用部署文件覆盖，覆盖后 UI 只读） | ✅ 命名配置 + 稳定 ID + `defaultStorageId` | **原地不动**：“A new default is not a storage migration” | 0.31 起不再返回预签名 URL，改由自己的文件路由代理（支持 Range） | 和 D1 几乎同构；“被引用的配置连同凭证要保留”；预签名直出会过期，所以改用稳定路由 |
| **Mastodon / GitLab** | 配置文件 / 环境变量 | ❌ 单套 | 需手动迁移 | 公开桶或 CDN 直出 | 反例：运维门槛高，改配置要重启；它们的用户是运维，我们的用户是后台管理员 |

> 说明：Mastodon/GitLab 一行的结论来自官方配置文档的总体描述，未逐项实测。

**比较结论**：Cloudreve 胜在厂商向导和 CORS 自动配置，Memos 胜在“默认只影响新上传”的数据模型。本方案的数据模型取 Memos，配置交互取 Cloudreve。文件访问方式上，Memos 全量代理对 AI 视频产品来说带宽成本太高，所以取 **302 跳转**这个折中（D2）。

### 4.2 四家存储的兼容要点

| 项 | 阿里云 OSS | 腾讯云 COS | AWS S3 / 兼容 | Cloudflare R2 |
|---|---|---|---|---|
| S3 兼容 Endpoint | `oss-<region>.aliyuncs.com`（或 `s3.oss-<region>.aliyuncs.com`） | `cos.<region>.myqcloud.com` | `s3.<region>.amazonaws.com` / 自定义 | `<ACCOUNT_ID>.r2.cloudflarestorage.com` |
| Region 示例 | `cn-hangzhou`（签名用的 region 写法**需真桶实测**） | `ap-guangzhou` | `us-east-1` | 固定 `auto`（空值、`us-east-1` 也会被当成 `auto`） |
| 寻址方式 | **只支持虚拟主机**（path-style 会报 “Please use virtual hosted style”） | 推荐虚拟主机 | 自动 | 虚拟主机、path 均可（**需实测**），预设用 path |
| 桶名 | 普通 | **带 APPID**，如 `canvas-1250000000` | 普通 | 普通 |
| 签名 | V4 支持，但**不支持 aws-chunked 流式签名** | V4 | V4 | V4 |
| 其他 | ETag 大写；分片 ETag 计算方式不同 | 部分第三方工具要求开启 path-style（我们用虚拟主机，不受影响） | — | 不支持 `x-amz-acl`、对象标签等，本方案没用到 |
| 浏览器直传 | 需在桶上配置 CORS | 需配置 CORS | 需配置 CORS | 需配置 CORS；**不支持 POST Policy（PostObject 返回 501），只能用预签名 PUT** |
| 公开访问 | 公共读 Bucket 或绑定 CDN | 公有读或 CDN | 公开桶或 CloudFront | 开启 `r2.dev` 子域或绑定自定义域名 |

对实现的影响：minio-go 需要按厂商设置 `BucketLookup`（OSS/COS 用 `BucketLookupDNS`），**OSS/COS 强制 HTTPS**，避免 minio-go 在 HTTP 下使用流式签名。COS 表单要校验桶名是否带 `-<APPID>` 后缀。R2 的直传必须走预签名 PUT，见 §6.4。

## 5. 设计原则

1. **素材一旦写入，地址终身不变**。payload 里只存稳定地址，存储怎么换都不改 payload。（来自缺口 3 + D2）
2. **默认存储只决定“新文件写到哪”**，读取永远按素材自己记录的 `storage_id`。（Memos 调研 + D1）
3. **配错要在保存前暴露**：测试连接分步执行，并给出可读的失败原因。（成功指标 + Cloudreve 向导）
4. **凭证只写不读**，和渠道 Key 同一套加密与权限。（项目约束）
5. **会让旧素材失效的操作，从入口上就不提供**：定位字段锁定，被引用不可删，换桶走新建。（D5、D7）
6. **厂商差异收敛在“预设”里**，管理员只填自己在云控制台能看到的东西：地域、桶名、密钥。（4.2）

## 6. 推荐方案

### 6.1 信息架构

后台侧边栏新增分组 **“系统设置 → 存储配置”**，路由 `/admin/settings/storage`。权限：admin 可看，super_admin 可改。

```
存储配置
├─ 顶部：当前默认存储卡片（名称 · 服务商 · 桶 · 状态 · 新上传都写到这里）
├─ 列表：所有存储（内置“本地磁盘” + 后台新建的）
│    列：名称 / 服务商 / 桶·地域 / 访问方式（签名·公开）/ 直传 / 素材数 / 连通状态 / 操作
│    行操作：编辑 · 测试连接 · 设为默认 · 删除
└─ 新建 / 编辑（右侧抽屉，同渠道页的交互）
     ① 选服务商（阿里云 OSS / 腾讯云 COS / AWS S3·兼容 / Cloudflare R2）
     ② 基本信息：名称、地域（下拉，自动推导 endpoint）、Bucket、路径前缀
     ③ 访问凭证：AccessKey ID / Secret（编辑时显示“已设置 ·••••末4位”，可替换）
     ④ 访问方式：私有（签名，有效期）/ 公开（填公开域名或 CDN）
     ⑤ 上传方式：□ 允许浏览器直传（勾选后提示 CORS 配置，附一键复制规则）
     ⑥ 高级：自定义 endpoint、寻址方式（仅 S3 可选）
     底栏：[测试连接]  [保存]  （保存时自动跑一次测试）
```

### 6.2 核心流程

**A. 首次接入（主路径）**

1. super_admin 进入“存储配置”，看到只有“本地磁盘（内置·默认）”，顶部提示“生产环境建议使用对象存储”，旁边是 [新建存储] 按钮。
2. 选“阿里云 OSS” → 地域选“华东1（杭州）”，endpoint 自动填 `oss-cn-hangzhou.aliyuncs.com`，HTTPS 和虚拟主机寻址都锁定。
3. 填 Bucket、AK、SK → 点 [测试连接] → 分步显示结果：
   `① 鉴权 ✓ 82ms → ② 写入探针对象 ✓ → ③ 读取 ✓ → ④ 签名地址可访问 ✓ → ⑤ 删除探针 ✓`
   勾选了直传时，再追加 `⑥ 浏览器直传（在当前浏览器里真实 PUT 一次） ✓/✗ CORS 未配置`。
4. 保存 → 列表出现新行，行内提示“设为默认后，新上传和新生成的素材将写入此存储” → 点 [设为默认] → 确认。
5. 完成。已有素材仍在本地磁盘，照常显示。

**B. 轮换密钥**：编辑 → 替换 Secret → 保存（自动测试，失败则不落库，原密钥继续可用）。

**C. 换桶 / 换厂商**：新建一套 → 测试 → 设为默认。老的保留；二期可用迁移任务把旧素材搬过来，再删除旧存储。

**D. 删除**：只有“非默认、非内置、素材数为 0”的存储可删。否则弹窗说明原因（“被 1,284 个素材引用；可先在二期迁移工具中迁走”）。

### 6.3 素材访问：稳定路由 + 302（D2）

```
payload.src = "/files/u12/202610/3f2a…e9.png"      ← 永久不变，和现在 local 的格式一致

GET /files/<key>
  → 按 storage_key 查 assets（唯一索引）拿到 storage_id
  → 内置本地：照旧 http.ServeContent（Range / 长缓存）
  → 对象存储·公开：302 → {public_base_url}/{prefix}{key}
  → 对象存储·私有：302 → 预签名 GET（有效期 = 该存储的 signed_ttl）
     签名结果按 (storage_id, key) 缓存 ttl/2，同一时间窗内 Location 不变，
     浏览器对图片、视频的缓存才能命中
  → 查不到：404
```

- `AssetView.url` 统一返回 `{base}/files/<key>`，**前端零改动**；历史 local 地址天然兼容。
- 给上游 AI 平台的 `AssetFile.URL` **不走 302**，直接给对象存储的签名或公开地址：上游未必跟随跳转，而且后端地址可能是内网地址。
- 安全等级和现在的 `/files` 相同：不鉴权，靠 uuid 不可猜测保护。302 响应带 `Cache-Control: private, max-age=<ttl/4>`，`Referrer-Policy: no-referrer`。

### 6.4 上传：中转 + 直传（D4）

```
前端上传
  └─ POST /assets/upload-intents {file_name, size, mime}
       ├─ 默认存储未开直传 → {mode:"proxy"}  → 走原有 POST /assets（不变）
       └─ 已开直传 → 按服务商预设的 direct_method 分两种：
            ├─ post_policy  → {mode:"direct", method:"post", intent_id, form:{url, fields}, expires_at}
            │                  前端 POST 表单直传（Policy 限定 key 与 content-length-range）
            └─ presigned_put → {mode:"direct", method:"put", intent_id, url, headers:{Content-Type, Content-Length}, expires_at}
                               前端 PUT 原始文件（Content-Length 已签入 URL，声明大小超过上限时直接拒签）
            └─ POST /assets/upload-intents/:id/complete
                 后端 Stat 对象 → 大小校验 → Range 读取头部做内容嗅探与元数据探测
                 → 类型不在白名单：删除对象并返回 400
                 → 插入 assets 行，返回 AssetView
```

- **两种直传方式，由服务商预设决定，管理员不用选**：
  - `post_policy`（S3、OSS、COS 的默认）：POST Policy 用 `content-length-range` 在桶侧强制大小上限，最硬。OSS 和 COS 对 PostObject 的兼容性**需真桶实测**，不通过就把预设改成 `presigned_put`。
  - `presigned_put`（R2 固定用这种，R2 不支持 PostObject）：大小靠两层防护：签名时签入 `Content-Length`（申请时声明超限就直接拒签），complete 时 `Stat` 实际大小，超限就删除对象并返回 413。
  - 两种方式在 complete 阶段的校验完全相同，下游逻辑不区分。
- 直传失败（CORS、网络）时，前端自动降级到中转并提示一次。
- **写到哪套存储，在“申请”那一刻就定下，之后不随默认存储变化**：
  - 中转上传：在 `ingest` 开始时取一次 `Registry.Default()`，写入、插行（`storage_id`）、生成 URL 都用这同一份，不会中途再取。
  - 直传：`/upload-intents` 把当时的默认存储 id 记进 `asset_upload_intents.storage_id`，`complete` 一律按它找存储，**不再看当前默认**。管理员在上传中途切换默认，这次上传仍落在申请时的存储，不会出现“文件在 A、记录指向 B”。
  - 生成产物转存：同中转，在转存开始时取一次默认存储。切换之后才转存的产物写入新存储。
  - 意图记录的存储在 complete 前被删除（只有“素材数为 0”的存储能删，而未完成的意图不算素材）：删除检查要把“未过期且未完成的上传意图”也算作引用，避免这种情况。
- 孤儿对象：`asset_upload_intents` 记录意图，过期未 complete 的由清理任务删除对象（复用 worker 的定时循环）；删除时同样按意图里的 `storage_id` 找存储。
- 视频时长等元数据在头部读不到（moov 在文件尾）时字段留 0，现有探测逻辑已经容忍这种情况；二期可以补“尾部 Range 读取”。

### 6.5 厂商预设

| 服务商 | endpoint 推导 | 寻址 | HTTPS | 额外校验 / 提示 |
|---|---|---|---|---|
| 阿里云 OSS | `oss-{region}.aliyuncs.com` | 虚拟主机（锁定） | 强制 | 地域下拉；提示“需在 OSS 控制台创建 Bucket 并授予 RAM 子账号读写权限” |
| 腾讯云 COS | `cos.{region}.myqcloud.com` | 虚拟主机（锁定） | 强制 | 桶名必须匹配 `^[a-z0-9-]+-\d{10}$`（带 APPID） |
| AWS S3 / 兼容 | `s3.{region}.amazonaws.com`，高级里可填自定义 endpoint（如 S3 的区域专用域名） | 自动 / path 可选 | 默认开，可关（仅自定义 endpoint） | 自定义 endpoint 时不推导 |
| Cloudflare R2 | `{account_id}.r2.cloudflarestorage.com`（只填 Account ID） | path（锁定） | 强制 | Region 锁定 `auto`，不显示地域下拉；Account ID 校验 32 位十六进制；直传方式锁定 `presigned_put`；提示“公开访问需在 R2 控制台开启 r2.dev 或绑定自定义域名” |

各预设另带一个 `direct_method`：S3、OSS、COS 默认 `post_policy`，R2 为 `presigned_put`。这个值不存表，跟着预设走。

预设放在后端 `storage/presets.go` 一处，前端通过接口读取，避免两边各维护一份。

### 8.6 难点与风险

| 风险 | 应对 |
|---|---|
| OSS 对 minio-go 的 V4 签名、POST Policy、ETag 等细节兼容性 | 强制 HTTPS；对四家真桶各跑一遍集成测试（用环境变量注入密钥，CI 默认跳过）；不通过时再考虑引入原生 SDK 驱动 |
| 多实例的客户端缓存不一致 | `version` + 30s TTL，改配置的实例立即失效；其他实例最多 30s 后生效（Redis 广播未做，见 §13） |
| `/files` 反查多一次 DB 查询 | `storage_key` 唯一索引；进程内缓存 key → storage_id（素材不可变，可长期缓存） |
| 直传绕过了后端的内容嗅探 | 在 complete 阶段补做嗅探，不合法就删除对象；POST Policy 限定 key 和大小 |
| R2 没有 POST Policy，预签名 PUT 无法在桶侧硬性限制大小 | 签入 `Content-Length` + complete 时 `Stat` 检查，超限就删除；签名有效期设短（如 15 分钟）；如需更硬的限制，二期可在 R2 前加 Worker 校验 |
| 签名 URL 每次都不同，浏览器缓存失效 | 签名结果按 ttl/2 缓存（§6.3） |

## 9. 方案取舍

### 9.1 决策矩阵（素材访问方式，D2）

权重来自已确认的目标：可靠（不过期、可切换）> 成本（带宽）> 实现量。

| 方案 | 可靠 ×3 | 带宽成本 ×2 | 实现量 ×1 | 加权 |
|---|---|---|---|---|
| **稳定路由 302** | 5 | 5 | 4 | **29** |
| 前端按 assetId 刷新 | 3（长时间停留仍会过期） | 5 | 2（读 src 的地方太多） | 21 |
| 后端代理字节流 | 5 | 1 | 4 | 21 |
| 只允许公开桶 | 4（不能私有） | 5 | 5 | 27，但牺牲了私有桶这一安全选项，否决 |

### 9.2 明确放弃

- **按用户组分配存储**（Cloudreve 的做法）：当前没有用户组概念，全站只有一个默认存储就够用。
- **全量代理**：带宽成本不可接受。
- **七牛、华为 OBS 等更多厂商**：MVP 不做。其中 S3 兼容的厂商可以直接用“AWS S3 / 兼容”类型 + 自定义 endpoint 接入，不在预设里单列。R2 例外，单独做了预设：它的 Region 和直传方式都和 S3 默认值不同，让用户自己摸索容易配错。
- **自动给桶配置 CORS**：需要更高权限的 AK，MVP 改为“一键复制规则 + 浏览器内真实直传测试”，二期再评估。

### 13.2 与设计不一致的地方

| 设计里写的 | 实际 | 原因 / 影响 |
|---|---|---|
| 更新后通过 Redis 广播让其他实例失效 | **未做**，只有本实例立即失效 + 每项缓存 30 秒到期重读 | 多实例部署时，改配置或切换默认存储最多 30 秒后在其他实例生效，其间旧实例仍按旧默认写入，但素材都记录了自己的 `storage_id`，不会读不到。需要即时一致时再补 Redis 订阅 |
| 测试连接共 6 步，第 6 步在浏览器里真实直传一次验证 CORS | 后端只有 5 步；**第 6 步未实现**，改为表单里给出 CORS 规则一键复制 | 直传是否可用要等第一次真实上传才知道；失败时前端自动降级到后端中转，不会影响用户上传 |
| 探针第 1 步「鉴权」 | 第 1 步是「鉴权与桶」，用 HEAD 桶（`BucketExists`）实现 | **实测发现**：minio-go 对象级 HEAD 没有响应体，桶不存在与对象不存在都是 404，读一个不存在的对象无法发现填错的桶名。此前 `isS3NotFound` 把 `NoSuchBucket` 也当成“对象不存在”，已一并修正 |

### 13.3 已验证与未验证

**已验证（自动化测试 + 真实开发库）**

- 存储层：四家预设的 endpoint 推导与校验、OSS/COS 虚拟主机寻址与 R2 path 寻址（用签名地址的主机名与路径断言）、POST Policy 字段与大小上限、预签名 PUT 的签名头、探针与错误翻译（用本地假 S3 服务，含 `NoSuchBucket` / `AccessDenied` / aws-chunked 解码）。
- 服务层：创建（先测后存、写密钥失败回滚）、修改（定位字段锁定、版本冲突、按需重测）、换密钥（先测后换）、设默认、删除保护、升级导入、直传申请与登记（含“申请后切换默认存储仍落在申请时的存储”）、过期清理。
- 仓储层（真实 PostgreSQL，隔离 schema）：默认存储唯一、乐观锁、被引用拒绝删除并同时删密钥、素材 `storage_key` 唯一、迁移幂等与旧素材回填。
- 开发环境实测：热重载后迁移成功，内置「本地磁盘」成为默认，39 个存量素材回填到它；存量素材的 `/files/<key>` 仍返回 200，Range 返回 206，未知 key 与路径穿越返回 404。
- 对关键规则做过变异验证（去掉字段锁定、去掉“测试未通过不能设默认”，测试都能抓到）。

**未验证，上线前必须补**

- **没有对真实的 OSS / COS / S3 / R2 桶跑过**：所有对象存储行为都是对本地假 S3 的验证。OSS 签名使用的 region 写法、OSS/COS 对 POST Policy 的兼容性、HTTPS 下是否会触发 OSS 不支持的 aws-chunked、R2 对 `Content-Length` 签名的实际约束，都需要各用一个真桶按「测试连接 → 上传 → 直传 → 播放视频」走一遍。
- 浏览器端直传（含 CORS）未在真实浏览器里验证。
- 302 跳转后浏览器对视频 Range 请求与缓存命中的行为，只是推断，未实测。
- 探针第 4 步由**后端服务器**去访问签名地址：若桶只允许特定来源访问、或服务器出网受限，会误报失败；自定义 endpoint 只有 super_admin 能配置。
