片场平台适配

分镜只写 Seedance，到片场再按模型转写

今天视频提示词在出分镜时就按项目视频模型定了格式，到片场换模型只能手改或重出分镜。改成：分镜一律写 Seedance 原稿；片场顶栏选了 H3 或通用格式的模型时，右侧多出一个「转写」标签，手动点转写得到目标格式的提示词，生成提交的就是它。原稿永远保留，不被覆盖。

阅读说明。现状结论都对照过仓库代码（路径见 Markdown 文档 §2）；界面与接口是设计提案，尚未实现；原型里的转写结果是示意文字，不调用模型。

主线：一段提示词从分镜到提交

格式只在片场决定一次，原稿和转写稿各存各的。

分镜脚本固定用 Seedance 模板，写进片段 prompt（原稿）
片场选模型读模型的 prompt_format：seedance / h3 / 通用
点「转写」项目文本模型按转写模板改写，存进 adaptations[h3]
看 / 微调两个标签切换对照，转写稿可手改
生成提交当前格式那一份；原稿改过就先确认
设计：原稿是唯一事实来源，转写稿只从原稿派生、不反写原稿。转写按格式存而不按模型存，同一格式的多个模型共用一份转写稿。
回退：选的是 Seedance 模型时没有转写这一步，片场和今天完全一样。转写失败时旧转写稿不被覆盖；没有转写稿时「立即生成」禁用并写明原因，不会把 Seedance 原稿偷偷交给 H3。

转写稿的四种状态

决定生成按钮能不能点、点了以后会发生什么。

未转写

转写标签显示空状态和「转写为 H3」。生成按钮禁用，悬停原因「先把原稿转写为 H3」。

转写中

编辑器只读，生成禁用。换片段不打断，结果回来会推到界面。

最新

直接生成，提交转写稿。手改过也算最新。

已过期

原稿在转写后改过（指纹不同）。生成时问：重新转写并生成 / 仍用当前转写稿。改回原样自动恢复。

为什么选「手动转写 + 标签切换」

三种触发方式的对比，权重来自访谈：可控性最重要。

A 手动转写（选定）B 生成时自动转写C 选模型即转写整集
转写前能否先看能，转写完先看再生成不能，生成后才知道交了什么能
操作步数多一步「转写」最少少
文本模型开销只转用到的片段只转生成的可能转了用不到的
实现复杂度中中高：要整集后台任务
同类产品做法Runway / Kling 的「提示词增强」直接替换输入框，原文要撤销找回；本项目要求原稿永久保留，所以另存转写稿 调研未复核
核实度提案已放弃已放弃

批量生成时，有的片段还没转写，会发生什么

批量是最容易「静默用错格式」的地方，所以一律先问。

  1. 统计待生成片段分出：已就绪、未转写 N、已过期 M、其中手改过 K
  2. N+M>0 时弹窗「转写后生成」/「只生成已转写的」/ 取消
  3. 选「转写后生成」并发 3 依次转写，转完的立刻提交；失败的跳过
  4. 结束 toast「已提交 X 段，Y 段转写失败：片段 03、05」
边界：重新转写会覆盖手改
  • 弹窗里单独写「其中 K 个转写稿被手改过，将被覆盖」。
  • 「只生成已转写的」也跳过已过期的，不在批量里用旧稿。
  • H3 单段上限 15 秒，20 秒的片段转写后仍会被现有时长校验拦下，转写不改时长。

交付时要告知：旧项目里按 H3 / 通用模板出的片段，原稿标签仍写「Seedance」（待确认是否补标记）。

转写与生成伪代码

// 后端（提案）
Adapt(user, sid, format, revision):
  seg = load(sid, user)                      // user_id 隔离
  if format not in {generic, h3}: ErrAdaptFormat
  if trim(seg.prompt) == "": ErrAdaptEmpty
  lock(sid + format) else ErrAdaptBusy
  hash = sha256(seg.prompt)
  out = callDrama("adapt_" + format, {source_prompt, seconds, ratio, style, assets(refs in prompt)},
                  validate: nonEmpty, refs ⊆ sourceRefs 且 sourceRefs 每个至少出现一次,
                            h3: 三字段齐全且切点 < seconds; generic: 终点 ≤ seconds)
  seg.adaptations[format] = {prompt: out.prompt, source_hash: hash, edited: false, updated_at: now}
  save(seg, revision)  → revision+1; broadcast drama.segment

// 前端：生成前取提交文字（提案）
textToSubmit(seg, format):
  if format == seedance: return seg.prompt
  a = seg.adaptations[format]
  if !a: blocked("先把原稿转写为 " + label(format))
  if adapting(seg, format): blocked("正在转写")
  if sha256(seg.prompt) != a.source_hash:
    choice = confirm("原稿在转写后改过", ["重新转写并生成", "仍用当前转写稿生成"])
    if choice == 重新转写: if a.edited: confirmOverwrite(); a = await adapt(seg, format)
  return a.prompt

已确认的决定

  1. 转写手动触发：可控性优先，不偷偷花文本模型调用。
  2. 原稿 / 转写两个标签切换：右栏宽度有限，一次看一份。
  3. 转写稿可改，原稿变了标「已过期」：生成时确认，重转覆盖手改前再确认。
  4. 先做现有三种格式：通用 / Seedance / H3；以后加平台 = 加枚举 + 加模板。
  5. 批量生成先弹窗问是否全部转写。
  6. 分镜固定写 Seedance；旧片段照旧当原稿，不迁移。
  7. 转写扣积分（2026-11-10）：按文本模型定价，只收通过校验的那次，失败不扣，积分明细里能看到是哪集哪段。
  8. 已搁置：生成时自动转写、选模型即整集转写、后台自定义格式。
