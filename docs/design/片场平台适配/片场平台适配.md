# 片场视频平台适配（提示词转写）

> - **范围**：短剧工作室「片场」页。分镜脚本统一写成 Seedance 格式（原稿），在片场按顶栏所选视频模型的提示词写法，把原稿**转写**成目标平台格式；用户能同时看到原稿和转写稿。
> - **日期 / 状态**：2026-11-09，已实现未提交（见 §13），未浏览器验收、未真实模型联调。
> - **证据约定**：**事实**附文件路径；**推断**是基于事实的判断；**提案**是尚未实现的设计。
> - **方案演进**：原来是「一开始适配」——生成分镜时按项目视频模型挑模板。本次改为「分镜固定 Seedance，片场按需转写」，原因见 §1。实现时调整了两处默认值（转写超时、计费），见 §11 和 §13。
> - **配套演示**：[片场平台适配-演示.html](片场平台适配-演示.html)

## 1. 设计摘要

- **问题**：分镜阶段就按视频模型定格式，意味着「先选好模型、再出分镜」。到片场换模型（例如 Seedance 换 MiniMax H3）后，片段提示词仍是旧格式，只能手改或重出整集分镜。而且旧代码里片场切模型只存在本机，重新生成分镜时格式仍按建剧时的模型、时长上限却按片场选的模型，两者对不上。
- **目标**：模型选择推迟到片场；同一份原稿可以随时转写成任意已支持格式，原稿始终保留、可对照。
- **结论**：
  1. 分镜阶段固定用 Seedance 模板，删去按模型挑模板的逻辑。
  2. 片段新增「转写稿」，按格式各存一份；片场提示词框上方用两个标签切换「原稿 · Seedance」与「转写 · H3」。
  3. 转写**手动触发**；转写稿可手改；原稿改动后转写稿标「已过期」，生成时确认。
  4. 批量生成遇到未转写 / 已过期的片段，弹窗问是否先全部转写再生成。
  5. 后台「提示词格式」字段下加用途说明。

### 约束

- `@[名](节点id)` 引用决定参考图怎么挂，转写后必须保留，否则参考素材会丢。
- 转写不改时长；H3 单段上限 15 秒，超长片段由现有生成校验拦下。
- 同步转写请求必须在 60 秒写超时内返回。

## 3. 用户与场景

- **用户**：短剧创作者，熟练用片场逐段生成、挑选视频。
- **主任务**：选模型 → 看到原稿 → 点转写 → 看一眼、必要时微调 → 生成。
- **成功标准**：换模型不需要重出分镜；生成提交的内容就是转写标签里看到的内容；原稿不被覆盖。

## 4. 调研

> 外部调研未联网逐条复核，标「调研未复核」。

| 方案 | 观察 | 启发 | 不适用处 |
| --- | --- | --- | --- |
| 即梦 / Seedance 写法 | 中文分栏、时间轴逐镜 | 作为原稿格式 | — |
| MiniMax H3（本机 `h3-prompt-writing` skill） | 三个英文字段、`[Shot N] At MM:SS.mmm` 切点 | 转写规则复用原 `storyboard_h3.md` 正文 | — |
| Runway / Kling「提示词增强」 | 一键改写并替换输入框 | 一键触发 | 替换原文不适合：原稿要保留可对照 |
| LibTV / 即梦「提示词优化」 | 结果单独展示 | 原稿与结果分开 | 没有「原稿变了结果过期」 |

依赖框架：不需要新依赖。前端 SHA-256 在没有 `crypto.subtle` 的环境（http + 局域网 IP）用自带的纯 JS 实现兜底。

## 5. 设计原则

1. **原稿是唯一事实来源**，转写稿只从原稿派生、不反写原稿。
2. **提交所见即所得**：生成提交当前格式那一份文字。
3. **用户掌控转写时机**（手动转写）。
4. **改动不静默丢失**：重新转写覆盖手改前先确认。
5. **格式扩展只加模板**：新平台 = 加枚举值 + 加转写模板。

## 6. 方案

### 6.1 格式判定

- 目标格式 = 顶栏视频模型的 `capabilities.prompt_format`：`seedance` → 不需要转写；`h3` → h3；空或其他 → generic。还没加载到模型时按 Seedance 处理。
- 这个字段由管理员在后台配置，**不按模型名称识别**；字段下方有用途说明。

### 6.2 右侧编辑区

- 目标是 Seedance：界面与改动前一致。
- 否则提示词框上方一组清透胶囊标签「原稿 · Seedance｜转写 · H3」，右侧「转写为 H3」/「重新转写」。
- 转写标签状态：未转写（空状态：图标 + 标题 + 按钮）、转写中（转圈，编辑器只读）、最新（绿点）、已过期（黄点 +「已过期」，标签内提示条「原稿已修改」+「重新转写」）、失败（错误条 + 重试，旧稿不动）。
- 默认标签：有转写稿显示转写，否则原稿；点转写立即切到转写标签看进度。

### 6.3 生成

| 当前格式的转写稿 | 行为 |
| --- | --- |
| 目标是 Seedance | 提交原稿 |
| 未转写 | 按钮禁用，原因「先把原稿转写为 H3」 |
| 转写中 | 按钮禁用，原因「正在转写」 |
| 最新 | 提交转写稿 |
| 已过期 | 选择弹窗：重新转写并生成 / 仍用当前转写稿生成 / 取消 |

### 6.4 过期与手改

- 转写时记原稿指纹 `source_hash`（原稿全文 UTF-8 的 SHA-256 小写 hex，前后端同算法）；与当前原稿指纹不同即已过期。原稿改回原样，过期消失。
- 转写稿用同一个 `@` 编辑器自动保存，服务端置 `edited=true`，指纹不变。重新转写清掉 `edited`；`edited` 为真时重新转写前确认覆盖。

### 6.5 批量生成

目标非 Seedance 且有未转写 / 已过期片段时弹窗，写明已就绪、未转写 N、已过期 M，以及「其中 K 个转写稿被手改过，将被覆盖」：

- 「转写后生成」：并发 3 转写，转完即提交；失败的跳过并 toast 列出片段号。
- 「只生成已转写的」：未转写和已过期都跳过。
- 取消。

### 6.6 转写规则（后端）

- 模板 `backend/internal/drama/prompts/adapt_h3.md`、`adapt_generic.md`，正文由原 `storyboard_h3.md`、通用 `storyboard.md` 改写为单段转写。
- 输入：`source_prompt`、`seconds`、`assets`（原稿引用的 node_id + 名称）、`ratio`、`style`、`validation_error`。输出 `{"prompt": "..."}`。
- 校验（`drama.ValidateAdapt`），不合格带反馈重写一次：非空；原稿每个引用至少保留一次且不得出现原稿没有的引用；H3 三个字段齐全；时间轴与切点不超过 `seconds`。
- 使用项目文本模型（停用时回落第一个可用 Agent 模型）。
- **计费**（2026-11-10 用户确认要扣）：按项目文本模型定价和实际用量，口径同其他短剧文本步骤，只算通过校验的那一次。调模型前按预估费用检查可用积分，不够返回 40001 不调模型；转写稿写回与扣费同一事务，转写失败不扣。实扣封顶在可用积分；成对写冻结 + 结算流水（同 Agent 对话），流水 `drama_segment_id` 关联片段、备注「片场转写 · 第 N 集片段 MM · H3」，在个人中心积分明细显示（迁移 0028）。

### 6.7 分镜阶段

- 分镜固定用 Seedance 模板（原 `storyboard_seedance.md` 改名为 `storyboard.md`，删 `storyboard_h3.md`，通用正文迁入 `adapt_generic.md`）；`prompt_format` 变量固定为 `seedance`，留给引用它的自写提示词。
- 分镜时长上限 `max_seconds` 仍取片场所选模型。

## 7. 状态与异常

| 情况 | 处理 |
| --- | --- |
| 原稿为空 | 转写按钮禁用；后端返回 67024 |
| 格式不支持 | 67023（seedance 不需要转写） |
| 同片段同格式重复转写 | 进程内锁，67025；多实例部署最坏各转一次，后写覆盖 |
| 模型两次输出不合格 / 上游失败 / 超时 | 67026，旧转写稿保留 |
| 没有可用文本模型 | 67007 |
| 可用积分不够预估费用 | 40001，不调模型 |
| 版本不一致 | 转写前比较 revision，不一致返回冲突码；写回时不再比较（见下） |
| 转写期间原稿被改 | 结果照写，指纹记转写时的原稿，前端显示已过期 |
| 手改不存在的转写稿 | 67027 |

## 8. 数据与接口（已实现）

- `drama_segments.adaptations jsonb not null default '{}'`（迁移 `backend/migrations/0027_drama_segment_adaptations.sql`），键 `h3` / `generic`，值 `{prompt, source_hash, edited, updated_at}`。
- `POST /drama-segments/:sid/adapt`，body `{format: "h3"|"generic", revision}`，同步返回片段视图并推 `drama.segment` 事件。
- `PATCH /drama-segments/:sid` 新增可选 `adaptation: {format, prompt}`。
- 片段视图新增 `adaptations`（总是对象）。生成接口不变，前端把提示词换成转写稿。

## 9. 方案取舍

| 维度（权重） | A 手动转写 + 标签（选定） | B 生成时自动转写 | C 选模型即转写整集 |
| --- | --- | --- | --- |
| 可控性（3） | 高 | 中 | 中 |
| 步骤数（2） | 多一步 | 最少 | 少 |
| 模型开销（2） | 只转需要的 | 只转生成的 | 可能浪费 |
| 复杂度（1） | 中 | 中 | 高 |

放弃：B、C；上下并列 / 弹窗对照；转写稿只读；后台自定义格式。

## 10. 验收

1. 选 H3 模型，未转写时「立即生成」禁用并给原因。
2. 转写成功后转写标签显示结果，生成请求里的 prompt 等于转写标签文字。
3. 改原稿一个字 → 已过期；改回 → 过期消失。
4. 手改转写稿后重新转写，弹覆盖确认。
5. 批量生成弹窗数量正确；「只生成已转写的」跳过未转写和已过期。
6. 转写稿里的 `@` 引用都来自原稿；参考素材条与原稿一致。
7. 切回 Seedance 提交原稿；再切回 H3，转写稿仍在。
8. 重新生成分镜，不管选哪个模型，产出都是 Seedance 写法。
9. 用 http + 局域网 IP 打开片场，过期判断正常（纯 JS SHA-256 兜底）。

后续：新平台（Kling、Veo、Sora、Wan）、开拍设置里自定义转写模板、差异高亮。
