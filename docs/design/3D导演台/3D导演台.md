# 画布「3D 导演台」节点设计

> **范围**：在无限画布里新增第 5 种节点「导演台」。双击打开全屏 3D 编辑器，在里面摆放灰模人物、几何体道具和机位，用「预设运镜 + 录制关键帧」做出镜头运动，最后导出**灰模运镜预览视频**（附首帧机位图）回到画布，作为 AI 生视频的参考。
> **日期与状态**：2026-10-19 设计确认；2026-10-19 第一期已实现、未提交、**未在浏览器里实际验证**（见 §13）。人物已换成 Quaternius 的人台模型（见 §6.4、§13）。
> **证据约定**：**事实**附文件路径或来源链接；**推断**是基于事实的判断；**提案**是尚未实现的设计；**未验证**需要实现时实测。
> **方案演进**：起点是用户给的两张参考截图（图 1：导演台全屏界面，有图层、机位小窗、「生成机位1图」；图 2：多了道具、轨迹绘制、底部关键帧时间轴和「导出视频」）。调研发现截图形态最接近 LibTV 的「导演台」节点，而 LibTV 早期的主产物是**机位截图**。访谈中用户把主线定为**运镜预览视频**（§11 Q1），因此本设计以时间轴和视频导出为骨架，机位图降为附带产物；轨迹绘制、群众阵列、全景背景都移到后续阶段。
> **配套演示**：[3D导演台-演示.html](3D导演台-演示.html)（含可点击原型：画布节点 → 打开导演台 → 套用运镜预设 → 打关键帧 → 导出 → 画布上长出视频节点；3D 视口、机位小窗和缩略图用 three.js r170 真实渲染，可旋转视角、点选并拖动变换控件；离线时退回俯视示意；编码和上传是模拟的）。

## 1. 设计摘要

- **问题**：AI 生视频的运镜靠提示词描述（"镜头缓慢推近"），结果不可控；人物站位、机位角度、景别也只能靠运气。没有 3D 经验的创作者没有办法"先把镜头排出来再生成"。
- **目标**：创作者在 3 分钟内完成"摆一个人 → 放一台机位 → 套一个运镜 → 导出 5 秒预览视频"，再把视频连到视频生成节点当参考，得到运镜可控的成片。
- **推荐结论**：
  1. **新节点 + 全屏编辑器**：新增 `director` 节点种类，场景数据存在节点 `data.scene`，双击进入全屏导演台（用户确认，§11 Q5）。
  2. **主产物是灰模预览 MP4**，每个机位导出一段，可附带首帧机位图；导出才在画布上建节点，用户自己连到生成节点（用户确认，§11 Q1、Q6）。
  3. **面向无 3D 经验的用户**：默认场景开箱即有一个人和一台机位；运镜靠预设（推/拉/摇/移/环绕/升降/跟拍）一键生成关键帧，再允许"记录当前视角为关键帧"微调（用户确认，§11 Q2、Q4）。
  4. **人物只做位置 + 朝向 + 姿势预设**，不做关节摆姿；人物可以打位置/朝向关键帧做简单走位（用户确认，§11 Q3、Q9）。
  5. **依赖**：引用 `three` + `@react-three/fiber` + `@react-three/drei`，导演台按需懒加载；视频编码复用仓库已有的 `mediabunny`（用户确认 R3F 选型，§11 Q7）。
  6. **人物**：预设灰模，即内置一个带人形骨骼的灰色人体模型文件 + 预烘姿势数据，随前端静态资源发布；不是资产库资产，后端不改素材白名单（用户确认，§11 Q8、Q12）。
  7. **保存**：场景自动保存到节点（防抖写入 → 画布自动保存）；编辑器有独立撤销栈；只有「导出视频」会在画布上新建节点（用户确认，§11 Q10、Q11）。
- **第一版刻意不做**：轨迹绘制、群众阵列、全景/参考图背景、关节摆姿和走路循环动画、多机位切镜剪辑、深度/姿态控制视频、上传 GLB 模型、Agent 搭场景、导演台内直接提交 AI 生成（见 §10）。

### 设计约束（推断）

- 场景数据放在**节点 `data.scene`**，不放 payload 顶层 `directorScenes`：顶层字段前端会丢、还要改三处；放节点里能复用节点的复制、删除、撤销、Agent 读图结构，一个画布也能有多个导演台。
- three/R3F 体积大（three 打包后数百 KB 量级，**未验证**），**画布节点视图绝不能 import three**；节点只显示缩略图，编辑器整块懒加载。
- 导出必须**离线逐帧渲染 + mediabunny 编码**，不能用实时录屏（帧率不稳、多为 WebM）；结果走既有上传通道，受 200MB 上限约束（15 秒 1080p 远低于此，推断）。
- 加新种类要两端同步：前端 `NODE_LIBRARY`、`DOWNSTREAM_KINDS`、`canvas-node.tsx` 分派、`PersistedCanvasNodeDto.kind`、`serializeGraph`/`deserializeGraph` 白名单；后端 `canvasgraph/ops.go` 的 kinds/downstream/kindLabel。

### 当前缺口

- 没有任何 3D 渲染、相机、关键帧插值、场景序列化代码。
- 没有全屏编辑器的承载方式（现有模式都挂在节点下方）。
- 没有内置 3D 资产（人物模型、姿势数据）的存放和加载约定。

## 3. 用户与场景

- **用户**：AI 视频创作者（短剧、广告、自媒体），懂"推拉摇移、景别"这类镜头语言，**没有 3D 软件经验**（用户确认，§11 Q2）。
- **触发场景**：
  1. 想要一个"从中景缓慢推到近景"的镜头，提示词怎么写都推不准。
  2. 两个人物对话，要保证站位和机位轴线一致，多个镜头连续可剪。
  3. 人物从画面左走到右，镜头跟着横移。
- **主任务**：画布上建导演台 → 双击进入 → 拖动默认人物到位 → 选机位，套「推近」预设 → 播放看一眼 → 导出 → 把预览视频连到视频生成节点 → 写提示词生成。
- **成功指标**（提案）：
  - 新用户从建节点到导出第一段视频 ≤ 3 分钟（可用性测试）。
  - 打开导演台：首次 ≤ 3 秒出现可操作的场景，再次打开 ≤ 1 秒（示意，需实测）。
  - 5 秒 720p 预览视频导出（渲染 + 编码）≤ 15 秒（示意，需实测）。

## 5. 设计原则

1. **先有镜头，再有参数**（用户为无 3D 经验创作者）：打开就有一人一机位，运镜一键套预设；精确数值放属性面板，不挡主路径。
2. **所见即所导**：小窗看到的画面就是导出的画面（同画幅、同 FOV、无辅助线和 UI），逐帧离线渲染保证时间精确（来自 updream 切镜延迟的教训）。
3. **导演台只出素材，不做生成**：产物变成普通的视频/图片节点，复用现有连线、参考和模型能力判断；不在导演台里重建一套生成面板（用户确认，§11 Q6）。
4. **编辑不打扰画布**：场景改动不进画布撤销栈、不新建节点；只有导出这一次性动作改画布结构（用户确认，§11 Q10）。
5. **重的东西按需加载**：画布不为导演台付出任何体积和性能成本。

```
        ├─ 左侧：工具竖条（折叠/展开资产面板 · 移动(1) · 旋转(2) · 聚焦选中(F) · 删除）+ 可折叠的「资产」面板（人物 / 物体 / 机位三个标签页，搜索 + 分类小标签 + 预览卡片，点卡片就往场景里加）
        ├─ 中央：3D 主视口（导演视角）
        ├─ 右下：机位取景小窗（当前机位、画幅、FOV，可切机位 tab、可放大）
        ├─ 右侧面板：[图层] 人物 / 道具 / 机位分组  ·  [属性] 选中对象的参数
        └─ 底部：时间轴（播放控制 · 时长 · 运镜预设 · 每机位/每人物一条轨道 · 关键帧菱形）
   └─ 导出 → 在导演台节点右侧新建「预览视频」节点（+ 可选「首帧图」节点），来源线连接
```

### 6.2 导演台节点（画布上）

- **新建**：添加节点菜单新增「导演台 · 3D 摆位与运镜预演」；也可在空白处双击菜单里选。新建后的节点**直接带默认场景**（1 个人物「角色A」站在原点、1 台「机位1」位于正前方 4m、高 1.6m、FOV 50°、16:9，时长 5s）。
- **节点本体**：没有缩略图时是占位图标 + 说明"在 3D 空间中设计角色、机位与镜头" + 居中的「进入导演台」按钮；有缩略图（最近一次关闭编辑器或导出时，用当前机位渲染）时，缩略图当背景、盖一层黑色蒙版，居中仍是「进入导演台」按钮，底部一行机位 chip（`机位1 · 5.0s`）。进入的方式有两种：点按钮、双击节点。编辑器全屏盖住画布，所以节点标题行不再显示「编辑中」。
- **连线**：导演台**不接受上游**、**不能作为生成节点的上游**（`DOWNSTREAM_KINDS.director = []`，其他种类的下游也不含 director）。唯一的线是导出时自动画的"来源线"（导演台 → 导出节点），只表示出处。
- **功能区**：选中节点时不出功能区，也不显示生成面板（2026-10-19 去掉了原先的「打开导演台」「导出视频」两个按钮：进编辑器走节点正文里的按钮和双击，导出在编辑器顶栏里）。
- **复制/粘贴/删除**：复用节点通用行为，复制会深拷贝 `scene`（新 id）。

### 6.3 全屏编辑器

- **承载**：画布页上 `fixed inset-0` 的覆盖层（同灯箱的层级做法），画布在下面保持挂载，自动保存照常进行。状态在新 store `store/director.ts`：`nodeId`、`enter(id)`、`leave()`，与截帧/修剪/扩图互斥（进入导演台先退出其他模式）。
- **加载**：`React.lazy` 加载编辑器 chunk（含 three/R3F/drei 与人物 GLB）。加载中显示全屏骨架 +「正在加载 3D 引擎…」。
- **视口操作（导演视角）**：左键拖空白处旋转视角，右键/中键拖平移，滚轮缩放；按住右键时 WASD 飞行，速度由顶栏「移动速度」0.5×/1×/2×/3× 决定。点选对象出现变换控件（TransformControls），1/2/3 切换移动/旋转/缩放。吸附开启时移动按 0.25m、旋转按 15° 步进。
- **机位小窗**：右下角，按机位画幅显示当前机位实时画面；tab 切换机位，「+」新建机位；可拖动位置、拖角缩放、切到"机位视角"走视口底部的切换器（实际做法见 §13：鼠标拖动调朝向，没做 WASD 驾驶）。
- **图层面板**：人物/道具/机位三组，可折叠；行内操作：显隐、锁定、重命名、删除。点击行即选中并在视口高亮。
- **属性面板**（选中对象时）：
  - 人物：名称、颜色（区分角色，灰模着色）、位置 X/Z、朝向（°）、姿势预设下拉、体型缩放（0.8–1.2）。
  - 道具：形状（立方体/圆柱/球体/平面）、位置、旋转、尺寸 W/H/D。
  - 机位：名称、画幅（16:9 / 9:16 / 1:1 / 4:3 / 21:9）、焦距预设（广角 24mm / 标准 35mm / 50mm / 中焦 85mm / 长焦 135mm，对应 FOV 换算显示）+ FOV 精调、位置/高度、俯仰/偏航、看向目标（无 / 某人物）。不做滚转。
- **默认标签**：人物头顶显示名称标签（图 1、2 中的「角色A」），顶栏「标签」可隐藏；**导出画面永远不带标签和辅助线**（原则 2）。

### 6.4 人物与姿势

- **预设灰模 = 内置一个带人形骨骼的灰色人体模型文件**（GLB，体积目标 ≤ 1.5MB，示意），随前端静态资源发布于 `web/public/director/mannequin.glb`（实测 404KB）。它不是资产库里的资产，也不允许用户上传或替换（用户确认，§11 Q12）。不采用"代码拼几何体假人"：那样像火柴人，导出给 AI 时人物不好认。
- **模型来源（已落地）**：Quaternius **Universal Base Characters** 免费 Standard 版里的 Superhero 男性（CC0，可商用无需署名，<https://quaternius.com/packs/universalbasecharacters.html>）。免费版只含 Superhero 男女两种体型，Regular、Teen 在付费 Source 版里。处理成「灰色人台」：去掉眼睛、眉毛和全部贴图，只留身体网格（7281 个顶点）、65 根标准人形骨骼和一个中性灰材质；原模型是 T 字形、脸朝 +z、身高 1.81m，加载时外面套一层转 180° 的外壳，并缩放到 1.78m。许可证说明随模型放在 `public/director/LICENSE.txt`。原型里用胶囊体拼的人物只是示意。
- 姿势预设 12 个（提案）：站立、行走、奔跑、坐、蹲、单手指向、双手抱胸、挥手、对话、举手、回头、倒地。每个预设是一份"骨骼名 → 欧拉角（度）"的表（`web/src/utils/director/poses.ts`，旋转轴和符号约定见 `pose.ts`），在人台上正向运动学摆出来，再按姿势自动落地（站着脚踩地、坐着脚踩地、躺着后背贴地）。**姿势不进时间轴**（一段镜头内姿势固定）；切换时的 0.2s 过渡没做，直接换。
- **男女两个人台**（用户确认，2026-10-19）：男性、女性，骨骼名称完全相同，姿势数据共用；人物属性里可以随时切换男女（`model` 字段）。女性身高 1.68m、男性 1.78m。
- 人物上限 8 个、道具上限 30 个、机位上限 6 个（提案，性能保护；达到上限时添加按钮禁用并提示原因）。

### 6.5 时间轴与运镜

- **时长**：1–15 秒，默认 5 秒，0.5 秒步进（15 秒上限对齐主流参考视频时长，推断）。播放/导出帧率固定 24fps。
- **轨道**：每个机位一条轨道（位置、朝向、FOV 一起打帧），每个人物一条轨道（位置 X/Z、朝向一起打帧）。道具不动画。
- **关键帧**：
  - 「◇ 记录关键帧」（快捷键 K）：把选中对象当前状态写到播放头位置；同一时间已有关键帧则覆盖。
  - 拖动菱形改时间；选中菱形按 Delete 删除；右键菱形切换插值「缓入缓出（默认）/ 线性」。
  - 只有 0 个关键帧 = 用对象当前静态状态；只有 1 个 = 全程保持该状态。
  - **没有关键帧的对象**：拖动直接改它的静态状态。**已有关键帧的对象**：在任意时刻拖动都只是"临时姿态"，对象旁和时间轴显示「未记录 · 按 K 记录」，移动播放头或播放时丢弃——避免用户以为改了却没进轨道（做演示原型时补充的决定）。
  - 插值：位置按段插值（缓入缓出 = smoothstep），偏航 / 俯仰按最短方向插值，FOV 线性；插值方式由前一帧决定。
- **运镜预设**（选中机位时可用，下拉 + 强度滑杆 + 起止时间，默认作用于整段时长）：

  | 预设 | 生成方式（相对机位在起点时的状态） | 默认强度 |
  | --- | --- | --- |
  | 固定 | 清空该机位关键帧，只留 1 帧 | — |
  | 推近 / 拉远 | 沿视线方向前进 / 后退，距离 = 到目标距离 × 强度 | 40% |
  | 左摇 / 右摇 | 原地偏航 ± 角度 | 30° |
  | 上摇 / 下摇 | 原地俯仰 ± 角度 | 15° |
  | 左移 / 右移 | 沿相机右方向平移 | 2m |
  | 升 / 降 | 竖直平移，同时保持看向目标 | 1.5m |
  | 环绕 | 绕目标水平旋转，**每 0.5 秒烘焙 1 帧**以走出圆弧 | 90° |
  | 跟拍 | 保持起点时与目标人物的相对偏移，按人物轨道**每 0.5 秒烘焙 1 帧** | — |

  - "目标"= 机位属性里的看向目标；没设时取视线方向上最近的人物，再没有则取前方 4m 的点。
  - 套用预设**替换**该机位在起止时间内的关键帧，其余保留；整个操作在编辑器撤销栈里算一步。
  - 跟拍要求目标人物有轨道；没有时预设仍可套用但效果等同固定，并提示"先给人物打走位关键帧"。

### 6.6 导出

- **入口**：编辑器顶栏「导出视频」（节点功能区的入口已去掉）。
- **对话框**：勾选机位（默认当前机位）、分辨率（720p 默认 / 1080p，按机位画幅计算宽高，长边 1280 / 1920）、帧率 24（固定显示）、「同时导出首帧图」（默认勾选）、预计时长与大小（示意）。
- **过程**（每个机位依次）：
  1. 隐藏标签、网格、变换控件、选中描边；用导出尺寸的离屏 RenderTarget。
  2. 逐帧：按 `t = i / 24` 计算所有对象状态 → 渲染 → 交给 mediabunny `CanvasSource` 编码 H.264 MP4（不依赖 requestAnimationFrame，帧时间精确）。
  3. 首帧图：t=0 的那一帧另存 PNG。
  4. 进度条显示"机位1 渲染 72/120 帧"；可取消（丢弃已编码内容）。
- **回到画布**：全部机位完成后，`history.record()` 一次，在导演台节点右侧按顺序新建节点（复用 `place-beside` 摆放）：
  - 视频节点：标题 `{导演台名}·{机位名}`，`uploaded: true`，`mediaAspect` = 画幅；
  - 首帧图节点（若勾选）：标题 `{导演台名}·{机位名}·首帧`；
  - 来源线：导演台 → 每个导出节点。
  然后交给 `uploadRunner` 上传；节点显示「上传中 x%」，失败可重试（沿用现有行为）。
- **重复导出**：每次都新建节点，不覆盖旧导出（非破坏，与视频修剪一致）。
- 导出完成后编辑器**保持打开**，toast「已导出 2 段视频到画布」+「回到画布查看」按钮。
- **用户接下来**：把预览视频节点连到视频生成节点（模型支持参考视频时作为参考视频），或把首帧图连过去做图生视频。导演台不自动建生成节点（用户确认，§11 Q6）。

| 状态 | 表现 | 下一步 |

| 导出：不支持 H.264 编码 | 导出前用 mediabunny `canEncode` 检测；不支持则「导出视频」禁用并写原因 | — |

**撤销/重做**：编辑器独立撤销栈（Ctrl+Z / Ctrl+Shift+Z，上限 100 步），记录场景快照；拖动中不记，松手算一步；关闭编辑器即清空。画布撤销栈不记录场景改动，**导出建节点**是画布撤销里的一步（撤销会删掉导出节点，不影响场景）。

**权限**：导演台跟随画布权限（画布只属于拥有者，后端按 `user_id` 隔离），无新增权限点。

## 8. 数据与工程影响（提案）

### 8.1 节点数据

`CanvasNodeData` 新增可选字段 `scene?: DirectorScene`，仅 `kind === "director"` 使用：

实现见 `web/src/types/director.ts`。坐标单位米、角度单位度；y 向上，地面 y = 0；偏航 yaw 为 0 时朝 -z 看、向 +x 转为正，俯仰 pitch 抬头为正。

```ts
interface DirectorScene {
  version: 1;                       // 场景结构版本，便于以后迁移
  duration: number;                 // 秒，1–15，0.5 步进
  activeCameraId: string;           // 小窗与缩略图使用的机位；没有机位时为空串
  characters: DirectorCharacter[];  // ≤ 8
  props: DirectorProp[];            // ≤ 30
  cameras: DirectorCamera[];        // 0–6；导出要求 ≥ 1
  thumb?: { assetId: string; url: string }; // 缩略图素材，关闭编辑器时渲染上传
}

interface DirectorCharacter {
  id: string; name: string; color: string;   // 例 "#d4d4d8"
  model?: "male" | "female";                 // 灰模男女；缺省（旧场景）按男性
  pose: PoseId;                              // 12 个预设之一
  scale: number;                             // 0.8–1.2
  x: number; z: number; yaw: number;         // 静态站位（无关键帧时使用）
  keys: { t: number; x: number; z: number; yaw: number; ease: "smooth" | "linear" }[];
  hidden?: boolean; locked?: boolean;
}

interface DirectorProp {
  id: string; name: string;
  shape: PropShape;                          // 几何体 box|cylinder|sphere|plane；物体 table|chair|sofa|bed|cabinet|door|wall|stairs|car|tree
  x: number; z: number; yaw: number;         // 放在地面上，只绕竖轴转
  w: number; h: number; d: number;           // 宽、高、深
  hidden?: boolean; locked?: boolean;
}

interface DirectorCamera {
  id: string; name: string;
  aspect: "16:9" | "9:16" | "1:1" | "4:3" | "21:9";
  x: number; y: number; z: number;
  yaw: number; pitch: number;                // 俯仰限制在 ±85°
  fov: number;                               // 垂直视场角，度，10–120
  lookAt?: string;                           // 人物 id，运镜预设拿它当目标
  keys: { t: number; x: number; y: number; z: number; yaw: number; pitch: number; fov: number; ease: "smooth" | "linear" }[];
}
```

- **实现时的调整**：原提案用四元数存朝向，实现改为**偏航 / 俯仰角（度）**，不做滚转。原因：数值直观、运镜预设和插值都简单（角度按最短方向插值）；机位俯仰限制在 ±85°，不会遇到万向节锁。道具只绕竖轴转。

- 体积估算：6 机位 × 31 帧（环绕烘焙）+ 8 人物 × 10 帧，约 30KB（示意）。写入节点前校验场景 JSON ≤ 256KB，超出则不写入，顶栏显示「场景过大，未保存」并提示（`sceneSizeError`）。
- 关键帧数组按 `t` 升序，`t` 精确到 0.01s，同一 `t` 唯一。

### 8.4 核心流程伪代码

```ts
// 导出（提案）
async function exportCameras(scene, cameraIds, opts, engine /* 注入：render、encode */) {
  const results = [];
  for (const camId of cameraIds) {
    const { width, height } = sizeFor(camera(scene, camId).aspect, opts.resolution);
    const frames = Math.round(scene.duration * 24);
    const enc = await engine.createEncoder({ width, height, fps: 24 }); // mediabunny CanvasSource
    let firstFrame: Blob | undefined;
    for (let i = 0; i < frames; i++) {
      if (opts.signal.aborted) { await enc.cancel(); throw new AbortError(); }
      const state = sampleScene(scene, i / 24);           // 纯函数，可单测
      const canvas = engine.render(state, camId, { width, height, overlays: false });
      if (i === 0 && opts.withFirstFrame) firstFrame = await engine.toPng(canvas);
      await enc.add(canvas, i / 24);
      opts.onProgress(camId, i + 1, frames);
    }
    results.push({ camId, video: await enc.finish(), firstFrame });
  }
  return results; // 调用方：history.record() → buildDirectorExportNodes → uploadRunner.start
}
```

## 9. 方案取舍

### 9.1 决策矩阵

权重来自访谈：主线是运镜视频（Q1）、用户是新手（Q2）。

| 维度（权重） | A 节点 + 全屏编辑器（采用） | B 画布级工具 + 顶层 directorScenes | C 绑在视频生成节点上 |
| --- | --- | --- | --- |
| 新手上手（3） | 5：画布上看得见、双击就进 | 3：入口藏在顶栏 | 4：路径短 |
| 运镜视频产出（3） | 5 | 5 | 4：只服务一个节点 |
| 场景复用到多个镜头（2） | 5：一个场景多机位多次导出 | 3：一个画布一个场景 | 1 |
| 与现有架构契合（2） | 4：复用节点存储/复制/撤销 | 2：顶层字段前端会丢，要改三处 | 3：要改生成面板 |
| 实现成本（1） | 3 | 3 | 3 |
| **加权合计** | **51** | 37 | 35 |

### 9.2 明确放弃

- **导演台内直接 AI 生成**：要重建一套模型选择和参数面板，重复且难维护（Q6）。
- **显式「完成/放弃」保存**：崩溃或关页会丢掉大量摆位工作（Q10、Q11）。
- **关节摆姿**：交互和实现成本高，新手用不上（Q3）。
- **theatre.js / mannequin.js / Mixamo**：许可证或可用性问题（§4.4）。
- **实时录屏导出**：帧率不稳，时间不准。

## 10. MVP 与后续

### P1（MVP）

导演台节点 + 全屏编辑器；人物（12 个姿势预设、位置/朝向关键帧）；几何体道具；多机位 + 小窗；运镜预设 + 记录关键帧；时间轴播放；导出 MP4 + 首帧图到画布；缩略图；自动保存；独立撤销栈。

**验收**：
1. 新建导演台节点即有默认场景；双击进入，3 秒内可操作（示意）。
2. 选中机位套「推近」，播放可见推近；导出 5 秒 720p 视频，画布右侧出现视频节点和首帧图节点并上传成功，视频时长 5.0s ±1 帧、帧率 24、画面无标签和网格。
3. 给人物打 2 个位置关键帧，机位套「跟拍」，导出视频中机位跟随人物。
4. 编辑后关闭页面再打开画布，场景完整恢复；画布上撤销不影响场景。
5. 导出的视频节点能连到支持参考视频的视频生成节点并成功提交任务。
6. 画布页首屏 JS 体积不因导演台增加（three 只出现在懒加载 chunk 里）。

### P2

群众阵列（N×M 方阵）、全景/参考图背景（导演台接受上游图片）、地面轨迹绘制、多机位切镜按时间轴拼成一段视频、任意时刻截图、导出时附运镜文字描述（填进下游提示词）。

### P3

深度/姿态控制视频、用户上传 GLB 人物/道具（后端扩白名单）、关节摆姿与走路循环、Agent 搭场景、VRM 人物。

### 与设计的出入

- **进入导演台的加载层（2026-10-19 追加）**：原先点进入后 `Suspense fallback={null}`，下载 three.js 这一大块时画面没有任何反应，节点上只多一个「编辑中」。现在 `DirectorHost`（`components/director/director-host.tsx`）在会话打开的那一刻就挂上和进画布共用的 `FocusLoader`（加了可选的进度条），预加载由 `utils/director/preload.ts` 编排：编辑器代码块占总进度 60%，人台模型占 40%。人台模型的进度是真实的下载字节数（`readWithProgress` 读 Content-Length，压缩传输时读的过程中最多报 99%）；代码块的动态 import 拿不到进度，进度条在这段时间缓慢爬到 48% 为止，免得一动不动再猛跳。模型提前在加载层里读好，进编辑器时不再有人物先是胶囊后变人台的闪换；模型加载失败不拦着进入，编辑器里照旧用简化形体并提示重试。加载层套了 `dark`，和始终深色的编辑器衔接。
- **节点正文**：按参考图改成说明 + 居中进入按钮，有缩略图时盖黑色蒙版（`bg-black/55`）；纯展示部分抽到 `components/director/director-node-body.tsx`，不碰画布组件树，便于单测。选中节点不出功能区（用户明确不要）。

- **朝向表示**：四元数改为偏航 / 俯仰角，不做滚转（§8.1 已回写）。
- **资产面板（2026-10-19 追加）**：按参考截图把左侧做成「工具竖条 + 可折叠的资产面板」。面板三个标签页——**人物**（分类：全部 / 男性 / 女性）、**物体**（分类：全部 / 几何体 / 物体，全部时按分类分组显示）、**机位**（新建机位、当前视角机位）；有搜索框，点卡片添加并选中。原来工具竖条上的「添加人物 / 道具 / 机位 / 当前视角机位」四个按钮并进了面板。折叠状态和当前标签页是偏好：折叠状态记在浏览器 localStorage（存不进去就用默认展开），当前标签页只在内存里。预览图在浏览器里用离屏渲染器现拍（一个渲染器排队一张一张拍，拍好缓存、失败退回图标），不另存图片文件。「我的」分类（用户上传）不做，因为不让用户上传模型；「图片」标签页对应第二期的参考图背景，没做。
- **物体（用户选定「代码用几何体拼」）**：桌子、椅子、沙发、床、柜子、门、墙、楼梯、汽车、树共 10 个，每个由 2 到 7 个盒子 / 圆柱 / 球拼成（`utils/director/prop-presets.ts`），整体放进单位立方体再按道具的宽高深拉伸；没有模型文件和许可证问题。朝向和人物一致，正面朝 -z（椅子、沙发、床的靠背在 +z，车头在 -z，楼梯往 -z 方向上行）。新加的道具错开摆放，一行 4 个。用软件渲染画出来逐个核对过。

- **编辑器内不用 Portal 组件**：项目的下拉、对话框、提示都渲染到 `body`，会跳出编辑器的深色范围，所以编辑器里用原生下拉、`title` 提示，导出对话框画在编辑器内部。
- **机位小窗**用独立的离屏渲染器每帧出图（不用 drei 的 View），这样小窗、缩略图、导出走同一条"干净舞台"渲染路径。
- **左右分栏（2026-10-19 追加）**：小窗右上角的按钮不再是"放大"，改成在两种摆法间切换——浮窗（视口右下角）和左右分栏（左半是导演视角、右半整块是机位画面，画面按画幅在右半居中放到最大，四周留 16px）。分栏时右半有机位 tab、FOV / 画幅 / 时间标签和切回浮窗的按钮。摆法是偏好，记在浏览器 localStorage（键 `director:preview-split`），不在会话里重置。两种摆法是同一棵元素树只换样式，离屏渲染器不重建，窗格大小变化只调 `setSize`；导演视角的视口容器收窄时视口不重新挂载（WebGL 上下文不丢）。尺寸计算在 `utils/director/layout.ts`。原先"放大一档"的做法去掉了。
- **快捷键**：在捕获阶段统一处理并拦截，编辑器打开时画布的删除、复制、粘贴快捷键不生效。
- **画布撤销**：`contentKey` 本来就不看 `scene`，所以场景改动不会产生画布撤销步；另在 `restoreNodes` 里让 `scene` 取当前值，防止撤销别的操作时把场景倒回去。
- **视角切换（2026-10-19 追加）**：主视口底部居中有一个切换器（药丸按钮，点开向上展开菜单：「导演视角」，下面有多少台机位就列多少项，当前项打 ✓），这是原先设计里"一键放大为主视口"那一步的落地方式。
  - 导演视角就是原来的样子。
  - 机位视角：点菜单里的某台机位，相机就站进那台机位里看，药丸上写「机位视角 · 机位1」；它同时成为当前机位并被选中（只是视图状态，不进撤销栈）。多台机位之间随时在菜单里切；图层列表、机位画面的标签里选机位也会跟着换。场景里没有机位时菜单里提示「先添加一台机位」，删光机位自动退回导演视角。画面按机位的画幅在视口里居中取景，画幅外压暗，框左上角写机位名、画幅和视场角；视口比画幅窄时竖直视场角会自动放大，保证画幅左右边刚好顶到视口两边（`viewFov`）。
  - 按住左键拖动调整机位朝向：画面跟着手走（向右拖机位向左转、向下拖向上抬），每像素转"视场角 ÷ 视口高度"度，和导演视角里的拖动手感一致；俯仰限制在 ±85°。一次拖动算撤销栈一步，拖动时暂停播放；已有关键帧的机位拖动后是"未记录"，画幅框顶上提示"按 K 记录关键帧"。
  - 机位视角里不点选对象、不出变换控件（左键专用于调朝向），要走位或改机位位置就切回导演视角；自己的机位模型和视锥线不画；轨道控制器停用，退出时导演视角的位置原样放回。
  - 视角是会话状态：每次打开编辑器都从导演视角开始。菜单自己画（编辑器里不用 Portal 组件），支持键盘上下选、Esc 收起。
  - 纯计算在 `utils/director/camera-view.ts`，取景框遮罩 `camera-frame.tsx`，切换器 `view-mode-switch.tsx`。
- **没做**：时间轴上关键帧的批量选择；机位视角下用 WASD 驾驶机位（只做了鼠标调朝向）和滚轮改视场角；对象锁定（字段已留）。
