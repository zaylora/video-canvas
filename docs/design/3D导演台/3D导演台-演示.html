3D 导演台演示

在画布里先把镜头排出来，再交给 AI 生成

新增一种画布节点「导演台」：双击进入全屏 3D 场景，摆灰模人物、几何体道具和机位，用预设运镜一键做出推拉摇移，再用关键帧微调，最后导出灰模运镜预览视频（附首帧图）回到画布，连到视频生成节点当参考。导演台只产出素材，不在里面提交 AI 生成；场景自动保存在节点里，只有「导出视频」会在画布上新建节点。

阅读说明。本页对应 Markdown 设计文档 3D导演台.md（准绳）。尚未实现；原型的 3D 视口、机位小窗和缩略图用 three.js r170（CDN）真实渲染，灰模人物用胶囊体拼成（真实产品用内置的带骨骼人体模型文件），离线时退回俯视示意；编码、上传都是模拟。竞品信息来自 2026-10-19 的检索。

主线：一个镜头从摆位到成片怎么走

导演台负责前三步，第 4 步回到画布已有的能力，导演台不重复造生成面板。

① 建导演台节点自带默认场景：1 个人物 + 1 台机位、5 秒
② 摆位拖人物、选姿势、加几何体道具、加机位
③ 运镜选机位 → 套「推近 / 环绕 / 跟拍…」→ 按 K 微调关键帧
④ 导出逐帧离线渲染 → MP4 + 首帧图 → 画布上新建节点并上传
⑤ AI 成片用户把预览视频连到视频生成节点做参考视频
设计：主产物是运镜视频（访谈 Q1），所以时间轴和导出是骨架；导出物就是普通的视频 / 图片节点，复用现有连线规则和模型能力判断（Q6），不在导演台里重建模型选择。
回退 / 兜底：模型不支持参考视频 → 用首帧机位图做图生视频；人物模型加载失败 → 用简化形体（胶囊）代替，导出照常；浏览器不支持 WebGL2 → 打不开导演台，但节点和已导出的视频照常可用；不支持 H.264 编码 → 「导出视频」禁用并写明原因。

创作者要做"人物从左走到右、镜头跟拍"时，会发生什么

这是人物走位 + 跟拍预设的组合，也是 MVP 里最复杂的一条路径。

  1. 播放头放在 0s，把角色A拖到左边，按 K人物轨道出现第 1 个关键帧
  2. 播放头拖到 5s，把角色A拖到右边，按 K第 2 个关键帧；播放可见人物平移（不带走路循环动画，姿势选「行走」）
  3. 选中机位1，看向目标设为角色A，套「跟拍」按人物轨道每 0.5 秒烘焙一个机位关键帧，保持起点的相对位置
  4. 导出视频画布上出现「导演台1·机位1」视频节点和首帧图节点，开始上传
  5. 把视频节点连到视频生成节点，写提示词，生成模型需支持参考视频（看后台模型能力 refs.video）
边界：一段镜头里人物姿势固定，只能平移和转向。
  • 没有走路循环动画，预览视频里人物是"滑"过去的；AI 模型会按提示词补出走路动作（未验证效果）。
  • 人物没有关键帧时套「跟拍」= 固定机位，并提示"先给人物打走位关键帧"。
  • 改了跟拍之后再改人物走位，机位不会自动重算，需要再套一次预设。

交付时要告知：预览视频是"运镜与站位参考"，不是动作参考；动作细节靠提示词描述。

运镜预设：一键生成关键帧

选一个预设，改强度，左边俯视图看机位轨迹，右边看机位画面（three.js 渲染）循环播放，下面是生成的关键帧。这是给无 3D 经验用户的主路径：不用理解关键帧也能出运镜。

// utils/director/export.ts（提案）—— 引擎注入，便于用假实现单测
async function exportCameras(scene, cameraIds, opts, engine) {
  const results = [];
  for (const camId of cameraIds) {
    const { width, height } = sizeFor(camera(scene, camId).aspect, opts.resolution); // 长边 1280 / 1920
    const frames = Math.round(scene.duration * 24);
    const enc = await engine.createEncoder({ width, height, fps: 24 });   // mediabunny CanvasSource → H.264 MP4
    let firstFrame;
    for (let i = 0; i < frames; i++) {
      if (opts.signal.aborted) { await enc.cancel(); throw new AbortError(); }
      const state = sampleScene(scene, i / 24);                            // 纯函数
      const canvas = engine.render(state, camId, { width, height, overlays: false }); // 不带标签 / 网格 / 控件
      if (i === 0 && opts.withFirstFrame) firstFrame = await engine.toPng(canvas);
      await enc.add(canvas, i / 24);                                        // 不依赖 rAF，帧时间精确
      opts.onProgress(camId, i + 1, frames);
    }
    results.push({ camId, video: await enc.finish(), firstFrame });
  }
  return results;
}

已确认的决定

  1. 主线是运镜预览视频喂给 AI 生视频：机位图降为附带的首帧图。
  2. 用户是无 3D 经验的 AI 视频创作者：默认场景 + 预设优先，精确参数放属性面板。
  3. 人物只做位置 + 朝向 + 姿势预设：不做关节摆姿。
  4. 运镜 = 预设运镜 + 录制关键帧：轨迹绘制不进 MVP。
  5. 新节点「导演台」+ 全屏编辑器：场景存在节点里，一个画布可以有多个导演台。
  6. 导出生成视频节点 + 首帧图节点，用户自己连：不自动建生成节点，不在导演台里提交 AI 生成。
  7. 引用 three + R3F + drei：懒加载；时间轴自写（theatre studio 是 AGPL 且停更）。
  8. 人物是预设灰模，不是资产：内置一个带骨骼的灰色人体模型文件 + 预烘姿势，随前端静态资源发布，后端不扩白名单；不用代码拼几何体（像火柴人，AI 不好认）。
  9. 保存冲突（409）沿用画布现有处理：Agent 改动自动合并；否则弹「画布已在别处修改」前先关闭导演台编辑器，场景作为本地改动跟着「另存为新画布」或「加载最新」走（用户确认）。
  10. MVP 追加几何体道具和人物位置关键帧走位；群众阵列、全景背景放 P2。
  11. 场景只在编辑器内保存，编辑器独立撤销栈；只有「导出视频」才写回画布（新建节点）。
  12. 场景自动保存到导演台节点：随画布自动保存落库，关页不丢。
  13. 已搁置：截图里的「AI 生成」按钮（不做）；轨迹绘制、群众阵列、全景背景（P2）。
  14. 主文档已回写：带关键帧的对象在非关键帧时刻拖动只是临时姿态，显示「未记录 · 按 K 记录」（§6.5，做原型时补充）。
