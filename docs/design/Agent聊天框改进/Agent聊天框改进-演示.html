Agent 聊天框改进

画布 Agent 聊天框的三处改进

① 聊天框里加的图片不再落到画布，作为附件显示在输入框上方，随消息发给模型；② 每段工具调用收起后有一句模型写的说明，每条操作有自己的图标；③ 修掉回答结束时消息闪一下、跳一下的问题。三件事互相独立，可以分开上线。

阅读说明。现状来自代码（master 5a06833）。原型里的图片、耗时、模型说明都是示意，所有调用都是模拟的，刷新页面就复原。设计还没有实现。完整的依据和细节见 Agent聊天框改进.md。

用户贴一张角色照片，说「用这张图当参考生成三视图」，会发生什么

把三个改动串起来走一遍，以及要提前说清的一条边界。

  1. 粘贴图片托盘出现缩略图并显示上传进度；画布节点数不变。
  2. 发送托盘清空，用户气泡上方显示这张图；Go 校验通过，模型收到文字和图片。
  3. Agent 回答「先看下画布」，并调用读取画布、查看图片活动行运行中展开，每行是动作图标；这段结束后先显示「读取了画布、查看了图片」，约 1 秒后换成模型写的说明。
  4. Agent 用「修改画布」带 assetId 建参考图节点，再申请生成画布上出现一个已完成的图片节点（来自附件），连到三视图节点。
  5. 回答结束正文原地定稿，状态行换成底栏，没有闪动。
边界：附件本身不进画布，落到画布的是 Agent 新建的节点
  • 撤销本轮时，这个节点随其他改动一起撤销；素材本身不删。
  • Agent 只能用用户自己的图片素材建节点（Go 靠素材归属把关；别人的素材和不存在一样报错）。
  • 模型的说明可能比动作短语晚 1–2 秒到；失败时一直显示动作短语。
  • 本地磁盘存储下，单张图片超过 5 MB 发不出去（沿用「查看图片」的限制）。

上线时要告诉用户：聊天框加的图不会再出现在画布上；想把它放到画布上，可以让 Agent 放，或者自己拖进画布。

回答结束时为什么「刷一下」

左边按现在的代码重现，右边是修复后的行为。点「播放回答结束」，看最后那一刻。打开「慢放」更容易看清；左边被重建的元素会闪红框。这是对代码行为的模拟，不是真实录屏，修完后需要真机确认手感。

关系

附件、节点、活动段各自属于谁。

对象属于为什么
附件一条用户消息（message.user.attachments），引用素材 asset_id附件是对话里的临时参考，不是作品的一部分
附件落成的节点本轮运行的画布改动能和其他改动一起撤销；只能用本会话出现过的附件
活动段说明一段连续工具调用，group_id = 第一个工具调用的 id前后端都能从事件里算出同一个 id，不用另外分配

数据模型

都放在现有的 agent_events.payload（SQLite）里，不新建表、不改结构。

AgentAttachment（message.user.attachments[]，0–9 项）
asset_idstring，素材 id；同一条消息里不重复
namestring，展示名（原文件名或「图片 N」）
mime_typepng / jpeg / webp / gif
width / heightnumber，可选，缩略图占位用
urlstring，素材的稳定路径 /files/*（后端 302 现签名，不过期）；缩略图加 ?v=thumb。不存签名直链
activity.summarized（新的持久化事件）
group_idstring，本段第一个 tool.start.data.id
textstring，清洗后 1–24 字，没有结尾标点
何时发段闭合，并且工具数 ≥ 2、没有中止、总结成功；失败时不发
前端ActivityItem 加 groupId 和 summary?；没有就用兜底短语

已确认的决定

  1. 图片作为附件上传，显示在聊天框上方，随消息带上 URL：不再落到画布。
  2. 附件当生成参考时，由 Agent 自己落到画布：需要给「修改画布」加上 assetId。
  3. 每段工具调用各自折叠（和截图一样）：保留文字和工具交错的结构。已搁置：整轮过程折成一行。
  4. 收起时用一句自然语言说明：写的是「做成了什么」。
  5. 说明由每段结束后的异步总结生成：到达前、只有一个工具时、失败时，都用动作短语兜底。
  6. 展开行用动作图标打头，状态靠颜色和右侧文字表示：成功不再画对勾。
  7. 附件地址用后端重定向路径 /files/*：签名直链会过期，重定向路径不会。
  8. 上下文图片只保留最近 2 条带图的消息：实现时确认仓库里没有现成逻辑，改为新写（Agent 服务发请求前裁剪）。
  9. 活动段总结复用当前会话模型，计入用量：和自动命名一致，照常计费（先前写成「不计入」，已更正）。
  10. 去掉流式输出时的闪烁光标（F5）：文字自己在增长，不需要光标。
  11. 主文档已回写：Markdown 6.1.2、6.1.3、6.2.3、6.3.2、8.2、8.5、11 节。
