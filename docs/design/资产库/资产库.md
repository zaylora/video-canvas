# 资产库设计：生成历史 + 个人资产库 + 画布引入弹框

> - **范围**：重做「资产」这一块——(1) 资产页「生成历史」接入真实数据，并且包含画布里的生成结果；(2) 在资产页新增「个人资产库」，支持新建文件夹和上传；(3) 画布里的「画布素材」侧边栏改成弹框，从资产库或生成历史里引入素材。不含「主体」「文档」类型、素材存储回收、协作共享。
> - **日期 / 状态**：2026-10-15 · 设计已确认，待实现。
> - **证据约定**：**事实**附文件路径或来源链接；**推断**是基于事实的判断；**提案**是尚未实现的设计；**默认值**是用户没被问到、由本文暂定的做法，实现前可推翻。
> - **方案演进**：原《首页生成与对话》§6.5、§10.2 规划资产页「生成历史」读 `GET /conversation-records`（只含首页对话）。用户本次明确要求「画布里的生成历史也要在这里」，所以改为按素材读取（§6.3），原规划作废，实现时需回写那份文档（见 §11.3）。
> - **配套演示**：[资产库-演示.html](资产库-演示.html)（建议先读，里面有可点击原型）。

## 1. 设计摘要

- **问题**：
  1. 资产页的「生成历史」现在是样例数据，用户在首页和画布里生成的内容在那里看不到。
  2. 用户没有地方长期保存、分类自己的素材（上传的图片、满意的生成结果）。
  3. 画布里的「画布素材」侧边栏只列当前这张画布的节点产物，点一张是定位到节点，不能把别处的素材引进来。
- **目标**：
  - 在资产页一处看到自己所有的生成结果。
  - 有一个自己管理的个人资产库，能分文件夹。
  - 在任何画布里用一个弹框，从个人资产库或生成历史里挑素材放上画布。
- **推荐结论**：
  - 资产页三个范围：**生成历史 / 画布 / 个人资产库**（顺序与用户截图的红框位置一致）。
  - 「生成历史」读后端新接口 `GET /assets/generated`，合并首页对话和所有画布的生成结果。
  - 「个人资产库」是用户主动管理的集合，只有一层文件夹；新增 `asset_folders` 与 `asset_library_items` 两张表，**不复制文件**，同一条 `assets` 记录多一个库归属。
  - 画布侧：底栏「画布素材」按钮和「添加节点」菜单新增的「从资产库添加」打开同一个弹框；确认后每个素材建一个节点，整齐排在落点附近，算一次撤销。旧的侧边栏删除。
  - 删除只是「移出资产库」，不删文件，画布里已引用的素材不受影响。

### 2.2 设计约束

- 资源都按 `user_id` 隔离；新接口必须带用户条件（`repository/asset.go` 的 `GetByID` 就是这样）。
- `assets.storage_key` 是 `/files/<key>` 的反查依据，素材行不能随便改写或删除。
- 画布保存依赖 `revision` 乐观锁；引入素材只在前端改画布内容，走现有自动保存与冲突流程，不需要新的画布接口。
- 画布在另一个标签页打开时是只读（见 `canvas-locked-notice.tsx`），引入入口必须同样禁用。
- 前端格式化只用 oxfmt / oxlint；测试放 `web/src/tests/`、`backend/internal/tests/`；先写失败测试再实现（`AGENTS.md`）。

### 2.3 当前缺口

- 缺「按用户列出已生成素材」的接口，以及它所需的索引。
- 缺文件夹与资产库归属的模型、接口和页面。
- 缺画布里的选择弹框；`addUploadedNodes` 只接收本地文件，没有「用已有素材建节点」的函数。
- `docs/design/画布UI设计/画布UI设计.md:991` 当时写明「从资产库添加」不做，因为没有资产库；这次补上。

## 3. 用户与场景

- **用户**：在连镜里反复创作的个人用户，会跨多张画布、多次对话产出素材，也有自己的参考图、角色图。
- **触发场景**：
  1. 「我上周在另一张画布里生成过一张很好的图，想拿来当这次的参考」。
  2. 「我有一批常用的角色图 / 场景图，想放在一起，每次直接拖进画布」。
  3. 「我想翻一下自己都生成过什么」。
- **主任务**：
  - 在资产页浏览生成历史 → 把满意的加入资产库 → 在画布里从资产库引入。
  - 在资产页上传素材到文件夹 → 在画布里引入。
- **成功指标**（提案，实现后可核对）：
  - 从打开弹框到素材出现在画布 ≤ 3 次点击（打开、勾选、确认）。
  - 生成历史覆盖首页对话和画布两个来源，数量与任务成功产物一致。

### 4.2 比较表（本方案 vs 常见做法）

| 维度 | 生成物自动进库（Runway 式） | 本方案：历史与库分开，按需加入 | 只有历史、没有库（Krea 式） |
| --- | --- | --- | --- |
| 学习成本 | 中：一个入口里要区分系统文件夹 | 低：「历史」是流水，「库」是我整理的 | 最低 |
| 库的整洁度 | 低：所有生成都进来 | 高：只有用户挑的 | 无库 |
| 复用路径 | 直接从库引入 | 历史里也能直接引入，满意的再「加入」 | 只能从历史引入 |
| 数据模型 | 需要系统文件夹的特殊规则 | 一张归属表 + 一张文件夹表 | 无新表 |
| 实现复杂度 | 中 | 中 | 低 |
| 数据模型匹配度 | 一般 | 好：复用 `assets` 行 | 好 |

### 4.3 依赖框架调研

- **结论**：本方案**不新增依赖**，因此没有需要征求用户的引用决定。
- 已在 `web/package.json` 的：`react-dropzone`（文件选择和拖入上传，第 46 行）、`@base-ui/react` 与 `radix-ui`（对话框、下拉等现有 UI 基础）、`motion`（过渡）。
- 考察过但不采用：
  - 拖拽库（如 dnd-kit）：用户没有选「拖拽归档」，本期用「移动到…」菜单，不需要。
  - 虚拟列表（如 @tanstack/react-virtual）：本期用游标分页 + 滚动到底加载，单页 40 条，不虚拟化；若后续单次渲染超过几百张再评估。**以上依赖的版本、许可证未联网核对**（本次调研未访问其官网），评估时再补。

## 5. 设计原则

1. **历史是流水，库是整理**：生成历史自动、只读；资产库由用户主动放入，可分类。两者不重叠、不自动同步。
2. **不复制文件**：库只是同一条 `assets` 记录的归属；移出库不动文件，画布里的引用永远有效。
3. **一个选择器，两处使用**：资产页和画布弹框共用同一套卡片、过滤和分页组件，只有「选择模式」不同。
4. **和现有画布行为对齐**：引入素材落成的节点，与「上传素材」落成的节点是同一种数据，不引入新的节点概念。
5. **不为没有的功能留空位**：没有「文档」「主体」，就不放标签；还没做的能力不灰着占位（用户明确要求去掉文档标签）。

## 6. 推荐方案

### 6.1 信息架构

```
/assets?tab=history|canvas|library&folder=<id>
├─ 生成历史   图片 | 视频 | 音频   [筛选 ▾] [时间 ▾] [排序 ▾]   搜索提示词
├─ 画布       （现状，不改）
└─ 个人资产库 图片 | 视频 | 音频                            搜索文件名   [＋ 新建 ▾]
              根目录：文件夹卡片 + 未归档素材；进入文件夹：面包屑 个人资产库 / 文件夹名

画布内
├─ 底栏「资产库」按钮（原「画布素材」，图标不变）──┐
└─ 「添加节点」菜单 → 「从资产库添加」─────────────┴→ 资产库弹框
   弹框：[个人资产库 | 生成历史]  图片 | 视频 | 音频  搜索 / 时间 / 筛选   已选择 N 个素材 [确认]
```

- 资产页三个范围用现有 `Segmented`（`variant="track"`）；`tab` 和 `folder` 进地址栏，刷新和后退可恢复。
- 内容类型标签只有图片、视频、音频，默认图片。「文档」标签删除（用户决定）。
- 个人资产库的类型标签只过滤素材；**文件夹在根目录始终显示**（搜索时隐藏，搜索结果跨文件夹平铺）。

### 6.2 页面与交互

**生成历史**

- 卡片：封面（图片用 `?v=thumb`，视频用 `?v=poster`，无封面显示占位图标）、视频带时长角标；悬停浮出提示词（2 行）与「模型 · 日期」，沿用现有 `HistoryCard` 样式。
- 卡片角标：已在资产库的素材显示「已在资产库」。
- 点卡片：打开预览（实现时核对 `components/canvas/media-lightbox.tsx` 能否在画布外复用，不能则做一个只读预览）。
- 卡片 ⋯ 菜单：「加入资产库…」（弹小选择器：根目录 / 各文件夹，可就地「新建文件夹」）、「在画布中打开」（有来源画布时，新窗口）。
- 筛选（用户决定启用）：
  - 筛选：来源 = 全部 / 首页对话 / 某张画布（选画布时从 `GET /canvas` 列表里选）。
  - 时间：全部 / 今天 / 近 7 天 / 近 30 天。
  - 排序：最新优先（默认）/ 最早优先。
  - 搜索框：匹配提示词（关键字包含）。
- 不提供删除（用户决定）。

**个人资产库**

- 标题「个人资产库」（进入文件夹后变面包屑）。右上：搜索、「＋ 新建」下拉（「新建文件夹」「上传资产」，对应用户第 3 张参考图）。
- 文件夹卡片：文件夹图标、名称、创建日期、⋯ 菜单（重命名 / 删除）。点击进入；只有一层，进入后不再有「新建文件夹」。
- 素材卡片：封面、文件名；⋯ 菜单（移动到… / 移出资产库）。
- 上传：多选文件，逐个上传（走现有 `uploadAsset`，直传优先、失败降级中转），上传完成后调用 `POST /asset-library/items` 登记到当前文件夹；卡片上显示进度，失败显示「重试」和原因。
- 删除文件夹：确认框「将移除文件夹及其中 N 个素材；画布里已使用的素材不受影响」（用户决定：文件夹里的素材一起移出，而不是退回根目录）。
- 空状态：根目录「还没有资产，点右上角“新建”上传」；文件夹「这个文件夹是空的」；搜索「没有找到“xx”」。

**画布里的资产库弹框**（对应用户第 5 张参考图）

- 顶部：来源切换 [个人资产库 | 生成历史]，右上关闭；第二行类型标签（图片 / 视频 / 音频，带下划线选中态），右侧搜索框；生成历史来源下再显示「时间」「筛选」两个图标按钮；个人资产库来源下显示「上传」按钮（用户决定：弹框内直接上传）。
- 内容区：网格，多选；卡片左上角勾选框；个人资产库来源在根目录显示文件夹卡片，点击进入，顶部出现面包屑。
- 底部：左「已选择 N 个素材」，右「确认」（0 个时禁用并提示「请先选择素材」）。**一次最多 20 个**（默认值），超出时禁用其余卡片并提示「一次最多引入 20 个」。
- 确认后：弹框关闭；前端为每个素材建一个节点（见 §6.4）。
- 入口：
  - 底栏「资产库」按钮（替换原「画布素材」，tooltip 文案改为「资产库」）。落点：视口中心偏上，与 `viewportCenter` 一致。
  - 「添加节点」菜单在「上传素材」旁新增「从资产库添加」。落点：菜单位置。
  - 手机宽度：弹框全屏；底栏按钮仍隐藏（沿用 `max-sm:hidden`），手机上从「添加节点」菜单进入。
- 画布只读（另一标签页占用）时：两个入口都禁用，原因文案沿用现有「已在另一个标签页打开」。
- 不做类型限制（用户未选「拉线落空时只显示接得上的类型」）：从某节点拉线落空进入弹框时，可选所有类型，不匹配的素材照常建节点，连线按现有 `link-rule` 判断，不合法就不连。**推断**：此时不自动连线，只建节点。

### 6.3 数据来源与归属规则

- **生成历史** = `assets` 中 `source='generated'`、所属任务非试跑（`generation_tasks.is_test=false`）的素材，按 `assets.created_at` 倒序。一个任务出多个素材就是多张卡。
  - 来源判定（**推断**，依据 §2.1「对话提交不设置 canvas_project_id」）：`canvas_project_id` 为空 = 首页对话，非空 = 画布。
  - 提示词取 `input_json.prompt`，模型名取 `config_snapshot.model.label`，退回 `model_id`（复用 `libraryTaskPrompt` / `libraryTaskModelLabel` 的解析方式，但**不要**沿用它的 80 字截断，历史里要完整提示词，前端用 2 行省略）。
- **个人资产库** = `asset_library_items` 里属于该用户的行。进库的途径只有三种：资产页「上传资产」、弹框「上传」、生成历史「加入资产库」（用户决定：画布节点上传和首页参考图上传**不自动进库**）。
- 一个素材在同一用户的库里**最多一条归属**（默认值）：要换文件夹用「移动到…」。生成历史里的素材加入库后，历史里仍在。
- 来源是上传的素材如果没进库（画布里临时上传的），不出现在任何列表里，只活在引用它的画布中。

### 6.4 引入画布的行为

1. 弹框确认返回选中的素材列表（`AssetDto`：id、url、kind、尺寸、时长、文件名）。
2. 画布新增 `addAssetNodes(assets, origin)`（建议放在 `use-canvas-menu.ts` 里 `addUploadedNodes` 旁边）：每个素材按 `kind` 建图片 / 视频 / 音频节点，写入 `src`、`assetId`、`mediaType`、尺寸，`status='done'`，不触发上传。
3. 排列（默认值）：从落点起，横向最多 4 列，节点间距 40px，超过 4 个换行；落点避开已有节点的规则沿用 `addUploadedNodes` 现有逻辑。
4. 整次引入是**一条撤销记录**（和一次批量上传一致）；画布提示「已引入 N 个素材」。
5. 画布自动保存走现有 `revision` 乐观锁与冲突弹窗，不新增接口。
6. 素材地址用 `AssetView.url`（与「上传素材」节点写入的值一致）。**待核对**：若这个地址是带过期时间的签名地址，则按现有「素材加载」文档的做法刷新，见 `docs/design/画布素材加载设计/画布素材加载设计.md`。

## 7. 状态与异常

| 场景 | 行为 |
| --- | --- |
| 列表加载中 | 骨架卡片（沿用资产页现有 `Skeleton`） |
| 列表为空 | 见 §6.2 各空状态 |
| 加载失败 | 「加载失败」+「重试」按钮（沿用现有样式） |
| 滚动到底 | 用 `next_cursor` 加载下一页；底部小转圈；没有更多时不显示 |
| 筛选后无结果 | 「没有符合条件的素材」+「清除筛选」 |
| 上传中 | 卡片进度条；可取消（沿用 `AbortController`） |
| 上传失败 | 卡片显示失败原因与「重试」；类型不支持 / 超过大小上限直接用后端业务错误文案 |
| 新建 / 重命名文件夹 | 名称去首尾空白后 1–30 字；重名（同一用户，忽略大小写）提示「已有同名文件夹」；每用户最多 100 个（默认值），超出提示「文件夹数量已达上限」 |
| 文件夹或素材在别处被删（404） | toast「该内容已不存在」并刷新当前列表 |
| 加入资产库时素材已在库里 | 幂等：返回现有归属，提示「已在资产库」，不报错 |
| 移出库 | 立即从列表消失（乐观更新），失败回滚并 toast |
| 删除文件夹 | 确认框写明数量；成功后回到根目录；失败不改列表 |
| 画布引入 | 见 §6.4；画布只读时入口禁用；画布保存冲突走现有冲突弹窗 |
| 权限 | 所有接口按登录用户隔离；别人的 `asset_id` / `folder_id` 一律按 404 处理 |
| 撤销 / 恢复 | 画布引入可撤销（一条记录）；资产页的删除不可撤销，靠确认框兜底 |

## 8. 数据与工程影响

### 8.1 新增表（迁移 `backend/migrations/0004_asset_library.sql`，编号以实现时为准）

**`asset_folders`**

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | bigint 主键 | 对外用十六进制串（`idcodec.ID`，与画布、对话一致） |
| user_id | bigint not null | 所属用户 |
| name | varchar(30) not null | 1–30 字 |
| created_at / updated_at | timestamptz | |

约束：唯一索引 `(user_id, lower(name))`。

**`asset_library_items`**

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | bigint 主键 | 归属 ID |
| user_id | bigint not null | |
| asset_id | bigint not null | 指向 `assets.id` |
| folder_id | bigint null | `null` = 根目录 |
| created_at | timestamptz | 加入时间，库内默认按它倒序 |

约束：唯一索引 `(user_id, asset_id)`；索引 `(user_id, folder_id, created_at desc, id desc)`。删除文件夹时在同一事务里先删它的归属行再删文件夹，不依赖数据库外键级联（项目现有迁移没有大量外键，保持一致，**待实现时核对**）。

**`assets` 新增索引**：`(user_id, source, kind, created_at desc, id desc)`，给生成历史按用户 + 类型分页用。

### 8.2 接口（提案，路径放在 `auth` 组下）

| 方法与路径 | 说明 | 业务错误 |
| --- | --- | --- |
| `GET /assets/generated` | 生成历史。参数：`kind`（必填 image/video/audio）、`source`（all / conversation / canvas，默认 all）、`canvas_id`、`created_from`（RFC3339，由客户端按本地时区算「今天 / 近 7 天」）、`order`（desc 默认 / asc）、`q`、`cursor`、`limit`（默认 40，最大 100） | 参数非法 400 |
| `GET /asset-folders` | 当前用户全部文件夹（≤100，不分页），含 `item_count` | — |
| `POST /asset-folders` | `{name}`，201 | 名称不合法 400；重名 409；数量上限 409 |
| `PATCH /asset-folders/:id` | `{name}` | 同上；不存在 404 |
| `DELETE /asset-folders/:id` | 删除文件夹及其归属行，返回 `{removed}`；不动 `assets` 与存储文件 | 不存在 404 |
| `GET /asset-library/items` | 参数：`folder_id`（`root` 默认 / 具体 id / `all`）、`kind`、`q`（文件名）、`cursor`、`limit`。有 `q` 时前端传 `folder_id=all` | 文件夹不存在 404 |
| `POST /asset-library/items` | `{asset_id, folder_id?}`，加入资产库；已存在则 200 返回现有归属 | 素材不存在或不属于该用户 404；文件夹不存在 404 |
| `PATCH /asset-library/items/:id` | `{folder_id: id \| null}`，移动 | 不存在 404 |
| `DELETE /asset-library/items/:id` | 移出资产库，不动 `assets` | 不存在 404 |

`GET /assets/generated` 的单项（提案）：

```json
{
  "asset": { "id": 12, "kind": "image", "url": "/files/g/…", "mime_type": "image/png", "width": 1024, "height": 1024, "duration_ms": 0, "file_name": "…" },
  "prompt": "雪地里的旧楼，黄昏",
  "model_label": "Seedream 4",
  "canvas": { "id": "1f", "title": "扩图" },
  "created_at": "2026-10-14T10:20:00Z",
  "library_item_id": null
}
```

- `canvas` 为 `null` = 首页对话；画布已被删除时返回 `{ "id": "1f", "title": "", "deleted": true }`，前端显示「已删除的画布」且不给「在画布中打开」。
- `library_item_id` 非空表示已在资产库（页内一次 `IN` 查询补齐，避免 N+1）。
- 游标是 `(created_at, id)` 的不透明编码；`order=asc` 时反向。
- `q` 在 `input_json->>'prompt'` 上做大小写不敏感的包含匹配。**风险**：没有全文索引，按用户 + 类型先缩小范围，单用户数据量可接受；若出现慢查询再评估。

## 9. 方案取舍

### 9.1 决策矩阵

用户已确认的优先级：覆盖「画布生成历史」、文件夹只有一层、不复制文件、不做文档。其余默认权重：实现风险 > 学习成本 > 扩展性。

| 方案 | 满足用户 3 个诉求 | 实现风险 | 学习成本 | 扩展性 | 结论 |
| --- | --- | --- | --- | --- | --- |
| **A. 历史与库分开，按需加入（推荐）** | ✅ | 中（两张新表 + 一个联表查询） | 低 | 好（以后可加标签、收藏、多层文件夹） | 采用 |
| B. 生成物自动进库（Runway 式） | ✅ | 中高（系统文件夹规则） | 中 | 中 | 放弃：库会被生成物淹没，与「上传为主」的用户决定冲突 |
| C. 只读对话记录做历史（原规划） | ❌ 看不到画布生成 | 低 | 低 | 差 | 放弃：违背用户第 1 点 |
| D. 弹框只有资产库，历史须先加入库 | 部分 | 低 | 中 | 中 | 放弃：用户选了「两个来源」 |

### 9.2 明确放弃

- 多层文件夹、拖拽归档、批量选择与批量移动 / 删除、素材重命名、收藏、库内排序。
- 「文档」类型、「主体」。
- 弹框按拉线上下文限制可选类型。
- 生成历史里的删除。
