生成多张图，都落在同一个节点里

现在「生成数量 4」会在画布上凭空多出 3 个一模一样的节点。新方案：N 张结果都归在发起生成的那个节点里，节点右上角出现「3 ▾」徽标，点开是「历史记录」大弹窗，单击哪张，哪张就是主图，下游节点读到的也是它。同一个节点重新生成多次，也是同样的做法。 后端基本不用改：仍然是 N 个独立任务（各自冻结、各自退款），只是它们都绑在同一个节点上。

阅读说明。这是设计稿，尚未实现。「现状」来自读 2026-10-15 的仓库代码；原型里的生成、失败、耗时都是浏览器里模拟，没有调用任何真实服务；主图的缩略图用渐变色块代替。对应 Markdown：docs/design/多结果归并/多结果归并.md（§6 方案、§7 异常、§8 工程影响）。

一次「生成数量 4」怎么走

这张图回答：4 个任务、1 个节点，每一步谁负责什么。

点发送前端发一次请求，node_ids = 同一个节点 id 写 4 遍。画布上不再多出节点
后端拆 4 个任务各自冻结积分，都带 node_id = 这个节点；某个失败只退自己
节点进入生成中记下 pendingTaskIds（4 个）
先到先显示第一张成为主图；后到的只追加进历史，不抢主图
用户挑主图徽标 → 弹窗 → 单击一张。下游读主图
设计：把「几个任务」和「几个节点」解开。任务是计费和审计单位，节点是创作意图单位；N 个任务对应 1 个节点，回填时一个任务追加一版，复用现有的 outputs[]。
出问题时（回退，永远可用）：提交整体失败 → 节点不动，错误就地显示在提示词面板里；只提交成功了一部分（积分只够 2 个）→ 成功的照常生成，toast 说明另外几张没提交；某个任务生成失败 → 只退它自己的积分，其他照常；全部失败才把节点标成失败态。老画布、单个任务的路径完全不变。

节点会处在哪几种形态

形态由「有几版结果」和「有没有任务还在跑」决定，徽标和弹窗里的格子跟着变。

只有 1 版
无徽标

没有历史入口。功能区的「历史」按钮已删除，所以单版本节点看不到入口——再生成一次就有了。

有 2 版及以上
徽标「3 ▾」

数字 = 历史版本总数，不是本次数量。点开是弹窗，单击设主图。

批次还在生成
徽标带转圈

第一张出来后就能挑。还没出第一张时节点是占位，弹窗里的格子可看、不可设主图。

四种做法对比

为什么选「归并 + 弹窗」，以及放弃了什么。

复制 N 个节点（现状）归并 + 弹窗（推荐）节点内展开1 个任务出 N 张
画布整洁度差：多 N−1 个节点好节点被撑大，挤邻居好
并排比较直接在画布上弹窗网格，够大受节点宽度限制同归并
后端改动无近 0：补测试和注释同归并大：每个插件要支持一次出 N 张；计价退款变成全有或全无
部分失败只退失败那份只退失败那份同归并整体失败
前端复杂度已有中：批次回填 + 弹窗高：布局联动小
用户的选择推翻已确认放弃用户未选
核实度已核对代码提案Weave 式，调研检索已核对代码

外部做法：Figma Weave（原 Weavy）把同一节点的多次结果存在节点里、可「Unpack」拆成独立节点；FLORA 的批量变体可以叠在一个节点里；ComfyUI 一批图默认整批传下游，社区另做了「预览后选一张」的节点。调研检索，未逐条复核 来源见 Markdown §4、§12。

用户把生成数量设成 4 并点发送，会发生什么

五步，以及几个需要提前说清的边界。

  1. 点发送，画布节点数不变节点进入「生成中」占位，底栏积分按 4 个任务合计冻结
  2. 第一张完成：占位换成这张图，自动成为主图右上角出现「1 ⟳」
  3. 后三张陆续到达：只追加进历史数字依次变 2、3、4，主图不动，转圈消失
  4. 点徽标，在弹窗里点中一张它立刻成为主图，节点上的图跟着换，⌘Z 可撤销
  5. 需要的话「全部添加到画布」每一版拆成一个独立节点，摆在原节点右侧
边界：和旧做法不一样的地方
  • 不再多出节点；以前能在画布上直接并排比的，现在要点开弹窗比。
  • 取消 = 取消本节点全部进行中的任务，已出的图保留。
  • 已经被旧方案复制出来的兄弟节点保持原样，不提供合并（已确认）。
  • 画布 Agent 助手生成媒体仍固定一次 1 张、各建节点，本期不动。
  • 每个节点最多留 50 版（原来 20），超出丢最旧的引用，素材本身不删。

上线时要告诉用户：旧缩略图条没有了，历史入口是节点右上角的徽标；拖缩略图到画布建节点改成「添加到画布」按钮。

原型覆盖的状态

          
不可用的操作都是禁用并写原因，不是隐藏。

          

            

              
状态怎么触发看什么

              
                
单版本（无徽标）原型起点已是 3 版，无法触发规则见总览「形态」：只有 1 版的节点不出徽标，也没有历史入口

                
生成中，还没出第一张点「生成」后的 1 秒内节点是占位；弹窗里骨架格 + 其他格「设主图」禁用，悬停有原因

                
已出第一张，其余在跑点「生成」1 秒后主图已换；徽标带转圈；弹窗里剩余骨架格；此时可以设主图，后到的不抢

                
部分失败失败情形 = 最后一个任务失败toast「有 1 张生成失败，积分已退回」；弹窗里有一个失败格，关掉弹窗后消失

                
全部失败失败情形 = 全部失败节点变失败态（原因 + 积分已退回 + 任务编号）；徽标仍在，可以在弹窗里把旧版本找回来

                
提交部分失败失败情形 = 积分只够 2 个只创建 2 个任务；toast「有 2 张没能提交：积分不足」

                
一个任务返回多张「每个任务返回」选 2 张4 个任务出 8 张：每个任务的第一张先成主图，其余全部进历史，徽标数字一次 +2

                
取消节点占位上的「取消」，或弹窗「···」→ 取消剩余取消本节点全部进行中任务；已出的图保留

                
生成按钮禁用生成中再点「生成」按钮旁写明原因「生成中」

              
            

          

        

      


      
      

        
数据与接口（提案）

        
下面都是设计提案，尚未实现。对应 Markdown 设计文档 §8（数据与工程影响）和 §7（状态与异常）。后端不新增表、字段、接口，只放开并测试「多个任务绑同一节点」；主要改动在前端节点数据和回填。


        

          
关系

          
谁绑谁、为什么。

          

            

              
对象允许的关系为什么

              
                
节点 ↔ 任务1 : N（一次提交最多 8 个；多次提交累积）任务是计费、审计单位，节点是创作意图单位。generation_tasks.node_id 无唯一约束（已核对）

                
任务 ↔ 产物1 : k（view.outputs 里每个有 url 和 asset_id 的成员各一版）全部进历史（已确认）。今天豆包 Seedream 组图一个任务就返回多张，但现状回填只取第一张（firstOutput），其余被丢

                
节点 ↔ 历史版本1 : ≤50（outputs[]，旧在前）生成数量最多 8，连点几次就超过 20，所以从 20 提到 50

                
节点 ↔ 主图1 : 1（activeOutputId → src / assetId 镜像）下游、预览、下载都读镜像，不读 outputs[]

                
节点 ↔ 进行中任务pendingTaskIds 是 outputs 之外的另一个集合任务终态后移出集合；集合空了才算这一批结束

              
            

          

        


        

          
数据模型

          
全部是前端节点数据（随画布整块 JSONB payload_json 保存，后端不校验节点内字段），沿用现有 revision 乐观锁和自动保存。

          

            

              
CanvasNodeData（web/src/types/canvas.ts）

              
                
pendingTaskIds?: string[]新增。本节点进行中的任务 id 集合；一次提交成功创建 ≥2 个任务才写；任务终态后回填把它移出；空了删掉字段。不含密钥。需加入 history.ts 的 TASK_FIELDS（撤销不倒回）和 canvas-persistence.ts（序列化）

                
taskId?: string不变。一次提交里第一个成功创建的任务 id；进度、追溯、对账兼容、Agent 绑定都用它

                
outputs?: NodeOutput[]不变。每版 { id = 素材 id, src, mediaType, assetId, taskId, model, createdAt }，同一素材不重复

                
activeOutputId?: string不变。当前主图的 outputs[].id；设主图改它，同时刷新 src / mediaType / assetId 镜像

                
MAX_NODE_OUTPUTS常量 20 → 50；超出丢最旧引用，主图被丢时改为最新一版

              
            

          

          

            

              
节点 status条件迁移规则

              
                
running本次还没有任何一张落下来提交成功后进入；第一张成功 → done；pendingTaskIds 空了仍无产物 → error；取消且空了 → 回到当前版本（done）或 idle

                
done + 非空 pendingTaskIds第一张已到，其余在跑后到的成功只追加（不动主图）；失败只移出集合；集合空了 → 纯 done

                
error全部任务失败在弹窗里设主图 → done（和今天「失败后点当前版本找回」一致）

              
            

          

        


        

          
接口

          
没有新接口。POST /api/v1/generation-tasks 的 node_ids 从「每个任务一个不同节点」放宽为「可以重复」。

          

            

              
方法与路径说明

              
                
POST /api/v1/generation-tasks请求：{ kind, model_id, canvas_id, node_id, node_ids, input }，头 Idempotency-Key。node_ids 长度必须等于生成数量（1–8），元素可以相同。返回 202 { items: [{ node_id, task? , error? }] }，按 node_ids 的下标逐项对应（前端必须按下标取，不能按 node_id 查找）。
整体错误（一个任务都不建）：10001 参数不合法（含 node_ids 数量不等于生成数量、超过 8 个）、模型不可用、素材无效。
单项错误（写在这个下标的 error 里，其余照常创建）：积分不足 40001（HTTP 402）、并发已满 40002（429）。
幂等：第 i 个任务的键 = key（i=0）或 key#i，重复提交返回已创建的任务，失败的下标会重试

                
GET /api/v1/generation-tasks?ids=…对账：最多 100 个 id。重开画布时除了 status: running 的节点，还要带上所有节点的 pendingTaskIds

                
POST /generation-tasks/:id/cancel不变；取消本节点全部进行中任务 = 对 pendingTaskIds（无则 taskId）逐个调用，某个失败不影响其他

                
WebSocket 任务推送不变。快照里本来就有 node_id；前端按任务 id 回填

              
            

          

          

            
            
后端要补的测试（backend/internal/tests/handler/generation_task_test.go）：node_ids: ["a","a","a"] + 生成数量 3 → 202，3 个任务 node_id 都是 a，items 按下标对应；余额只够 2 个 → 前 2 项有任务、第 3 项积分不足；同一 Idempotency-Key 重发 → 同样 3 个任务。实现时先写这组失败测试

已确认的决定

          

            
    
              
  1. 后端仍拆 N 个任务，都绑同一节点：改动最小，各自冻结 / 退款，失败互不影响；代价是节点要记 pendingTaskIds。（放弃：1 个任务出 N 张、新增批次表）
    2. 
              
  2. 先到先显示，本次第一张自动成主图；后到的只追加进历史，不抢主图。（放弃：全部完成后再换、主图跟着最新到的走）
    3. 
              
  3. 历史记录弹窗里单击一张直接设为主图；另有放大按钮，放大只看不改。用户说的「放大之后选中什么就设为主图」，这里的「放大」指把节点放大成弹窗。
    4. 
              
  4. 本期覆盖图片 + 视频节点：视频也有「生成数量」，只改图片会让两边行为不一致。
    5. 
              
  5. 附加功能做：全屏网格视图、下载全部、全部添加到画布；不做「删除某一版」。
    6. 
              
  6. 去掉功能区里的「历史」按钮，只保留节点右上角徽标；单版本节点因此没有历史入口。（放弃：保留按钮、两个入口并存）
    7. 
              
  7. 插件一个任务返回多张图时，全部进历史：第一张（本次最先到的）设为主图，其余只追加。回填从「取第一份」改成「取全部」。
    8. 
              
  8. 全屏查看只做网格，不做列表（单图）模式：要看大图点「放大」，走灯箱。
    9. 
              
  9. 老画布里旧方案已复制出来的兄弟节点不做合并迁移：老画布数据不动，用户需要的话自己删。
    10. 
              
  10. 已搁置：按批次分组显示、删除某一版、两图对比滑块、Agent 助手生成多张时归并；「生成数量」改成一次调用原生出 N 张（调研见 Markdown §12：OpenAI、阿里万相能，Seedream 靠组图，Gemini 图片和所有视频插件不能），一期仍拆 N 个任务。
    11. 
              
  11. 默认值（不需要决定）：最新在前；每节点最多 50 版；取消 = 取消本节点全部进行中任务；「全部添加到画布」含主图、超过 8 个先确认。
