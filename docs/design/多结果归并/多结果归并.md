# 多结果归并到同一节点 · 历史记录弹窗设计

> **范围**：图片、视频节点。「生成数量 N」不再复制出 N 个节点，N 个结果都落在发起生成的那个节点里；同一个节点重新生成多次，也都归在这个节点的历史里。节点右上角出现「3 ▾」徽标，点开是「历史记录」弹窗（网格）、可全屏查看、全部下载、全部添加到画布。点哪张，哪张就是主图。
> **日期与状态**：2026-10-15，设计中（已与用户逐题确认，待用户确认文档后实现）。
> **证据约定**：**事实**附文件路径；**推断**是基于事实的判断；**提案**是尚未实现的设计；**未验证**需要实现时实测。
> **方案演进**：这份设计**推翻了一条已确认的旧决定**——`docs/design/后台管理设计/编辑模型补齐设计.md` §6.x 写的是「生成数量 = 复制出 N 个节点 = N 个任务（已确认）」。本次保留其中「N 个独立任务、各自冻结 / 退款」的部分，只把「N 个节点」改成「1 个节点」。旧文档里关于复制节点的段落需要在实现时同步标注作废（见 §10）。
> **配套演示**：[多结果归并-演示.html](./多结果归并-演示.html)（先打开它读，再回来看依据）。
> **参考图**：4 张——节点右上角「3 ▾」徽标；「历史记录 3」弹窗（2 列网格，当前图片高亮）；悬停时右上角出现复制、下载，当前图标「当前图片」；「全屏查看」黑底全屏，顶部左侧列表 / 网格切换、「下载全部」「全部添加到画布」，主图带「主图」角标。

## 1. 设计摘要

- **问题**：生成数量 N>1 时画布上凭空多出 N−1 个一模一样的节点，用户要挑一张图得在画布上一个个比；而同一节点重新生成的旧结果，只藏在功能区「历史」里一排 58×30 的小缩略图，看不清、没法比。
- **目标**：一次生成的 N 张图（或同一节点生成多次的结果）都在**一个节点**里；用户在一个够大的弹窗里并排挑，挑中的就是节点的主图，下游节点读到的也是它。
- **推荐结论**：
  1. 后端**仍拆 N 个任务**（各自计价、冻结、退款、失败互不影响），只是 N 个任务的 `node_id` 填同一个节点。后端几乎不用改，主要补测试和注释。
  2. 前端节点新增 `pendingTaskIds`（本节点进行中的任务集合），回填逻辑按「一个任务一份产物」追加进现有 `outputs[]`；`outputs[]`、`activeOutputId` 和 `src / assetId` 镜像机制**全部复用**。
  3. 新增「多版本徽标」和「历史记录」弹窗；功能区的「历史」按钮和缩略图条**删除**。
- **第一版刻意不做**：删除某一版、Agent 助手生成多张时归并（Agent 本来就固定每次 1 张）、音频节点、文本节点、对比滑块、按批次分组显示。

### 设计约束

- 下游节点永远读主图（`src / assetId` 镜像）；**不要**让下游读 `outputs[]`。
- 任务是审计和对账依据，不能删除；**一个任务可以返回多份产物**（`TaskOutput[]`），**全部**进历史（用户确认，2026-10-15）。今天就有这种情况：豆包 Seedream 组图（`sequential_image_generation`，运营配在模型 `extra` 里）一个任务就返回多张，但现在回填只取第一张，其余被丢弃。
- 画布保存靠 `revision` 乐观锁；弹窗里设主图要像现在切版本一样走撤销栈（`history.record()`）。
- 前端格式化和 lint 只用 oxfmt / oxlint；测试放 `web/src/tests/`、`backend/internal/tests/`。

### 当前缺口

- 节点没有「一批任务」的概念：`taskId` 是单值，对账、取消、进度都按单任务。
- 回填不区分「本次第一张」和「后到的」：每次成功都会抢主图。
- 没有任何地方能把一个节点的全部结果并排看（现在是 58×30 缩略图）。

## 3. 用户与场景

- **用户**：在画布上编排 AI 图片 / 视频的创作者；经常一次出 2–4 张再挑一张接着做。
- **场景**：① 生成数量选 4，几秒内陆续出 4 张，挑一张接图生视频；② 对一张图不满意，原节点上再生成一次，想和上一次的结果并排比；③ 挑完后把另外几张也留在画布上做备选。
- **主任务**：生成 → 看到第一张 → 点徽标 → 在大格子里比 → 点中一张成为主图 → 关弹窗继续接线。
- **成功指标**：生成数量 4 时画布上只多 **0** 个节点；弹窗里一屏同时看到 ≥8 张（不需要滚动就能比较）；设主图 ≤2 次点击（徽标 → 点图）。

- **未发现需要引入的依赖。** 弹窗用已有的 `@base-ui/react` Dialog（灯箱就是它）；动画用 `motion`；网格用 CSS grid；不需要虚拟列表（每节点 ≤50 版，缩略图走已有的 `MediaPreview mode="thumb"` 懒加载）。

## 5. 设计原则

1. **一个节点就是一次创作意图**：同一个提示词 / 模型 / 参数产生的所有结果，住在同一个节点里。_依据：用户要求；Weave、FLORA 的做法。_
2. **主图是唯一对外的结果**：下游、预览、下载、画布缩略都读主图；挑选只是移动指针。_依据：现有 `src` 镜像机制。_
3. **先到先显示，后到不抢**：用户一旦开始看，不能被后到的结果顶掉。_依据：用户确认。_
4. **一个任务一份结果，一个任务一份钱**：失败只退自己那份。_依据：`编辑模型补齐设计.md` 已确认的计价规则，本次沿用。_
5. **按需出现**：徽标只在有多版本时出现；弹窗不占画布。_依据：`画布UI设计.md` 的「按需出现」原则。_
6. **一个入口**：删掉旧的缩略图条，不让两套 UI 做同一件事。_依据：用户确认「去掉」。_

## 6. 推荐方案

### 6.1 信息架构

```
节点（图片 / 视频）
 ├─ 右上角「多版本徽标」 3 ▾         ← 唯一的历史入口
 │    └─ 点击 → 「历史记录」弹窗（模态，居中）
 │         ├─ 网格：每张 = 一版；当前主图高亮 +「当前图片」
 │         │     ├─ 单击：设为主图（生成中且还没出第一张时禁用）
 │         │     └─ 悬停工具：放大 / 复制（仅图片）/ 下载 / 添加到画布
 │         ├─ 头部：全屏查看 ｜ ··· ｜ ×
 │         │     └─ ···：下载全部 / 全部添加到画布 / 取消剩余（有进行中任务时）
 │         ├─ 放大 → 灯箱（单图 + 缩略条，只看不改主图）
 │         └─ 全屏查看 → 全屏层（只有网格，不做列表模式）
 │               ├─ 顶部左：下载全部，全部添加到画布
 │               └─ 网格：单击 = 设为主图，主图带「主图」角标；悬停放大 → 灯箱（只看不改）
 └─ 功能区：不再有「历史」按钮（放大、下载保留）
```

### 6.2 多版本徽标

- **位置**：节点预览区右上角，距边 8px；黑色 70% 圆角胶囊，白字，`3` + chevron-down。不随选中显隐。
- **显示条件与数字**：数字是**预计总数** = `outputs.length` + 还在生成的任务数（`pendingTaskIds.length`，单任务生成中算 1），总数 ≥2 才显示。所以一提交 4 个任务、一张都没出，徽标就是「⟳ 4」；陆续出图时总数不变，不是只数已成功的；某个任务失败后它不再计入（积分已退回）。有进行中任务时数字旁加 12px 转圈。图片和视频节点才有。（_2026-10-15 用户反馈：生成时就要显示，并显示真实数量。_）
- **点击**：打开「历史记录」弹窗；`nodrag nopan`，不改变节点选中状态，不触发节点双击预览。
- **键盘**：可聚焦，Enter / Space 打开；`aria-label="历史记录，共 3 版"`。
- **单版本节点没有徽标，也就没有历史入口**（用户确认删掉功能区按钮的后果，可以接受）。

### 6.3 「历史记录」弹窗

- **容器**：`@base-ui/react` Dialog，居中，`min(1100px, 92vw)`，`rounded-2xl`，`bg-card`；遮罩沿用灯箱的 `bg-cover-scrim`。进入 / 退出沿用灯箱的 240ms / 170ms 淡入 + 0.96 缩放。
- **头部**：左「历史记录」+ 灰色计数 `3`；右「全屏查看」「···」，竖线分隔，「×」。
- **网格**：自适应列 `repeat(auto-fill, minmax(150px, 1fr))`，间距 10px，弹窗宽 `min(720px, 92vw)` 时一行 4 张（≤480px 屏宽时 2 张）；**格子要小，一屏能同时看到 ≥8 张**，细看靠「放大」。格子比例取**主图的画幅**（首次读到图片尺寸后固定；读到之前按 1:1），图用 `object-contain`、深色底。弹窗内容区最高 `min(520px, 85svh)`，超出纵向滚动；打开时滚动到主图所在行。_2026-10-15 用户看原型后反馈「图片太大」，从 2 列改为自适应小格子。_
- **排序**：**最新在前**（默认值，见 §11）；同一批内按完成先后。
- **格子状态**：

| 状态 | 表现 |
| --- | --- |
| 普通 | 1px 描边，hover 描边变亮 |
| 当前（主图） | 白色 2px 外框 + 左上渐变条「当前图片」（图标 + 文案） |
| 悬停 / 聚焦 | **右下角**出现一排 26px 图标按钮：放大、复制（视频无）、下载、添加到画布（放右下是为了不和左上角的「当前图片」挤在小格子里）。触屏设备常驻 |
| 生成中占位 | 最前面追加 `pendingTaskIds.length` 个骨架格 + 转圈 +「生成中」；完成后原地淡入替换成实图（`DURATION.base`） |
| 生成失败 | 占位格变成失败格：图标 + 失败原因 + 「积分已退回」，不可点；来自任务库，只显示最近一批；不入历史 |
| 图片加载失败 | 显示「加载失败」+ 重试，仍可设为主图（素材本身在后端） |

- **单击格子**：设为主图。
  - 已是主图：什么也不做。
  - 节点 `status === "running"`（本次第一张还没出，节点上还是占位）：**禁用**并给 tooltip「生成中，出第一张后可切换」。沿用现有「生成中不能切换版本」。
  - 其余：`history.record()` 后 `selectOutput`，节点主图即时变化（弹窗关着时也能看到），弹窗里「当前图片」标记用 `layoutId` 弹簧滑到新格子。⌘Z 可撤销。
- **键盘**：格子是 `button`，`aria-pressed` 表示主图；方向键在网格内移动焦点，Enter / Space 设主图，Esc 关闭弹窗。
- **「···」菜单**：下载全部、全部添加到画布；有进行中任务时多一项「取消剩余（k 个）」。

### 6.4 放大（单图）

- 复用 `MediaLightbox`，`items` = 这个节点的 `outputs`（`PreviewItem.id = output.id`），`target` 从被点的格子开始；`countLabel` = 「历史版本」。
- **只看不改**：翻页不改变主图（`onActiveChange` 只更新灯箱自己的位置）。
- 灯箱新增一个**可选**的底部按钮插槽：当前看的不是主图时出现「设为主图」，是主图时显示「主图」徽章。不传插槽时灯箱行为和今天一致。
- 关闭灯箱回到弹窗，弹窗不重新滚动。

### 6.5 全屏查看

- 黑底全屏层（`bg-black`），**不**用灯箱的模糊遮罩，方便比较。**只有网格，没有列表（单图）模式**（用户确认不做；要看大图点「放大」）。
- 顶部左：「下载全部」「全部添加到画布」；右：「×」。
- **网格**：自适应列（每格 ≥150px，全屏下约 6–8 列），格子 = 图 / 视频封面；单击 = 设为主图，主图带「主图」角标；悬停工具与弹窗里一致（放大、复制、下载、添加到画布）。
- **放大**（悬停图标或双击格子）：打开 §6.4 的灯箱，叠在全屏层上面；关闭灯箱回到全屏网格。
- Esc：灯箱开着先关灯箱；再按一次关闭全屏层，回到「历史记录」弹窗。

### 6.6 下载全部 / 全部添加到画布

- **下载全部**：逐个调用现有 `downloadMedia(src, downloadName(label, src))`，文件名带序号 `名称-1.png`。浏览器会拦截连续下载时，toast 提示「请允许本站下载多个文件」。进行中的任务不包含。
- **全部添加到画布**：每一版建一个新节点（`status: done`、`outputs: [output]`、`activeOutputId`，与现在「拖缩略图建节点」产出的节点相同，没有来源线），摆在**原节点右侧**，沿用 `duplicateNode` 的摆位算法（右侧起、每行 4 个、避开已有节点，抽成公共函数），新建的节点处于选中状态；整个动作是**一步撤销**。
  - 包含主图（用户点的是「全部」）；原节点的 `outputs` 不变，不会因为「添加到画布」而删掉版本。
  - 单张的「添加到画布」是同一个动作，只建一个节点。
  - 总数超过 8 个时先二次确认（避免一下子铺满画布）。
- 标签名：`原节点名 · 版本k`，k 为在 `outputs` 里的序号（从 1 起，旧的在前）。

### 6.7 生成流程（用户视角）

1. 选生成数量 4，点发送。**画布上不再多出节点**；节点进入生成中占位（和现在一个任务时一样），底栏积分按 4 个任务合计冻结。
2. 第一张完成：占位换成这张图，**它自动成为主图**；节点右上角出现「1 ⟳」徽标；弹窗里已有 3 个骨架格。
3. 后到的 3 张：陆续追加进历史，徽标数字 +1，**不改主图**；全部到齐徽标转圈消失。
4. 用户随时打开弹窗点任意一张设为主图。
5. 同一节点再点一次发送：和第 1 步一样，只是历史里已经有旧版本；本次第一张到达时主图切到新图，旧版本留在历史里。

### 6.8 节点上的状态

| 节点状态 | 条件 | 节点正文 | 徽标 | 重新生成按钮 |
| --- | --- | --- | --- | --- |
| 空 | 没有结果、没有任务 | 空占位 | 无 | 可用 |
| 生成中，还没出结果 | `status: running` | 生成中占位（原有） | 有历史时显示，无历史时无 | 禁用「生成中」 |
| 已出第一张，其余在跑 | `status: done` 且 `pendingTaskIds` 非空 | 主图 | 有，带转圈 | 禁用「生成中」 |
| 全部完成 | `pendingTaskIds` 为空 | 主图 | `outputs ≥ 2` 时有 | 可用 |
| 全部失败 | 所有任务终态且没有任何产物 | 失败态（原因 + 积分已退回 + 任务编号，原有） | 有历史时显示 | 可用 |
| 部分失败 | 有 ≥1 张成功、有 ≥1 个任务失败 | 主图（正常） | 有 | 可用；toast「有 k 张生成失败，积分已退回」（原因取第一个失败任务的文案） |
| 已取消 | 用户取消 | 有历史回到当前版本，没有回到空 | 同上 | 可用 |

## 7. 状态与异常

| 情形 | 行为 |
| --- | --- |
| 提交时请求本身失败（未登录、参数不合法、模型下线、网络） | 一个任务都没建：**节点不动**（不再像旧方案那样把 N 个节点都标成失败），错误就地显示在提示词面板里（与 N=1 一致） |
| 提交时部分任务失败（积分只够 K 个 / 并发已满） | 成功的 K 个任务进 `pendingTaskIds`；节点正常进入生成中；toast「有 (N−K) 张没能提交：积分不足」。失败的任务没有冻结，不用退 |
| 一个任务返回多张（如 Seedream 组图） | 全部进历史；第一张（本次最先到的）设为主图，其余只追加；返回里个别成员失败（只带 error、没有 url）跳过，不算整个任务失败；全部成员都不可用才按失败处理 |
| 某个任务生成失败 / 超时 | 该任务从 `pendingTaskIds` 移除，退自己的积分；其余照常；全部都失败才把节点标成失败态 |
| 用户取消 | 点节点上的取消 = 取消**本节点全部进行中任务**；弹窗「取消剩余」同理；已完成的结果保留 |
| 取消后部分已完成 | 保留已完成的，节点显示当前主图（若还没有主图则回到取消前的版本或空） |
| 刷新 / 重开画布 | `pendingTaskIds` 随画布保存；打开时收集所有 `pendingTaskIds`（不只 `status: running` 的节点）去对账；服务端没有这些任务时从集合里移除，空了且没产物 → 报「任务状态已失效，请重新生成」 |
| WebSocket 断线 | 沿用任务对账；回填幂等，重复推送不会重复追加 |
| 节点在生成中被删除 | 任务继续跑完（积分照扣）；结果因找不到节点被忽略（与现状一致）。**不新增**取消逻辑 |
| 撤销 / 重做 | `outputs`、`pendingTaskIds`、`taskId`、`status` 不被倒回；`activeOutputId` 被倒回（设主图是一步撤销）；「全部添加到画布」是一步 |
| 超过 `MAX_NODE_OUTPUTS` | 从最旧的丢引用；主图正好被丢时，主图改为最新一版（极端情况，不弹提示） |
| 保存冲突（revision） | 不新增处理；`outputs` / `pendingTaskIds` 与其他节点字段一样随整块 payload 保存 |
| 权限 | 不新增；任务和素材仍按 `user_id` 隔离，画布只读时（被锁）弹窗里「设为主图」「添加到画布」禁用，可看、可下载 |
| 老画布 | 只有 `taskId` 的运行中节点按原路径回填；没有 `outputs` 的老节点由 `readOutputs` 当成一版（已有行为） |

## 8. 数据与工程影响

### 8.1 前端数据（提案）

| 字段 | 位置 | 含义 |
| --- | --- | --- |
| `pendingTaskIds?: string[]` | `CanvasNodeData` | **本节点进行中的任务 id 集合**（N≥2 的一次提交才写；单个任务仍只用 `taskId`）。任务到达终态时回填把它从集合里移除，空了就删掉这个字段 |
| `taskId` | 不变 | 一次提交里**第一个成功建出的任务**的 id，保持原语义（进度、重试、追溯、对账兼容、Agent 绑定都用它） |
| `outputs[]`、`activeOutputId`、`src / mediaType / assetId` | 不变 | 复用 |
| `MAX_NODE_OUTPUTS` | 常量 | 20 → **50**（生成数量最多 8，连点几次就会超过 20） |

不新增后端表、字段、接口。`pendingTaskIds` 写进 `payload_json`，后端不校验节点字段（`canvas_project.go:88-92`）。`canvas-persistence.ts` 要加上这个字段的序列化；`canvasgraph/catalog.go` 的 `hiddenData` 要加上它，避免 Agent 看到。

### 8.2 回填规则（提案）

`planBackfill(data, view)` 的匹配条件从「`data.taskId === view.id`」扩成「`data.taskId === view.id` **或** `data.pendingTaskIds` 包含 `view.id`」。对**成功**的任务，**取全部产物**（不再只取第一份）：

```
taskKey = String(view.id)
outs    = view.outputs 里 url 和 asset_id 都有的那些，按原顺序      // 缺 url / asset_id 的成员跳过
if outs 为空：按失败处理（与现状同文案「生成结果为空，请重试」）
patch = { pendingTaskIds: without(data.pendingTaskIds, taskKey) }     // 空则删字段
fresh = outs 里还不在 outputs 中的                                    // 幂等：重复推送、重复对账
if fresh 为空：return patch
if data.status == "running":                  // 本次还没有任何一张落下来
    // 这个任务的第一张设为主图，其余的只追加
    return { ...patch, status: "done", ...appendOutputs(data, fresh, { activeIsFirst: true }) }
else:                                         // 已经有本次的第一张
    return { ...patch, ...appendOutputs(data, fresh, { activeIsFirst: false }) }  // 不动 activeOutputId / src 镜像
```

失败 / 过期的批次任务：移除出 `pendingTaskIds`；若此时 `pendingTaskIds` 空且 `status === "running"`（一张都没成功）→ `status: error`（现有文案与 `errorTaskRef`）；否则保持 `done`，并通过回填事件让 `use-task-backfill.ts` 弹 toast。
取消：移除；空了且 `status === "running"` → 走现有 canceled 分支（回到当前版本或 idle）。

`appendOutputs(data, list, { activeIsFirst })` 放在 `utils/canvas/outputs.ts`：一次追加多版（`NodeOutput.taskId` 都是同一个任务），`activeIsFirst` 为真时把第一版设为主图并刷新镜像，否则不动主图；同样受 `MAX_NODE_OUTPUTS` 限制、同一素材不重复。原 `appendOutput` 保留给单张的旧路径，或改成对它的单元素封装。

### 8.3 提交（提案）

`use-task-generation.ts`：

- **删除** `fanOut`（复制节点）与 `markFailed` 对副本节点的写入。
- N≥2：`node_ids = Array(N).fill(nodeId)`，一次请求；**按下标**而不是按 `node_id` 对应响应项（`items.find(entry => entry.node_id === id)` 在 id 重复时会全部命中第一项）。
- 成功的任务 id 列表 → `buildSubmittedPatch` 写 `taskId = 第一个`、`pendingTaskIds = 全部成功的`、`status: running`、清 `src`。只有 1 个成功时不写 `pendingTaskIds`，与 N=1 完全一致。
- 全部失败：节点不动，错误交回调用方就地提示。

`use-task-node.ts`：`running` 改为「`status === running` 或 `pendingTaskIds` 非空」，用于禁用生成按钮和取消按钮；`cancel` 取消 `pendingTaskIds`（没有则取消 `taskId`）。价格展示、`fanoutCount` 不变。

`utils/tasks/reconcile.ts`：`collectRunningTaskIds` 增加 `pendingTaskIds` 的收集（不要求 `status: running`）。

### 8.6 实现难点

1. **回填的幂等与「先到先显示」要靠 `status === "running"` 判断**，所以任何地方不能在第一张到达前把 `status` 改成 `done`（比如「设主图」「撤销」）；`history.ts` 的 `TASK_FIELDS` 要加上 `pendingTaskIds`，否则撤销会把它倒回去。
2. **回填要从「取第一份」改成「取全部」**：`backfill.ts` 里的 `firstOutput`、`status.ts` 的 `firstOutput` 要换成遍历；文本节点（`script`）仍只取正文，不受影响。一个任务返回 k 张时历史一次 +k，徽标数字也 +k；`MAX_NODE_OUTPUTS` 照常生效。对话页的 `record-view.tsx` 本来就按多产物渲染，不用改。
3. **同一素材重复**：上游极端情况下两个任务返回相同素材 id，`appendOutput` 去重后历史里只有一份，徽标数字会比 N 小，属于预期。
4. 视频的格子只显示封面，不挂载 `<video>`（沿用 `VideoPoster`），全屏网格也一样，避免同屏多个解码器。

## 9. 方案取舍

| | 方案 A：归并 + 弹窗（推荐） | 方案 B：仍复制 N 个节点，加「合并」按钮 | 方案 C：1 个任务出 N 张 |
| --- | --- | --- | --- |
| 画布整洁度 | 好 | 差 | 好 |
| 后端改动 | 近 0（补测试） | 0 | 大：每个插件都要支持一次出 N 张；计价、退款变成全有或全无 |
| 前端改动 | 中 | 小 | 小（`taskId` 仍单值） |
| 与既有设计一致 | 推翻「N 个节点」，保留「N 个任务」 | 一致 | 推翻「各自结算」 |
| 部分失败 | 只退失败那份 | 同 A | 整体失败 |

**放弃的东西**：
- 方案 C（一个任务出 N 张）：用户在访谈中选择了「仍拆 N 个任务」。
- 「批次」概念（新建 batch 表）：工作量最大、本期不需要。
- 节点内展开（Weave 式）：会撑大节点、挤占相邻节点，画布布局抖动。
- 弹窗里的「删除某一版」：用户未选，`outputs` 仍然只能靠超出上限丢最旧的。
- 拖缩略图到画布建节点：随旧缩略图条下线，由「添加到画布」按钮取代。

## 11. 待确认问题与已确认事项

### 已确认（用户的回答，2026-10-15）

1. **后端仍拆 N 个任务，都绑同一节点**（推荐项）。
2. **先到先显示，本次第一张自动成主图**；后到的只追加进历史，不抢主图。
3. **历史记录弹窗里单击一张直接设为主图；另有放大按钮**（放大只看不改）。用户最初的说法是「放大之后选中什么就设为主图」，这里的「放大」指的是点徽标把节点放大成弹窗。
4. **本期覆盖图片 + 视频节点**。
5. **附加功能做：全屏网格视图、下载全部、全部添加到画布**；不做「删除某一版」。
6. **去掉功能区里的「历史」按钮**（点开是一排小缩略图的那个），只保留节点右上角的徽标。
7. **插件一个任务返回多张图时，全部进历史**（2026-10-15）。第一张设为主图（本次最先到的），其余只追加。
8. **全屏查看只做网格，不做列表（单图）模式**（2026-10-15）。要看大图点「放大」，走灯箱。
9. **旧方案已经复制出来的「兄弟节点」不做合并迁移，保持原样**（2026-10-15，推荐项）。老画布数据不动；用户需要的话自己删。

### 已搁置的决定

- 方案 C「一个任务出 N 张」作为**生成数量的实现方式**：2026-10-15 调研（见 §12）显示 OpenAI（`n` 1–10）、阿里万相（`n` 1–4）能一次出多张，Seedream 靠组图，Gemini 图片和所有视频插件不行；用户决定先不改，一期仍拆 N 个任务。以后若要做，作为模型能力开关（每个模型声明「拆任务」还是「原生多张」），需要后端补「按实际张数结算」。一期的回填已经能处理一个任务多张（见已确认 7），所以不需要再改节点数据。
- 「批次」表：若以后需要按批次统计 / 展示，再加。

### 默认值（不需要用户决定，实现时按此做；有异议再改）

- 历史排序：最新在前。
- `MAX_NODE_OUTPUTS`：20 → 50。
- 格子比例取主图画幅，图片 `object-contain`。
- 灯箱里有「设为主图」按钮；翻页不改主图。
- 取消 = 取消本节点全部进行中任务。
- 部分失败用 toast 说明，不在历史里留失败格。
- 「全部添加到画布」含主图，>8 个先确认，摆位沿用复制节点的算法，不接任何连线。
- 只有 1 版的节点没有徽标，也就没有历史入口（用户删功能区按钮的后果）。
- 下游节点只读主图，不读 `outputs[]`。
- Agent 助手生成媒体时仍固定 1 张、仍各建节点，本期不动。
