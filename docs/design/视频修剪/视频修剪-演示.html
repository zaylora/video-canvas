视频修剪 演示

视频节点「视频修剪」：拖两端、点 ✓，右边长出一个剪好的新节点

选中视频节点，点功能区「视频修剪」，在节点下方拖两端手柄选出要保留的片段，点 ✓ 后在浏览器里编码，产出一个新的「剪辑」视频节点。 原节点原样保留；不扣积分；后端不改。第一版只做去音轨，不做循环预览和快捷键面板。

阅读说明。本页对应 Markdown 设计文档 视频修剪.md 的 §1、§4、§6、§9。设计尚未实现；原型里的缩略图、编码耗时、体积都是示意，编码是模拟的。参考图来自用户给的 5 张截图。

设计：整条链路都在前端——和用户参考图里"先编码、再上传"的顺序一致。修剪模式照扩图模式做（独立状态 + 取代功能区和生成面板），新节点摆放和上传都复用现成代码，不新造。
出问题时（回退）：浏览器不支持、读不到视频、编码失败，都不会改动原节点；编码失败会回到可编辑状态并保留手柄位置，可直接重试。

三种做法

差别在"谁来剪"，它决定了要不要动后端、产出的是什么。

浏览器里剪
采用

Mediabunny（WebCodecs）重新编码。产出一个新 MP4 文件，走现有上传。后端零改动。

后端 ffmpeg 剪
放弃

要装 ffmpeg、新增接口和任务队列。违背"后端只做存储"，还多一次上传 + 等待。

只记入点 / 出点
放弃

不产出新文件。下游生成、下载都要理解裁切元数据，改动面最大。

用户点 ✓ 之后，会发生什么

编码要跑一段时间；用户已确认：这段时间面板锁定，不能随手退出。

  1. 手柄锁定，✓ 变成转圈面板下方出现细进度条和「编码中 12%」
  2. 编码完成（100%）右侧立刻长出「剪辑」节点和连线，面板退出
  3. 新节点显示「上传中 x%」传完变成可播放的视频；失败显示「上传失败，请重试」
  4. 撤销一次新节点和连线一起消失，原节点不变
边界：编码中取消选中、按 Esc 都不会退出
  • 只有 × 能中止，并且要二次确认。
  • 取消选中后面板收起、编码继续，源节点标题行显示「编码中 x%」，再选中面板回来。
  • 刷新页面会丢掉编码中的任务（与现在上传中刷新一致）。
  • 同一时刻只允许一个修剪会话。

对象存储已配置 CORS（用户确认），不用再告知；Range 相关响应头是否放行，实现时用真实桶实测一次（未验证）。

可点击原型

数据在内存里，刷新复原。已放好一个 29 秒的视频节点，点它 → 点功能区「视频修剪」，拖两端手柄，点 ✓ 走完整流程。选中「剪辑」节点可以看到它下方没有提示词框。想看失败：勾上方「存储没开跨域」再点 ✓（编码到 60% 时失败）。编码、上传都是模拟，耗时为示意。

video-canvas / 画布 / 视频修剪原型
设计：面板取代了平时的功能区和生成面板（和扩图一致）；去掉了参考图里的键盘图标和循环图标（用户确认第一版只保留去音轨）；✓ 在"没修剪"或"选区太短"时禁用而不是隐藏，并写明原因。
原型里能试的东西
  • 拖两端手柄（或聚焦后按 ← / →，Shift 加速）；最小间隔 0.5s，拖到极限会停住。
  • 点播放：从入点播到出点自动停。条上点空白处：在选区内定位。
  • 点 × 退出；编码中点 ×，会先问「中止编码？」。Esc 在编辑态退出，编码中无效。
  • 编码中点画布空白处：面板收起、编码继续，点回源节点面板回来。
  • 画布左下「撤销」：删掉最近建的「剪辑」节点和连线。

// utils/canvas/trim-run.ts（提案；Mediabunny API 名以安装版本为准，未验证）
async function runTrim(id, { src, start, end, muted, fileName }, hooks) {
  const { Input, Output, UrlSource, Mp4OutputFormat, BufferTarget, Conversion, ALL_FORMATS } =
    await import("mediabunny"); // 动态加载，进入修剪模式时才下载
  const input = new Input({ source: new UrlSource(trimUrl(src)), formats: ALL_FORMATS });
  const output = new Output({ format: new Mp4OutputFormat(), target: new BufferTarget() });
  const conversion = await Conversion.init({
    input, output, trim: { start, end },
    audio: muted ? { discard: true } : undefined,
  });
  if (!conversion.isValid) throw new TrimError(reasonOf(conversion.discardedTracks));
  sessions.set(id, { cancel: () => conversion.cancel() });
  conversion.onProgress = (p) => hooks.progress(Math.floor(p * 100));
  await conversion.execute();
  return new File([output.target.buffer], fileName, { type: "video/mp4" });
}

// 点 ✓：先拦、再编码、成功后建节点并交给 uploadRunner
if (estimatedSize(source, start, end) > UPLOAD_SIZE_LIMIT.video) return showError("预计超过 200MB…");
const file = await runTrim(id, params, hooks);          // 失败 → 回 editing

已确认的决定

  1. 引用 Mediabunny：浏览器内剪辑；放弃 ffmpeg.wasm（core 约 31MB、COOP/COEP 副作用）和 MediaRecorder 自研。
  2. 面板第一版只做「去音轨」：循环预览、键盘快捷键说明面板都留到后续；两端手柄、时长标签、×、✓ 默认都做。
  3. 编码期间面板锁定到编码完：取消选中和 Esc 不退出，只有 × 能中止。「点确认立刻建节点、后台编码」和「可收起面板」两个方案已搁置，将来要支持连续剪多段时可启用。
  4. 对象存储已配置 CORS：对象存储里的素材可直接读取来修剪；Range 头仍在实现时实测。
  5. 新节点标题用「剪辑」，重名「剪辑 2」。
  6. 剪辑节点下方没有提示词框，和扩图出来的节点一样：它是上传素材（uploaded: true），选中后只出功能区。现有代码已满足，不用为此改动。
  7. 主文档已回写：以上全部在 Markdown §6.5、§11；截取帧分支合并后取流地址函数怎么合并，写在 §11 默认值里，不影响本次实现。
