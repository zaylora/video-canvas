Agent 运行观测

让 AI 读懂线上每一次 Agent 运行，再反过来改 Harness

线上每次 Agent 运行都会被完整记下：用户要什么、Agent 想了什么、调了哪些工具（参数和结果）、改了画布哪里、用户有没有撤销或点踩。你在仓库里跑一条 /agent-review，Claude Code 或 Codex 就会拉取这些记录、逐条判断“需求有没有完成”，再按失败类别排序，指出该改提示词、工具还是技能。 分析全在本地按需运行，线上只提供只读数据，不调用模型、不花额度；完整轨迹保留 30 天，摘要和反馈长期保留。

阅读说明。 “项目现状”来自 2026-10-21 master 分支的代码；外部方案来自检索调研。本文所有新增表、接口、CLI、skill 都是提案，尚未实现。原型和演示里的运行数据都是示意。完整依据见 Agent运行观测.md。

今天已经有什么、缺什么

先说清楚哪些数据现在就有、只是看不到，哪些是这次要补的。

已经落库已核对项目代码
  • agent_events：用户消息、Agent 回复、工具开始和结束（只有摘要）、审批、计划、状态
  • agent_mutations：每次画布改动，以及是否被撤销
  • agent_model_calls：每次模型调用的 token 和错误
  • agent_approvals：批准、拒绝，以及“拒绝并说明”
  • 插话（steer）、停止、步数或预算耗尽都有记录
缺口已核对项目代码
  • 后台没有任何地方能看 Agent 运行，AI 也拿不到数据
  • 工具的参数和完整结果只在会被压缩覆盖的 session_jsonl 里
  • 运行没记录Harness 版本（提示词 v9 只在代码里），无法按版本对比
  • 没有点赞或点踩；撤销本轮不产生事件
  • 模型调用没有耗时和 stop_reason；Node 的诊断信息会丢失

主线：一次线上运行怎么变成一条改进

从用户在画布上用 Agent，到你改完 Harness 再验证，一共五步，形成一个闭环。

① 线上采集补齐工具参数和结果、Harness 版本、运行摘要、👍/👎
② 只读导出/admin/agent/runs*，分析令牌只读、会过期、每次拉取都审计
③ 本地拉取agent-trace pull：每次运行一份 Markdown，AI 按顺序读
④ AI 判定与归类/agent-review：逐条判定 → 失败分类 → 定位到代码 → 报告
⑤ 改完再对比发版后用 agent-trace compare 按 Harness 版本看指标
设计：线上只负责“记全、给读”，判断交给本地 AI。这样线上不新增服务，不花模型额度，分析方法也能随 skill 迭代而不必发版。放弃了 Langfuse 这类现成 UI 和标注队列，换来零运维和贴合 AI 的导出格式。
回退和兜底：采集任何一步写库失败，都只打一条 Warn 日志，不影响用户的运行，导出里该步显示“未记录参数”。超过 30 天的运行，工具参数和结果显示“已过保留期”，但摘要、反馈和 Harness 版本仍在，版本对比不受影响。令牌失效时 CLI 明确提示去后台重新签发。

发版后想知道“新提示词有没有变好”时，会发生什么

这是最典型的一次闭环，你在本地仓库里完成。

  1. 改 system.md，把 prompts.Version 改成 10，然后发版新运行自动带上 prompt_version=10，harness_key 也随之变化
  2. 等线上积累一周数据用户照常使用，有人点 👎，有人撤销
  3. 跑 /agent-review --since 7d拉取 60 条（点踩、撤销、失败的优先），AI 逐条判定，写入 verdicts.jsonl
  4. 跑 agent-trace compare --by prompt_versionv9 和 v10 的点踩率、撤销率、失败结束率、AI 判定失败率并排列出
  5. 看报告里排名靠前的失败类别每类附 2–3 个样本运行和建议改动的文件，再进入下一轮
边界：样本少于 30 的版本，不下“变好或变坏”的结论
  • CLI 只显示数值并标注“样本不足”
  • 点踩率的分母是“有反馈的运行”，反馈率低时波动大，要和撤销率、AI 判定一起看
  • AI 判定失败率只来自你本地已判定的运行，换一台机器需要重新判定
  • 同一次发版里如果同时改了工具声明，tools_hash 也会变，按 harness_key 分组看更准确

需要提前说清：导出的是用户原文，会落到你本机的 .traces/（已加入 gitignore），并发送给 Claude 或 Codex。用户协议里是否补一句“对话用于改进服务”，由你决定（待确认）。

关系

所有新数据都挂在已有的运行（run）上，运行本身就是一条 trace。

对象挂在哪为什么
工具调用agent_tool_calls.run_id，唯一键 (run_id, tool_call_id)和 tool.start / tool.end 事件一一对应；脚本子调用用 parent_id 关联
运行摘要agent_run_digests.run_id（主键）一次运行对应一行，长期保留，版本对比和列表只查这张表
用户反馈agent_feedback，唯一键 (run_id, user_id)每个运行每人只有一条，改选就是覆盖
Harness 版本agent_runs 新字段，摘要里冗余一份运行创建时就确定，续跑也不变
trace_id直接使用 run_id不另造 ID；桥的访问日志带 run_id，由 Go 从桥令牌解析（不靠 Node 自报）
分析令牌admin_api_tokens.created_by 指向签发人签发人降权后令牌立即失效

接口

/admin/agent/runs* 和 /admin/agent/stats 用新中间件 AdminOrAnalysisToken：先认 vca_ 令牌，认不出就退回 JWT + RequireAdmin。令牌管理接口只接受 JWT。

方法与路径说明业务错误
PUT /agent/runs/:rid/feedback用户端。body 为 {rating, reasons?, comment?}；写事件 feedback.set，并更新摘要ErrAgentRunMissing（60012，别人的运行也返回它）· ErrAgentRunNotEnded（60014）· 参数错误
DELETE /agent/runs/:rid/feedback取消反馈，幂等ErrAgentRunMissing（60012）
GET /admin/agent/runs摘要列表。参数：since、until、status、feedback、undone、harness_key、prompt_version、model_key、user_id、cursor、limit（≤ 500）参数错误
GET /admin/agent/runs/:rid详情：digest、events、tool_calls、model_calls、mutations、approvals、feedback，以及前 2 轮上下文ErrAgentRunMissing（60012）
GET /admin/agent/runs/:rid/export?format=md|json|bothAI 可读导出；md 返回 {format, content}，json 直接返回结构化对象，both 返回 {format, content, data}（本地 CLI 一次请求拿全）；Markdown 每段截到 2KB，JSON 里工具结果最长 32KBErrAgentRunMissing（60012）
GET /admin/agent/stats按 harness_key、prompt_version 或 model_key 分组聚合参数错误
GET/POST /admin/agent/tokens
DELETE /admin/agent/tokens/:id		令牌列表、签发（明文只返回一次）、注销；均写审计有效期超过 90 天
导出边界：原样导出用户原文，但渠道 Key 仍是 ***，不含图片签名 URL（与 session_jsonl 的规则一致），用户只给出 id 和用户名。用令牌访问时每次列表、导出都写一条 admin_audit_logs（管理员自己看不写）；每个令牌限流每分钟 120 次。

// 中间件 AdminOrAnalysisToken
if strings.HasPrefix(bearer, "vca_") {

  rateLimit(t.ID, 60/min); audit(t, c.Request.URL.Query()); touch(t.LastUsedAt)
} else { JWTAuth → RequireAdmin }

已确认的决定

  1. 第一读者是 AI，人为辅：一期先做导出、CLI 和 skill，后台只做最简的令牌页，运行列表和详情放二期。
  2. 自研，复用现有 PostgreSQL：不引入 Langfuse、Phoenix 或 OTel SDK，字段按 gen_ai.* 命名，为以后迁移留出口。
  3. AI 读数据的方式：本地 CLI 拉成文件，再配分析 skill：Claude Code 和 Codex 通用，可以离线反复读。
  4. 失败信号：点赞点踩 + AI 全量判定：撤销、拒绝、插话只作为导出字段供 AI 参考，不另建打标系统。
  5. 隐私：原样导出：Key 和图片签名 URL 仍按现有规则不出现。
  6. 按需手动分析：线上不调用模型做判定（每日自动 judge 已搁置）。
  7. 按 Harness 版本对比指标：不建离线回归评测（已搁置，需要回放环境）。
  8. 保留期：完整轨迹 30 天，摘要和反馈长期保留。
  9. 主文档已同步：本页的数字和决定与 Agent运行观测.md 第 6、8、11 节一致，本页没有新增决定。
