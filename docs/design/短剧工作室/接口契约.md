# 短剧工作室一期 · 前后端接口契约

> 前后端并行开发的唯一约定。设计依据见同目录 `短剧工作室.md`（§6、§7、§8、§10 一期、§13）与 `短剧工作室原型.html`。
> 改契约必须两边同时知道：谁需要改，在本文件末尾「变更记录」追加一行，不要静默改。

## 1. 通用约定

- 所有接口在 `/api/v1` 已登录分组，响应外壳沿用 `pkg/response`（`{code, msg, data}`），按 `user_id` 隔离；别人的资源一律按「不存在」处理。
- 短剧、任务的 ID：`idcodec.ID`，JSON 里是**十六进制字符串**（同角色卡）。画布 ID 用现有画布接口的对外编码。
- 集用**集号** `no`（从 1 开始的整数）定位，不对外暴露集的行 ID。
- 字段 snake_case；前端在 `web/src/api/drama/index.ts` 里 map 成 camelCase。
- 时间是 ISO 字符串。
- 文本模型用和 `GET /models?kind=text` 返回项里**同一个标识字段**（前端节点 `data.model` 存的那个模型 key）；下文记作 `text_model`，空串表示「跟随后台『文本』类别第一个启用模型」。

### 3.1 规则（后端强制）

- `POST /dramas`：原文提取为纯文本后 1–300,000 字；docx 只取正文段落文本。成功后 `status = analyzing`，排队 `analyze`；`analyze` 成功自动接 `outline`。
  - 原文已带分集标记（如「第1集」「第一集」）时：`outline` 直接把各集原文整理进 `script_md`，`script_status = ready`，不再需要 `scripts`。
- 同一部短剧同时只能有一个 `queued / running` 的流水线任务 → 否则 67004。
- 前置：`scripts` 需要已有集；`breakdown` 需要所选集 `script_status = ready` 且未锁定；不满足 → 67006。
- `breakdown` 成功后：所选集 `locked = true`；按 §4 写入短剧画布；自动接 `asset_prompts`（只为本次新建的资产写提示词）。
- 锁定集的 `PATCH` 改 `script_md` / `synopsis` → 67005（改 `title` 允许）。
- 模型输出 JSON 校验不过：同一请求自动重试 1 次；仍失败 → 任务 `failed`、`error_code = 67008`、**不扣积分**。
- 文本模型解析：`text_model` 非空且仍启用 → 用它；否则用「文本」类别第一个启用模型；一个都没有 → 67007。

## 4. 短剧画布节点（后端写入，前端读取）

拆解结果写进 `canvas_id` 对应画布的 `payload_json`，走画布现有的 `revision` 乐观锁，写完推 `canvas.patch`（与 Agent 写画布同一路径、同一事件格式）。节点结构与前端 `PersistedCanvasNodeDto` 一致，额外字段：

```json
{
  "id": "n_xxx",
  "type": "canvas",
  "position": { "x": 0, "y": 0 },
  "data": {
    "kind": "character",                 // character | image
    "label": "林川 · 童年",
    "characterId": "3c1d",               // 仅 character：指向 §5 的角色卡
    "labelCache": { "name": "林川" },     // 仅 character
    "params": { "prompt": "…资产提示词…" }, // asset_prompts 写入；拆解刚完成时可以没有
    "drama": {
      "type": "character",               // character | scene | prop
      "name": "林川",                     // 资产名，合并与 @ 候选用
      "look": "童年",                     // 造型 / 变体名，可空串
      "episodes": [1, 2]                 // [] = 全集
    }
  }
}
```

- 场景、道具：`kind = image`，`drama.type = scene | prop`。
- 合并规则：同 `drama.type` 下 `name + look` 相同（忽略大小写和首尾空格），或命中模型给出的别名 → 视为同一资产，只把新集号并进 `drama.episodes`，不新建。
- 节点摆放：按类型分行（角色一行、场景一行、道具一行），新节点追加在该行末尾，不压到已有节点。
- 没有 `drama` 字段的节点 = 未分类，后端不碰。

## 5. 角色卡改动

- `character_cards` 增加：`drama_id`（可空，指向短剧）、`look_name`（≤ 64 字，默认空串）、`voice_prompt`（音色描述，≤ 500 字，默认空串）。
- **去掉** 名称唯一索引（66001 不再触发，常量保留）；`avatar_asset_id` 改为可空。
- `CharacterView` 增加 `drama_id`（字符串，可空）、`look_name`、`voice_prompt`；`avatar` 为 null 时含义改为「没有形象或素材已不可用」。
- `GET /characters` 默认只返回 `drama_id` 为空的卡；`?ids=` 批量读取不受此限（画布节点要读短剧角色）。
- `PATCH /characters/:id` 支持改 `avatar_asset_id`、`look_name`、`voice_prompt`（短剧里生成形象后由前端写回主图）。
- 删短剧时连带删它的角色卡。

## 6. 画布

- `canvas_projects` 增加 `drama_id`（可空）。画布列表、首页最近画布、画布导出都排除 `drama_id` 非空的行。
- 短剧画布可以照常用 `GET / PUT /canvas/:id` 读写、生成任务照常用 `POST /generation-tasks`。

## 7. WebSocket

- 新事件 `drama.job`：`{ "drama_id": "1a2b", "job": JobView }`，任务状态或进度变化时推（进度至少每 10% 推一次）。
- 任务结束时，若改了集或项目数据，前端收到 `succeeded` 后自行重新拉 `GET /dramas/:id`。

# 二期：分镜脚本与片段工作区

> 设计依据：`短剧工作室.md` §6.2 第 7–8 步、§6.3「分集视频页」「片段工作区」、§8.1 `drama_segments`、§10 二期、§13；原型 `短剧工作室原型.html` 的「分集」与片段工作区。一期接口全部沿用。

## 9. 新增视图

### 9.1 `EpisodeSummary` 增加字段

```json
{
  "storyboard_status": "ready",   // empty | generating | ready | failed
  "segment_count": 4,
  "segment_seconds": 50,          // 各片段时长之和
  "done_segment_count": 1         // 有「采用」视频的片段数
}
```

### 9.2 `SegmentView`

```json
{
  "id": "5d2a",                    // idcodec 十六进制
  "episode_no": 1,
  "seq": 0,                        // 从 0 开始，按它排序
  "seconds": 12,
  "prompt": "本片段场景设定在 @[山村街道](n_abc)。分镜 1（8s）：…",  // @[名](短剧画布节点 id)
  "shots": [ { "seconds": 8, "shot_size": "全景", "camera": "平视固定", "action": "…", "dialogue": "" } ],
  "keyframe": null,                // AssetView | null：首帧图；有则生成视频走 i2v
  "takes": [                       // 本片段的视频生成结果，按创建时间正序
    { "task_id": "123", "status": "succeeded", "asset": { /* AssetView */ }, "error_message": "", "created_at": "…" }
  ],
  "chosen_task_id": "123",         // 采用的那一条；"" = 没有
  "status": "done",                // idle | running | done | error（由最近一条 take 推出）
  "revision": 1,
  "updated_at": "…"
}
```

- `takes` 由后端按 `generation_tasks.node_id = "seg:{片段id}"` 查出来（同首页对话 `rec:` 的做法），不另存一份结果。
- 首帧图的生成任务 `node_id = "segkf:{片段id}"`，成功后后端把产物写进 `keyframe`（最新一张成功的为准）。
- `status`：最近一条 take 是 `pending/queued/running/finalizing` → `running`；`failed` → `error`；有 `chosen_task_id` 或有成功的 take → `done`；否则 `idle`。
- 第一条成功的 take 自动成为 `chosen_task_id`（之前没有采用时）。

## 10. 新增接口

| 方法与路径 | 请求 | 成功响应 | 业务错误 |
| --- | --- | --- | --- |
| `POST /dramas/:id/jobs` 新步骤 `storyboard` | `{step: "storyboard", episodes: [n], max_seconds: 15}`；`max_seconds` 取前端所选视频模型的时长上限，缺省 15，范围 4–60 | `JobView`（202） | 67004、67006（该集未拆解 / 剧本未就绪）、67007 |
| `GET /dramas/:id/episodes/:no/segments` | — | `{items: SegmentView[]}`，按 `seq` | 67001 |
| `POST /dramas/:id/episodes/:no/segments` | `{prompt?, seconds?, after_seq?}`；不传 `after_seq` 追加到末尾 | `SegmentView`（201） | 67001 |
| `PATCH /drama-segments/:sid` | `{revision, prompt?, seconds?, chosen_task_id?}`；`chosen_task_id` 必须是本片段某条成功的 take | `SegmentView` | 67009、67011、409 |
| `DELETE /drama-segments/:sid` | — | 204 | 67009 |
| `PUT /dramas/:id/episodes/:no/segments/order` | `{ids: [...]}`，必须恰好是该集全部片段 | `{items: SegmentView[]}` | 67009、67012 |
| `POST /drama-segments/:sid/generate` | `{model_id, input}`；`input` 与现有 `POST /generation-tasks` 的 `input` 完全同构（前端已把 `@` 引用解析成参考图 / 参考音频 URL 或素材，按模型 capabilities 组装）；`kind` 固定 `video` | `{task: TaskView}`（202） | 67009；其余沿用生成任务的现有错误（模型不可用、参数校验、积分不足等） |
| `POST /drama-segments/:sid/keyframe` | `{model_id, input}`，`kind` 固定 `image` | `{task: TaskView}`（202） | 同上 |

- `generate` / `keyframe` 在服务端调用现有生成任务创建逻辑：`canvas_id` = 短剧画布，`node_id` = `seg:{sid}` / `segkf:{sid}`，幂等键沿用请求头 `Idempotency-Key`。
- 删除片段不删生成任务和素材。
- 重新生成某集的分镜脚本（`storyboard` 再跑一次）会**替换**该集全部片段；如果该集已有任何 take，返回 67013，前端需先确认（二期前端提示「会清空已有片段」，确认后先逐个删片段再重跑）。

### 10.1 `storyboard` 步骤规则

- 输入：该集 `script_md`、该集出现的资产（短剧画布上 `data.drama` 命中该集或全集的节点：节点 id、类型、名称、造型、提示词摘要）、`max_seconds`、项目比例与画风。
- 输出（JSON 校验）：`segments[]`，每段 `seconds ≤ max_seconds`，`shots[].seconds` 之和 = `seconds`；`prompt` 里 `@[名](节点id)` 的节点 id 必须在输入的资产列表里（不在的去掉 `@` 只留名字，不算失败）。
- 成功：写 `drama_segments`，集 `storyboard_status = ready`；失败沿用 67008 与不扣费规则。

## 11. WebSocket

- 新事件 `drama.segment`：`{ "drama_id": "1a2b", "episode_no": 1, "segment": SegmentView }`，片段被改、take 状态变化、首帧写入时推。
- 片段的生成任务本身照常推 `task.status`（`node_id` 带 `seg:` / `segkf:` 前缀）；前端可以只依赖 `drama.segment`。

## 13. 前端资产引用解析（只在前端，写在这里供后端理解 input 来源）

- 提示词 `@[名](节点id)` → 节点：`character` 节点经角色卡展开为主图 + 补充图（参考图）与声音（参考音频）；`image` 节点取当前素材；没图的资产只保留文字。
- 按所选视频模型 `refs` 上限截断，超出时提示；模型不收参考音频时只用图片并提示「声音未生效」。
- 有首帧且模型支持 `i2v` 时用 `i2v`，否则 `omni`（或模型支持的参考方式）。
