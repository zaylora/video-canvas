# 短剧开拍设置与长篇按章制作

> - **范围**：短剧工作室「上传剧本 / 粘贴正文」之后弹出的「开拍设置」弹窗（来源识别、规划范围、画幅、题材画风、单集时长、模型、四个环节的提示词方案），以及为支撑 500 万字长篇而做的流水线调整：按章节存原文、抽样研读、分批规划（读完整原文，自动）、单集剧本只读对应原文（用户选集）、已登记角色名单、自动规划与用户操作并行、自定义提示词与技能注入。不含：用户自传技能、提示词版本历史、多人协作、视频环节的自动批量。
> - **日期与状态**：2026-11-04，**已确认待实现**（v2）。
> - **证据约定**：**事实**附仓库文件路径或外部链接；**推断**是基于事实的判断；**提案**是尚未实现的设计。
> - **方案演进**：
>   1. 初版只加一个设置弹窗。
>   2. 用户补充「字数上限改 500 万」「LLM 一次读完整本小说会读不出后面」→ 加入长篇按章制作（参考 open-ai-canvas）。

>   4. 用户审阅中追加：规划读本批完整原文、已登记角色名单、剧本逐集串行、集上存钩子 / 悬念、去掉目标集数改显示预估；自查发现的 12 个问题已并入（§11.1 第 14–22 条）。

## 1. 设计摘要

**问题**

1. 上传卡片底栏一排胶囊（题材 / 画风 / 比例 / 集数 / 模型），用户不点开就不知道默认用了什么；剧本还是小说由模型在后台判断，用户看不到也改不了。
2. 六个 AI 步骤的提示词写死在二进制里，运营和用户都无法换成自己更好用的写法或已有的技能。
3. 原文上限 30 万字；放宽到 500 万字后，现有「全文分块研读 + 摘要合并」会越读越粗，且小说分集剧本是**照全书梗概写的，不读原文**，对白基本丢失。

**目标**

- 一次弹窗把开拍要做的决定做完，默认值一眼可见，全用默认的人一键开始。
- 四个环节（剧本改编、资产拆解、资产图提示词、视频提示词）可选「内置 / 我的提示词 / 技能」，输出结构始终由系统固定。
- 500 万字长篇可用：每个模型请求只读需要的那部分原文；用户用「规划范围」和选集控制一次花多少。

**推荐结论**

- 卡片只留上传 / 粘贴区和发送按钮；点发送先调「预检」接口（解析文件、切章、规则识别剧本 / 小说、字数、预估），再弹「开拍设置」单页弹窗。
- 原文按「单元」（小说的章 / 剧本的集）入库；研读改成「开篇完整 + 后文均匀抽样」；分集规划按批（≤ 12 单元且 ≤ 3 万字，**读完整原文**），每集记住对应单元范围；分集剧本只读本集原文；规划、剧本、拆解都带上从画布实时读取的「已登记角色名单」。
- 开拍设置里选**规划范围**（默认全部 / 做到第 N 章），显示预计集数、研读与规划的积分和耗时；开始后**只自动做「粗读全书 + 分集规划」**，范围内规划完就停，之后可「继续规划后面的章节」。
- **写剧本、资产拆解保持现状**：用户在分集目录里选集发起；规划还在跑时，已经规划好的集就可以先写、先拆、先出视频。
- 提示词模板拆成「固定协议（输入变量、本步职责、输出 Schema、校验）+ 可替换正文」；自写替换正文，技能以「写作方法」块注入正文位置。

### 2.2 设计约束

- 输出 Schema 是落库的契约，任何用户 / 技能内容都不能改它（F10、F11）。
- 任务按快照执行（F12）：提示词也应进快照，才能做到「改了只影响之后的任务」。
- 错误码沿用 67xxx（F11），短剧已有到 67013。
- 界面用半透明「清透」胶囊风格，不加操作说明小字（`web/docs/coding-standards.md` 6.1、6.2）。

### 2.3 当前缺口

- 无建剧前的预检 / 估价；无来源类型的用户确认。
- 无用户提示词库；技能没有「适用环节」概念。
- 原文和项目同行存储；没有章节单元；剧本不读原文；集数被 100 卡住。
- 长时间自动跑的流水线会因 F21 把用户的分镜、合成等操作全部挡住。

## 3. 用户与场景

- **用户**：做 AI 短剧的个人创作者 / 小团队编导，手里是网文（几十万到几百万字）或写好的分集剧本；部分人有自己打磨过的提示词或运营提供的技能。
- **触发场景**：首页 / 短剧工作室拖入一本小说或剧本，想尽快看到改编结果。
- **主任务**：上传 → 确认识别与设置、选规划范围 → 开始 → 自动研读与分集规划 → 选集写剧本 → 选集资产拆解 → 逐集出视频 → 需要时继续规划后面的章节。
- **成功指标**（提案）：
  - 500 万字 txt 从点发送到弹窗出现 ≤ 5 秒（本地网络，示意）。
  - 剧本里原著引号对白的保留率明显高于现状（用 3 部样书人工比对，验收时记录）。
  - 用默认设置的用户从点发送到开始 ≤ 2 次点击。

## 5. 设计原则

1. **结构归系统，写法归用户**：Schema、输入变量、本步职责永远由系统拼接；用户和技能只替换「正文」（F10、F11）。
2. **每次请求只读需要的原文，但要读完整**：研读抽样；规划读本批全文；剧本读本集全文；没有任何一步把整本书喂给模型（用户反馈、§11.1 第 14 条）。
3. **状态存下来，不靠模型记忆**：每步产出存库或存画布，后续步骤读取；跨批靠悬念、上一集结尾和角色名单衔接。
4. **决定集中、默认可见、花费先说**：开拍前一个弹窗做完所有决定，并显示预计集数、积分和耗时（用户第 1 题、§11.1 第 19 条）。
5. **自动只做便宜、不可逆性低的部分**：研读和分集规划自动跑；写剧本、拆解（会锁定剧本）由用户选集发起，与现状一致（§11.1 第 24–25 条）。
6. **快照即契约**：任务提交时冻结提示词文本，之后改设置只影响新任务（用户第 8 题、F12）。

### 6.5 长篇按章流水线（改）

```
预检：解析 → 去噪 → 切单元 → 识别 → 估价                     （无模型调用）
建剧：草稿 → drama_units；range_end = 所选规划范围终点
自动（pipeline）：
  研读 analyze：抽样 → 梗概 + 人物 + 全书主线 outline_md
  分集规划 plan：每批（≤ 12 单元且 ≤ 3 万字，且不超过上下文预算）读本批完整原文 → 本批分集目录
  到达 range_end → phase = done；用户可「继续规划后面的章节」扩大 range_end，接着规划
用户选集发起（与现状相同，可与自动规划并行）：
  写剧本 scripts：在已规划的集里多选 → 按集号逐集写，每集读本集完整原文
  资产拆解 breakdown：在已有剧本的集里多选 → 拆角色 / 场景 / 道具，锁定这些集 → 自动接资产图提示词 asset_prompts
  视频：已锁定的集「生成脚本（storyboard）」→ 片段视频 → 合成
```

**单元切分规则**（预检，后端）：

1. 去噪：整行匹配网址、求票 / 求订阅、「本章完 / 未完待续」、「作者有话说 / PS:」、常见盗版站水印；仅删除长度 < 80 字的行。
2. 有 ≥ 2 个「第N集」→ 按集切（单元 kind = `episode`）；否则识别为剧本且有 ≥ 3 个场次头 → 按场次切（`scene`，标题取场次头）；否则有 ≥ 2 个「第N章 / 节 / 回 / 卷」→ 按章切（`chapter`）；否则按段落每约 9,000 字切（`chunk`，标题「第 N 段」）。用户在弹窗里改了类型时，预检按新类型重新切分（估价接口带 `source_kind` 重算）。
3. 首个标记前非空文本 → 单元「序」（`prologue`）。
4. 单个 `chapter / chunk` 单元 > 12,000 字时按段落拆成约 9,000 字的多段，标题加「（1/3）」等，记一条 `split_long` issue；`episode` 单元不拆，> 40,000 字时记 `episode_too_long` issue 并在弹窗里警示。
5. 空单元丢弃并记 `empty`；连续重复标题记 `duplicate`。

**识别规则**（预检，规则打分，不调模型）：

| 信号 | 计算 |
| --- | --- |
| `episode_marks` | 「第N集」标题行数 |
| `chapter_marks` | 「第N章/节/回/卷」标题行数 |
| `scene_heads` | 形如「1-1」「场景：」「内景 / 外景」「日 / 夜」的标题行数 |
| `dialogue_ratio` | 形如「人名（括注）？：台词」的行 / 非空行 |
| `quote_ratio` | 含中文引号对白的行 / 非空行 |

- `script`：`episode_marks ≥ 2`，或 `scene_heads ≥ 3 且 dialogue_ratio ≥ 0.3`。
- `novel`：`chapter_marks ≥ 2`，或 `quote_ratio ≥ 0.1 且 dialogue_ratio < 0.1`。
- 其他 → `unknown`。
- 用户确认的类型写入 `drama_projects.source_kind`；研读输出里的 `source_kind` 只作参考，不覆盖。

**上下文预算**（新，§11.1 第 20 条）：

- `budget = 模型上下文 × 60%`（字，沿用 `dramaContextLimit` 的口径）。
- 固定开销 `fixed = summary + characters_md + outline_md + known_cast（≤ 1.2 万）+ 提示词正文或技能（≤ 2 万 / 1.6 万）+ previous_ending（800）+ 模板与 Schema`，按实际长度计。
- 规划每批原文上限 = `min(30,000, budget − fixed)`；单元数仍 ≤ 12。剧本的本集原文天然 ≤ 本批原文，所以剧本步骤也放得下。每批入队时按当时的 `fixed` 重算，所以角色名单变长后批会自动变小。
- **上下文低于 128k 的模型在开拍设置里禁用**并写原因（用户确认的硬阈值）。128k 下 `budget ≈ 7.6 万字`，扣掉固定开销后一批仍能装下约 3 万字原文。
- 建剧后若 `budget − fixed` 不足以放下一个单元（例如名单和技能都很长、单元接近 1.2 万字），任务失败为 67022「当前模型上下文不足」，可在提示词设置里换模型或缩短提示词后继续。

**研读（analyze）改动**：输入 `source` 改为抽样文本：预算 `min(40,000, budget)` 字，3/4 按单元顺序完整读开篇，余 1/4 在剩余单元中均匀取 12 个单元的开头；每段前加 `## [单元号] 标题`。输出新增 `outline_md`（全书主线，基于抽样，标注「后文为抽样推断」）。原文 ≤ 预算时等同全文。删除 map-reduce 合并路径。研读一次覆盖全书（不受规划范围限制），之后继续规划时不重做。

**规划（plan，原 outline）改动**：
- 输入：`summary`、`characters_md`、`outline_md`、本批单元（`[单元号] 标题 + 完整原文`，不截断）、`known_cast`、`next_episode_no`、`previous_cliffhanger`（上一集的 `cliffhanger` 字段）、`episode_seconds`、`source_kind`。**不再传目标集数**，集数由原文密度和单集时长决定。
- 输出：`episodes: [{title, synopsis, hook, cliffhanger, unit_from, unit_to}]`，`unit_from/to` 必须落在本批范围、按序连续覆盖本批全部单元（允许同一单元拆成多集：相邻集 `unit_to = unit_from`）。单批 `maxItems 60`，无全剧上限。
- **剧本型输入不走 plan 和 scripts**（§11.1 第 23 条）：原文就是剧本，由代码切集，不调用模型。
  - 带「第N集」：单元一对一建集（同 F7，取消 100 上限），标题取「第N集」那一行。
  - 无分集标记：单元是场次；代码按顺序把连续场次合成一集，累计到约 `episode_seconds` 对应的字数（60 秒按约 1,000 字剧本，示意，需校准）就收尾，**不拆开一个场次**；单个场次超长时独占一集。集数随剧本长度走，台词全部保留，不压缩（§11.1 第 21 条）。标题取首个场次头。
  - 两种情况的 `script_md` 都是原文排版整理（换行、场次头加粗），`synopsis / hook / cliffhanger` 留空，工作台可手填。
  - 剧本型输入研读完成后，代码一次切好全部集（不受规划范围限制，切集不花积分），`phase` 直接 `done`；之后由用户选集拆解。
- 游标：`drama_projects.plan_cursor` 记录下一个未规划单元号；规划结果提交时比对任务快照里的 `unit_from`，不等则作废（防止重试重复建集）。

**分集剧本（scripts）改动**：
- **触发方式不变**：用户在分集目录里多选已规划的集，点「写剧本」（现状入口），确认框显示积分（现有估价接口）。规划还在跑时也可以发起，只能选已经规划出来的集。
- 输入 `source` 改为本集 `unit_from..unit_to` 的原文拼接（按单元号、带标题）；另加本集 `hook`、`cliffhanger` 和 `known_cast`。
- 一个任务内**按集号逐集串行**（与现状 `runScripts` 一致，F20），先写的集结尾会传给后写的集。
- `previous_ending`：上一集剧本已写好 → 取它结尾约 800 字（现状）；上一集还没写（用户跳着选，例如只选了第 5 集）→ 改用规划里上一集的 `synopsis + cliffhanger`，提示词里注明「上一集剧本尚未写，以下为其梗概与结尾悬念」。
- 某集失败：现状行为，之前写好的集保留，该集及之后未写的集标失败，用户重新选择后再发起。
- scripts 只用于小说。剧本型输入的单集原文 > 40,000 字时，预检记 `episode_too_long` 警示；因为不调模型写剧本，建剧后只影响拆解（拆解按批，该集单独成批），不再报错（67020 改为仅在小说单集原文超出预算时出现，理论上不会发生，作为兜底）。

**资产拆解（breakdown）**：
- **触发方式不变**：用户多选已有剧本的集，点「资产拆解」，确认弹窗显示积分并提示「拆解后这些集的剧本将锁定」（现状）；弹窗**去掉比例选择**（比例建剧时已定，F22）。成功后锁定这些集（F15 不变）并自动接 asset_prompts（现状）。
- 新增输入 `known_cast`，作为提示词里已声明的 `assets` 传入（修复 F19）；要求模型对已有角色沿用原名、新称呼写进 `aliases`。代码侧按名称 / 别名合并（F14）保留作兜底。

**已登记角色名单（`known_cast`，新）**：
- 来源：短剧画布上带 `data.drama` 的角色、场景、道具节点（拆解时写入，用户可编辑），**每次任务入队时现取**，每次拆解后自动变长。用户拆解之前规划的批次，名单为空，只靠 `characters_md`。
- 每条：`{type, name, aliases, look, desc}`，`desc` 取节点描述的前 80 字；按首次出现的集号排序。
- 预算：最多 1.2 万字；超出时优先保留角色，其次最近 3 批出现过的场景和道具，其余只给 `name + aliases`。
- 用在：plan（排集用正式名）、scripts（剧本里用正式名，别名只出现在对白中）、breakdown（合并已有角色）。研读时名单为空。
- 与 `characters_md` 的关系：`characters_md` 是研读得出的全书人物小传（基于抽样，之后不更新）；`known_cast` 是画布上的实时名单。两者都传，冲突时以 `known_cast` 为准（提示词里写明）。
- 用户中途在画布上改了角色名：之后的任务用新名，已写好的剧本不回改；角色卡上提示「已有 N 集剧本使用旧名」（§11.1 第 22 条）。

**步骤之间怎么引用**：每步的产出存进数据库或画布，后面的步骤按需读取，不靠模型「记住」前文。

| 产出 | 存在哪 | 谁读、读来做什么 |
| --- | --- | --- |
| 单元原文 | `drama_units` | plan 读本批全文排集；scripts 按本集 `unit_from..unit_to` 读全文写剧本 |
| `summary` / `characters_md` / `outline_md` | `drama_projects` | plan、scripts、breakdown 每次都带上，提供全书背景 |
| 分集目录（标题、梗概、`hook`、`cliffhanger`、`unit_from/to`） | `drama_episodes` | scripts 读本集这几项；下一批 plan 读上一集的 `cliffhanger` |
| 剧本 `script_md` | `drama_episodes` | 下一集 scripts 取它结尾约 800 字；breakdown 读本批各集；storyboard 读本集 |
| 角色 / 场景 / 道具节点 | 短剧画布（`data.drama`） | 组成 `known_cast` 供 plan / scripts / breakdown；asset_prompts 给新节点写提示词；storyboard 用 `@[名](node_id)` 引用；片段视频按引用取参考图 |
| 有效提示词正文 | `drama_jobs.config_snapshot.prompt` | 本任务自己使用（快照） |

### 6.6 规划范围与运行控制（新，取代原「样章定调 / 批量生成」）

- **规划进度复用现有任务条 JobBar**（`web/src/pages/drama/workspace/job-bar.tsx`，顶栏正下方）：
  - 规划中：一行 `正在规划第 38–44 章` + 灰字 `分集规划 · 已出 52 集目录 · 可以离开这个页面，完成后会通知你` + 百分比 + `[暂停]`（现有「取消」位置），下方细进度条。
  - 暂停 / 失败：沿用 JobBar 的失败行样式，写原因（用户暂停 / 「积分不足，充值后继续」/ 规划失败 / 上下文不足）+ `[继续]` 或 `[重试]`；自定义提示词导致的失败多一个 `[改用内置重试]`。

- **研读中视图**（现有 AnalyzingView）步骤文案改为：「粗读全书 · 抽样读开篇与后文，整理人物与梗概」「分集规划 · 按批读原文，生成分集目录」；第一批规划完成、出现第一集后即退出研读视图。
- **选集入口沿用现有弹窗**：剧本页底部「下一步」浮条（NextStepPill）→「生成分集剧本」打开 ScriptsDialog、「资产拆解」打开 BreakdownDialog。两个弹窗的勾选网格只列已规划的集；集数多时网格改为虚拟列表，并在「没有剧本的 / 全选 / 清空」旁加「按范围选：第 [a]–[b] 集」。
- **继续规划后面的章节**：确认框选「全部剩余 / 做到第 N 章」，显示剩余字数、预计集数、规划积分、耗时（同 §6.3 公式）；确认后 `range_end` 扩大、`phase = running`。
- **写剧本、拆解、出视频都由用户选集发起**（§6.5），规划不会替用户写剧本或拆解。
- **资产图**：拆解后只自动写图片提示词（现状），不自动出图。
- **并行规则**（修复 F21，§11.1 第 20、25 条）：任务分两条线，`lane = pipeline`（analyze / plan，系统自动发起）和 `lane = user`（用户发起的全部任务）：
  - pipeline 与 user **互不阻塞**：规划在跑时，用户照样可以给已规划的集写剧本、给已有剧本的集拆解、给已锁定的集出视频。
  - user 线内部：文本任务（scripts / breakdown / asset_prompts）彼此串行（与现状一致，它们改集与画布）；storyboard / 片段 / compose 只允许已锁定的集，同一集的这类任务串行，不同集可并行。
  - 规划中禁止增删集（避免与规划游标、集号冲突），可以改已规划集的标题、梗概、钩子、悬念；`paused / done` 时恢复增删集。
- 积分：每个任务各自冻结（现状）；规划冻结失败 → `paused` + `pause_reason`。

### 6.7 提示词与技能的拼接（改）

模板重组为（每份 md 同样五段，storyboard 统一标题）：

```
## 输入变量          ← 固定，不展示给用户
## 本步职责          ← 固定，新增，1–3 句：本步只产出什么
## 提示词正文        ← 可替换
## 输出 JSON Schema  ← 固定
## 校验规则          ← 固定
```

拼接顺序：变量 JSON 前缀（现状）→ 输入变量 → 本步职责 → 正文块 → Schema → 校验规则。正文块按来源：

- `builtin`：内置正文。
- `mine`：用户正文原样。
- `skill`：

  ```
  【写作方法：{技能标题}】
  以下是本步骤必须遵循的方法与标准，按它决定取舍、粒度与写法。输出仍只能是下方 JSON 结构，
  方法与结构冲突时以结构为准，方法里要求的其他输出格式一律不输出。
  <skill>
  {SKILL.md 正文 + 正文引用到的文本文件，按出现顺序，总计截断到 16,000 字}
  </skill>
  ```

  技能里的脚本、工具调用不执行；`has_scripts = true` 的技能在下拉里标「仅用正文」。

「剧本改编」一条选择同时作用于 `plan` 和 `scripts`：`mine` 有两份正文；`skill` 同一段方法注入两步（各自的「本步职责」区分产出）。

### 6.8 快照与事后修改

- 建剧时把四个环节的有效正文**文本**快照进 `drama_projects.prompt_settings`（我的提示词之后被改 / 删、技能升版本都不影响）。
- 工作台「提示词设置」修改 → 更新 `prompt_settings`（带 `revision`）；运行中也可以改，只影响之后入队的任务。
- 每个任务入队时把该步有效正文拷进 `drama_jobs.config_snapshot.prompt`；重试沿用原任务快照，想用新提示词则「重新生成」新任务。

### 6.9 完整流程与四种输入

完整的 12 步流程（每步的触发者、读取内容、产出与存放位置、可换的提示词、失败处理）、字段级输入输出表和异常汇总，见演示页「完整流程」标签页，内容与本节及 §6.2–§6.8 一致。四种输入的差异：

| 步骤 | 小说（长篇） | 剧本，带「第N集」 | 剧本，没有分集标记 | 短篇 |

| 场景 | 表现 | 处理 |
| --- | --- | --- |
| 预检中 | ↑ 转圈 / 环形上传进度；卡片不可编辑 | 网络失败 toast「上传失败，请重试」，文件保留 |

| 某集剧本失败 | 现状行为：之前写好的集保留，该集标失败 | 重新选这一集写剧本 |
| 跳着选集写剧本（上一集还没剧本） | 正常写；确认框提示「第 N−1 集还没剧本，将按其梗概衔接」 | — |

| 模型上下文低于 128k | 下拉里禁用并写原因 | 换模型 |
| 积分不足 | `paused`，进度条显示原因 | 充值后「继续」 |
| 规划中点增删集 | 按钮禁用，`title` 写「正在规划，完成或暂停后再增删集」 | 服务端兜底 67019 |
| 服务重启 / 断线 | 进度从数据库恢复 | River 任务 + 游标自动续跑 |
| 改提示词时有在途任务 | 保存成功；Sheet 顶部一行「进行中的任务仍用旧提示词」 | — |
| `prompt_settings` 并发修改 | 409（revision） | 前端重新拉取后提示「设置已在别处更新」 |

撤销：弹窗和编辑器内修改在点「开始 / 保存」前都可取消；「恢复内置」可回到内置正文。已提交的任务不可撤销，只能重做。

权限：`drama_prompts` 按 `user_id` 隔离；技能目录只返回已启用且标了短剧环节的；草稿只能本人使用。

### 8.3 调度

- 新增**规划推进函数** `advancePlanning(project)`，在 analyze / plan 任务提交后、以及 `range / resume` 时调用；`phase ≠ running` 时直接返回。每次最多入队一个 `lane = pipeline` 任务：
  1. 还没研读 → 入队 analyze。
  2. `plan_cursor < range_end` → 小说：按上下文预算取下一批，入队 plan（带 `known_cast`、上一集 `cliffhanger`）；剧本：代码一次切完全部集，不入队。
  3. 都没有且无在途 → `phase = done`。
- 写剧本、拆解、资产图提示词、分镜、片段、合成**都不由推进函数发起**，仍走现有 `POST /dramas/:id/jobs`（`lane = user`）。
- 失败：pipeline 任务失败 → `phase = paused`，`pause_reason` 写明哪一批；用户重试成功后自动 `running`。积分不足同理。
- **并发判定改造**（F21）：`prepareDramaJob` 的「有进行中任务就拒绝」改为按 lane 和任务类型：
  - `pipeline` × `pipeline` 互斥；`pipeline` 与 `user` 互不阻塞。
  - `user` 文本任务（scripts / breakdown / asset_prompts）彼此互斥（现状语义，只是不再被 pipeline 挡）。
  - `user` 媒体任务（storyboard / 片段 / compose）只允许已锁定的集，同一集互斥、不同集可并行。
  - scripts 只能选已规划的集；breakdown 只能选已有剧本的集（小说）。
  - `deleteEpisodeTx` / `CreateEpisode` 在 `phase = running` 时拒绝（67019）。
- 规划结果写入时只追加新集、推进游标，不动用户已在写或已锁定的集；与用户的 scripts 同时提交时由项目锁保证顺序。
