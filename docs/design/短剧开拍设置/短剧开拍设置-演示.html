短剧开拍设置

点发送后先「预检」，在一个弹窗里定好怎么拍；系统自动研读和分集，剧本由你选集来写

上传卡片只留上传区和发送键。点发送，后端先解析文件、切章、判断剧本还是小说，再弹出开拍设置：识别结果、规划范围（全部 / 做到第 N 章）、画幅三选一、题材画风单集时长模型、四个环节的提示词（内置 / 我的 / 技能）。 点开始后只自动做「粗读全书」和「分集规划」；写剧本、资产拆解和现在一样，由你在分集目录里选集发起，规划还在跑时，已规划好的集就能先写、先拆、先出视频。 为了撑住 500 万字：研读只读抽样，分集规划按批读完整原文，每集剧本读这一集的完整原文。剧本型输入不走小说转剧本。

设计：自动只做研读和分集规划，成本低，也不会锁定任何东西；写剧本和拆解花钱更多、拆解还会锁定剧本，所以保持现状由用户选集发起。没有哪一步把整本书交给模型。
兜底：识别不出类型 → 让用户选，选之前不能开始；上下文低于 128k 的模型 → 不能选；规划失败或积分不足 → 规划暂停，已规划的集照常可写可拆；自定义提示词或技能导致输出不合格 → 任务失败并提供「改用内置重试」；服务重启 → 规划从数据库里的进度接着跑。

提示词的三种来源

四个环节（剧本改编、资产拆解、资产图提示词、视频提示词）各自选一种。不管选哪种，输出结构都由系统固定。剧本型输入没有「剧本改编」。

内置
默认

就是今天的提示词。只是拆成「固定协议 + 正文」两部分。

我的提示词
替换正文≤ 2 万字

从内置正文复制起步，改完整段替换；存进按环节分类的「我的提示词」，下次直接选。

技能
后台导入注入 ≤ 1.6 万字

管理员给技能标「短剧适用环节」后才会出现；SKILL.md 正文作为「写作方法」放进正文位置，脚本不执行。

用户上传一本 486 万字的网文时，会发生什么

按时间顺序走一遍，以及需要提前说清楚的边界。

  1. 拖入 docx，点 ↑预检切出 1,215 章，识别为小说，清掉 312 行网文站插入语
  2. 开拍设置：规划到第 120 章弹窗显示「预计约 160–260 集 · 研读与规划约 1,700 积分 · 约 20 分钟」（示意）
  3. 自动研读 + 分集规划每批读约 3 万字原文，分集目录一批批出现在分集栏里
  4. 边规划边写第 1 批规划好，就可以勾选第 1–10 集点「写剧本」
  5. 选集资产拆解写好的第 1–10 集勾选「资产拆解」，拆完锁定、自动写图片提示词，然后出视频
  6. 第 120 章规划完，停下需要时点「继续规划后面的章节」
边界
  • 研读是抽样，后期才出场的人物靠每次拆解登记进角色名单，之后的规划、剧本、拆解再带上。
  • 跳着选集写剧本时（比如只写第 5 集），上一集没有剧本，就用上一集的梗概和结尾悬念衔接。
  • 开拍设置里的预估只算研读和规划；写剧本、拆解的积分在选集时再显示（现有估价）。
  • 拆解后这些集的剧本锁定（现状）。

交付时要提前告诉用户：预计集数的系数是初值，需要用样书校准；识别规则的阈值同理。

完整流程：从拖入文件到每集成片

一共 12 步：开拍前（1–3）、自动（4 粗读全书、5 分集规划，规划到范围终点就停）、用户选集（6 写剧本、7 资产拆解、8 资产图提示词自动接上）、继续规划（9）、逐集出视频（10–12）。 自动和用户选集两条线可以同时进行。每一步的产出都存进数据库或画布，后面的步骤去读，不靠 AI 记住前文。AI 读原文的地方：粗读全书读抽样；分集规划读本批完整原文；写剧本读本集完整原文。剧本型输入跳过第 5、6 步。 全部为提案，对应主文档 §6.2–§6.9。

每一步做什么

固定看五项：谁触发、读什么、产出什么（存在哪）、提示词能不能换、失败了怎么办。

开拍前
1

上传或粘贴

用户
做什么拖入 txt / md / docx，或粘贴正文，点 ↑。卡片上只有这一个动作，所有设置都在第 3 步的弹窗里。 限制500 万字以内；上传请求最大 64MB。 失败格式不对、为空（67002），超过 500 万字（67003）：红字提示在卡片里，不弹窗。
2

预检

代码 · 不花积分POST /drama-sources/preflight
做什么
  • 去噪：删掉网址、求票、「作者有话说」这类短行（80 字以内）。
  • 识别：按「第N集」「第N章」、场次头、「人名：台词」行的比例，判断剧本 / 小说 / 识别不出。
  • 切单元：有「第N集」按集切；剧本有场次头按场次切；小说按「第N章」切；都没有每约 9000 字一段。超过 1.2 万字的章按段落拆开。
  • 估价：按规划范围、单集时长、模型，估算集数，以及研读与规划的积分、耗时。
 产出一份草稿，24 小时过期，每人最多 3 份。返回 source_token，文件只上传这一次。 失败网络失败：提示重试，卡片里的文件保留。
3

开拍设置 → 开始

用户POST /dramas
确认什么
  • 识别结果（剧本 / 小说，可改；识别不出时必须先选）。
  • 规划范围：全部，或做到第 N 章。旁边显示预计集数、研读与规划的积分和耗时。剧本型输入不需要选（一次切完）。
  • 画幅 9:16 / 16:9 / 4:3；题材、画风、单集时长（没有目标集数）、文本模型（上下文低于 128k 的禁用）。
  • 四个环节的提示词，各选内置 / 我的 / 技能。剧本型输入的「剧本改编」置灰。
 产出建好短剧：单元存进单元表；四个环节的提示词正文文本快照进项目；草稿删除；开始自动研读和规划。 失败草稿过期（67014）：回到卡片重新预检。提示词被删 / 技能停用（67016 / 67018）：该行回落为「内置」并标红。
自动（研读 + 分集规划，规划到范围终点就停）
4

粗读全书（研读）

AI · 1 次 · 自动提示词固定
读抽样原文，约 4 万字（不超过模型上下文的 60%）：开头 3/4 按顺序完整读，剩下 1/4 从后面均匀抽 12 章、各取开头。全书不到 4 万字就读全文。覆盖全书，不受规划范围限制，之后继续规划也不重做。 产出存进短剧项目的三样：人物表、全书梗概、全书主线。之后每一步都会带上。
5

分集规划（每批）

AI · 每批 1 次 · 自动剧本改编仅小说
批多大最多 12 章，原文最多 3 万字；模型上下文扣掉人物表、角色名单、提示词等固定内容后放不下时，批自动变小。 读
  • 本批章节的完整原文。
  • 人物表、全书梗概、全书主线。
  • 已登记角色名单（从画布实时读取；用户还没拆解时为空）。
  • 上一集的结尾悬念、下一集编号、单集时长。不传目标集数。
 产出本批的分集目录，存在每一集上：标题、梗概、开场钩子、结尾悬念、对应第几章到第几章。一章可以拆成两集，几章也可以合成一集。规划好的集立即出现在分集栏里，可以被勾选去写剧本。 剧本不调 AI：有「第N集」一个单元一集；没有标记时，代码把连续场次累计到约单集时长对应的长度合成一集，不拆开场次。一次切完全部集。 失败输出不合格自动重试；还不行规划暂停（自定义提示词或技能时报 67015，可「改用内置重试」）。已规划的集照常可写可拆。
用户选集（入口和现在一样，可与自动规划同时进行）
6

选集 → 写剧本

用户发起AI · 每集 1 次剧本改编仅小说
怎么发起在分集栏里勾选已规划的集（可 Shift 连选），点「写剧本」，确认框显示积分（现有估价）。 顺序这次选中的集按集号一集一集写，先写的集结尾传给后写的集。 读
  • 本集对应章节的完整原文。
  • 本集的标题、梗概、钩子、悬念。
  • 上一集剧本的结尾约 800 字；上一集还没剧本（跳着选）时，改用上一集的梗概和结尾悬念。
  • 人物表、全书主线、已登记角色名单。
 产出本集剧本（场次、动作、台词），原著引号里的对白逐字保留。写好后可以手动修改，直到拆解前。 失败现状行为：之前写好的集保留，该集标失败，重新勾选再写。
7

选集 → 资产拆解

用户发起AI · 每次 1 次资产拆解
怎么发起勾选已有剧本的集（剧本型输入任意集），点「资产拆解」，确认弹窗显示积分并提示「拆解后这些集的剧本将锁定」。弹窗不再选比例（建剧时已定）。 读所选各集的剧本、人物表、已登记角色名单（现在的代码没传这一项，这次补上）。 产出角色（含造型和音色描述）、场景、道具，写进短剧画布的节点。名字或别名对得上的只补「出现在哪几集」，对不上的才新建，新称呼记进别名。名单因此变长，之后的规划、剧本、拆解都能看到。所选各集剧本锁定。
8

资产图提示词

AI · 自动接在第 7 步后资产图提示词
读第 7 步新建的节点、画风、题材。 产出给每个新节点写一段图片提示词，存在节点上（现状）。不自动出图，图片在资产库里一键批量生成。
继续规划
9

规划完成 / 继续规划后面的章节

用户
看到规划进度条显示「已规划第 1–120 章 · 共 168 集」；还有剩余章节时出现「继续规划后面的章节」。 继续选「全部剩余」或「做到第 N 章」，确认框显示剩余字数、预计集数、规划积分和耗时；确认后回到第 5 步接着规划。 规划中可以暂停 / 继续、修改提示词设置（只影响之后的任务）；不能增删集（避免和集号冲突），暂停或完成后可以。
逐集出视频（已拆解的集随时可做）
10

生成脚本（分镜）

AI · 每集 1 次视频提示词
条件这一集已拆解（剧本已锁定）。 读这一集的剧本，加上画布上的资产节点（带节点 id）、画幅、画风、视频模型单段时长上限。 产出这一集切成若干片段，每段一条视频提示词，用 @[沈砚](节点id) 引用角色、场景、道具。
11

片段视频

用户触发 · 视频模型
读片段提示词，用「参考生视频（omni）」方式提交。按 @ 引用解析参考素材：角色取主图和补充图，场景、道具取图片，角色有声音的带上参考音频；首帧可选。没出图的资产只按文字描述。 产出每段可以生成多次，结果都保留，选一个「采用」。 失败原因显示在片段上，可重新生成；积分先冻结，失败退回。
12

用户触发 · 代码
做什么工作台按顺序连续播放采用的片段做预览；点「合成整集」后服务端用 ffmpeg 拼成一个视频文件。 失败有片段还没有采用结果时报 67010。片段改动后成片标为「已过期」，需要重新合成。

text  = parse(file)              // 复用 drama.ParseSource
text, noise = stripNoise(text)   // 整行 < 80 字才删
kind  = guess(signals(text))
units = splitUnits(text, kind)
  // ≥2 个「第N集」→ episode
  // 剧本且 ≥3 个场次头 → scene
  // ≥2 个「第N章/节/回/卷」→ chapter
  // 否则每 ~9000 字 → chunk；chapter/chunk > 12000 字按段落拆
draft = save(user, text, units, kind, ttl=24h)  // 每人 ≤ 3 份
// 自动规划（analyze / plan 提交后、range / resume 时调用）
advancePlanning(p):
  if p.phase != running: return
  if !analyzed: enqueue(analyze); return
  if p.plan_cursor < p.range_end:
     if kind == novel:
        n = min(30000, ctx*0.6 - fixed(cast, prompt, …))
        enqueue(plan, nextBatch(≤12 单元, ≤n 字),
                knownCast(canvas), lastEp.cliffhanger)
     else: buildEpisodesByCode()   // 一次切完，不调 AI
  elif 无在途 pipeline: p.phase = done
  // 失败 / 积分不足 → paused + pause_reason
// 写剧本、拆解仍由用户经 POST /dramas/:id/jobs 发起
// 写剧本（用户选集，提案）：所选集按集号逐集
for ep in sorted(selected):
  prev = episode(ep.no - 1)
  prevCtx = prev.script ? tail(prev.script, 800) : "上一集剧本尚未写：" + prev.synopsis + " / " + prev.cliffhanger
  call(scripts, source=units[ep.from..ep.to], ep.hook, ep.cliffhanger, prevCtx, knownCast(canvas))
// 并发（提案）：prepareDramaJob 从「有任何在途就 67004」改为按 lane 判定
