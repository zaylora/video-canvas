# 短剧开拍设置 · 前后端接口契约

> 前后端并行开发的唯一约定。设计依据：同目录 `短剧开拍设置.md`（准绳，§6–§8、§11）与 `短剧开拍设置-原型.html`（界面）。
> 沿用 `../短剧工作室/接口契约.md` 的通用约定（`/api/v1`、`{code,msg,data}`、`idcodec.ID` 十六进制、snake_case、集用 `no` 定位、`text_model` 语义）。
> 改契约两边都要知道：在本文末尾「变更记录」追加一行，不要静默改。

## 0. 不变的部分

- `GET /drama-styles`、`GET/PATCH/DELETE /dramas/:id`、集的增删改查、片段与合成接口：路径和字段不变，只按下文加字段。
- `POST /dramas/:id/jobs` 仍是用户发起任务（scripts / breakdown / asset_prompts / storyboard / compose）的唯一入口；`analyze` / `outline` 不再由用户提交（见 §4）。

## 1. 预检

### `POST /drama-sources/preflight`

multipart：`file`（txt / md / docx，二选一）或 `text`（粘贴正文）；可选 `source_kind`（`script` / `novel`，用户在弹窗里改类型后带上重新切分）、`text_model`（用于估价，空串 = 默认模型）、`episode_seconds`（默认 60）。请求体上限 64MB。

返回 `data`：

```json
{
  "source_token": "9f2c…",              // 草稿 id，24 小时有效
  "filename": "霜刃.docx",
  "chars": 4860000,                     // 去首尾空白后的 Unicode 字符数（与 SOURCE_MAX_CHARS 同口径）
  "kind_guess": "novel",                // script | novel | unknown
  "kind_signals": "找到 1,215 个“第N章”，对白多为叙述内引号",   // 一句话依据，界面直接显示
  "unit_kind": "chapter",               // episode | scene | chapter | chunk（按 kind 切分的结果）
  "units": [                            // 只给目录，不给正文
    { "no": 1, "title": "第1章 雪夜入门", "chars": 3980 }
  ],
  "units_total": 1215,
  "issues": [                           // 处理记录，界面折叠显示
    { "kind": "noise_removed", "count": 312, "message": "清掉 312 行网文站插入语" },
    { "kind": "split_long", "count": 3, "message": "3 章超过 1.2 万字，已按段落拆开" },
    { "kind": "episode_too_long", "count": 1, "message": "第 12 集超过 4 万字" }
  ],
  "estimate": {                         // 自动部分（研读 + 规划）的预估，range_end = 全部
    "episodes_min": 900, "episodes_max": 1400, "episodes_exact": false,
    "credits": 3200, "minutes": 40
  }
}
```

- 剧本带「第N集」或按场次切集时 `episodes_exact = true`，`episodes_min = episodes_max`。
- `units` 最多返回全部单元（500 万字约几千条，每条很小）；前端用虚拟列表。
- 错误：67002 格式不支持 / 内容为空；67003 超过 5,000,000 字；67014 不会出现在这里。
- 每个用户最多保留 3 份有效草稿，新的挤掉最旧的。

### `POST /drama-sources/:token/estimate`

JSON `{ "source_kind": "novel", "range_end": 120, "episode_seconds": 60, "text_model": "" }` → 返回同上 `estimate` 结构。开拍设置里改范围 / 时长 / 模型时调用（前端 300ms 防抖）。草稿过期 → 67014。

## 2. 建剧

### `POST /dramas`（改为 JSON）

```json
{
  "source_token": "9f2c…",
  "source_kind": "novel",               // 必填，用户确认的类型
  "range_end": 0,                       // 0 = 全部；否则规划到第 N 个单元（1..units_total）
  "title": "",                          // 空串用文件名
  "ratio": "9:16",                      // 必填，9:16 | 16:9 | 4:3
  "genre": "", "style_key": "xianxia", "style_custom": "",
  "episode_seconds": 60,                // 30..180
  "text_model": "",
  "prompts": {                          // 四个环节；省略的环节 = 内置
    "adapt":  { "source": "builtin" },
    "assets": { "source": "skill", "skill": "cross-episode-continuity" },
    "asset_prompts": { "source": "mine", "id": "1f" },
    "video":  { "source": "builtin" }
  }
}
```

- `prompts.*.source`：`builtin` | `mine`（带 `id`）| `skill`（带 `skill` 技能 name）。`source_kind = script` 时 `adapt` 必须是 `builtin`（忽略其他值）。
- 返回 201，`data` 为 `DramaView`（§5）。建好后后端自动入队研读（`lane = pipeline`）。
- 旧的 multipart 建剧**删除**（前端同时切换）；`target_episodes` 不再接受。
- 错误：67014 草稿过期；67016 我的提示词不存在；67018 技能不可用（未启用或未标该环节）；67022 模型上下文低于 128k；67007 没有可用模型。

## 3. 提示词

### 内置正文 `GET /drama-prompt-templates`

```json
{ "items": [
  { "step": "adapt",  "pages": [ { "key": "plan", "label": "分集规划", "body": "…" }, { "key": "scripts", "label": "分集剧本", "body": "…" } ] },
  { "step": "assets", "pages": [ { "key": "breakdown", "label": "资产拆解", "body": "…" } ] },
  { "step": "asset_prompts", "pages": [ { "key": "asset_prompts", "label": "资产图提示词", "body": "…" } ] },
  { "step": "video",  "pages": [ { "key": "storyboard", "label": "视频提示词", "body": "…" } ] }
] }
```

只返回可替换的正文，不返回输入变量和输出结构。

### 我的提示词 `/drama-prompts`

| 方法 | 说明 | 错误 |
| --- | --- | --- |
| `GET /drama-prompts?step=adapt` | 列表（`step` 可省略返回全部），按 `updated_at` 倒序 | — |
| `POST /drama-prompts` | `{ "step": "adapt", "name": "我的改编", "bodies": { "plan": "…", "scripts": "…" } }` → 201 返回项 | 67017 正文为空或超 20,000 字；名称同环节内重复 → 67017 |
| `PUT /drama-prompts/:id` | 同上字段 + `revision`（乐观锁） | 67016、409 冲突 |
| `DELETE /drama-prompts/:id` | 删除；已建的剧不受影响（快照） | 67016 |

返回项：`{ "id": "1f", "step": "adapt", "name": "我的改编", "bodies": {…}, "revision": 1, "updated_at": "…" }`。`bodies` 的键必须是该环节 `pages[].key` 的子集，缺的页面用内置。

### 可用技能 `GET /drama-skills?step=assets`

`{ "items": [ { "name": "cross-episode-continuity", "title": "跨集连续性", "description": "…" } ] }`：只列已启用、且管理员标了该环节的技能。

### 后台：技能适用环节

`PUT /admin/agent/skills/:name/drama-steps`，`{ "steps": ["assets", "video"] }`（`adapt | assets | asset_prompts | video` 的子集，可为空）。`GET /admin/agent/skills/:name` 返回项新增 `drama_steps: []`。需要管理员，写审计 `agent_skill.drama_steps`。

### 已建剧的提示词设置

- `GET /dramas/:id` 的 `DramaView` 带 `prompt_settings`（§5）。
- `PATCH /dramas/:id` 新增可选字段 `prompts`（同建剧结构）；保存时重新快照正文，**只影响之后提交的任务**；`text_model` 可改（上下文 < 128k → 67022）。

## 4. 自动规划（pipeline）

### 阶段

`DramaView.phase`：`running`（研读 / 规划中）→ `paused` ⇄ `running` → `done`。老项目为 `done`。

### 接口

| 方法 | body | 说明 | 错误 |
| --- | --- | --- | --- |
| `POST /dramas/:id/planning/pause` | — | `running → paused`；在途的那一个任务跑完后停（不中途取消） | 67019 状态不对 |
| `POST /dramas/:id/planning/resume` | — | `paused → running`；失败的批会重试；仍不足积分 → 保持 paused | 67019 |
| `POST /dramas/:id/planning/range` | `{ "range_end": 240 }` | `done` 时扩大范围（只能变大，0 = 全部）→ `running` | 67019；range 不合法 → 10001 |
| `POST /dramas/:id/planning/estimate` | `{ "range_end": 240 }` | 「继续规划」确认框的预估，返回 §1 `estimate` 结构 | — |
| `POST /dramas/:id/planning/retry-builtin` | `{ "step": "adapt" }` | 把该环节改回内置后 resume（自定义提示词导致失败时） | 67019 |

### 任务视图

`DramaJobView` 新增：`lane`（`pipeline` | `user`）、`step` 新值 `plan`、`batch_from` / `batch_to`（plan 任务对应的单元号）。pipeline 任务失败时项目进入 `paused`，`DramaView.pause_reason` 写原因，`pause_code`：`user` | `credits` | `failed` | `context` | `custom_prompt`（custom_prompt 时界面多给「改用内置重试」）。

### 推进

- 剧本型输入：研读完后代码一次切完全部集，`phase` 直接 `done`，不产生 plan 任务。
- 小说：每批规划完成后，新集立即可见（WS 推送 `drama_episode` / `drama` 消息，沿用现有类型），前端可以马上对它们发起 scripts。

## 5. 视图字段变化

### `DramaView` 新增

```json
{
  "source_kind": "novel",
  "source_chars": 4860000,
  "units_total": 1215,
  "unit_kind": "chapter",
  "phase": "running",
  "plan_cursor": 44,                    // 已规划到第几个单元
  "range_end": 1215,                    // 0 已归一为 units_total
  "pause_reason": "", "pause_code": "",
  "prompt_settings": {
    "adapt":  { "source": "builtin", "label": "内置" },
    "assets": { "source": "skill", "skill": "cross-episode-continuity", "label": "技能 · 跨集连续性" },
    "asset_prompts": { "source": "mine", "id": "1f", "label": "我的 · 古风资产", "missing": false },
    "video":  { "source": "builtin", "label": "内置" }
  }
}
```

`missing = true` 表示快照来源（我的提示词 / 技能）已被删或停用：快照照常可用，界面在该行标红提示。`target_episodes` 保留只读（老数据）。

### `DramaEpisodeSummary` / `DramaEpisodeView` 新增

`hook`、`cliffhanger`（string）、`unit_from`、`unit_to`（int，0 = 未关联单元）。`PATCH /dramas/:id/episodes/:no` 可改 `hook`、`cliffhanger`（同 `revision`）。

### 单元原文（可选，前端「对应原文」查看）

`GET /dramas/:id/units?from=1&to=12` → `{ "items": [ { "no": 1, "title": "…", "chars": 3980 } ] }`；`GET /dramas/:id/units/:no` → 带 `text`。

## 6. 用户任务规则变化（`POST /dramas/:id/jobs`）

- `Episodes` 去掉 `max=100` 的上限（集号上限放到 100000，单次最多 200 集）。
- **并行**：pipeline 在跑时，用户任务照常可以提交。用户文本任务（scripts / breakdown / asset_prompts）彼此互斥（仍报 67004）；媒体任务（storyboard / compose / 片段）只允许已锁定的集，同一集互斥。
- `scripts`：只能选已规划的集（有 `title`）；上一集没有剧本时照常写，后端用上一集 `synopsis + cliffhanger` 衔接。小说专用，`source_kind = script` 的剧提交 scripts → 67006。
- `breakdown`：`ratio` 字段忽略（比例以项目为准）；小说只能选有剧本的集。
- 规划中（`phase = running`）`POST /dramas/:id/episodes`（新增集）和删集 → 67019。
- `estimate` 接口同步支持 `scripts` 时提示上一集缺剧本：返回新增 `gap_episodes: [8]`（选中集里上一集既没剧本、也不在本次选择中的集号）。

## 7. 错误码（新增 67014–67022）

| 码 | 含义 |
| --- | --- |
| 67014 | 文件已过期，请重新上传 |
| 67015 | 自定义提示词或技能导致输出不合格（附带环节） |
| 67016 | 我的提示词不存在 |
| 67017 | 提示词正文为空、超长或名称重复 |
| 67018 | 技能不可用 |
| 67019 | 当前阶段不允许这个操作（规划中增删集、暂停 / 继续状态不对等） |
| 67020 | 单集对应原文过长（兜底，正常不会出现） |
| 67021 | 预留 |
| 67022 | 模型上下文不足（低于 128k 或装不下一个单元） |

## 8. WebSocket

沿用现有 `drama` / `drama_episode` / `drama_job` 消息，不新增类型；`drama` 消息到达时前端重新拉 `GET /dramas/:id`（含 `phase`、`plan_cursor`）。
