# Agent 组与布局修复设计

可交互演示：[Agent组与布局修复-演示.html](Agent组与布局修复-演示.html)

状态：待确认（未实现）。来源：产品文档《Agent项目》前 3 条。

## 1. 问题与根因

| # | 现象 | 根因（已读代码核实） |
|---|------|------|
| 1 | Agent 打组 / 整理组后，组框常框不全节点 | 后端 `canvasgraph/layout.go` 的 `nodeSize()` 把所有普通节点当成 576×324。前端用 `node.measured`，节点框短边固定 324，竖图是 324×长边，音频 1:1。后端存档里普通节点不带宽高，所以算出的框偏小 |
| 2 | Agent 批量建节点重叠 | 不是并发没加锁：一个 `ApplyOps` 批次在拷贝上顺序执行，版本冲突会重读重试。真正的缺口是：① 同上的尺寸假设；② `placeFree` 只看组外节点的右缘，不看组框，空组先建、成员后 `refit` 变大，会压住之后放的节点；③ `placeInGroup` 固定放在最后一个成员右侧，不做碰撞检测；④ 模型自己传 `position` 时不检查 |
| 3 | `ask_user` 弹窗选项过长看不全 | `decision-dock.tsx` 选项按钮固定 `h-9`，文字带 `truncate` |

解组（`Delete` 先让成员脱离并保持绝对坐标）算法已与前端 `ungroup` 一致，不改算法。

## 2. 方案

### 2.1 节点尺寸对齐（解决 1，并为 2 打底）

后端新增 `nodeFrame(n Node) (w, h)`，按前端 `resolveNodeAspect` 的优先级取宽高比，再套 `nodeFrameSize` 规则：

1. 音频：1:1。
2. `data.mediaAspect`（前端量到成片后回写并持久化；Agent 的 `frames.go` 也会写）。
3. `data.params.aspect_ratio` / `ratio`，格式 `W:H`，Auto 或解析失败视为没有。
4. 都没有：16:9。

尺寸规则：宽高比 ≥ 1 时 `w = round(324×ratio), h = 324`；否则 `w = 324, h = round(324/ratio)`。

`nodeSize()` 改调 `nodeFrame()`。常量 324 和默认 16:9 在 Go 里各定义一处，注释写明对应前端 `web/src/utils/canvas/node-frame.ts`，与现有留白常量的做法一致。

**保证两端一致的办法**：不共用代码（TS 与 Go），而是共用一份测试夹具 `testdata/node-frame-cases.json`（输入 data 与期望宽高），Go 与前端各写一个测试读同一份文件。

### 2.2 防重叠（解决 2）

在 `canvasgraph` 里新增碰撞检测，照搬前端 `place-beside.ts` 的口径：间隔 `AVOID_GAP = 40`，向下错开，最多试 60 次。

采用**两阶段「延后放置」**，让放置结果和 ops 的先后顺序无关（演示稿「延后放置」页对比过三种做法）。

- **阶段一：顺序执行 ops。** 建节点、建组、连线、改成员照常处理。**不带 `position` 的新自由节点和新组，只记下尺寸，先不放位置**，进入「待放置」列表。组内成员的相对排布照常算（第一个在 `(48, 72)`，之后放在最后一个成员右侧、用真实宽度、间隔 `defaultGapX`），组框大小随成员变动重算。
- **阶段二：统一放置。** 所有组框都定型后，按创建顺序依次把「待放置」项放到画布上：每个新组（连成员作为一整块）和每个自由节点，候选位置是「现有内容右侧、顶部对齐」，撞上就整体向下错开。避让对象是此刻所有顶层矩形（已有节点、已放好的组框和自由节点）。成员的绝对坐标 = 组块位置 + 成员相对坐标。
- **不需要「组整体平移」的兜底**：放置发生在所有组框定型之后，先放的节点不会被后撑大的组框压住。
- 模型显式传了 `position`：尊重它，不自动挪动，但在返回结果里追加一条 warning「与节点 X 重叠」，让模型下一步用 `move` 或 `arrange` 修正。
- 只处理本次批次新建或被改动的对象，不去挪用户已有的、互相重叠的老节点。

### 2.3 选项换行（解决 3）

`decision-dock.tsx`：选项按钮 `h-9` 改为 `min-h-9`，`items-center` 改 `items-start` 并给文字加 `py`，主标题去掉 `truncate` 改 `break-words`（`sub` 同理），序号圆点与右侧 `meta` 保持顶对齐。选项列表容器已有 `max-h` 与滚动的话保持，没有则加 `max-h-[40vh] overflow-y-auto`。纯样式改动，不动数据与键盘逻辑。

## 3. 不做的事

- 不改 Agent 工具的入参和返回结构，不改画布存档格式（`mediaAspect`、`params` 已在存档里）。
- 不新增后端存储的节点宽高字段。
- 不处理前端手动操作（前端已经是对的）。

## 4. 测试（先写失败测试）

后端 `backend/internal/tests/agent/`（或现有 canvasgraph 测试目录）：

- 竖图、音频、`mediaAspect` 优先于 `aspect_ratio`、`Auto` 回落 16:9 的 `nodeFrame` 用例；与共享夹具对拍。
- 建组包含竖图成员时，组框恰好包住成员加留白。
- 一批创建 N 个节点（含混合尺寸、含进组与不进组）后，任意两矩形间距 ≥ 40。
- 空组先建、再往里加成员后，后续自由节点不压住组框。
- **顺序无关**：同一批 ops（建空组 G、自由节点 F1/F2、三个成员）换各种合法顺序，最终都不重叠，且组没有被挪动。
- 两个新组同批创建，成员数量不同，不互相压住。
- 显式 `position` 重叠时不挪，返回 warning。

前端 `web/src/tests/`：读同一份夹具，断言 `nodeFrameSize` 的结果；选项长文本换行用现有组件测试方式断言不再带 `truncate`（不做浏览器端到端）。

验证命令：后端 `go test ./internal/tests/...` 定向 canvasgraph 与 agent 目录；前端 `bun test` 定向，加 oxlint / oxfmt。

## 5. 风险

- 文本（script）节点真实高度可能随内容变化，前端靠 `measured`。后端只能按 16:9 估算，仍可能偏差。缓解：组框以 `refit` 为准，前端打开画布后若量到更大，用户可点整理；本期不解决，列为已知局限。
- 角色卡、素材库节点不在 Agent 可创建范围，但可能已在画布上。它们的 `mediaAspect` 若存在则正确，不存在时按 16:9，可能略小。
- 防重叠会让新节点位置比现在更靠下或更远，属预期；上限 60 次后仍撞则放弃避让并给 warning，不会卡死。

## 6. 已确认的决定

1. **采用两阶段「延后放置」**：比「每加一个成员就贴合 + 批末下移兜底」更好。后者在 180 种合法 ops 顺序里有 144 种要把组整体挪走（演示稿模拟），而延后放置一种也不挪、也不重叠。
2. **主文档已回写**：2.2 节由「即时贴合 + 兜底下移」改为两阶段放置，原待确认的「组与组重叠怎么处理」随之取消。
