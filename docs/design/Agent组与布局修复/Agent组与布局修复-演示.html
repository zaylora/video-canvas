延后放置的两个阶段

  1. 阶段一：顺序执行 ops建节点、建组、连线、改成员。不带 position 的新自由节点和新组，只记下尺寸，先不放位置；组内成员的相对排布和组框大小照常算好。
  2. 阶段二：统一放置按创建顺序，把每个组（连成员作为一整块）和每个自由节点放到「现有内容右侧、顶部对齐」，撞上就向下错开（间隔 40，最多 60 次）。
  3. 写入整批原子写入，沿用 revision 乐观锁。
和 ops 顺序无关。放置时所有组框都已定型，所以不会出现「先放好的节点被后撑大的组框压住」，也不需要把组整体平移的兜底。
代价：要在 apply.go 里多一个「待放置」列表和第二阶段；Agent 在批次内部看不到这些节点的位置（它本来也只用 tempId 引用，不受影响）。
不受影响的情形：用户已有的节点不挪；模型显式给了 position 的节点不延后、也不挪，只在返回里提醒重叠。

// nodeFrame：与前端 resolveNodeAspect + nodeFrameSize 一致（提案）
func nodeFrame(n Node) (w, h float64) {
    if n.IsGroup() { return max(groupMinW, n.Width()), max(groupMinH, n.Height()) }
    ratio := 16.0 / 9
    switch {
    case n.Kind() == KindAudio:        ratio = 1
    case data["mediaAspect"] > 0:      ratio = data["mediaAspect"]
    case parseAspect(params["aspect_ratio"] ?? params["ratio"]) > 0:
                                       ratio = that
    }
    if ratio >= 1 { return round(324 * ratio), 324 }
    return 324, round(324 / ratio)
}

// 放置（提案）：候选位置撞上就向下错开，间隔 40，最多 60 次
func (g *Graph) avoid(cand rect, taken []rect) rect {
    for i := 0; i < 60 && anyOverlap(cand, taken, gap=40); i++ {
        cand.y += cand.h + 40
    }
    return cand   // 60 次后仍撞：放弃，并给 warning，不卡死
}

// Apply 的两阶段（提案）
phase1: for op in ops { run(op) }          // 不带 position 的新节点 / 新组 → a.pending（只记尺寸）
phase2: for u in a.pending {               // 此时所有组框已定型，按创建顺序放置
    cand := rightOfContent(topLevelRects()); cand = avoid(cand, topLevelRects())
    place(u, cand)                          // 组：成员绝对坐标 = 组位置 + 相对坐标
}

测试清单（先写失败测试）

  • 竖图、音频、mediaAspect 优先于 aspect_ratio、Auto 回落 16:9；与共享夹具对拍。
  • 建组含竖图成员：组框恰好包住成员加留白。
  • 一批混合尺寸的节点（含进组、不进组）：任意两矩形间距 ≥ 40。
  • 空组先建、再加成员：后续自由节点不压组框。
  • 顺序无关：同一批 ops 换各种合法顺序，最终都不重叠、组也不被挪动。
  • 显式 position 重叠：不挪，返回 warning。
  • 前端：同一夹具断言 nodeFrameSize；选项样式断言不再带 truncate。

已确认的决定

  1. 采用两阶段「延后放置」：它在 180 种合法 ops 顺序里没有一种重叠，也没有一种要挪动组；「即时贴合」有 144 种要把组整体挪走（示意模拟，非真实画布）。
  2. 主文档已回写：Markdown 2.2 节改为两阶段放置，原「组与组重叠怎么处理」的问题随之取消。
