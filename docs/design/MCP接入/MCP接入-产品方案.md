# 画布 MCP 接入 · 产品方案

> - **状态**：一期已交付并在 2.88 生产验证（`0.7.9-mcp8`，2026-11-23）。实现细节见同目录 `MCP接入.md`。
> - **本文范围**：只讲产品是什么、给谁用、能做什么、怎么管、怎么验收。不含技术实现。
> - **一句话**：把画布的画布读写、素材生成、成片合成、打包下载能力，以标准协议开放给外部 AI 编程工具，让用户在自己的 AI 工具里直接操作画布。

## 1. 要解决的问题

画布已经具备完整能力：读画布状态、改节点与连线、生成图片视频、合成成片、按节点打包素材。但这些能力现在只有两个入口——网页端手动操作，和平台内置的创作助手。

结果是：

- **专业用户被迫在两个窗口之间搬运**。他们在 Claude Code、Codex、Cursor 这类工具里写脚本、理素材、批量处理，想动画布却只能切回浏览器手动点。
- **批量与自动化做不了**。例如「把这个文件夹里 30 张图逐张挂到对应分镜镜头」「把所有 v1 版本统一替换成 v2」，网页端只能一条条点。
- **AI 工具看不到画布**。它不知道画布上有什么节点、哪些镜头还缺视频，只能靠用户口述。

## 2. 产品定位

给平台加一个**标准协议端点**，让外部 AI 工具把画布当成一个可调用的工具集。

这不是做一个新客户端，也不是把网页塞进别的工具里。定位是**能力出口**：网页端继续服务普通用户，外部工具服务自动化和批量场景，两者读写同一份画布数据。

## 3. 用户与场景

### 3.1 两类角色

| 角色 | 是谁 | 关心什么 |
| --- | --- | --- |
| 接入用户 | 用外部 AI 工具的专业创作者 | 自己就能开通，配一次就能用，清楚自己在动哪个画布 |
| 平台管理员 | 运营 / 技术负责人 | 出了事能一眼看到谁开了、能立刻停掉 |

**开通权在用户手里**：这是用户给自己名下的画布授权一个工具，不需要走审批。管理员的角色是兜底——代客开通、以及违规时停用。

### 3.2 典型场景

- **批量挂素材**：在 AI 工具里说「把 `~/素材/第01-30镜/` 按文件名数字挂到对应镜头」，工具调接口逐个写入。
- **状态体检**：问「这个画布上哪些镜头还没有视频，哪些成片过期了」，工具读一次画布就能答。
- **批量重整**：让工具把某一列节点按顺序重排、统一改提示词，而不是点 40 次。
- **成片重跑**：改了某个镜头后，让工具触发一次重新合成并等结果。

## 4. 产品形态

两件东西：

1. **一个协议端点**：`POST /api/v1/mcp`。外部工具按标准协议连上即可，不需要装插件、不需要开浏览器。
2. **两个入口，一套数据**：
   - 用户自助「我的 MCP 接入」（侧栏账号菜单）：自己建项目、签令牌、随时停用或重新签发。
   - 管理员视角「AI 配置 › MCP 接入」：代客开通、看全部项目、停用任何一条，但**不是开通的前置条件**。
   两个入口用的是同一个新建弹窗（名称 + 能力）、同一套令牌逻辑（一项目一枚、可复制明文、留空用默认有效期）。

## 5. 能力清单（一期）

一期开放 19 个工具，分**两条能力域、十档**权限，按「一次授权对应一类可感知的能力」切，不做粗粒度读写。
默认只勾「读画布」（连同它依赖的「浏览目录」），其余档位由用户自己按需勾。

### 5.0 画布域

| 档位 | 能力 | 工具 |
| --- | --- | --- |
| `canvas:browse` 浏览目录 | 列画布、列模型、搜技能、读技能、查任务，全部无副作用 | 5 个 |
| `canvas:read` 读画布 | 读节点与连线结构；改画布之前必须先有它 | 1 个（`canvas_get_state`） |
| `canvas:media` 查看素材 | 看图片、看视频、从视频抓一帧 | 3 个 |
| `canvas:write` 改画布 | 改节点属性、改生成提示词 | 1 个（`canvas_apply_ops`） |
| `canvas:layout` 重排布局 | 移动节点、整理分组与顺序 | 1 个（`canvas_arrange`） |
| `canvas:compose` 合成成片 | 触发成片合成（消耗算力，不消耗积分） | 1 个（`canvas_compose`） |
| `canvas:generate` 生成素材 | 出图、出视频、出配音（**花归属用户的积分**） | 1 个（`generate_media`） |

### 5.0' 短剧域

短剧不挂在 `canvas:` 前缀下。它确实建立在画布之上（`canvas_projects.drama_id`），
但对外是一套完整能力：剧本、分集、片段、流水线任务。混进画布档位会让人以为「勾了画布权限就能改剧本」，
而改的是用户逐字写的剧本原文。

| 档位 | 能力 | 工具 |
| --- | --- | --- |
| `drama:read` 读短剧 | 列短剧、读大纲人物、读单集全文、读片段 | 2 个（`drama_list` / `drama_read`） |
| `drama:write` 改剧本 | 改大纲人物、改分集标题梗概剧本、改片段提示词与秒数 | 3 个 |
| `drama:run` 跑短剧任务 | 分集剧本、资产拆解、资产提示词、分镜、合成整集（**花归属用户的积分**，合成一步免费） | 1 个（`drama_run_job`） |

**为什么需要一个 `drama_list`**：网页端画布列表有意排除短剧（`drama_id IS NULL`），
`canvas_list` 里看不到短剧画布。没有这个工具，外部工具永远不知道该往 `drama_*` 的 `canvas` 参数里填什么。

**档位之间是依赖闭包，不是互斥**：画布域除「浏览目录」外每一档都要求「读画布」，而「读画布」要求「浏览目录」。
勾「改画布」却不给「读画布」等于给了把用不了的钥匙（工具改之前必须先读），所以界面上勾一档会把它的依赖一起勾上，
取消一档会把它依赖者的档一起取消。这个闭包在写入时和鉴权时各展开一次，改库、直接调接口都留下不了残废配置。

短剧域自成闭包（`write` / `run` → `read`），**不依赖 `canvas:*`**：短剧画布靠 `drama_list` 自己发现，
不该逼用户顺手把画布权限也开出去。

### 5.1 素材生成为什么开放（本期修正）

早期判断是「需要人工确认的操作一期都不开放」，把生成也归进去了。这个判断站不住：**不给生成，MCP 就只剩「看」和「整理」**，
用户真正想自动化的「这几镜重出一遍」用不了，接入的价值掉一半。

真正需要挡住的是**不可逆、又没有天然上限**的操作。生成不是这一类：

- 生成的代价是积分，而积分有余额这个天然上限，烧的是归属用户自己的额度；
- 生成的产品语义本来就是「先出去、不满意再重出一遍」，撤销成本低；
- 外部工具那边弹不出我们的审批卡片，用户点不了「批准」——审批在这里没有落点。

所以对 MCP 改成「**权限档 + 余额**」兜底：勾了「生成素材」才能看到这个工具，任务创建时照常校验余额，
花的是归属用户名下的积分，不额外设项目额度。代价说清楚：这一档会花钱，界面文案直说。

**删除节点仍然不开放**：它不可逆、没有「余额」这种上限，绕过审批就是数据丢失。将来打通审批链路再谈。

### 5.2 短剧为什么整体开放（本期新增）

短剧的写与跑在内置对话里同样是「必须审批」的，但外部接入没有可点的卡片——和生成是同一个问题、同一个解法。
所以短剧的四个写/跑工具也走「权限档 + 余额」，并且复用**同一套业务校验**（锁定集只能改标题 `67005`、
同项目只能一个进行中任务 `67004`、revision 冲突、积分冻结），没有第二份实现。

差别在粒度：短剧拆成读 / 写 / 跑三档。改剧本是覆盖用户原创内容，能读不等于能改；跑任务是花钱，能改不等于能跑。

### 5.3 仍然刻意不开放的能力

| 不开放 | 原因 |
| --- | --- |
| 后台运营类工具（14 个） | 这些是运营后台的读写能力，开放等于把后台权限交给外部工具 |
| 网页交互类（提问、卡片展示） | 外部工具没有对应界面，调用只会卡住 |
| 联网搜索与抓取 | 外部工具自己就有，重复暴露会干扰选择 |
| 删除节点、计划更新 | 需要人工审批才生效，而审批在外部工具上没有落点，且删除没有「余额」这种上限（见 5.1） |


## 6. 权限模型

三层，缺一不可：

```
用户（权限的真正单位）
  └─ 名下资源：这个用户的所有画布与短剧；每次调用只能是其中之一
      └─ 接入项目（配置容器，不是权限边界）
           ├─ 默认画布（可空）：调用没指定时用哪块，仅此而已
           ├─ 权限档位：两条能力域共十档，按需勾选，默认只给「读画布」（+浏览目录）
           ├─ 启停开关：停用后立刻全部失效
           └─ 令牌（凭证，**一个项目只有一枚**）
                ├─ 再签发就是轮换：新令牌立刻可用，旧令牌当场失效，列表里永远只有一枚
                ├─ 明文随时可复制（列表行上的「复制」按钮），不用怕第一次没存下来
                ├─ 有效期默认 30 天（后台可配 1–90），不允许永久
                └─ 可随时注销，注销后立即失效
```

设计要点：

- **令牌不等于账号**。令牌做的事全部记在归属用户名下，管理员始终知道「这个动作是谁授权的」。
- **权限边界是「这块画布属不属于你」**，不是某个字段。每次调用都带画布 code，服务端按归属用户查一次；
  参数被改只会被拒，不会越界。默认画布只是省一次填写，改了它不改变边界。
- **一个项目一枚令牌**。换机器就重新签发，旧的自然作废；不靠「手动注销旧的那一枚」这种容易忘的动作。
  轮换是「先建后删」，中途失败也不会出现「一枚都没有」的空窗。
- **明文可回看，但只对能用的令牌**。明文另存加密副本（AES-GCM），只在令牌未注销、未过期、令牌自己那枚密文存在时才能取回；
  失效的令牌取不出明文——取出来也没用，反而容易让人以为它还能用。
- **失效是立即的**。令牌注销、被轮换、项目停用、归属用户被禁用，四者任一发生，下一次调用立刻被拒，不等缓存过期。
- **错误信息不区分原因**。「无效 / 过期 / 已停用」统一回一句话，避免被拿来试。
- **频率有上限**。每个令牌每分钟请求数有天花板，超了直接拒。

### 6.1 两个时间概念，别混

| 概念 | 管什么 | 默认 | 范围 | 配在哪 |
| --- | --- | --- | --- | --- |
| 令牌有效期 | 这枚令牌什么时候失效 | 30 天 | 1–90 天 | 签发时填；留空用后台「令牌默认有效期」 |
| MCP 调用超时 | **一次调用**最多等多久 | 60 秒 | 5–300 秒 | 后台「MCP 调用超时」，服务端与客户端各有一份 |

两者互不相干：有效期到了要重新签发，超时到了只是这次调用中止（令牌照旧能用）。

超时不是协议层错误，而是一条可执行提示：「这次调用超过 N 秒还没完成，把范围拆小重试，或让管理员调大超时」——
模型读到这句能自己纠正。配置片段里的 `timeout: 60` 是**客户端**等待上限，服务端另有一份，两者设成一样最省心。

## 7. 三个操作流程

### 7.1 用户给自己开通（主路径）

账号菜单 →「我的 MCP 接入」→ 点「新建接入项目」填个名字、勾需要的能力 → 保存 →
在列表里点「签发令牌」（用途随填，有效期可留空）→ 弹窗给明文，同时也给一段可直接粘贴到外部工具的配置片段。
归属就是自己，默认画布留空（调用时自己带，多画布场景本来就要带）。全程不需要管理员参与。

### 7.1' 管理员代客开通（备用）

后台 →「AI 配置 › MCP 接入」→ 同样一个「新建接入项目」弹窗，填名称、勾能力 → 签发令牌。
归属用户在新建时**不用填**（默认落在操作者名下），要代客开通就在「编辑」里改归属——这是「配一次」的事，不该挤进新建。
场景是帮不熟悉配置的同事开通，或者给某个账号预先配好。

### 7.2 用户配置外部工具

把配置片段贴进自己工具的配置里，重连。工具会列出可用能力，用户就能用自然语言使唤它。
端点地址和配置片段常驻在页面顶部，随时可复制，不用回头找那份一次性的弹窗。

### 7.3 一次调用的生命周期

外部工具发起调用 → 校验令牌（未注销、未过期、项目启用、用户可用、频率未超）→
校验工具在开放清单内且权限档位够 → 定画布（参数里指定的 > 项目默认的）→ 校验该画布属于这个用户 →
执行（有单次超时）→ 返回结果。任何一步不过都立刻拒绝，并且不产生副作用。

画布没指定、也没有默认画布时，返回的不是协议错误，而是一句可执行的提示：
「先调 canvas_list 拿到画布 code，再填进 canvas 参数」——这样模型能自己纠正，用户不用猜。

列模型、搜技能、查任务这类工具**不落在任何画布上**，没有画布也照常能调。

### 7.4 生成素材与短剧任务怎么走

外部工具调 `generate_media` 或 `drama_run_job` 时不像网页端那样弹审批，而是直接建任务：
校验权限档与余额 → 按调用 id 生成幂等键（同一次调用重试不会重复建任务）→ 建任务 → 返回任务号。

**提交即返回，不等跑完**：外部工具一次调用最多等几十秒，等一批视频跑完只会撞上超时。
所以契约是「提交 → 拿任务号 → 用 `task_get` 查进度」，工具说明里也这么写，不留给模型「一次调用等到结果」的错觉。

短剧的写（改大纲 / 分集 / 片段）同样是立即生效，不走审批；业务校验（集锁定、revision、并发任务数）
全部由短剧服务执行，和网页端是同一份规则。


## 8. 安全与计量

| 关注点 | 做法 |
| --- | --- |
| 凭证泄露 | 鉴权只认哈希；明文另存加密副本（AES-GCM，副本只服务「复制」这一个动作）；有效期默认 30 天、上限 90 天；可即时注销；一项目一枚，泄漏了直接重新签发即作废 |
| 越权 | 两条能力域共十档权限 + 工具开放清单双重校验；短剧档不依赖画布档，改剧本要单独授权；不开放后台运营类能力 |
| 绕过审批 | 只剩删除这类不可逆操作需要审批，仍不开放；生成与短剧的写/跑改成「权限档 + 余额」兜底（见 5.1、5.2） |
| 花超 | 生成与短剧任务走现有积分校验，烧归属用户自己的余额；不设项目额度，也没有「先超再补」的口子 |
| 卡死 | 单次调用有 5–300 秒上限（默认 60），超时中止并回可执行提示，不把客户端挂着 |
| 写冲突 | 与网页端同一套冲突检测：版本不一致就失败并让工具重新读，不做「最后写入者赢」 |
| 审计 | 建项目、改权限、发令牌、注销令牌都进后台操作审计；每次调用更新项目与令牌的最近使用时间 |
| 计量 | 生成 / 合成任务走现有任务队列，可在「任务队列」页看到；一期不做按项目计费 |

## 9. 验收标准

一期算完成，必须全部满足：

1. 新建接入项目只填名称与能力就能保存：归属默认是操作者，默认画布留空，权限在新建时就能勾。
2. 令牌列表能直接复制明文；有效期留空时用后台配的默认天数（改后台的值，新签的令牌跟着变）。
3. 同一项目再签发一次令牌，旧令牌当场失效、列表里只剩一枚；旧令牌调用回 401。
4. 令牌过期 / 注销 / 项目停用 / 归属用户禁用，四种情况调用都被拒，且错误文案一致。
5. 只读令牌调写接口被拒；没有合成档位的令牌调合成被拒；没有生成档位的令牌连 `generate_media` 都看不到；
   后台运营类工具在清单外（连名字都看不到）。
6. 外部工具能列出工具清单，且清单与勾选的权限严格一致，不多不少。
7. 未先读画布直接写，被拒（沿用现有「读前写」约束）。
8. 勾了生成素材就能从外部工具直接出图：返回任务号、花的是归属用户积分，同一次调用重试不重复出图。
9. 「合成成片」能从外部工具触发并返回任务号，结果能在网页端看到。
10. 不落在画布上的工具（列模型、搜技能、查任务）在项目没配默认画布时也能调通。
11. 单次调用超过后台配的超时，返回「拆小重试 / 让管理员调大」的可执行提示，而不是挂住或协议错误。
12. 同一画布在网页端和外部工具同时改，版本冲突时明确失败，不静默覆盖。
13. 后台操作审计里能查到建项目、发令牌、注销令牌三类记录。
14. 勾「读短剧」后能 `drama_list` 到短剧画布 code，并用它 `drama_read` 读大纲与单集；**不需要同时勾画布权限**。
15. 没勾短剧时，清单里连 `drama_list` 都没有；勾「改剧本」看不到 `drama_run_job`，勾「跑短剧任务」才看得到。
16. 勾「改剧本」后从外部工具改大纲，立即生效（不出现「等待审批」），内容能在网页端短剧页看到。
17. 勾「跑短剧任务」后能提交任务、返回任务号并扣归属用户的积分；同一短剧已有进行中任务时被拒并说明原因。
18. 用普通画布调 `drama_read`，返回「只有短剧画布能用」的业务错误，不是协议错误。

## 10. 不做的事

- 不做第三方自助注册与授权页（一期所有接入由用户本人或管理员开）。
- 不做按项目计费、不做额度包。
- 不做网页端与外部工具的实时同步（通过版本号冲突检测保证一致性即可）。
- 不做**营销工作室**的对外工具：它是一套六七个有状态的步骤（项目 → 商品图 → 事实卡 → 拆解 → 脚本 → 出片），
  没有界面时很难用好；营销出片后「发到画布」，外部工具在画布上接着改更实际。
- 不开放删除节点、后台运营能力。
- 不改画布的编辑模型与渲染链路——本方案只加一层能力出口。

## 11. 分期

| 期 | 内容 | 用户能感知到的变化 |
| --- | --- | --- |
| 一期（已交付） | 端点 + 自助/后台两个入口 + 19 个工具（两条能力域共十档），含**生成直连**与**短剧写/跑直连** | 能在外部 AI 工具里看画布、改画布、出图出视频、触发合成，也能读写剧本、提交短剧任务 |

| 三期 | 自助授权、技能包（让外部工具更懂画布业务） | 第三方可自助接入 |
