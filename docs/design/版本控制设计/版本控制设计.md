
## 1. 数据模型

保留现有 `canvas_projects`：

```text
canvas_projects
- id
- user_id
- title
- payload_json       当前画布快照
- revision           乐观锁版本号
- updated_at
```

新增 `canvas_project_versions`：

```text
canvas_project_versions
- id
- canvas_project_id
- version_no         画布内递增版本号
- payload_json       完整 JSON 快照
- title
- revision           创建该版本时对应的主表 revision
- created_by
- source             autosave / manual / rollback
- label              用户命名或标记
- note               版本备注
- is_pinned          是否永久保留
- created_at
```

自动版本保留最近 100 个，命名或标记的版本永久保留。

## 2. 保存流程

前端：

1. 每次编辑先写入本地撤销栈。
2. 停止编辑 3 秒后触发自动保存，连续编辑最长等 30 秒（见[自动保存节奏设计](../自动保存节奏设计/自动保存节奏设计.md)）。
   - **约束**：后端实现版本表时，`source = autosave` 的版本必须按时间窗口合并（如同一画布 10 分钟内的自动保存合并为一个版本），不要每次 `PUT` 都落一条，否则 100 条的上限很快会被挤满。前端降频只能减轻，不能替代服务端合并。
3. 请求携带当前 `revision` 和完整 `payload_json`。
4. 保存成功后清空已提交的撤销栈，并更新本地 `revision`。

后端在一个事务中：

1. 校验客户端 `revision`。
2. 更新 `canvas_projects` 的当前快照并递增 `revision`。
3. 插入一条 `canvas_project_versions` 历史版本。
4. 根据保留策略清理未标记的旧自动版本。

这样主表继续满足现有读取逻辑，版本表负责恢复和审计。

## 3. 回滚流程

回滚旧版本时：

1. 获取目标版本快照。
2. 将目标快照写入主表。
3. 生成一个新的版本号。
4. 新增一条 `source = rollback` 的历史版本。
5. 保留原来的所有历史版本。

因此回滚本身也是一个新版本，用户可以再次回到回滚前的内容。

## 4. 并发冲突

继续使用现有乐观锁：

```text
revision 不匹配 → 返回 409
```

前端提示：

- 加载最新版本
- 另存为新画布
- 覆盖保存

覆盖保存应明确生成一个新版本，并保留冲突前的历史快照。

## 5. 撤销与重做

撤销重做只放在当前浏览器会话：

```text
undoStack
redoStack
```

建议按“用户可感知操作”入栈，例如：

- 创建节点
- 删除节点
- 修改节点属性
- 移动节点
- 修改连线
- 修改时间线

连续拖动可以合并成一个操作，避免一次拖动产生大量历史记录。刷新页面或更换设备后，撤销栈清空；服务端版本仍然可以恢复。

## 6. 版本接口

建议增加：

```text
GET    /api/v1/canvas/:id/versions
GET    /api/v1/canvas/:id/versions/:versionNo
POST   /api/v1/canvas/:id/versions/:versionNo/rollback
PATCH  /api/v1/canvas/:id/versions/:versionNo
DELETE /api/v1/canvas/:id/versions/:versionNo
```

其中：

- 列表接口返回自动版本折叠后的关键版本
- 详情接口返回完整快照
- 回滚接口创建新版本
- 修改接口用于命名、备注、标记永久保留
- 删除接口只允许删除未标记的自动版本

## 7. 差异比较

差异按画布语义展示：

- 节点新增、删除、修改
- 连线新增、删除、修改
- 时间线片段变化
- 导演场景变化
- 外观和视口变化

后端可以先返回结构化差异数据，前端负责展示。不要直接把整段 JSON 当作用户界面。

这套设计与当前项目的 `payload_json + revision` 结构兼容，第一阶段可以先实现完整快照版本表、自动保存、列表、预览和回滚；操作级撤销重做放在前端实现。
